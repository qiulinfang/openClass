问题序号：2：编辑消息重复生成用户气泡问题

## 问题元信息
- **问题分类**：前端
- **严重程度**：中
- **影响范围**：ChatView 编辑消息交互（AI 通用/教材场景）
- **发现日期**：2025-12-11
- **解决状态**：已解决

## 问题现象
点击聊天气泡的“编辑”后，在输入框内修改内容并发送，消息列表中会出现两条内容几乎相同的用户消息：前一条为旧内容，后一条为编辑后的新消息，导致列表重复、上下文混乱。

## 复现步骤
1. 打开任一 AI 聊天会话（ai-general 或 ai-textbook）。
2. 对最后一条用户消息点击“编辑”。
3. 修改文本后点击发送。
4. 消息列表中旧消息仍保留，新消息重新插入，形成两条用户气泡。

## 用户体验
- 同一语义出现两条用户消息，用户无法判断哪一条被 AI 继续回答。
- 聊天上下文被截断：旧 AI 回复仍挂在旧消息后，导致历史与当前回答混在一起。
- 重复气泡造成列表冗余，滚动和引用操作都更困难。

## 相关文件/模块
- **涉及文件**：
  - `imates-web/src/components/chat/ChatView.vue`：`updateEditedMessage` 的调用入口。
  - `imates-web/src/components/chat/strategies/AiGeneralStrategy.ts`：编辑流程逻辑。
  - `imates-web/src/components/chat/strategies/AiTextbookStrategy.ts`：同类逻辑。
- **涉及模块**：
  - Chat 策略层（AiGeneralStrategy / AiTextbookStrategy）。
  - Pinia Store（aiGeneralChatStore / aiTextbookChatStore）。

## 技术原因 (❌)
1. 策略层 `updateEditedMessage` 在更新消息内容后，直接调用 `sendMessage`，未告知 store “跳过创建用户消息”，导致新的用户气泡被再次插入。
2. 删除历史的逻辑只截断 AI 回复，未对旧用户消息做任何替换或移除。
3. ChatInput 端没有额外的去重机制，因此重复气泡直接展示。

```ts
// ❌ 原实现节选（AiGeneralStrategy）
await this.sendMessage(newContent, { selectedModel: options?.selectedModel })
// sendMessage 会默认创建一条新的用户消息
```

## 正确实现方案 (✅)
1. 仍旧地更新原消息内容并截断其后的历史。
2. 在重新发送时传入 `skipUserMessage: true`，让 store 只发送 AI 请求、不再生成新的用户气泡。
3. 复用同一消息 ID，确保引用/重试逻辑一致。

```ts
// ✅ 修复后的实现（AiGeneralStrategy / AiTextbookStrategy）
await this.sendMessage(newContent, {
  selectedModel: options?.selectedModel,
  skipUserMessage: true,
})
```

## 关键代码/公式
- 代码片段1（截断历史并更新内容）：
```ts
messages[messageIndex].content = newContent
const keep = messages.slice(0, messageIndex + 1)
this.aiGeneralStore.messages.length = 0
this.aiGeneralStore.messages.push(...keep)
```
- 代码片段2（跳过重新创建用户气泡）：
```ts
await this.sendMessage(newContent, {
  selectedModel: options?.selectedModel,
  skipUserMessage: true,
})
```

## 测试验证
- **测试场景**：
  - 场景1：编辑最后一条用户消息并发送，列表应只保留一条气泡且内容更新；AI 回复重新开始。
  - 场景2：在编辑状态下切换不同聊天策略（教材/通用），行为保持一致。
- **验证方法**：
  - 方法1：观察 Pinia devtools，确认 `messages` 数组长度不变，仅内容更新。
  - 方法2：调试 `sendMessage` 入参，查看 `skipUserMessage` 标记已传递。

## 预防措施
- 在策略层统一封装编辑流程，确保所有场景都显式控制 `skipUserMessage`。
- 为编辑功能添加 E2E/UI 测试，验证不会额外插入用户气泡。
- 在发送接口层增加断言：编辑模式下禁止再创建新用户消息。

## 相关链接/参考
- `ChatView` 编辑模式交互设计说明：`docs/ChatInput组件响应式布局优化.md`

## 可复用经验
- 编辑功能应“就地更新”而非重新追加，必要时通过标记参数控制流程。
- Chat 策略层与 Store 层要明确沟通“是否需要创建用户消息”。
- 任何会影响 `messages` 数组长度的操作，都应配合测试确保不会重复。
