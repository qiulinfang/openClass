问题序号：题目卡片图片点击放大功能实现

## 问题元信息
- **问题分类**：`前端`
- **严重程度**：`低`
- **影响范围**：`题目列表组件（QuestionList.vue）中的图片显示功能`
- **发现日期**：`2025-11-13`
- **解决状态**：`已解决`

## 问题现象
题目卡片中的图片无法点击放大查看，用户需要查看图片细节时体验不佳。题目内容中可能包含数学公式图片、几何图形、图表等，这些图片在题目卡片中显示较小，用户需要放大查看细节。

## 复现步骤
1. 步骤1：打开题目列表页面，查看包含图片的题目
2. 步骤2：题目卡片中显示图片，但图片较小，无法看清细节
3. 步骤3：尝试点击图片，发现无法放大查看

## 用户体验
（描述问题对用户体验的影响，使用列表格式）
- 影响点1：无法查看图片细节，影响题目理解
- 影响点2：图片较小，特别是数学公式、几何图形等需要放大查看
- 影响点3：缺少图片预览功能，用户体验不完整

## 相关文件/模块
- **涉及文件**：
  - `imates-web/src/components/QuestionList.vue`：题目列表组件，需要添加图片预览功能
- **涉及模块**：
  - 题目内容渲染模块：负责渲染题目内容，包括图片
  - 图片预览模块：新增模块，负责图片放大预览

## 技术原因 (❌)
（描述导致问题的技术原因，使用列表格式）
1. 原因1：题目内容中的图片没有点击事件监听器，无法响应点击操作
2. 原因2：缺少图片预览对话框组件，无法实现全屏预览功能
3. 原因3：图片样式缺少交互提示（如 cursor: pointer），用户不知道图片可以点击

## 正确实现方案 (✅)
（描述正确的解决方案，使用列表格式）
1. 方案1：添加图片预览对话框组件，使用 Quasar 的 `q-dialog` 组件实现全屏预览
2. 方案2：在题目内容渲染完成后，为所有图片添加点击事件监听器
3. 方案3：添加状态管理，控制预览对话框的显示和隐藏
4. 方案4：优化图片样式，添加 hover 效果和 cursor 提示，提升用户体验
5. 方案5：使用防重复机制，避免重复添加事件监听器

### 实现代码

#### 1. 添加状态管理

```typescript
// 图片预览相关状态
const showImagePreview = ref(false)
```

#### 2. 添加图片点击事件监听器函数
```typescript
// 给元素内的所有图片添加点击事件监听器
const attachImageClickListeners = (container: HTMLElement) => {
  const images = container.querySelectorAll('img')
  images.forEach((img) => {
    // 避免重复添加监听器
    if (img.dataset.hasClickListener === 'true') {
      return
    }
    
    img.dataset.hasClickListener = 'true'
    img.style.cursor = 'pointer'
    
    img.addEventListener('click', (e) => {
      e.stopPropagation()
      const imageUrl = img.src
      if (imageUrl) {
        previewImageUrl.value = imageUrl
        showImagePreview.value = true
      }
    })
  })
}
```

#### 3. 在内容渲染完成后调用监听器添加函数
```typescript
// 在 setContentRef 函数中，题目内容渲染完成后添加图片点击监听器
const setContentRef = async (el: HTMLElement, questionId: string) => {
  if (!el || contentRefs.value.has(questionId)) return

  contentRefs.value.set(questionId, el)

  await nextTick()
  attachImageClickListeners(el)

  // 标记为已渲染完成
  renderedQuestionIds.value.add(questionId)
```

#### 4. 添加图片预览对话框模板
```vue
<!-- 图片预览对话框 -->
<q-dialog 
  v-model="showImagePreview" 
  class="image-preview-dialog"
  :maximized="true"
  transition-show="fade"
  transition-hide="fade"
>
  <div class="preview-overlay" @click="showImagePreview = false">
    <!-- 关闭按钮 -->
    <q-btn
      flat
      round
      dense
      icon="close"
      color="white"
      class="close-btn"
      @click.stop="showImagePreview = false"
    />
    
    <!-- 图片预览区域 -->
    <div class="preview-content" @click.stop>
      <img
        v-if="previewImageUrl"
        :src="previewImageUrl"
        alt="题目图片"
        class="preview-image"
      />
    </div>
  </div>
</q-dialog>
```

### 关键实现点

1. **防重复添加监听器机制**：
```typescript
if (img.dataset.hasClickListener === 'true') {
  return
}
img.dataset.hasClickListener = 'true'
```
使用 `data-has-click-listener` 属性标记已添加监听器的图片，避免重复添加。

2. **事件冒泡控制**：
```typescript
img.addEventListener('click', (e) => {
  e.stopPropagation() // 阻止事件冒泡，避免触发题目卡片点击
  // ...
})
```
点击图片时阻止事件冒泡，避免触发题目卡片的点击事件。

3. **响应式图片尺寸**：
```scss
.preview-image {
  max-width: 90vw;
  max-height: 90vh;
  object-fit: contain;
}
```
使用视口单位（vw/vh）确保图片在不同屏幕尺寸下都能正确显示。

4. **对话框关闭机制**：
```vue
<div class="preview-overlay" @click="showImagePreview = false">
  <div class="preview-content" @click.stop>
    <!-- 图片内容 -->
  </div>
</div>
```
点击遮罩层关闭对话框，点击图片内容区域不关闭（使用 `@click.stop`）。

## 预防措施
（如何避免类似问题再次发生）
- 措施1：在添加事件监听器时，始终使用防重复机制（如 `data-*` 属性标记）
- 措施2：对于动态渲染的内容，在内容渲染完成后统一添加事件监听器
- 措施3：使用 Vue 的响应式状态管理对话框显示状态，避免直接操作 DOM
- 措施4：对于需要阻止事件冒泡的场景，明确使用 `stopPropagation()` 或 `@click.stop`
- 措施5：图片预览功能应该考虑响应式设计，适配不同屏幕尺寸

## 可复用经验
（从这个问题中总结出的可复用经验、最佳实践、设计模式等）
- 经验1：**动态内容事件监听器管理**：对于动态渲染的内容（如 Markdown 渲染的 HTML），应该在内容渲染完成后统一添加事件监听器，并使用标记机制避免重复添加
- 经验2：**事件冒泡控制**：在嵌套的交互元素中，需要明确控制事件冒泡，避免触发不期望的父元素事件
- 经验3：**响应式图片预览**：图片预览功能应该使用视口单位（vw/vh）和 `object-fit: contain` 确保在不同屏幕尺寸下都能正确显示
- 经验4：**用户体验优化**：为可交互元素添加视觉提示（如 `cursor: pointer`），提升用户体验
- 经验5：**对话框关闭机制**：提供多种关闭方式（关闭按钮、遮罩层点击），提升用户体验，同时注意区分可点击区域和不可点击区域
