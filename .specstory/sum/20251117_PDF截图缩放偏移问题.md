问题序号：PDF 截图在缩放下与框选区域发生偏移问题

## 问题元信息
- **问题分类**：前端
- **严重程度**：中
- **影响范围**：Web 端 PDF 截图与手写高亮的交互体验
- **发现日期**：2025-11-17
- **解决状态**：已解决

## 问题现象
在 Web 端 PDF 阅读器中：

- 使用截图工具在页面上拖出一个矩形区域，在 100% 缩放下截图内容与框选区域基本对齐。
- 当将 PDF 放大（例如 200%）或缩小后：
  - 截图得到的图片内容相对于屏幕上看到的框选矩形发生偏移，表现为“截图偏右下”或“偏左上”。
  - 与此类似，手写高亮的实时预览在缩放情况下也曾出现相对于指针的系统性偏移，但最终写入 PDF 的 Ink 注释位置又是正确的。

## 复现步骤
1. 打开 Web 端 PDF 阅读页面，加载任意 PDF。
2. 使用手势或工具将 PDF 缩放到 200% 或 50%。
3. 切换到“截图”工具，在某页上拖出一个矩形选区。
4. 松开鼠标/手指触发截图，对比：
   - 截图对话框中预览的图片内容
   - 页面上看到的选框位置
5. 可以观察到截图内容相对于框选区域发生偏移。

## 用户体验
- 选中的内容与实际截图不一致，用户需要多次尝试才能截到正确区域。
- 在高倍缩放下偏移更明显，影响对细节内容的截取。
- 用户对截图工具的直觉期望被破坏，降低工具的信任度。

- **涉及文件**：

- **涉及模块**：
  - PDF 渲染模块（MuPDF 渲染到 canvas）。
  - 截图工具模块（框选、裁剪、事件派发）。

## 技术原因 (❌)
1. **混用了 CSS 坐标与 canvas 像素坐标**：
   - 框选矩形 `screenshotRect` 的 `x1, y1, x2, y2` 是通过 `getBoundingClientRect()` 得到的，属于 DOM 的 **CSS 像素坐标**。
   - PDF 页面渲染时，canvas 采用高 DPI 渲染：
     ```typescript
     const baseDpr = window.devicePixelRatio || 1
     const renderDpr = baseDpr * 2
     canvas.width = renderWidth * renderDpr
     canvas.height = renderHeight * renderDpr
     canvas.style.width = `${renderWidth}px`
     canvas.style.height = `${renderHeight}px`
     ```
   - 因此 canvas 内部的像素坐标 = CSS 坐标 × `renderDpr`。

2. **截图裁剪时直接使用 CSS 坐标调用 `drawImage`**：
   - 原始实现（简化示例）：
     ```typescript
     const x1 = Math.min(rectInfo.x1, rectInfo.x2)
     const y1 = Math.min(rectInfo.y1, rectInfo.y2)
     const x2 = Math.max(rectInfo.x1, rectInfo.x2)
     const y2 = Math.max(rectInfo.y1, rectInfo.y2)

     const width = x2 - x1
     const height = y2 - y1

     const pageCanvas = pageCanvasRefs.value[pageIndex]

     const offscreen = document.createElement('canvas')
     offscreen.width = width
     offscreen.height = height

     const ctx = offscreen.getContext('2d')

     // ❌ 直接用 CSS 坐标去裁剪高 DPI canvas
     ctx.drawImage(pageCanvas, x1, y1, width, height, 0, 0, width, height)
     ```
   - `x1, y1, width, height` 属于 CSS 坐标，而 `pageCanvas` 的内部像素基于 `renderDpr`，坐标系不一致，导致截图区域系统性偏移。

3. **类似问题也影响手写高亮预览**：
   - 手写预览绘制在 `drawingCanvas` 上，如果同样直接使用 CSS 坐标，而 `drawingCanvas` 也是高 DPI canvas，会导致预览轨迹在缩放后偏移；
   - 不过最终写入 PDF 的 Ink 注释使用的是 PDF 坐标，因此 Ink 本身位置是正确的，只是预览偏移。

## 正确实现方案 (✅)
1. **在截图裁剪前，将 CSS 坐标转换为 canvas 像素坐标**：
   - 根据 `canvas.width / clientWidth` 动态计算当前 canvas 的 DPR 比例，而不是依赖渲染时的局部变量 `renderDpr`：
     ```typescript
     const styleWidth = pageCanvas.clientWidth || parseFloat(pageCanvas.style.width) || widthCss
     const styleHeight = pageCanvas.clientHeight || parseFloat(pageCanvas.style.height) || heightCss
     const dprX = pageCanvas.width / styleWidth
     const dprY = pageCanvas.height / styleHeight
     ```

2. **将框选矩形的 CSS 坐标统一转换到 canvas 坐标系**：
   ```typescript
   const sx = x1Css * dprX
   const sy = y1Css * dprY
   const sWidth = widthCss * dprX
   const sHeight = heightCss * dprY
   ```

3. **使用转换后的像素坐标进行裁剪与绘制**：
   ```typescript
   const offscreen = document.createElement('canvas')
   offscreen.width = sWidth
   offscreen.height = sHeight

   const ctx = offscreen.getContext('2d')
   ctx!.drawImage(pageCanvas, sx, sy, sWidth, sHeight, 0, 0, sWidth, sHeight)
   ```

✅ 实现后的关键截图裁剪代码（节选自 `handleHighlightPointerUp` 截图分支）：

```typescript
if (
  isScreenshotMode.value &&
  isDraggingScreenshot.value &&
  screenshotRect.value &&
  screenshotRect.value.pageIndex === pageIndex
) {
  isDraggingScreenshot.value = false

  const rectInfo = screenshotRect.value
  screenshotRect.value = null

  const x1Css = Math.min(rectInfo.x1, rectInfo.x2)
  const y1Css = Math.min(rectInfo.y1, rectInfo.y2)
  const x2Css = Math.max(rectInfo.x1, rectInfo.x2)
  const y2Css = Math.max(rectInfo.y1, rectInfo.y2)

  const widthCss = x2Css - x1Css
  const heightCss = y2Css - y1Css
  if (widthCss <= 5 || heightCss <= 5) {
    return
  }

  const pageCanvas = pageCanvasRefs.value[pageIndex]
  if (!pageCanvas) return

  // 根据 canvas 实际像素和 CSS 宽度计算 DPR
  const styleWidth = pageCanvas.clientWidth || parseFloat(pageCanvas.style.width) || widthCss
  const styleHeight = pageCanvas.clientHeight || parseFloat(pageCanvas.style.height) || heightCss
  const dprX = pageCanvas.width / styleWidth
  const dprY = pageCanvas.height / styleHeight

  // CSS 坐标 → canvas 像素坐标
  const sx = x1Css * dprX
  const sy = y1Css * dprY
  const sWidth = widthCss * dprX
  const sHeight = heightCss * dprY

  const offscreen = document.createElement('canvas')
  offscreen.width = sWidth
  offscreen.height = sHeight

  const ctx = offscreen.getContext('2d')
  const pageCtx = pageCanvas.getContext('2d')
  if (!ctx || !pageCtx) return

  ctx.drawImage(pageCanvas, sx, sy, sWidth, sHeight, 0, 0, sWidth, sHeight)

  offscreen.toBlob(
    (blob) => {
      if (blob) {
        emit('screenshot-captured', blob)
      }
    },
    'image/jpeg',
    0.9
  )
  return
}
```

## 关键代码/公式
- **关键公式**：
  - `canvas 像素坐标 = CSS 坐标 × (canvas.width / clientWidth)`
  - 该公式统一了 DOM 坐标与 canvas 坐标，避免 DPI / 缩放导致的偏移。

- **渲染时设置 canvas 尺寸的关键代码**：
  ```typescript
  const baseDpr = window.devicePixelRatio || 1
  const renderDpr = baseDpr * 2
  const matrix: mupdf.Matrix = [renderScale * renderDpr, 0, 0, renderScale * renderDpr, 0, 0]

  canvas.width = renderWidth * renderDpr
  canvas.height = renderHeight * renderDpr
  canvas.style.width = `${renderWidth}px`
  canvas.style.height = `${renderHeight}px`
  ```

## 预防措施
- 在涉及 canvas 的所有交互（截图、手写预览、橡皮擦预览等）中：
  - 明确区分“CSS 坐标”和“canvas 像素坐标”，在使用 `drawImage` 或 `stroke` 之前统一转换。
- 为关键模块（截图、手写预览）增加缩放场景下的测试用例，避免只在 100% 缩放下验证。
- 在代码注释中明确标注当前函数使用的是哪种坐标系，提醒后续维护者不要混用。

## 可复用经验
- 在高 DPI 场景中使用 canvas 时：
  - 始终将 DOM / CSS 坐标统一转换为 canvas 像素坐标后再绘制。
  - 通过 `canvas.width / clientWidth` 动态推导 DPR，而不是依赖全局常量，避免将来渲染策略变化时出现隐性 bug。
- 在多模式交互（手写、截图、拖拽）中，尽量保证所有模式使用同一套坐标转换工具函数，减少重复实现和错误概率。
- 对于可视 overlay（框选矩形）和实际绘制层（canvas），可以允许使用不同坐标系，但必须在交汇点（如截图裁剪）做一次明确的转换。
