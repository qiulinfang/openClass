问题序号：统一聊天面板与对话框模式切换实现问题

## 问题元信息
- **问题分类**：`前端`
- **严重程度**：`中`
- **影响范围**：`主页右侧聊天面板 MainChatPanel 与 UnifiedChatDialog 的切换体验`
- **发现日期**：`2025-11-27`
- **解决状态**：`已解决`

## 问题现象
需求：
- 主页右侧有一个聊天面板 `MainChatPanel`（panel 模式）。
- 另有一个全屏统一聊天对话框 `UnifiedChatDialog`（dialog 模式，内部使用 `DraggableDialog` 全屏）。
- 需要在两者之间实现**双向切换**：
  - 从右侧面板点击 Switcher 图标，切换到全屏对话框；
  - 在全屏对话框右上角点击 Switcher 图标，切换回右侧面板。

最初实现中：
- 只实现了 `MainChatPanel` 触发的 `toggle-mode` 事件，在 MainView 里关闭面板并打开对话框；
- `UnifiedChatDialog` 与 `DraggableDialog` 虽有全屏逻辑，但没有向 MainView 冒泡“切回面板”的事件。

## 复现步骤
1. 打开首页，点击右下角悬浮按钮，右侧 `MainChatPanel` 打开。
2. 点击 `MainChatPanel` 左侧 Switcher 图标：
   - 面板关闭，`UnifiedChatDialog` 全屏打开（已实现）。
3. 在 `UnifiedChatDialog` 中尝试通过某个按钮切回 panel：
   - 早期版本中没有对应事件链路，无法做到“从对话框切回面板”。

## 用户体验
- 只能从 panel 进入 dialog，无法从 dialog 返回 panel，模式切换不对称。
- 用户在全屏聊天里无法回到右侧浮动面板的视图，只能直接关闭整个对话框重新通过 FAB 打开 panel，操作路径长。

## 相关文件/模块
- **涉及文件**：
  - `imates-web/src/views/MainView.vue`：负责面板、对话框的整体协调与显示控制。
  - `imates-web/src/components/MainChatPanel.vue`：右侧主聊天面板，提供 `toggle-mode` 事件。
  - `imates-web/src/components/UnifiedChatDialog.vue`：统一聊天对话框，内部包装了 `DraggableDialog`。
  - `imates-web/src/components/DraggableDialog.vue`：基础对话框组件，提供 `toggle-fullscreen` 事件。
- **涉及模块**：
  - 聊天 UI 栈（面板 + 对话框）。

## 技术原因 (❌)
1. **事件只实现了单向链路**：
   - `MainChatPanel` 定义了 `toggle-mode` 事件，MainView 有 `handleToggleMainChatMode`，但对话框方向没有对应事件。
2. **DraggableDialog 未暴露模式切换意图**：
   - 全屏时的 Switcher 图标仅存在于视觉层，未向外发出“模式切换”的事件。
3. **MainView 未统一管理两种形态**：
   - 面板与对话框的开关逻辑在不同地方控制，缺少一个中心化的“模式切换控制器”。

不完整实现示例：
```ts
// MainView.vue
const handleToggleMainChatMode = () => {
  showMainChatPanel.value = false
  uiStore.openAIChatDialog()
}
// 缺少 dialog -> panel 的反向逻辑
```

## 正确实现方案 (✅)
1. **在 DraggableDialog 中增加 toggle-fullscreen 事件**：
   - 定义 `emit('toggle-fullscreen')`，表示“大小切换”的意图，由上层决定具体行为。
2. **UnifiedChatDialog 将 toggle-fullscreen 转换为 toggle-mode**：
   - 在 `UnifiedChatDialog` 中监听 `@toggle-fullscreen`，并向外转发为自身的 `toggle-mode` 事件。
3. **MainView 统一实现双向模式切换**：
   - 保留 `handleToggleMainChatMode`：panel -> dialog；
   - 新增 `handleToggleUnifiedChatMode`：dialog -> panel。

关键实现：

**DraggableDialog.vue**
```ts
const emit = defineEmits<{
  'update:modelValue': [value: boolean]
  'splitter-change': [value: number]
  'toggle-fullscreen': []
}>()

const handleToggleFullscreen = () => {
  // 通知父组件执行全屏 / 非全屏大小切换
  emit('toggle-fullscreen')
}
```

**UnifiedChatDialog.vue**
```vue
<DraggableDialog 
  v-model="localVisible" 
  title="聊天对话"
  ...
  :fullscreen="true"
  @toggle-fullscreen="emit('toggle-mode')"
>
  ...
</DraggableDialog>
```

```ts
const emit = defineEmits<{
  'update:modelValue': [value: boolean]
  'session-created': [sessionId: string, type: 'ai-general' | 'teacher-general']
  'toggle-mode': []
}>()
```

**MainView.vue 模式切换控制**
```ts
// 在右侧 panel 和统一 AI 聊天对话框之间切换
const handleToggleMainChatMode = () => {
  showMainChatPanel.value = false
  uiStore.openAIChatDialog()
}

// 从全屏统一聊天对话框切换回右侧聊天面板
const handleToggleUnifiedChatMode = () => {
  // 关闭 AI 统一聊天对话框
  uiStore.showAIChatDialog = false
  // 打开主页右侧聊天面板
  showMainChatPanel.value = true
}
```

模板绑定：
```vue
<UnifiedChatDialog 
  v-model="uiStore.showAIChatDialog" 
  @toggle-mode="handleToggleUnifiedChatMode"
/>

<MainChatPanel
  v-if="showMainChatPanel"
  @close="showMainChatPanel = false"
  @toggle-mode="handleToggleMainChatMode"
/>
```

## 关键代码/公式
- 事件链路：
  - `DraggableDialog.handleToggleFullscreen` → `emit('toggle-fullscreen')`。
  - `UnifiedChatDialog @toggle-fullscreen="emit('toggle-mode')"`。
  - `MainView @toggle-mode="handleToggleUnifiedChatMode"`。

## 测试验证
- **测试场景**：
  - 场景1：从 FAB 打开右侧 `MainChatPanel`，点击其 Switcher，确认切换到全屏 `UnifiedChatDialog`。
  - 场景2：在全屏对话框中点击右上角 Switcher 图标，确认关闭 dialog 并重新打开右侧 panel。
  - 场景3：多次来回切换，确认状态（`showMainChatPanel`、`uiStore.showAIChatDialog`）始终互斥且正确。
- **验证方法**：
  - 用 Vue Devtools 观察两个状态的变化。
  - 在不同路由下测试，确认不会受其他逻辑（如 PDF 专用 ChatPanel）干扰。

## 预防措施
- 对于有多种“形态”的 UI（panel / dialog / fullscreen），应统一在一个上层容器（如 MainView）中集中管理状态与切换，而不是分散在多个组件中。
- 事件命名应表达“意图”而非“具体行为”（如 `toggle-fullscreen` 而不是 `open-panel`），方便在不同场景复用。
- 每个方向的模式切换都要实现对称逻辑，避免只做单向转换。

## 可复用经验
- 对话框和面板的模式切换是一种常见 UI 需求，通过事件链路 + 中央控制器（如 MainView）可以优雅地实现。
- 形态切换的入口（Switcher 按钮）应尽量统一为“只负责发出意图事件”，具体行为由上层组件决定。
- 将“形态切换”与“业务逻辑”解耦，有利于后续在其他模块中复用相同的 DraggableDialog 形态控制模式。
