问题序号：作业页学科筛选 ID 映射问题

## 问题元信息
- **问题分类**：`前端`
- **严重程度**：`中`
- **影响范围**：`作业查看页学科筛选、/blw-edu-yb/api/app/topic-package-page 接口`
- **发现日期**：`2025-12-12`
- **解决状态**：`已解决`

## 问题现象
作业查看页（`MyHomeworkView`）的学科筛选控件只提供语文/数学等中文名称选项，但提交给后台的值仍使用旧的英文字符串（例如 `math`、`physics`）。后台新版接口期望 1-9 的学科 ID，且在“全部”场景下不应提交 `subject` 字段，导致筛选条件与后台不一致，默认值也无法代表“全部”。

## 复现步骤
1. 进入“作业查看”页面，保持默认的日期和学科筛选。
2. 切换学科为“英语”或“物理”，触发 `apiService.getTopicPackagePage` 请求。
3. 抓包可见请求 Body 中 `subject` 仍为 `math/physics` 等字符串，后台按照 ID 判断，导致筛选条件失效，且默认选中数学无法查看全部学科。

## 用户体验
- 学科筛选看似成功，实际上后台未生效，获取到的作业列表不正确。
- 默认进入页面时就锁定为“数学”，无法立即看到所有科目。
- “全部”选项缺失，用户无法快速清除筛选。

## 相关文件/模块
- **涉及文件**：
  - `imates-web/src/views/MyHomeworkView.vue`：筛选控件与 API 调用。
  - `imates-web/src/services/api-service.ts`：`getTopicPackagePage` 的请求体。
- **涉及模块**：
  - 作业查看视图。
  - 通用 API 服务层。

## 技术原因 (❌)
1. 学科选项仍旧使用英文字符串 value，未与后台最新协议（1-9 ID）同步。
2. `selectedSubject` 默认值设置为 `'math'`，即视图加载即带筛选条件，没有“全部”态。
3. 请求参数直接传入字符串，未对空值进行处理，导致“全部”场景也会传空字符串。

错误示例：
```vue
// ❌ 旧版学科配置
const subjects = [
  { label: '数学', value: 'math' },
  { label: '生物', value: 'biology' },
  { label: '物理', value: 'physics' },
  { label: '化学', value: 'chemistry' },
]

const selectedSubject = ref('math')

await apiService.getTopicPackagePage(pageNumber.value, pageSize.value, selectedDate.value)
```

## 正确实现方案 (✅)
1. 统一使用 1-9 的学科 ID 映射，新增“全部”选项，value 为空字符串。
2. `selectedSubject` 默认值设为 `''`，表示全部科目，用户手动选择才带入筛选。
3. 调用接口时将空字符串转为 `undefined`，确保“全部”不传 `subject` 字段。

正确示例：
```vue
const subjects = [
  { label: '全部', value: '' },
  { label: '语文', value: '1' },
  { label: '数学', value: '2' },
  { label: '英语', value: '3' },
  { label: '物理', value: '4' },
  { label: '化学', value: '5' },
  { label: '生物', value: '6' },
  { label: '政治', value: '7' },
  { label: '历史', value: '8' },
  { label: '地理', value: '9' },
]

const selectedSubject = ref('')

await apiService.getTopicPackagePage(
  pageNumber.value,
  pageSize.value,
  selectedDate.value || undefined,
  selectedSubject.value || undefined,
)
```

## 关键代码/公式
- 学科映射数组：`MyHomeworkView.vue` 中的 `subjects`。
- API 调用：`apiService.getTopicPackagePage(pageNumber, pageSize, updateTime, subject)`。

## 测试验证
- **测试场景**：
  - 选择“英语”“物理”等科目，请求体中的 `subject` 应分别为 `3`、`4`。
  - 选择“全部”时不应包含 `subject` 字段，返回作业列表包含所有科目。
- **验证方法**：
  - 通过浏览器 DevTools 或抓包确认请求体。
  - 与后台校验筛选结果是否与 ID 对应。

## 预防措施
- 在接口联调前统一维护“学校/学科/年级”等 ID 映射常量，通过配置文件集中管理。
- `apiService` 层增加参数校验或断言，避免将非法值直接传给后台。
- 为筛选条件提供“全部”或“清空”入口，避免默认值意外带来筛选。

## 可复用经验
- 与后台协商字段变更后，应同步更新前端枚举值，并统一出口函数，减少散落常量。
- 表单筛选在默认态应展示“全部”，避免用户无感知地携带筛选条件。
- `|| undefined` 处理是向后台发送可选字段的简洁手段，可在 API 层沉淀成工具函数。
