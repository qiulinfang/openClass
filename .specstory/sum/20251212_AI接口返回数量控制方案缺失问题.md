问题序号：AI接口返回数量控制方案缺失问题

## 问题元信息
- **问题分类**：`[架构]`
- **严重程度**：`[中]`
- **影响范围**：`[所有依赖 AI 结果数量的业务（作业推荐、知识图谱、教师助手等）]`
- **发现日期**：`2025-12-08`
- **解决状态**：`[待解决]`

## 问题现象
前端直接把用户输入透传给大模型接口，未限制返回条数/内容长度，导致结果数量不可控、带宽与费用飙升，也无法给不同业务配置差异化的条数策略。

## 复现步骤
1. 在任意 AI 入口（如“作业智能分析”）提交问题。
2. 前端直接调用模型 HTTP 接口，不设置 `top_k` / `pageSize` / `max_tokens` 等限制。
3. 大模型一次性返回大量内容，导致页面展示拥挤且接口耗时不可控。

## 用户体验
- 影响点1：结果条数过多导致页面滚动困难。
- 影响点2：移动端渲染超长文本明显卡顿。
- 影响点3：接口超时或失败率上升，用户误以为功能不可用。

## 相关文件/模块
- **涉及文件**：
  - `imates-web/src/services/api-service.ts`：直接拼装请求参数。
  - `imates-web/src/views/*`：多个视图未做数量限制。
- **涉及模块**：
  - AI 服务调用层：缺少统一的分页/条数策略。
  - 业务页面：无法自定义展示条数。

## 技术原因 (❌)
1. 原因1：调用模型时缺失 `top_k`、`pageSize`、`max_tokens` 等硬性限制。
2. 原因2：缺乏统一服务层，前端各业务自行请求，导致策略无法复用。
3. 原因3：提示词未对结果数量做软约束。

```typescript
// ❌ 当前示例：直接发请求，没有任何数量限制
http.post('/ai/raw', {
  query,
  // 未设置 top_k / pageSize / max_tokens
})
```

## 正确实现方案 (✅)
1. 方案1：在服务端统一封装 AI 请求入口，显式暴露 `topK`、`pageSize`、`maxTokens` 等参数并设置上限。
2. 方案2：在 prompt 中明确“最多返回 N 条 / 控制在 M 字内”。
3. 方案3：前端展示前再切片（如 `results.slice(0, pageSize)`）保证兜底。

```typescript
// ✅ 建议实现：统一服务层设定数量限制
callAiService({
  query,
  topK: Math.min(requestedTopK ?? 5, 20),
  pageSize: Math.min(requestedPageSize ?? 10, 50),
  maxTokens: 1024,
})
```

## 关键代码/公式
- 代码片段1：`callAiService` 中的参数收敛与上限控制。
- 代码片段2：`results.slice(0, pageSize)` 的前端兜底逻辑。
- 公式/算法：无。

## 测试验证
- **测试场景**：
  - 场景1：请求 5 条数据，确认只返回 5 条。
  - 场景2：请求 100 条，验证被限制为 50 条并提示用户。
- **验证方法**：
  - 方法1：检查网络请求 payload 中的数量参数。
  - 方法2：查看日志确认后端已执行上限裁剪。

## 预防措施
- 措施1：所有 AI 接口必须通过统一服务封装。
- 措施2：为数量型参数增加默认值与最大值校验。
- 措施3：在监控中增加“超长响应”告警。

## 可复用经验
- 经验1：AI 接口必须“硬限制 + 软提示”双重控制。
- 经验2：数量策略纳入配置中心，方便按业务区分。
- 经验3：前端兜底切片可避免异常数据击穿 UI。
