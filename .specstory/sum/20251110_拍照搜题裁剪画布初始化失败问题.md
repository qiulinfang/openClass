问题序号：拍照搜题裁剪画布初始化失败问题

## 问题元信息
- **问题分类**：`兼容性`
- **严重程度**：`高`
- **影响范围**：`拍照搜题功能的裁剪画布初始化`
- **发现日期**：`2025-11-10`
- **解决状态**：`已解决`

## 问题现象

在拍照搜题功能中，当用户拍照后进入裁剪界面时，裁剪画布无法正常初始化，控制台报错：

```
ERR_INVALID_URL: Failed to load resource: net::ERR_INVALID_URL
```

具体表现：
- 裁剪画布显示为空白
- 无法看到拍摄的图片
- 用户无法进行图片裁剪操作
- 控制台出现 `ERR_INVALID_URL` 错误

## 复现步骤

1. 步骤1：在 Android 原生 WebView 环境中打开拍照搜题功能
2. 步骤2：点击拍照按钮，调用原生相机拍照
3. 步骤3：拍照完成后，原生端通过 `encodeImageToBase64` 方法将图片编码为 base64 字符串返回给前端
4. 步骤4：前端接收到 base64 字符串后，尝试将其赋值给 `img.src` 来初始化裁剪画布
5. 步骤5：浏览器无法识别纯 base64 字符串作为图片源，抛出 `ERR_INVALID_URL` 错误

## 用户体验

- 影响点1：用户无法看到拍摄的图片，无法确认拍摄效果
- 影响点2：无法进行图片裁剪操作，导致拍照搜题功能完全无法使用
- 影响点3：用户体验严重受损，核心功能无法正常工作

## 相关文件/模块

- **涉及文件**：
  - `imates-web/src/views/PhotoSearchView.vue`：拍照搜题视图组件，包含裁剪画布初始化逻辑
  - `app/src/main/java/com/cosinetech/imates/ui/webview/MainWebViewActivity.java`：原生端 WebView 活动，包含图片编码方法
- **涉及模块**：
  - 拍照搜题模块：负责图片拍摄、裁剪和识别
  - 原生桥接模块：负责原生端与 WebView 之间的数据传递

## 技术原因 (❌)

1. **原因1：原生端返回的 base64 字符串格式不完整**
   - 原生端 `encodeImageToBase64` 方法使用 `Base64.encodeToString` 直接编码图片字节数组
   - 返回的是纯 base64 字符串，缺少 `data:image/jpeg;base64,` 前缀
   - 浏览器无法识别纯 base64 字符串作为图片源

2. **原因2：前端直接使用 base64 字符串作为图片源**
   - 前端代码直接将 `currentImage.value.preview` 赋值给 `img.src`
   - 没有检查或转换 base64 字符串格式
   - 在多个地方（`drawImage`、`initCropCanvas`、`getCroppedImage`）都存在相同问题

3. **原因3：缺少数据格式验证和转换机制**
   - 前端没有统一的 base64 数据格式处理函数
   - 没有对原生端返回的数据格式进行兼容性处理

**错误代码示例**：

```typescript
// ❌ 错误：直接使用可能缺少前缀的 base64 字符串
img.src = currentImage.value.preview
```

```java
// ❌ 原生端返回纯 base64 字符串，缺少 data URL 前缀
private String encodeImageToBase64(java.io.File imageFile) {
    try {
        java.io.FileInputStream inputStream = new java.io.FileInputStream(imageFile);
        byte[] bytes = new byte[(int) imageFile.length()];
        inputStream.read(bytes);
        inputStream.close();
        return android.util.Base64.encodeToString(bytes, android.util.Base64.NO_WRAP);
        // 返回的字符串格式：纯 base64 字符串，如 "iVBORw0KGgoAAAANSUhEUgAA..."
    } catch (Exception e) {
        Log.e(TAG, "图片编码失败", e);
        return "";
    }
}
```

## 正确实现方案 (✅)

1. **方案1：创建数据格式转换辅助函数**
   - 创建 `ensureDataUrl` 函数，用于确保 base64 字符串是完整的 data URL 格式
   - 检查输入是否已经是 data URL 格式（以 `data:image/` 开头）
   - 如果不是，自动添加 `data:image/jpeg;base64,` 前缀

2. **方案2：在所有使用图片源的地方应用转换函数**
   - 在 `drawImage` 函数中使用 `ensureDataUrl` 转换
   - 在 `initCropCanvas` 函数中使用 `ensureDataUrl` 转换
   - 在 `getCroppedImage` 函数中使用 `ensureDataUrl` 转换

3. **方案3：增强错误日志**
   - 在 `img.onerror` 回调中添加详细的错误信息
   - 记录 preview 的类型、长度和开头内容，便于调试

**正确代码示例**：

```typescript
// ✅ 正确：创建数据格式转换辅助函数
// 确保 base64 字符串是完整的 data URL 格式
// 第1步：检查输入是否已经是 data URL 格式
// 第2步：如果不是，添加 data:image/jpeg;base64, 前缀
const ensureDataUrl = (base64: string): string => {
  if (!base64 || typeof base64 !== 'string') {
    return base64
  }
  
  // 如果已经是 data URL 格式，直接返回
  if (base64.startsWith('data:image/')) {
    return base64
  }
  
  // 否则添加前缀
  return `data:image/jpeg;base64,${base64}`
}
```

```typescript
// ✅ 正确：在所有使用图片源的地方应用转换函数
// drawImage 函数中
img.src = ensureDataUrl(currentImage.value.preview)

// initCropCanvas 函数中
img.onerror = (error) => {
  logFlow('初始化裁剪画布失败：图片加载失败', {
    previewType: typeof currentImage.value.preview,
    previewLength: currentImage.value.preview?.length,
    previewStart: currentImage.value.preview?.substring(0, 50),
    error: error instanceof Error ? error.message : String(error),
  })
}
img.src = ensureDataUrl(currentImage.value.preview)

// getCroppedImage 函数中
img.onerror = () => {
  resolve(null)
}
img.src = ensureDataUrl(currentImage.value.preview)
```

## 关键代码/公式

- **代码片段1：ensureDataUrl 辅助函数**
  ```typescript
  const ensureDataUrl = (base64: string): string => {
    if (!base64 || typeof base64 !== 'string') {
      return base64
    }
    
    if (base64.startsWith('data:image/')) {
      return base64
    }
    
    return `data:image/jpeg;base64,${base64}`
  }
  ```
  说明：该函数确保 base64 字符串具有完整的 data URL 格式，兼容原生端返回的纯 base64 字符串和前端已有的完整 data URL 格式。

- **代码片段2：原生端编码方法**
  ```java
  private String encodeImageToBase64(java.io.File imageFile) {
      try {
          java.io.FileInputStream inputStream = new java.io.FileInputStream(imageFile);
          byte[] bytes = new byte[(int) imageFile.length()];
          inputStream.read(bytes);
          inputStream.close();
          return android.util.Base64.encodeToString(bytes, android.util.Base64.NO_WRAP);
      } catch (Exception e) {
          Log.e(TAG, "图片编码失败", e);
          return "";
      }
  }
  ```
  说明：原生端返回纯 base64 字符串，不包含 data URL 前缀。前端需要兼容这种格式。

- **公式/算法：Data URL 格式**
  ```
  data:[<mediatype>][;base64],<data>
  
  示例：
  data:image/jpeg;base64,/9j/4AAQSkZJRgABAQEAYABgAAD...
  ```
  说明：完整的 data URL 格式包含协议前缀、MIME 类型、编码方式和实际数据。浏览器需要完整的 data URL 格式才能正确加载图片。

## 可复用经验

- 经验1：**跨平台数据格式兼容性处理**
  - 在 WebView 与原生端交互时，需要特别注意数据格式的兼容性
  - 原生端和前端可能对同一数据类型有不同的表示方式，需要在接口层进行统一转换
  - 建议在数据接收的入口处进行格式标准化，而不是在使用时再处理

- 经验2：**防御性编程**
  - 对于外部数据源（如原生端返回的数据），应该进行格式验证和转换
  - 使用辅助函数统一处理数据格式，避免在多个地方重复处理
  - 增强错误日志，记录详细的调试信息，便于问题定位

- 经验3：**Data URL 格式处理**
  - 浏览器对 data URL 格式有严格要求，必须包含完整的前缀
  - 纯 base64 字符串不能直接作为图片源使用
  - 创建通用的格式转换函数，确保数据格式的一致性

- 经验4：**错误处理策略**
  - 在图片加载失败时，提供详细的错误信息，包括数据类型、长度、开头内容等
  - 使用统一的日志记录机制，便于问题追踪和调试
  - 考虑添加用户友好的错误提示，而不是静默失败
