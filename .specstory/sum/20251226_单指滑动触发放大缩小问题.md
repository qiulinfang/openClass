问题序号：单指滑动触发放大缩小问题

## 问题元信息
- **问题分类**：`前端/事件处理`
- **严重程度**：`高`
- **影响范围**：`PDF阅读器移动端交互，单指滑动被误识别为缩放`
- **发现日期**：`2025-12-26`
- **解决状态**：`已解决`

## 问题现象
在PDF阅读器中：
- 用户单指滑动时意外触发了缩放功能
- 页面被放大或缩小，破坏了正常的浏览体验
- 特别是在移动设备上，单指滑动经常被识别为双指缩放

## 复现步骤
1. 步骤1：打开PDF阅读器，启用Pointer Events
2. 步骤2：用单指在页面上滑动
3. 步骤3：观察页面是否意外缩放

## 用户体验
- 影响点1：正常的页面浏览被意外缩放中断
- 影响点2：需要频繁手动恢复到合适缩放比例
- 影响点3：移动端交互体验严重下降

## 相关文件/模块
- **涉及文件**：
  - `index.html`：PDF阅读器Pointer Events实现
- **涉及模块**：
  - Pointer Events系统：pointerdown/move/up事件处理
  - 触点状态管理：activePointers Map管理
  - 双指缩放逻辑：多触点缩放检测

## 技术原因 (❌)
1. 原因1：**Pointer Events幽灵触点问题**
   - 鼠标悬停或系统级别的额外触点被错误纳入activePointers
   - 单指操作被误认为双指操作

2. 原因2：**触点状态管理不严谨**
   - 没有严格验证触点是否为真实的用户操作
   - 悬停状态的指针也被当作活动触点处理

3. 原因3：**事件过滤逻辑缺失**
   - 没有过滤掉非用户主动操作的触点
   - 系统生成的辅助触点影响了手势识别

错误示例：
```typescript
// ❌ 没有过滤幽灵触点
const onPointerDown = (e) => {
  activePointers.set(e.pointerId, { x: e.clientX, y: e.clientY });
  // 任何pointerdown都被记录，包括悬停
};

// ❌ 在move中直接使用所有活动触点
const onPointerMove = (e) => {
  if (activePointers.size === 1) {
    // 单指逻辑
  } else if (activePointers.size === 2) {
    // 双指缩放逻辑 - 可能被幽灵触点触发
  }
};
```

## 正确实现方案 (✅)
1. 方案1：**严格的触点验证**
   - 只处理通过pointerdown主动按下的触点
   - 过滤掉悬停状态的指针事件

2. 方案2：**改进Pointer Events策略**
   - 改回使用Touch Events和Mouse Events分离处理
   - 避免Pointer Events的兼容性问题

3. 方案3：**更好的触点状态管理**
   - 使用Map严格管理真实的用户触点
   - 在pointerup时立即清理无效触点

正确示例：
```typescript
// ✅ 严格验证触点来源
const onPointerMove = (e) => {
  // 关键：只处理已记录的活动触点
  if (!activePointers.has(e.pointerId)) return;
  
  activePointers.set(e.pointerId, { x: e.clientX, y: e.clientY });
  
  if (activePointers.size === 1) {
    // 单指逻辑 - 安全的
  } else if (activePointers.size === 2) {
    // 双指缩放逻辑 - 只有真实双指时才触发
  }
};

// ✅ 改用分离的事件处理策略
// 使用 touchstart/touchmove/touchend 处理触摸
// 使用 mousedown/mousemove/mouseup 处理鼠标
```
