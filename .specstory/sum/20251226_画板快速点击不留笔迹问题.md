问题序号：03 画板快速点击不留笔迹问题

## 问题元信息
- **问题分类**：`前端`
- **严重程度**：`中`
- **影响范围**：`imates-web DrawingBoard 普通画笔点按（无移动）不产生可见笔迹`
- **发现日期**：`2025-12-26`
- **解决状态**：`进行中`

## 问题现象
- 用户快速点按画布（按下立刻抬起），没有任何笔迹留下。
- 只有在拖动产生 `mousemove` 后才会出现线条。

## 复现步骤
1. 选择普通画笔（非 SignaturePad）。
2. 在画布上快速点击多次（不拖动）。
3. 观察没有任何可见点。

## 用户体验
- 点按无法标记重点、无法“点一点做标注”。
- 用户会误以为画笔失灵。

## 相关文件/模块
- **涉及文件**：
  - `imates-web/src/components/DrawingBoard.vue`：path 绘制与 tempObject 生成逻辑。
- **涉及模块**：
  - 鼠标事件（mousedown/mousemove/mouseup）
  - path 绘制策略

## 技术原因 (❌)
1. path 绘制逻辑通常要求 `points.length > 1` 才会绘制线段，因此单点路径直接被忽略。
2. 普通画笔的 `tempObject` 可能仅在 `mousemove` 时生成/更新，导致“无 move 时 mouseUp 无可提交对象”。

错误示例（概念示意）：
```ts
// ❌ 只允许多点绘制
if (obj.points && obj.points.length > 1) {
  drawPolyline(obj.points)
}

// ❌ tempObject 仅在 move 更新
handleMouseMove() {
  tempObject = { points: currentPath }
}
```

## 正确实现方案 (✅)
1. 支持单点 path：当 `points.length === 1` 时，绘制一个圆点（半径与 `lineWidth` 相关）。
2. 在 `mousedown` 即初始化 `tempObject`（含起点），保证无 move 也可在 `mouseup` 入栈。

正确示例（概念示意）：
```ts
if (points.length === 1) {
  ctx.arc(p.x, p.y, r, 0, Math.PI * 2)
  ctx.fill()
}

handleMouseDown() {
  currentPath = [p]
  tempObject = { type:'path', points:[p] }
}
```

## 关键代码/公式
- **点大小**：`r = max(1, lineWidth / 2)`

## 测试验证
- **测试场景**：
  - 场景1：快速点按 10 次，应产生 10 个点。
  - 场景2：点按 + 拖动混合，应同时正确显示点与线。
- **验证方法**：
  - 方法1：肉眼观察点按是否有痕。
  - 方法2：检查 `objects` 入栈数量是否增长。

## 预防措施
- 绘制模块设计时明确“点按”属于有效输入。
- 针对 `mousedown`-`mouseup` 无 `mousemove` 的场景增加自动化回归。

- 任何基于路径点的绘制工具都应处理“单点输入”作为合法路径。
