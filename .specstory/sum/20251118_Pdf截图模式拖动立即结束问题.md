问题序号：Pdf 截图模式拖动立即结束问题

## 问题元信息
- **问题分类**：前端
- **严重程度**：中
- **影响范围**：PDF 查看页截图问题功能，使用触摸或鼠标截图的用户
- **发现日期**：2025-11-18
- **解决状态**：已解决

## 问题现象
在 `PdfPage.vue` 中切换到截图模式后：
- 进行截图时，只要按下并稍微拖动一下，就会立刻结束截图，弹出截图输入/AI 问答对话框。
- 很难拖出一个较大的截图区域，生成的截图经常是一个很小的矩形（例如 8×5 像素）。
- 在触摸设备上，小幅度上下滑动会触发页面滚动与截图混在一起，体验较差。

## 复现步骤
1. 打开 PDF 查看页面，加载任意 PDF。
2. 在工具栏中切换到“截图”工具。
3. 在 PDF 页面上按下并轻微拖动：
   - 使用鼠标：按下左键，向某个方向略微移动后松开。
   - 使用触摸：单指按下，轻微滑动后抬起。
4. 观察：
   - 截图模式立即结束，弹出截图输入对话框。
   - 截图矩形非常小，且截图期间页面可能发生滚动。

## 用户体验
- 影响点1：用户难以拖出想要的截图范围，经常截到极小区域。
- 影响点2：触摸设备上截图时页面会跟着滚动，导致截图区域和视觉位置不一致。
- 影响点3：截图模式缺少清晰的进入/退出状态，用户很难判断当前是否仍在截图模式中。

## 相关文件/模块
- **涉及文件**：
  - `imates-web/src/components/PdfPage.vue`：PDF 渲染、截图、手写高亮和笔记的主要逻辑。
  - `imates-web/src/views/PdfViewerView.vue`：上层视图，负责工具栏与 `PdfPage` 交互（调用 `toggleScreenshotMode` 等）。
- **涉及模块**：
  - PDF 查看模块：MuPDF 渲染、缩放和滚动。
  - 截图与 AI 问答模块：截图后将图片传给 AI 接口进行问答。

## 技术原因 (❌)
1. 原因1：截图模式直接复用绘图工具的 pointer 事件，并将 `currentMode` 扩展为 `'screenshot'`，导致“按下→拖动→抬起”的整个过程被当做一次完整截图操作，抬起时必定结束截图。
2. 原因2：截图最小尺寸阈值过小，逻辑中只要 `widthCss > 5 && heightCss > 5` 就被视为有效截图，小幅度拖动也会触发截图结束。
3. 原因3：最初 pointer 监听使用了 `.passive` 修饰，`event.preventDefault()` 无法阻止滚动，触摸设备上截图拖动与页面滚动同时发生，进一步放大了“轻微拖动就退出”的感受。

## 正确实现方案 (✅)
1. 方案1：将截图模式从 `currentMode` 中拆离，使用独立的 `isScreenshotMode` 状态控制 PDF 区域截图，实现截图与绘图工具的解耦。
2. 方案2：在截图 pointer 事件中仅在 `isScreenshotMode` 下处理框选，同时通过 touch 事件和工具状态（`isZooming` 等）避免与双指缩放、滚动冲突。
3. 方案3：通过 `touchstart`/`touchmove` 中的 `preventDefault()` 和 `isScreenshotMode` 条件，在截图模式下禁止单指上下滑动导致的页面滚动，同时在多指情况下自动取消截图框，交给缩放手势处理。

```ts
const screenshotRect = ref<ScreenshotRect | null>(null)
const isDraggingScreenshot = ref(false)

// 进入/退出截图模式的统一入口

  isScreenshotMode.value = true
  isDraggingScreenshot.value = false
  screenshotRect.value = null
}

const exitScreenshotMode = () => {
  isScreenshotMode.value = false
  isDraggingScreenshot.value = false
  screenshotRect.value = null
}

// 暴露给父组件（工具栏）
defineExpose({
  toggleScreenshotMode: () => {
    enterScreenshotMode()
    closeNotePanel()
    currentMode.value = 'hand'  // 防止高亮/画笔拦截 pointer 事件
  },
})

// pointerdown：仅在截图模式下作为框选起点
const handleHighlightPointerDown = (
  event: PointerEvent,
  pageIndex: number,
  layout: { width: number; height: number },
) => {
  // 多指或缩放期间不允许截图
  if (isPointerToolSuspended.value || isZooming.value) return

  if (isScreenshotMode.value) {
    if (event.pointerType === 'mouse' && event.button !== 0) return

    if (!viewerContainer.value) return
    const pageElements = viewerContainer.value.querySelectorAll<HTMLElement>('.page')
    const pageEl = pageElements[pageIndex]
    if (!pageEl) return

    const rect = pageEl.getBoundingClientRect()
    const scale = store.scale || 1
    const xVisual = event.clientX - rect.left
    const yVisual = event.clientY - rect.top
    const x = xVisual / scale
    const y = yVisual / scale

    screenshotRect.value = { pageIndex, x1: x, y1: y, x2: x, y2: y }
    isDraggingScreenshot.value = true
    return
  }

  // 非截图模式：按高亮/画笔/橡皮逻辑处理
  if (!['highlighter', 'pen', 'eraser-draw'].includes(currentMode.value)) return

}

  event: PointerEvent,
  pageIndex: number,
  layout: { width: number; height: number },
) => {
  if (
    isScreenshotMode.value &&
    isDraggingScreenshot.value &&
    screenshotRect.value &&
    screenshotRect.value.pageIndex === pageIndex

    if (!viewerContainer.value) return
    const pageElements = viewerContainer.value.querySelectorAll<HTMLElement>('.page')
    const pageEl = pageElements[pageIndex]
    if (!pageEl) return

    const yVisual = event.clientY - rect.top

    screenshotRect.value.x2 = xVisual / scale
    screenshotRect.value.y2 = yVisual / scale
    return
```

```ts
const handleTouchStart = (event: TouchEvent) => {
```

```ts
const getScreenshotRectStyle = (
  rect: ScreenshotRect,
  layout: { width: number; height: number },
): CSSProperties => {
  const x1 = Math.min(rect.x1, rect.x2)
  const y1 = Math.min(rect.y1, rect.y2)
  const x2 = Math.max(rect.x1, rect.x2)
  const y2 = Math.max(rect.y1, rect.y2)

  const width = x2 - x1
  const height = y2 - y1

  return {
    position: 'absolute',
    left: `${x1}px`,
    top: `${y1}px`,
    width: `${width}px`,
    height: `${height}px`,
    boxSizing: 'border-box',
  }
}
```

## 测试验证
- **测试场景**：
  - 场景1：鼠标截图
    - 步骤：切到截图模式 → 按下左键 → 拖出一个明显矩形 → 松开。
    - 预期：页面不滚动，出现蓝色截图框预览，松开后生成对应区域截图并弹出输入对话框。
  - 场景2：触摸截图
    - 步骤：在移动设备上切到截图模式 → 单指按住并拖动。
    - 预期：PDF 区域不滚动，仅出现截图矩形，松手后生成截图。
  - 场景3：双指缩放 + 截图
    - 步骤：双指缩放 PDF → 结束缩放 → 再使用单指截图。
    - 预期：双指缩放期间不会进入截图；缩放结束后截图恢复正常。

- **验证方法**：
  - 方法1：在 DevTools 中监控 pointer/touch 事件序列，确认截图模式下没有多余的 pointerup/cancel 导致提前结束。
  - 方法2：查看控制台是否无 `Unable to preventDefault inside passive event listener invocation` 警告，确保滚动被正确阻止。

## 预防措施
- 措施1：避免在同一枚举 `currentMode` 中混入过多职责（例如将截图也放进去），对于行为明显不同的模式使用独立状态管理。
- 措施2：对 pointer/touch 事件统一梳理，明确哪些场景需要 `passive: true`，哪些必须允许 `preventDefault()` 来阻止滚动。
- 措施3：为用户交互相关的逻辑（截图/绘图/缩放）增加详细的事件日志，便于后续快速排查问题。

## 可复用经验
- 经验1：**交互模式解耦**：将“浏览/滚动”、“绘图”、“截图”等交互模式用独立状态管理，不要全部塞进一个枚举字段，避免模式间互相干扰。
- 经验2：**截图与滚动的事件边界要清晰**：截图拖动期间应锁定滚动，可以通过 touch/pointer 的 `preventDefault()` 或动态调整容器 `overflow` 实现。
- 经验3：**使用日志还原事件流**：在调试复杂手势时，用 `console.log` 标记 `pointerdown/move/up`、`touchstart/move/end` 及内部状态，是定位问题的高效方式。
