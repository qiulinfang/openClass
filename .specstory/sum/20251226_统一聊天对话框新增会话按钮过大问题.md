问题序号：统一聊天对话框新增会话按钮过大问题

## 问题元信息
- **问题分类**：`前端`
- **严重程度**：`低`
- **影响范围**：`统一聊天对话框（UnifiedChatDialog）AI通用聊天顶部“新增会话”按钮显示`
- **发现日期**：`2025-12-26`
- **解决状态**：`已解决`

## 问题现象
统一聊天对话框中，`ChatView` 头部右侧的“新增会话”按钮（加号图标）显示尺寸偏大，导致头部区域视觉不协调。

## 复现步骤
1. 打开统一聊天对话框：`UnifiedChatDialog`。
2. 切换到 AI 通用聊天界面（`type="ai-general"`）。
3. 观察聊天头部右侧的“新增会话”按钮（加号图标），其点击区域和图标尺寸明显偏大。

## 用户体验
- 头部操作区视觉不协调，显得“突兀”。
- 在紧凑布局/小屏下更容易产生拥挤感。
- 用户可能误以为该按钮优先级高于其它操作。

## 相关文件/模块
- **涉及文件**：
  - `imates-web/src/components/UnifiedChatDialog.vue`：`ChatView` 的 `header-right` 插槽内新增会话按钮（`add-session-btn` / `add-session-icon`）。
- **涉及模块**：
  - 统一聊天对话框 UI
  - ChatView 头部插槽区域

## 技术原因 (❌)
1. `header-right` 插槽里自定义的 DOM（`div` + `img`）缺少明确的尺寸约束。
2. 图标以图片形式渲染，默认受父容器/布局影响，容易出现放大（尤其在 flex 对齐或继承样式时）。

```vue
<!-- ❌ 仅示意：缺少按钮区域和图标尺寸约束 -->
<template #header-right>
  <div @click="handleNewChatClick" class="add-session-btn">
    <img :src="addSessionIcon" class="add-session-icon" alt="新增会话" />
  </div>
</template>
```

## 正确实现方案 (✅)
1. 在 `UnifiedChatDialog.vue` 的 `scoped` 样式内，对 `.add-session-btn` 与 `.add-session-icon` 增加明确尺寸约束。
2. 通过 `inline-flex` 保证图标在按钮区域内居中，避免布局挤压造成视觉放大。

```scss
/* ✅ 限制点击区域与图标大小（仅影响当前组件作用域） */
.add-session-btn {
  width: 28px;
  height: 28px;
  display: inline-flex;
  align-items: center;
  justify-content: center;
  cursor: pointer;
}

.add-session-icon {
  width: 18px;
  height: 18px;
  display: block;
}
```

## 关键代码/公式
- **代码片段1：新增会话按钮 DOM**
```vue
<template #header-right>
  <div @click="handleNewChatClick" class="add-session-btn">
    <img :src="addSessionIcon" class="add-session-icon" alt="新增会话" />
  </div>
</template>
```

- **代码片段2：按钮/图标尺寸约束（scoped CSS）**
```scss
.add-session-btn { width: 28px; height: 28px; }
.add-session-icon { width: 18px; height: 18px; }
```

## 测试验证
- **测试场景**：
  - 场景1：桌面端打开 `UnifiedChatDialog`，观察 AI 通用聊天头部新增会话按钮大小是否正常。
  - 场景2：模拟窄屏（或缩小窗口宽度），观察头部右侧按钮是否溢出/变形。
- **验证方法**：
  - 方法1：确认按钮点击区域变小但仍易点击，图标居中。
  - 方法2：对比修改前后头部区域的视觉一致性。

## 预防措施
- 对所有自定义插槽内的图标按钮统一抽取基础样式（尺寸、对齐、hover），避免各处默认样式不一致。
- 对 `img/svg` 图标类组件统一规定 `width/height`，避免继承导致的缩放异常。
- 在 PR Review 中增加 UI 细节检查项（头部按钮尺寸、间距、对齐）。

## 可复用经验
- 自定义 `header-right` / `slot` 区域时，建议把交互区域和图标尺寸显式写死（或使用统一组件），避免在不同容器中出现不可控的放大/挤压。
- `scoped` 样式优先用于局部修复，确保改动不外溢影响其它页面。
