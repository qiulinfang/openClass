问题序号：AI教材切换账号后端会话串线问题

## 问题元信息
- **问题分类**：`前端`
- **严重程度**：`高`
- **影响范围**：`AI教材问答（PdfViewerView/aiTextbook）切换账号后上下文串线`
- **发现日期**：`2025-12-26`
- **解决状态**：`已解决`

## 问题现象
A账号登录后在 AI 教材场景发送消息，退出后登录 B 账号再次发送消息，后端会话 `sessionId/thread_id` 仍沿用 A 的值，导致 B 的对话上下文混入 A 的历史（串会话）。

## 复现步骤
1. 步骤1：登录 A 账号（保证 ai-general/ai-textbook 都没有默认会话或会话为空）。
2. 步骤2：进入教材问答，发送一条消息。
3. 步骤3：退出登录 A，登录 B 账号（不刷新页面/Pinia store 未重置的场景更容易复现）。
4. 步骤4：进入教材问答再次发送消息。
5. 步骤5：观察网络请求/日志，后端 `sessionId` 仍为 A 的会话，B 的对话串入 A 的上下文。

## 用户体验
- 影响点1：不同账号的对话相互污染，答案上下文错误。
- 影响点2：排查困难（前端会话 id 看似不同，但后端 thread_id 复用）。
- 影响点3：存在潜在隐私风险（A 的对话上下文影响 B）。

## 相关文件/模块
- **涉及文件**：
  - `imates-web/src/stores/aiTextbookChatStore.ts`：后端 sessionId（thread_id）选择与缓存。
  - `imates-web/src/views/PdfViewerView.vue`：截图会话 sessionId（本地）生成。
- **涉及模块**：
  - aiTextbookChatStore：教材聊天 store
  - aiGeneralChatStore：通用聊天根会话来源

## 技术原因 (❌)
1. `aiTextbookChatStore.ensureTopGeneralSession()` 会优先复用内存中的 `backendSessionId`。
2. 切换账号时如果 Pinia store 未重建/未调用清理逻辑，`backendSessionId` 仍留在内存中。
3. 发送教材消息时请求参数使用 `sessionIdForBackend`（即后端 thread_id），与 PdfViewerView 自己生成的本地 `currentSessionId` 不是同一个概念，导致“表面看 sessionId 变了，但后端仍复用旧 thread”。

错误代码示例（节选）：
```ts
// ❌ 没有账号隔离：只要 backendSessionId 存在就复用
if (backendSessionId.value) {
  return backendSessionId.value
}
```

## 正确实现方案 (✅)
1. 在 `aiTextbookChatStore` 内记录 `backendSessionId` 的归属 userId。
2. `ensureTopGeneralSession()` 每次执行时读取 `localStorage.userId`，若与已记录的归属 userId 不一致，则丢弃旧 `backendSessionId` 并重新生成。
3. 在 `clearMessages()` / `setResourceId()` 重置 session 时同步清空归属信息。

正确代码示例（节选）：
```ts
const backendSessionOwnerUserId = ref<string | null>(null)

const ensureTopGeneralSession = async () => {
  const currentUserId = localStorage.getItem('userId') || ''

  if (backendSessionId.value && backendSessionOwnerUserId.value !== null && backendSessionOwnerUserId.value !== currentUserId) {
    backendSessionId.value = null
    backendSessionOwnerUserId.value = null
  }

  // ...后续正常选择/生成 session
}
```

## 关键代码/公式
- 代码片段1：`aiTextbookChatStore.ensureTopGeneralSession()`：后端 thread_id 的选择入口。
- 代码片段2：`aiTextbookChatStore.clearMessages()`、`setResourceId()`：重置会话相关状态。

## 测试验证
- **测试场景**：
  - 场景1：A 登录发送教材消息 -> 退出 -> B 登录发送教材消息；预期 B 生成新的 `textbook-session-...`（或对应 B 的 ai-general session），不复用 A。
  - 场景2：仅切换教材 resourceId；预期会话重置且不串线。
- **验证方法**：
  - 方法1：观察控制台日志中 `userId 变化，丢弃旧 backendSessionId` 与 `创建新 backendSessionId`。
  - 方法2：抓包/日志对比 A、B 的后端请求 `sessionId`。

## 预防措施
- 措施1：在“退出登录/切换账号”的统一入口显式调用各聊天 store 的清理方法（双保险）。
- 措施2：关键 store 内部增加“账号归属”校验，避免仅靠外部 reset。
- 措施3：区分“本地会话 id”与“后端 thread_id”的命名与日志，减少误解。

## 可复用经验
- 经验1：凡是“会话/缓存”一旦可能跨账号复用，都应加 owner key（userId/tenantId）做隔离。
- 经验2：UI 层的会话 id 与后端 thread_id 不是同一概念时，要在日志/变量命名中明确区分。
