问题01：聊天消息链接点击全局跳转问题

## 问题元信息
- **问题分类**：`前端`
- **严重程度**：`中`
- **影响范围**：`聊天消息气泡中的 URL/超链接点击行为（ChatView/UnifiedChatDialog 场景）`
- **发现日期**：`2025-12-26`
- **解决状态**：`已解决`

## 问题现象
在聊天消息气泡（Markdown 渲染内容）中点击网络链接时，页面发生全局跳转（离开当前聊天弹窗/页面），而不是在当前聊天对话框内以弹窗形式预览链接内容。

## 复现步骤
1. 进入任意聊天界面（例如 UnifiedChatDialog 内的 ChatView）。
2. 找到一条消息内容中包含 `http/https` 链接的气泡（Markdown 渲染产生 `<a>`）。
3. 点击链接。
4. 现象：浏览器默认行为触发全局跳转，导致当前聊天上下文被打断。

## 用户体验
- 点击链接后离开当前页面，聊天上下文中断。
- 在弹窗聊天模式下，用户会感觉“对话框被带走/消失”。
- 回退后可能需要重新定位消息位置，影响阅读连续性。

## 相关文件/模块
- **涉及文件**：
  - `imates-web/src/components/chat/ChatMessage.vue`：消息内容使用 `v-html` 渲染；需要拦截 `<a>` 点击。
  - `imates-web/src/components/ChatView.vue`：承接 `open-link` 事件并以弹窗展示链接（改为 `DraggableDialog`）。
  - `imates-web/src/components/DraggableDialog.vue`：弹窗组件；增强右下角 resize 把手的易用性。
- **涉及模块**：
  - 消息渲染（MarkdownIt + `v-html`）
  - 弹窗系统（DraggableDialog）

## 技术原因 (❌)
1. **Markdown 渲染后的链接是原生 `<a>`**：消息内容通过 `v-html` 注入 DOM，点击 `<a>` 会走浏览器默认导航。
2. **缺少事件委托拦截**：消息组件只处理了图片点击（预览），没有统一处理 `<a>` 点击。
3. **预览容器未隔离顶层导航**：即使改为 iframe 预览，iframe 内站点仍可能通过 `target="_top"`/`window.top.location` 触发顶层跳转。

```vue
<!-- ❌ 示例：消息内容 v-html 渲染，未拦截 a 点击 -->
<div v-html="renderedContent"></div>
```

## 正确实现方案 (✅)
1. **在 ChatMessage 内做事件委托拦截链接**：优先识别 `a[href]`，并 `preventDefault + stopPropagation`。
2. **通过组件事件向上抛出 open-link**：由父组件决定“如何打开”（弹窗/新窗口/复制）。
3. **在 ChatView 内使用 DraggableDialog 弹窗预览**：不再触发全局路由/页面跳转。
4. **iframe 增加 sandbox 防顶层跳转**：禁止 iframe 内页面把 `top` 导航走；兼顾基本可用性。
5. **增强 DraggableDialog resize 把手**：扩大右下角拖拽改大小的点击区域和可见性，避免 iframe 全铺导致难以拖拽。

```ts
// ✅ ChatMessage.vue：拦截 a[href] 并抛出事件
const linkElement = target?.closest?.('a[href]') as HTMLAnchorElement | null
if (linkElement && linkElement.href) {
  event.preventDefault()
  event.stopPropagation()
  emit('open-link', linkElement.href)
  return
}
```

```vue
<!-- ✅ ChatView.vue：使用 DraggableDialog + iframe 预览，并加 sandbox 限制 -->
<DraggableDialog v-model="showLinkDialog" title="链接预览" :initial-width="900" :initial-height="600">
  <iframe
    v-if="currentLinkUrl"
    :src="currentLinkUrl"
    sandbox="allow-same-origin allow-scripts allow-forms allow-popups"
    referrerpolicy="no-referrer"
    style="border: 0; width: 100%; height: 100%"
  ></iframe>
</DraggableDialog>
```

## 关键代码/公式
- `ChatMessage.vue`：`handleImageClick` 内增加对 `a[href]` 的事件委托拦截，并 `emit('open-link')`。
- `ChatView.vue`：监听 `@open-link="handleOpenLink"`，并维护 `showLinkDialog/currentLinkUrl`。
- `ChatView.vue`：链接预览 iframe 增加 `sandbox`，防止顶层导航。
- `DraggableDialog.vue`：扩大 `.resize-handle`（24px -> 36px）并提升可见性。

## 测试验证
- **测试场景**：
  - 场景1：点击聊天气泡中的普通链接（`https://...`）。
    - 预期：不发生全局跳转，弹出 `DraggableDialog`，iframe 内加载该链接。
  - 场景2：在预览 iframe 内继续点击站内链接。
    - 预期：仅在 iframe 内跳转，不影响顶层应用页面。
  - 场景3：尝试拖拽预览弹窗右下角改变大小。
    - 预期：右下角把手明显、容易点中，可顺滑 resize。
- **验证方法**：
  - 方法1：观察地址栏/路由不变化，页面不跳转。
  - 方法2：浏览器控制台无全局导航行为；顶层页面保持在聊天页面。

## 预防措施
- 在富文本/Markdown `v-html` 场景统一使用事件委托拦截（至少包含 `<a>`、`<img>`）。
- 对“外链预览”统一使用受控打开策略（弹窗/内嵌/新窗口），避免散落的默认 `<a>` 行为。
- iframe 预览默认开启 `sandbox`，并根据业务按白名单逐步放开权限。

## 可复用经验
- 富文本渲染（`v-html`）必须同步设计“交互拦截层”，否则会被浏览器默认行为带走。
- 预览外部网页时，`iframe sandbox` 是防止顶层跳转/隔离副作用的关键措施。
- 交互手柄（resize-handle）在“内容全铺（如 iframe）”场景需要更大的命中区域与更高层级。
