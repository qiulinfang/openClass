问题序号：PDF 截图框选功能实现问题

## 问题元信息
- **问题分类**：前端
- **严重程度**：中
- **影响范围**：教材 PDF 查看页中的截图提问功能
- **发现日期**：2025-11-17
- **解决状态**：已解决

## 问题现象
在新版 `PdfViewerView.vue` + `PdfPage.vue` 组合下，希望实现“在 PDF 上拖一个截图框，将截图和问题一起发送给 AI”的功能：

- 工具栏已有 `screenshot` 工具按钮，但点击后在 PDF 上拖拽只触发了手写逻辑，没有截图框选。
- 之前在旧版 `PdfViewerView111.vue` 中截图逻辑是基于虚拟滚动 `PdfPage` + 截图事件实现的，新版布局改为单个 `PdfPage`，旧逻辑无法直接复用。
- 后续在实现截图保存为 Blob 并传递给 AI 时，需要有**可视化裁剪框**，用户拖动时能看到选区范围。 

## 复现步骤
1. 在 `PdfViewerView.vue` 中配置工具栏 `pdfToolbarTools`，中间工具包含 `'screenshot'`：
   - `middle: ['hand', 'highlighter', 'pen', 'eraser-draw', 'screenshot']`。
2. 在浏览器中打开教材 PDF 查看页，点击工具栏中的截图工具。
3. 在 PDF 页面上按下鼠标左键并拖动。
4. 现象：
   - 要么仍然进入手写高亮/画笔逻辑；
   - 要么虽然后端代码尝试裁剪，但页面上没有可视的截图矩形，不知道最终截图范围。

## 用户体验
- 影响点1：用户无法直观地看到截图选区，很难精确选择题目或段落区域。
- 影响点2：拖拽操作和手写高亮混在一起，容易误操作，降低交互清晰度。
- 影响点3：即使后端正确拿到截图 Blob，前端没有可视反馈，用户体验不完整。

## 相关文件/模块
- **涉及文件**：
  - `imates-web/src/views/PdfViewerView.vue`：负责工具栏配置、当前工具切换、与 `PdfPage` 通讯以及接收截图 Blob 发送给 AI。
  - `imates-web/src/components/PdfPage.vue`：负责 PDF 渲染、手写/橡皮擦交互以及新增的截图框选逻辑。
- **涉及模块**：
  - PDF 渲染模块：MuPDF + `pageCanvasRefs`（每页主绘制 canvas）。
  - AI 问答模块：`useAiTextbookChatStore` + `ScreenshotInputDialog` + `ChatView`。

## 技术原因 (❌)
1. 原因1：原有 `PdfPage.vue` 中所有 pointer 事件（`handleHighlightPointerDown/Move/Up`）仅为高亮/画笔/橡皮服务，通过 `currentMode` 判断，缺少独立的“截图模式”分支，导致 screenshot 工具选中后仍走手写逻辑。
2. 原因2：没有维护截图拖拽状态和矩形数据结构（起点 x1/y1、终点 x2/y2 等），也没有对应的模板 overlay 元素来展示截图框，用户看不到选区。
3. 原因3：裁剪图片时，如果直接使用 DOM 坐标而没有考虑页面缩放、canvas 像素尺寸差异，容易出现截图偏移或模糊问题，因此需要在页面 DOM 坐标与 canvas 像素坐标之间做转换或保持一致性。

## 正确实现方案 (✅)
1. 方案1：在 `PdfPage.vue` 中新增独立的截图模式状态和矩形数据结构：
   - `isScreenshotMode: Ref<boolean>`：当前是否处于截图模式。
   - `screenshotRect: Ref<{ pageIndex, x1, y1, x2, y2 } | null>`：用户当前拖出的裁剪框。
2. 方案2：在 pointer 事件处理函数内优先判断 `isScreenshotMode`，实现“点击开始、拖动更新、松开结束并裁剪”的完整截图逻辑，并通过 `emit('screenshot-captured', blob)` 将裁剪结果传给父组件。
3. 方案3：在模板中为每一页添加一个绝对定位的 `div` 作为截图矩形 overlay，根据 `screenshotRect` 渲染实时裁剪框，并配合 CSS 透明背景 + 虚线边框提供可视化反馈。

✅ 实现后的关键代码示例（节选）：

```typescript
// ==================== 截图模式状态 ====================
interface ScreenshotRect {
  pageIndex: number
  x1: number
  y1: number
  x2: number
  y2: number
}
const screenshotRect = ref<ScreenshotRect | null>(null)
const isDraggingScreenshot = ref(false)
const isScreenshotMode = ref(false)

// defineExpose 中新增
defineExpose({
  toggleScreenshotMode: () => {
    // 进入截图模式时，关闭手写/笔记模式，只保留拖拽截图
    isScreenshotMode.value = !isScreenshotMode.value
    if (isScreenshotMode.value) {
      currentMode.value = 'hand'
    }
  },
  // ... 其他方法
})

// PointerDown：开始截图
const handleHighlightPointerDown = async (
  event: PointerEvent,
  pageIndex: number,
  layout: { width: number; height: number }
) => {
  // 截图模式：优先处理为框选起点
  if (isScreenshotMode.value) {
    if (event.pointerType === 'mouse' && event.button !== 0) return

    if (!viewerContainer.value) return
    const pageElements = viewerContainer.value.querySelectorAll<HTMLElement>('.page')
    const pageEl = pageElements[pageIndex]
    if (!pageEl) return

    const rect = pageEl.getBoundingClientRect()
    const x = event.clientX - rect.left
    const y = event.clientY - rect.top

    screenshotRect.value = { pageIndex, x1: x, y1: y, x2: x, y2: y }
    isDraggingScreenshot.value = true
    return
  }

  // 原有手写逻辑...
}

// PointerMove：更新裁剪框
const handleHighlightPointerMove = (
  event: PointerEvent,
  pageIndex: number,
  layout: { width: number; height: number }
) => {
  // 截图模式：拖动更新矩形
  if (
    isScreenshotMode.value &&
    isDraggingScreenshot.value &&
    screenshotRect.value &&
    screenshotRect.value.pageIndex === pageIndex
  ) {
    if (!viewerContainer.value) return
    const pageElements = viewerContainer.value.querySelectorAll<HTMLElement>('.page')
    const pageEl = pageElements[pageIndex]
    if (!pageEl) return

    const rect = pageEl.getBoundingClientRect()
    const x = event.clientX - rect.left
    const y = event.clientY - rect.top

    screenshotRect.value.x2 = x
    screenshotRect.value.y2 = y
    return
  }

  // 原有手写逻辑...
}

// PointerUp：结束拖拽并裁剪
const handleHighlightPointerUp = async (
  event: PointerEvent,
  pageIndex: number,
  layout: { width: number; height: number }
) => {
  // 截图模式：结束拖拽，裁剪截图
  if (
    isScreenshotMode.value &&
    isDraggingScreenshot.value &&
    screenshotRect.value &&
    screenshotRect.value.pageIndex === pageIndex
  ) {
    isDraggingScreenshot.value = false

    const rectInfo = screenshotRect.value
    screenshotRect.value = null

    const x1 = Math.min(rectInfo.x1, rectInfo.x2)
    const y1 = Math.min(rectInfo.y1, rectInfo.y2)
    const x2 = Math.max(rectInfo.x1, rectInfo.x2)
    const y2 = Math.max(rectInfo.y1, rectInfo.y2)

    const width = x2 - x1
    const height = y2 - y1
    if (width <= 5 || height <= 5) {
      return
    }

    const pageCanvas = pageCanvasRefs.value[pageIndex]
    if (!pageCanvas) return

    const offscreen = document.createElement('canvas')
    offscreen.width = width
    offscreen.height = height
    const ctx = offscreen.getContext('2d')
    const pageCtx = pageCanvas.getContext('2d')
    if (!ctx || !pageCtx) return

    ctx.drawImage(pageCanvas, x1, y1, width, height, 0, 0, width, height)

    offscreen.toBlob(
      (blob) => {
        if (blob) {
          emit('screenshot-captured', blob)
        }
      },
      'image/jpeg',
      0.9,
    )
    return
  }

  // 原有手写逻辑...
}
```

```typescript
const getScreenshotRectStyle = (
  rect: ScreenshotRect,
  layout: { width: number; height: number },
): CSSProperties => {
  const x1 = Math.min(rect.x1, rect.x2)
  const y1 = Math.min(rect.y1, rect.y2)
  const x2 = Math.max(rect.x1, rect.x2)
  const y2 = Math.max(rect.y1, rect.y2)

  const width = x2 - x1
  const height = y2 - y1

  return {
    position: 'absolute',
    left: `${x1}px`,
    top: `${y1}px`,
    width: `${width}px`,
    height: `${height}px`,
    boxSizing: 'border-box',
  }
}
```

## 测试验证
- **测试场景**：
  - 场景1：在普通 PDF 页面上切换截图工具，拖出一个矩形，松开后应弹出截图输入对话框，矩形位置与截图预览区域一致。
  - 场景2：在不同缩放比例下（缩小、放大）进行截图，确认裁剪区域和实际图像区域仍然对齐。
- **验证方法**：
  - 方法1：通过浏览器开发者工具查看 `screenshot-rect` 的 DOM 位置和尺寸，检查是否与鼠标拖拽区域一致。
  - 方法2：在 `handleScreenshotCaptured` 中临时将 Blob 渲染到 `<img>` 元素中，肉眼比对截图内容与选区是否一致。

## 预防措施
- 措施1：在设计交互模式时，将“截图模式”与“手写模式”逻辑显式分离，避免多个功能共用同一套 pointer 处理导致逻辑互相干扰。
- 措施2：所有依赖坐标转换的功能（手写、截图、缩放）应统一使用一套坐标系工具函数，并在缩放策略改变时同步更新。
- 措施3：在引入新交互模式时，尽早添加 UI 可视化反馈（如矩形框、半透明区域），提升调试和用户体验。

## 可复用经验
- 经验1：在复杂交互组件中，使用 "模式 + 状态"（如 `currentMode` + `isScreenshotMode`）可以清晰地分离不同功能的事件处理，避免条件判断混乱。
- 经验2：实时可视化（截图矩形、手写预览）不仅提升用户体验，也是调试复杂交互逻辑的有效工具。
- 经验3：当页面存在 CSS 缩放等视觉变换时，应该优先选择在“统一坐标系”里进行所有命中测试和裁剪，或者保证所有计算统一使用同一层的坐标。
