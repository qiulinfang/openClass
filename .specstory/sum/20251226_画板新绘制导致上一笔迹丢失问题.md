问题序号：02 画板新绘制导致上一笔迹丢失问题

## 问题元信息
- **问题分类**：`前端`
- **严重程度**：`高`
- **影响范围**：`imates-web DrawingBoard 画笔连续绘制；上一笔迹可能“视觉丢失”`
- **发现日期**：`2025-12-26`
- **解决状态**：`已解决`

## 问题现象
- 连续绘制多条笔迹时：
  - 新画一笔后，上一笔看起来消失
  - 实际上对象可能已经入栈到 `objects`，但画面未更新到静态层

## 复现步骤
1. 打开画板，选择普通画笔（非 SignaturePad 模式）。
2. 绘制一条笔迹并抬起。
3. 立刻开始绘制第二条。
4. 观察第一条笔迹在开始第二条时“消失”。

## 用户体验
- 用户误以为笔迹丢失，强烈不信任。
- 连续书写中断，影响作答效率。

## 相关文件/模块
- **涉及文件**：
  - `imates-web/src/components/DrawingBoard.vue`：离屏缓存引入后未正确标脏与重建。
- **涉及模块**：
  - 笔迹提交（mouseUp）
  - 缓存层重建（invalidate/rebuild）

## 技术原因 (❌)
1. 引入离屏缓存后，已完成对象绘制转移到缓存层，但在“提交笔迹到 objects”后未调用 `invalidateCache()`。
2. 下一次绘制时，主画布先贴回旧的缓存层（不包含刚提交的上一笔），再画临时笔迹，导致视觉上“上一笔丢失”。

错误示例（概念示意）：
```ts
// ❌ 提交 objects 后未标记缓存脏
objects.push(newStroke)
saveState()
requestRender() // 仍可能使用旧缓存
```

## 正确实现方案 (✅)
- 在任何改变 `objects` 的操作后（新增/删除/移动/撤销重做/清空等），统一执行：
  1. `invalidateCache()`
  2. `requestRender()`（或等价合帧渲染）

正确示例（概念示意）：
```ts
objects.push(newStroke)
saveState()
invalidateCache()
requestRender()
```

## 关键代码/公式
- **关键点**：`objects` 变更必须驱动“缓存脏”状态更新。
- **关键路径**：普通画笔 `handleMouseUp` 的提交分支。

## 测试验证
- **测试场景**：
  - 场景1：连续画 5 笔，每笔抬起后立刻画下一笔。
  - 场景2：撤销/重做后继续画，历史笔迹不应消失。
- **验证方法**：
  - 方法1：肉眼观察是否存在“上一笔消失”。
  - 方法2：在 `objects.length` 增长时，画面静态层同步增长。

## 预防措施
- 统一封装 `mutateObjects(fn)`：内部自动 `invalidateCache()+requestRender()`。
- 增加单测/回归用例：连续绘制 2~3 笔不丢失。

- 相关文档：`imates-web/src/components/DrawingBoard.vue`

## 可复用经验
- 引入缓存层后，必须明确“哪些状态变更会导致缓存失效”。
- 用统一入口封装数据变更，可避免遗漏 invalidation。
