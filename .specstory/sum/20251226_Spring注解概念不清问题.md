## 问题现象
在编写 Spring Boot Hello World 示例时，用户对 `@SpringBootApplication`、`@RestController`、`@GetMapping` 等注解的含义与作用不清楚，不理解“为什么加了注解就能生效”。

## 复现步骤
1. 步骤1：创建 Spring Boot 项目并编写 `DemoApplication` 与 `HelloController`。
2. 步骤2：看到类/方法上出现 `@SpringBootApplication`、`@RestController`、`@GetMapping` 等标记。
3. 步骤3：产生疑问：注解是什么、为什么能让路由生效、为什么不用手写大量配置。

## 用户体验
- 不理解注解含义会导致“照抄能跑、但不会改”的学习挫败感
- 难以定位问题（例如路由不通时不知道是否是注解/扫描路径问题）
- 影响后续学习依赖注入、AOP、配置等 Spring 核心概念

## 技术原因 (❌)
1. 原因1：对“注解=元数据（metadata）”的概念缺失，误以为注解本身会直接执行逻辑。
2. 原因2：不了解 Spring 启动过程会扫描 classpath 并通过反射读取注解，进而注册 Bean 与路由。
3. 原因3：不了解 Spring Boot 的“约定优于配置”，大量配置被 starter/auto-config 隐藏。

（容易产生的错误理解示例）
```java
// ❌ 误解：以为 @GetMapping 本身“主动去监听端口/处理请求”
@GetMapping("/hello")
public String sayHello() {
    return "Hello";
}
```

## 正确实现方案 (✅)
1. 方案1：明确注解的本质是“给代码贴标签”，由编译器/框架/工具读取并按规则处理。
2. 方案2：明确 Spring 的生效机制：启动时组件扫描 + 反射读取注解 + 注册 Bean + 注册映射。
3. 方案3：掌握最小必要的注解语义：
   - `@SpringBootApplication`：标记应用入口并开启自动配置/扫描
   - `@RestController`：标记控制器，返回值作为响应体
   - `@RequestMapping/@GetMapping`：声明路由映射

（正确理解示例）
```java
// ✅ 注解提供元信息，Spring 在启动时扫描到该类并注册为 Controller
@RestController
@RequestMapping("/api")
public class HelloController {

    // ✅ Spring MVC 读取该注解，建立 GET /api/hello -> sayHello 的映射
    @GetMapping("/hello")
    public String sayHello() {
        return "Hello, Spring Boot!";
    }
}
```

## 预防措施
- 措施1：学习注解时按“注解贴在哪里（类/方法/字段）-> 被谁读取（Spring/编译器）-> 产生什么效果（注册 Bean/路由）”的框架去记忆
- 措施2：遇到路由不生效优先排查：包扫描范围、注解是否贴对位置、路径是否拼接正确
- 措施3：建立一份常用 Spring 注解速查表（Controller/DI/Config/Test）便于回顾

## 可复用经验
- 经验1：注解不是“执行代码”，而是“描述代码”，执行逻辑在框架侧

- 经验3：理解“组件扫描范围”能解决很多新手阶段的“为什么不生效”问题
