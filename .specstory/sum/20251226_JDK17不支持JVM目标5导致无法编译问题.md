问题序号：JDK17不支持JVM目标5导致无法编译问题

## 问题元信息
- **问题分类**：`后端`
- **严重程度**：`高`
- **影响范围**：`spring-boot-tutorial 模块本地编译/构建；IDEA 增量编译与 CI 构建（若继承相同配置）`
- **发现日期**：`2025-12-19`
- **解决状态**：`待解决`

## 问题现象
在 IntelliJ IDEA（或构建工具）编译 Java 模块 `spring-boot-tutorial` 时失败，报错类似：

- `java: 无法编译为 JVM 目标 5 配置的模块 'spring-boot-tutorial': 当前与该模块关联的 JDK Eclipse Temurin 17.0.17 不支持所需的 jvm 目标 5。`

核心表现：项目/模块被配置为 `target=1.5`（Java 5 字节码），但使用的 JDK 为 17，导致编译器拒绝。

## 复现步骤
1. 使用 JDK 17（如 Eclipse Temurin 17.0.17）打开/导入项目。
2. 确保模块或构建配置中存在 `target=1.5` / `jvmTarget=1.5` / `-target 1.5`。
3. 在 IDEA 执行 Build / Rebuild，或执行 Maven/Gradle 编译任务。
4. 观察到编译报错：JDK 17 不支持 JVM target 5。

## 用户体验
- 无法在本地正常编译运行模块，开发被阻断。
- CI 可能失败（若 CI 使用 JDK 17 且目标仍为 1.5）。
- 新同学/新环境导入项目时更易踩坑，配置排查成本高。

## 相关文件/模块
- **涉及文件**：
  - `spring-boot-tutorial/pom.xml`：可能配置了 `maven-compiler-plugin` 的 `source/target` 为 `1.5` 或继承了旧父 POM。
  - `spring-boot-tutorial/build.gradle(.kts)`：若为 Gradle 项目，可能配置了 `sourceCompatibility/targetCompatibility` 或 Kotlin `jvmTarget`。
  - `.idea/`（仅本地）：IDEA 的 Java Compiler Target Bytecode Version / 模块语言级别可能被设置为 1.5。
- **涉及模块**：
  - `spring-boot-tutorial`：出现报错的目标模块。

## 技术原因 (❌)
1. **字节码目标版本过低**：项目或模块显式配置了 Java 5（`target=1.5`），这在现代 JDK 下已不被支持。
2. **JDK 与 target 不兼容**：JDK 17 编译器不再支持生成 Java 5 字节码目标。
3. **IDEA 与构建工具配置不一致**：即使 `pom.xml` 已改，IDEA 的 `Target bytecode version` 仍可能是 1.5，导致仍然报错。

错误配置示例（Maven ❌）：
```xml
<plugin>
  <groupId>org.apache.maven.plugins</groupId>
  <artifactId>maven-compiler-plugin</artifactId>
  <configuration>
    <source>1.5</source>
    <target>1.5</target>
  </configuration>
</plugin>
```

错误配置示例（Gradle ❌）：
```gradle
sourceCompatibility = 1.5
targetCompatibility = 1.5
```

错误配置示例（Kotlin/Gradle ❌）：
```kotlin
kotlinOptions {
    jvmTarget = "1.5"
}
```

## 正确实现方案 (✅)
1. **统一并提升 JVM target 到可用版本**：根据 Spring Boot 版本选择合适的 Java 版本。
   - Spring Boot 3.x：通常要求 Java 17
   - Spring Boot 2.x：常见为 Java 8/11
2. **优先使用 `release` 选项**（Maven/Gradle），避免 `source/target` 组合引发的兼容性问题。
3. **对齐 IDE 与构建配置**：IDEA 的 Project/Module language level 和 Target bytecode version 与构建工具保持一致。

正确配置示例（Maven ✅，推荐 `release`）：
```xml
<plugin>
  <groupId>org.apache.maven.plugins</groupId>
  <artifactId>maven-compiler-plugin</artifactId>
  <configuration>
    <release>17</release>
  </configuration>
</plugin>
```

正确配置示例（Gradle ✅）：
```gradle
java {
  toolchain {
    languageVersion = JavaLanguageVersion.of(17)
  }
}
```

正确配置示例（Kotlin/Gradle ✅）：
```kotlin
kotlinOptions {
    jvmTarget = "17"
}
```

IDEA 配置建议（✅）：
- `Project SDK`：选择 JDK 17
- `Project language level`：17
- `Settings -> Build Tools -> ...`：确保使用与构建一致的 JDK
- `Settings -> Build, Execution, Deployment -> Compiler -> Java Compiler`：`Target bytecode version` 设置为 17（或项目要求版本）

## 关键代码/公式
- Maven：编译目标版本控制点
```xml
<configuration>
  <release>17</release>
</configuration>
```

- Gradle Java Toolchain：统一 JDK/目标版本
```gradle
java {
  toolchain {
    languageVersion = JavaLanguageVersion.of(17)
  }
}
```

## 测试验证
- **测试场景**：
  - 场景1：IDEA 中 `Build -> Rebuild Project`，确认 `spring-boot-tutorial` 模块无编译错误。
  - 场景2：命令行执行 `mvn -q -DskipTests compile`（或对应 Gradle `./gradlew compileJava`），确认编译通过。
  - 场景3（可选）：CI 使用 JDK 17 构建，确认流水线通过。
- **验证方法**：
  - 方法1：检查编译输出中 `javac` 的 `--release 17`（或对应目标版本）生效。
  - 方法2：检查产物 class 文件版本与目标一致（例如 `javap -verbose` 查看 major version）。

## 预防措施
- 措施1：在父 POM/根构建脚本中统一声明 Java 版本（如 `<java.version>` 或 Gradle toolchain），避免子模块散落配置。
- 措施2：在 README/开发规范中明确要求的 JDK 版本与 Spring Boot 版本对应关系。
- 措施3：CI 中固定使用同版本 JDK 并加入校验（如构建时输出 Java 版本与 compiler release），尽早暴露不一致。

## 可复用经验
- 经验1：现代 JDK 下，优先用 `--release`（或 Maven 的 `<release>`）而不是散配 `source/target`。
- 经验2：遇到“模块编译目标版本不支持”时，先排查：构建工具配置 + IDE Target bytecode version + 父工程继承配置。
- 经验3：Spring Boot 版本与 JDK 版本强相关，升级/迁移时要先对齐 Java 基线。
