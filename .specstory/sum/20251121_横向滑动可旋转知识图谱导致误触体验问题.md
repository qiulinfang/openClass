问题序号：横向滑动可旋转知识图谱导致误触体验问题

## 问题元信息
- **问题分类**：`[前端/交互/体验]`
- **严重程度**：`[低~中]`
- **影响范围**：`[知识图谱视图，习惯上下滑动操作的用户]`
- **发现日期**：`2025-11-21`
- **解决状态**：`[已解决]`

## 问题现象
知识图谱支持通过拖拽手势来：
- 横向拖拽：旋转整个位于轨道上的月球（改变 `globalAngle`）。
- 纵向拖拽：切换上一章/下一章（使用 `SWITCH` 模式）。

但在实际使用中，用户更多是希望通过点击和指示器来切换章节，而横向拖拽旋转会带来：
- 无意中的误触（用户只是想点击，却稍微产生横向位移）。
- 轨道旋转导致位置变化，难以定位原有章节。

因此需求调整为：**移除横向拖拽旋转逻辑，只保留（或弱化）纵向切换**。

## 复现步骤
1. 打开知识图谱视图。
2. 在月球附近按住并横向拖动一小段距离。
3. 观察月球绕轨道旋转，`state.globalAngle` 持续变化。
4. 用户在频繁点击/拖动中容易不小心触发旋转，导致布局改变。

## 用户体验
- 影响点1：误操作频繁，用户难以控制图谱的视角。
- 影响点2：位置变化增加了理解成本（章节顺序和空间位置关联被打乱）。
- 影响点3：与常见知识图谱/章节导航的交互模式不一致。

## 相关文件/模块
- **涉及文件**：
  - `imates-web/src/components/knowledge-graph/newGrap.vue`：`onMove`、`switchFocus`、`state.globalAngle` 等交互逻辑。
- **涉及模块**：
  - Canvas 拖拽交互模块。

## 技术原因 (❌)
1. 原因1：在 `onMove` 中根据 `dx` 和 `dy` 的大小自动判断交互模式：
```ts
if (!state.interactionMode) {
  if (Math.abs(dx) > 10 || Math.abs(dy) > 10) {
    state.interactionMode = Math.abs(dx) > Math.abs(dy)
      ? 'ROTATE' // 横向 -> 旋转
      : 'SWITCH'; // 纵向 -> 切换
  }
}

if (state.interactionMode === 'ROTATE') {
  const delta = clientX - state.lastX;
  state.globalAngle += delta * 0.005; // 根据横向位移改变角度
  hideBubble();
}
```
2. 原因2：在移动端设备上，轻微的横向晃动也可能被判断为 `ROTATE`，导致知识图谱角度频繁变化。
3. 原因3：未对“是否真的需要横向旋转”做产品层面的细化设计，默认启用导致体验噪音。

## 正确实现方案 (✅)
1. 方案1：移除 `ROTATE` 模式的触发，只保留 `SWITCH` 模式用于纵向切换章节。
2. 方案2：在 `onMove` 中，仅在 `|dy| > |dx|` 且超过一定阈值时才进入 `SWITCH` 模式。
3. 方案3：将 `ROTATE` 分支逻辑清空或完全删除，确保横向拖拽不再改变 `state.globalAngle`。

✅ 修改后的 `onMove` 核心逻辑：
```ts
const dx = clientX - state.startX;
const dy = clientY - state.startY;

if (!state.interactionMode) {
  if (Math.abs(dx) > 10 || Math.abs(dy) > 10) {
    // 仅允许纵向切换，去除横向旋转
    if (Math.abs(dy) > Math.abs(dx)) {
      state.interactionMode = 'SWITCH';
    }
  }
}

if (state.interactionMode === 'ROTATE') {
  // 横向旋转逻辑已禁用
  // const delta = clientX - state.lastX;
  // state.globalAngle += delta * 0.005;
  // hideBubble();
} else if (state.interactionMode === 'SWITCH') {
  if (dy < -50) {
    switchFocus('next');
    state.isInteracting = false;
  } else if (dy > 50) {
    switchFocus('prev');
    state.isInteracting = false;
  }
}

state.lastX = clientX;
```

## 关键代码/公式
- 代码片段1：`onMove` 中移除横向旋转逻辑，仅保留纵向切换的判断。
- 代码片段2：`switchFocus` 逻辑，根据 `next/prev` 切换 `focusedIndex`。

## 测试验证
- **测试场景**：
  - 场景1：横向拖动知识图谱。
    - 预期：不再改变月球在轨道上的角度，图谱保持稳定。
  - 场景2：纵向快速拖动。
    - 预期：仍可触发上一章/下一章切换（如果该交互保留）。
- **验证方法**：
  - 在实际设备上多次横向/纵向拖动，确认图谱只对纵向滑动有反应。

## 预防措施
- 措施1：在设计交互时，应优先采用用户习惯的操作模式，避免多种手势叠加造成干扰。
- 措施2：为复杂交互（如拖拽）增加“死区”和明显阈值，避免轻微误操作被当作指令。
- 措施3：对于不确定用户是否需要的高级交互（如旋转视图），可以通过配置项或调试开关控制是否启用。

## 可复用经验
- 经验1：在信息展示型视图中，尽量减小视图本身的可变性（如任意旋转/缩放），以保证用户的空间记忆和导航效率。
- 经验2：手势交互应当单一清晰，避免多手势争用同一方向的位移信号（如同时用横向滑动做多种事情）。
- 经验3：可以通过实验性开关（如 `VITE_ENABLE_DEBUG`）在早期版本中验证新交互，再决定是否向所有用户开放。
