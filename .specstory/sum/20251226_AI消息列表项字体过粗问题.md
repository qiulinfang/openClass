问题序号：AI消息列表项字体过粗问题

## 问题元信息
- **问题分类**：`前端`
- **严重程度**：`低`
- **影响范围**：`AI/老师聊天气泡内 Markdown 列表（li）可读性与一致性`
- **发现日期**：`2025-12-17`
- **解决状态**：`已解决`

## 问题现象
AI 消息渲染 Markdown 列表时，列表项 `li` 的字体字重被设置为 `600`，导致列表内容看起来过于加粗，不符合预期（希望为正常字重 400）。

## 复现步骤
1. 打开聊天页面。
2. 让 AI 输出包含 Markdown 列表（`- item` / `1. item`）。
3. 观察列表项：字体加粗（600）。

## 用户体验
- 列表内容“压迫感”强，可读性下降
- 与普通段落字体风格不一致，影响整体 UI 统一

## 相关文件/模块
- **涉及文件**：
  - `imates-web/src/components/chat/ChatMessage.vue`：AI 消息 `.message-text` 的 Markdown 样式
- **涉及模块**：
  - 聊天消息渲染（MarkdownIt 输出的 HTML 样式）

## 技术原因 (❌)
1. **对 Markdown 元素做了统一加粗，误包含 li**：
   - `.message-text` 中通过 `:deep(...)` 将 `h1..h6/ol/ul/li` 等元素统一设置 `font-weight: 600`。
   - `li` 不应加粗，但被包含在该集合中。

错误示例（节选）：
```scss
/* ❌ li 被包含，导致列表项加粗 */
:deep(h1),
:deep(h2),
:deep(h3),
:deep(h4),
:deep(h5),
:deep(ol),
:deep(ul),
:deep(li),
:deep(h6) {
  font-weight: 600;
}
```

## 正确实现方案 (✅)
1. **标题保持 600**：`h1~h6` 仍使用 `font-weight: 600`。
2. **列表项单独设置 400**：将 `li` 从加粗集合中移除，并单独写 `:deep(li) { font-weight: 400; }`。

正确示例（节选）：
```scss
:deep(h1),
:deep(h2),
:deep(h3),
:deep(h4),
:deep(h5),
:deep(h6) {
  font-weight: 600;
}

:deep(li) {
  font-weight: 400;
}
```

## 关键代码/公式
- `ChatMessage.vue`：`.ai-message-content .message-text` 内的 `:deep(li)` 覆盖

## 测试验证
- **测试场景**：
  - 场景1：AI 输出无序列表，li 字重应为 400。
  - 场景2：AI 输出标题 `### xxx`，标题字重保持 600。
- **验证方法**：
  - 方法1：浏览器 DevTools 检查 `li` computed style。
  - 方法2：视觉回归对比（截图对比列表项与段落）。

## 预防措施
- 避免用“元素大集合”统一写死字体字重；对标题/正文/列表分别配置。
- 增加一条 UI 规范：正文文本默认 400，标题才加粗。
