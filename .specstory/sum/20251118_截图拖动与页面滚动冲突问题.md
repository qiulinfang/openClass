问题序号：截图拖动与页面滚动冲突问题

## 问题元信息
- **问题分类**：前端
- **严重程度**：中
- **影响范围**：在 PDF 页面使用触摸设备进行截图的用户
- **发现日期**：2025-11-18
- **解决状态**：已解决

## 问题现象
在 PDF 截图模式下，用户使用触摸设备进行单指拖动截图时：
- 页面会同时发生上下滚动；
- 截图矩形跟随手指移动，但因页面滚动，视觉上的截图区域与实际截图内容容易错位；
- 控制台中多次出现 `Unable to preventDefault inside passive event listener invocation` 警告。

## 复现步骤
1. 在移动端浏览器或带触摸屏的设备上打开 PDF 查看页面。
2. 加载任意 PDF 文件。
3. 在工具栏中切换到截图模式。
4. 在页面上单指按住并上下滑动：
   - 观察页面会跟着上下滚动；
   - 蓝色截图框出现且随手指移动，但位置与用户预期不一致。
5. 打开浏览器控制台，可见 `Unable to preventDefault inside passive event listener invocation` 日志。

## 用户体验
- 影响点1：用户很难精确控制截图区域，截图结果往往偏移或大小不符合预期。
- 影响点2：单指拖动既在滚动页面又在画截图框，交互混乱，学习成本高。
- 影响点3：在触摸设备上操作不稳定，严重影响截图相关 AI 问答功能的可用性。

## 相关文件/模块
- **涉及文件**：
  - `imates-web/src/components/PdfPage.vue`：定义了触摸/滚动/缩放/截图的主要事件处理（`handleTouchStart`、`handleTouchMove`、`handleHighlightPointerDown/Move/Up` 等）。
- **涉及模块**：
  - PDF 浏览与渲染模块（基于 MuPDF）。
  - 截图模块（负责生成截图并传递给 AI 问答）。

## 技术原因 (❌)
1. 原因1：页面上 `pointer`/`touch` 监听最初使用 `.passive`，浏览器强制将监听视为 passive，使得 `event.preventDefault()` 无法阻止滚动，导致触摸拖动时仍然触发原生滚动行为。
2. 原因2：截图逻辑仅在 pointer 事件里调用 `preventDefault()`，而容器滚动更多由 `touchmove` 驱动，导致单指上下滑动时，`touchmove` 没有被正确拦截。
3. 原因3：没有为截图模式设计专门的“滚动锁定”机制（例如控制容器 `overflow` 或在 `touchstart/move` 上分情况拦截），导致截图拖拽和页面滚动逻辑混杂。

❌ 错误/不完整实现示例：
```vue
<!-- 页面容器上的 pointer 事件（旧实现） -->
<div
  class="page"
  @pointerdown.passive="handleHighlightPointerDown($event, index, layout)"
  @pointermove.passive="handleHighlightPointerMove($event, index, layout)"
  @pointerup.passive="handleHighlightPointerUp($event, index, layout)"
>
```

```ts
  if (currentMode.value === 'screenshot') {
    // 试图阻止滚动，但由于 passive，preventDefault 实际无效
    event.preventDefault()
    // ... 更新 screenshotRect

```

## 正确实现方案 (✅)
1. 方案1：将截图模式从 `currentMode` 拆分为独立状态 `isScreenshotMode`，并在触摸事件中基于该状态进行精细判断，单指截图与多指缩放互不干扰。
2. 方案2：在 `touchstart`/`touchmove` 中针对截图模式和绘图模式明确调用 `event.preventDefault()`，避免触摸滚动与截图拖拽竞争；遇到多指时自动取消当前截图框，交给缩放手势处理。
3. 方案3：为多指缩放场景引入 `isZooming` 和 `isPointerToolSuspended` 状态，在缩放期间暂停绘图和截图逻辑，缩放结束后再恢复原工具，彻底避免“缩放+截图/绘图”交叉导致的滚动冲突。

✅ 正确实现关键代码示例：
```ts
// 独立的截图/缩放状态
const isScreenshotMode = ref(false)
const isDraggingScreenshot = ref(false)
const isZooming = ref(false)
const isPointerToolSuspended = ref(false)

// 触摸开始：区分截图模式与缩放模式
const handleTouchStart = (event: TouchEvent) => {
  // 截图模式 + 单指：优先用于截图，禁止默认滚动
  if (isScreenshotMode.value && event.touches.length === 1) {
    event.preventDefault()
    return
  }

  // 高亮/画笔/橡皮擦模式：优先绘制，禁止滚动
  if (['highlighter', 'pen', 'eraser-draw'].includes(currentMode.value)) {
    event.preventDefault()
  }

  if (!containerRef.value || !viewerContainer.value) return

  // 截图拖拽过程中一旦检测到多指，立即取消当前截图框
  if (isScreenshotMode.value && event.touches.length >= 2) {
    if (isDraggingScreenshot.value && screenshotRect.value) {
      isDraggingScreenshot.value = false
      screenshotRect.value = null
    }
  }

  // 多指开始：暂停绘图工具并标记缩放状态
  if (event.touches.length === 2) {
    if (!isPointerToolSuspended.value) {
      lastToolMode = currentMode.value
      isPointerToolSuspended.value = true
      if (currentMode.value !== 'hand') {
        currentMode.value = 'hand'
      }
    }
    isZooming.value = true
    event.preventDefault()
    // ... 记录捏合初始距离
  }
}

// 触摸移动：
const handleTouchMove = (event: TouchEvent) => {
  // 截图模式下单指移动：禁止滚动
  if (isScreenshotMode.value && event.touches.length === 1) {
    event.preventDefault()
    return
  }

  // 高亮/画笔/橡皮擦持续阻止默认滚动
  if (['highlighter', 'pen', 'eraser-draw'].includes(currentMode.value)) {
    event.preventDefault()
  }

  if (!containerRef.value || !viewerContainer.value) return

  // 两指捏合：走缩放和平移逻辑
  if (event.touches.length === 2) {
    event.preventDefault()
    // ... 缩放/平移计算
  }
}

// 触摸结束：恢复工具状态
const handleTouchEnd = (event: TouchEvent) => {
  if (event.touches.length < 2) {
    if (isPointerToolSuspended.value) {
      isPointerToolSuspended.value = false
      if (lastToolMode && lastToolMode !== 'hand') {
        currentMode.value = lastToolMode
      }
      lastToolMode = null
    }
    isZooming.value = false
    lastTouchDistance = 0
    isPinching = false
  }
}
```

## 测试验证
- **测试场景**：
  - 场景1：单指截图
    - 步骤：开启截图模式 → 单指按住并拖动截图 → 松手。
    - 预期：PDF 页面不滚动，仅截图矩形变化，松手后生成截图。
  - 场景2：两指缩放
    - 步骤：在非截图模式下两指捏合放大/缩小 PDF。
    - 预期：页面缩放和适度平移， 不会创建截图框或绘图笔迹。
  - 场景3：缩放后再截图
    - 步骤：两指缩放 → 缩放结束 → 切换截图模式 → 单指截图。
    - 预期：缩放结束后手势状态恢复，截图模式下页面不再滚动。

- **验证方法**：
  - 方法1：观察页面在截图模式下的单指拖动是否完全停止滚动，仅展示截图矩形。
  - 方法2：通过 DevTools Event Listeners 查看相关 `touch`/`pointer` 监听是否仍然带 `.passive`，避免再次出现 `Unable to preventDefault` 警告。

## 预防措施
- 措施1：在设计复杂手势交互（缩放、平移、截图、绘图）时，将不同模式的状态管理清晰分开，避免使用单一枚举状态承载所有逻辑。
- 措施2：统一梳理 `touch` 和 `pointer` 事件的使用场景，明确何处需要 `passive: true`（如纯滚动），何处必须关闭 `passive` 并允许 `preventDefault()`。
- 措施3：在调试阶段保留关键 `console.log` 用于追踪 pointer/touch 事件流，一旦行为异常，能迅速判断是浏览器特性还是代码问题。

## 可复用经验
- 经验1：触摸设备上，**滚动 vs 自定义手势** 必须通过 `preventDefault` 与 `passive` 明确界定，否则很容易出现“既滚动又绘制”的混乱行为。
- 经验2：对多指手势（双指缩放）应有单独的状态（如 `isZooming`），并在期间暂停其他工具，缩短问题排查路径。
- 经验3：复杂交互推荐引入“模式切换入口”（如 `enterScreenshotMode/exitScreenshotMode`），统一在入口处做副作用处理，如关闭笔记面板、重置绘图状态等。
