# 通用需求实现经验流程（以拍照搜题、截图问答为例）

> 目标：总结一套在 imates-web 中落地“通用新需求”的路径，既适合自己复盘，也方便以后复用。

---

## 1. 明确需求与场景

- **收集需求要点**
  - 用户操作入口：从哪里触发（工具栏按钮、抽屉按钮、长按等）。
  - 期望效果：界面形态（弹窗 / 抽屉 / toast）、交互文案、是否有后续跳转。
  - 约束条件：不能影响现有主流程（例如 PDF 浏览、聊天输入）、兼容移动端等。

- **典型例子**
  - 拍照搜题：
    - 新增灰色蒙版层上的框选提示，引导用户在中间区域框选题目。
    - 抽屉中的“加入练习”点击后，弹出对话框询问是否跳转到“我的习题”。
  - PDF 截图问答：
    - 截图完成后，在 ChatInput 内左上角展示缩略图；
    - 使用同一发送按钮，在有截图时发送带图消息，没有截图时发送纯文本。

---

## 2. 定位相关模块与数据流

### 2.1 先找“界面入口”

- 在视图层（`src/views`）寻找：
  - 例如 `PhotoSearchView.vue` 中的拍照搜题抽屉；
  - `PdfViewerView.vue` 中的 PDF 主视图和右侧 Chat 面板。

- 通过模板搜索关键字：
  - 按钮文案：如 `加入练习`、`拍照搜题`；
  - 组件标签：如 `<ChatView>`, `<PdfPage>`, `<ScreenshotInputDialog>`。

### 2.2 梳理数据流和事件

- 看父组件如何控制子组件：
  - 例如 `PdfViewerView.vue` 通过 `@screenshot-captured` 从 `PdfPage` 接收截图 `Blob`；
  - `PhotoSearchView.vue` 通过 `ChatView` 的插槽在抽屉中提供“再拍一题 / 收藏 / 加入练习”。

- 明确：
  - **状态放哪里**：如截图挂起状态 `pendingScreenshot`、对话框开关 `showAddToPracticeDialog`；
  - **事件谁发谁收**：如 `send-with-screenshot` 事件由 `ChatInput` 发出，经 `ChatView` 转发到 `PdfViewerView`。

---

## 3. 设计状态与接口（从内到外或从外到内）

### 3.1 优先确定“谁做中枢”

- PDF 截图场景：
  - 由 `PdfViewerView` 作为中枢：负责管理当前文件、聊天 Store、截图挂起状态；
  - 子组件 `PdfPage`、`ChatView`、`ChatInput` 尽量保持“无业务判断”，只处理交互和展示。

- 拍照搜题场景：
  - `PhotoSearchView` 既是拍照流程中枢，也是抽屉中 Chat 的宿主；
  - 由它统一持有：当前题目 `currentQuestionData`、收藏状态、练习列表状态、对话框开关等。

### 3.2 设计新状态 / 事件

- **状态例子**：
  - `const pendingScreenshot = ref<... | undefined>(undefined)`
  - `const showAddToPracticeDialog = ref(false)`

- **事件例子**：
  - `ChatInput` 新增：
    - `props.attachedScreenshot`（可选）；
    - emits：`'remove-screenshot'`, `'send-with-screenshot'`；
    - 行为：有截图时点击发送按钮触发 `send-with-screenshot`，否则 `send-message`。
  - `ChatView`：
    - 仅做“事件透传”和“状态下发”：
      - `:attached-screenshot="pendingScreenshot"`
      - `@send-with-screenshot="handleSendWithScreenshot"`
      - `@remove-screenshot="handleRemoveScreenshot"`。

---

## 4. 实现步骤拆解（实践范式）

### 4.1 从 UI 层着手：先让“看得见”

1. **在模板上加 UI 外壳**
   - 灰色蒙版上的框选提示：
     - 在 `PhotoSearchView.vue` 的 `crop-mask-full` 里嵌入：
       - `crop-hint-box`（居中容器）；
       - `crop-hint-rect`（虚线矩形框）；
       - `crop-hint-text`（提示文案）。
   - 抽屉里的关闭按钮：
     - 在 `drawer-content` 内增加右上角 `q-btn`，仍保留 `@click.self` 关闭行为。
   - 加入练习后的对话框：
     - 在根模板末尾增加 `q-dialog`，用 `v-model="showAddToPracticeDialog"` 控制。

2. **补充样式**
   - 单独给新元素写类（不动原有类）：
     - `.crop-hint-box`, `.crop-hint-rect`, `.crop-hint-text`；
     - `.drawer-close-btn` 等。
   - 注意：
     - 使用 `pointer-events: none` 保证提示层不挡住后续交互；
     - 遮罩层背景统一（例如拍照抽屉使用纯黑 `#000`）。

### 4.2 再接入业务逻辑

1. **状态初始化**
   - 在 `<script setup>` 顶部区域统一声明新状态：
     - 例如 `const showAddToPracticeDialog = ref(false)` 紧跟着其他 UI 状态。

2. **在关键逻辑点注入状态变更**
   - `handleAddToPracticeInChat` 成功分支：
     - 先保留原有逻辑：toast + `fetchQuestions`；
     - 然后再加上 `showAddToPracticeDialog.value = true`。
   - 截图挂起逻辑：
     - 在 `handleScreenshotCaptured` 中解析 `Blob` → base64 → 图像宽高，写入 `pendingScreenshot`；
     - 自动打开 Chat 面板并切到对应 Tab。

3. **封装用户决策**
   - 对话框按钮：
     - `handleStayInPhotoSearch`：仅关闭对话框；
     - `handleGoToMyExercises`：关闭对话框 + 使用 `router.push({ name: 'myExercises' })` 跳转。

### 4.3 保持单向数据流、避免耦合

- 不在深层组件里直接操作路由或全局 Store：
  - 截图发送逻辑只在 `PdfViewerView` 里触发，`ChatInput` 不知道 AI Store 细节；
  - 加入练习 / 跳转逻辑只在 `PhotoSearchView` 中处理，`ChatView` 只负责聊天。

## 5. 验证与迭代

1. **功能回归检查**
   - 验证新需求生效：
     - 拍照后蒙版有明显“中间框选”提示；
     - 抽屉中点击“加入练习” → 成功 → 弹出询问对话框；
     - 选择“前往我的习题”是否能正确跳转。
   - 回归旧逻辑：
     - 未改变截图质量、题目识别、聊天记录等。

2. **交互体验微调**
   - 文案、颜色、尺寸根据实际机型体验进行小幅调整；
   - 例如遮罩透明度、框选提示大小、对话框按钮文案等。

3. **经验沉淀**
   - 每次实现新需求后，在 `.specstory/sum` 下追加一篇小总结：
     - 记录：
       - 涉及的视图 / 组件文件；
       - 新增的状态与事件；
       - 易踩坑（例如触摸事件阻塞、Store 与路由的关系）。

---

## 6. 可以复用的“通用套路”

1. **需求分三层**：
   - 展示层（template + 样式）；
   - 状态层（ref/computed + Store）；
   - 行为层（函数：handleXxx）。

2. **父组件做中枢**：
   - 跨组件协作（如截图 + 聊天、拍照 + 练习）统一在父级视图里“汇总和分发”。

3. **渐进式改动**：
   - 先做 UI 壳 → 再接数据 → 最后加路由跳转、Store 操作。
   - 每一步尽量是“小补丁”，方便回滚和 diff。

4. **事件命名语义化**：
   - 如 `send-with-screenshot`、`remove-screenshot`、`handleAddToPracticeInChat`，一看就知道职责。

5. **对话框用于“二次确认或跳转决策”**：
   - 成功操作后不打断当前流程，但给予用户清晰的下一步选择，这是本次“加入练习后跳转”的可复用模式。
