问题序号：滚动区域点击未触发选中事件问题

## 问题元信息
- **问题分类**：`[前端]`
- **严重程度**：`[中]`
- **影响范围**：`[imates-web 相似题目/练习题列表组件 FindExerciseQuestionList.vue 的题目选择交互]`
- **发现日期**：`2025-11-25`
- **解决状态**：`[已解决]`

## 问题现象
- 在 `FindExerciseQuestionList.vue` 中，题目卡片外层绑定了点击事件用于切换选中状态（触发 `questionSelected` / `questionDeselected`）。
- 题目内容区域 `.question-content` 本身是一个可滚动容器，用户点击该区域期望也能切换题目选中状态。
- 实际表现：
  - 仅点击卡片空白区域可以切换选中（高亮 `question-selected`）并触发事件；
  - 点击内容滚动区域时，初始实现没有触发选中事件；
  - 后续在为滚动区域添加事件时，`handleQuestionClick(question)` 联动 `handleContentWheel` 等函数出现 `Cannot read properties of undefined (reading 'target')` 报错；
  - 在 `handleContentTouchStart` 中调用 `event.stopPropagation()` 后，`question-content` 上 `@click` 绑定的点击事件在移动端几乎不再触发，导致“点击=选中”的期望行为失效。

## 复现步骤
1. 打开 imates-web 中使用 `FindExerciseQuestionList` 的页面，加载出相似题目列表。
2. 在某个题目卡片上：
   1. 点击卡片非滚动内容区域（例如标题行），可以正常选中/取消选中；
   2. 点击题目内容滚动区域（有 Markdown 文本、支持滚动）时，初始版本不会切换选中状态；
3. 在尝试为滚动区域增加事件绑定后：
   1. 滚动区域绑定了 `@touchstart="handleContentTouchStart($event, question)"` 等；
   2. `handleContentWheel` 签名或内部对 `event.target` 的使用与模板绑定不一致，导致控制台报错：

```text
chunk-LG6AQRJS.js?v=65b2137f:2365 Uncaught TypeError: Cannot read properties of undefined (reading 'target')
    at Proxy.handleContentWheel (...)
    at onWheel (...)
```

4. 在 `question-content` 上增加 `@click.stop="handleQuestionClick(question)"` 之后：
   1. 虽然模板上声明了 `click` 事件；
   2. 但由于移动端中 `touchstart` 被 `handleContentTouchStart` 阶段 `stopPropagation`，且 BetterScroll 接管了 touch 事件，浏览器合成 `click` 的流程被打断，导致 `@click` 实际很难触发。

## 用户体验
- 影响点1：用户点击题目内容区域时，选中状态没有变化，交互不符合直觉。
- 影响点2：在滚动题目内容时偶发 JS 报错，可能影响后续事件处理或引发卡顿。
- 影响点3：对触摸滚动与 BetterScroll 事件的配合较为脆弱，稍有误用就会出现事件对象丢失或 click 不触发的问题。

## 相关文件/模块
- **涉及文件**：
  - `imates-web/src/components/FindExerciseQuestionList.vue`：题目列表组件，负责渲染题目卡片、处理选中状态和内部滚动。
- **涉及模块**：
  - `useBetterScroll` 组合式函数：封装 BetterScroll，用于外层滚动容器控制加载更多等逻辑。
  - `useMessageRenderer`：渲染题目 Markdown 内容。

## 技术原因 (❌)
1. 原因1：最初 `.question-content` 仅绑定了滚动相关事件（`touchstart` / `touchmove` / `wheel`），没有绑定点击事件来触发 `handleQuestionClick`，导致点击滚动区域不会改变选中状态。
2. 原因2：在改造中，为了在滚动容器有滚动条时阻止冒泡，封装了 `handleContentTouchStart` / `handleContentTouchMove` / `handleContentWheel`，但对 v-on 的事件对象传递规则理解不一致：
   - 有的写法是 `@touchstart="handleContentTouchStart($event, question)"`；
   - 有的仍是 `@wheel="handleContentWheel"`，但函数签名却写成 `(event: WheelEvent, question: { bmNo: string })` 或内部假设存在 `question`。
3. 原因3：在 `handleContentWheel` 中直接使用 `event.target`，而当模板绑定未显式传入 `$event`，或者参数顺序不一致时，`event` 实际为 `undefined`，访问 `event.target` 导致运行时报错。
4. 原因4：`handleContentTouchStart` 中为了阻止事件冒泡到 BetterScroll，调用了 `event.stopPropagation()`；在移动端环境下，`click` 通常由一系列 touch 事件合成，当 touch 流程在早期被拦截、并被 BetterScroll 等库消费后，组件模板层声明的 `@click` 常常不会真正触发，因此**依赖 `@click` 来完成“滚动区域点击=选中”的逻辑在此场景下不可靠**。

**错误代码示例 (部分抽象)：**

```vue
<!-- 模板中：wheel 没有显式传递 $event 和 question，click 事件在移动端因 touch 流程被拦截而难以触发 -->
<div 
  class="question-content"
  @click.stop="handleQuestionClick(question)"
  @touchstart="handleContentTouchStart($event, question)"
  @touchmove="handleContentTouchMove($event, question)"
  @wheel="handleContentWheel"  <!-- 这里没有传 $event, question -->
>
  <div v-html="renderQuestionContent(question)" class="markdown-content"></div>
</div>
```

```ts
// 脚本中：handleContentWheel 期望拿到 event 并使用 event.target
const handleContentWheel = (event: WheelEvent, question: { bmNo: string }) => {
  const container = findQuestionContentContainer(event.target)
  if (container && hasScrollbar(container)) {
    event.stopPropagation()
  }
}

// 当 Vue 只传一个参数且签名不匹配时，event 可能为 undefined，导致报错：
// Cannot read properties of undefined (reading 'target')
```

## 正确实现方案 (✅)
1. 方案1：区分滚动事件与点击事件，明确职责：
   - 滚动相关事件（`touchstart` / `touchmove` / `wheel`）只负责判断是否有滚动条，有则 `stopPropagation`，防止事件继续冒泡到 BetterScroll 外层；
   - 点击选中逻辑在移动端优先通过 `touchstart` 或 `touchend` 完成，而不是依赖合成的 `click`；在 PC 端则保留正常的 `@click` 行为即可。
2. 方案2：统一 v-on 事件对象传递方式：
   - 只需要事件对象时：`@wheel="handleContentWheel"` + `const handleContentWheel = (event: WheelEvent) => {...}`；
   - 同时需要事件对象与 `question` 时：`@wheel="handleContentWheel($event, question)"` + `const handleContentWheel = (event: WheelEvent, question: Question) => {...}`；
   - 保证 `$event` 在模板中的位置与函数签名中参数顺序严格对应。
3. 方案3：在滚动区域点击触发选中时，使用与外层相同的选中逻辑，避免重复实现：
   - 例如在 `handleContentTouchStart` 内，在有滚动条时 `stopPropagation`，同时调用 `handleQuestionClick(question)` 来切换选中状态；
   - 如果需要区分“点击”和“滑动”，可以增加 `touchstart` / `touchend` 间的位移阈值判断：移动距离很小才视为点击，从而避免用户轻微滚动时误触选中。

**正确代码示例 (简化版)：**

```vue
<!-- 模板：移动端主要靠 touch 事件，PC 仍可使用 click -->
<div 
  class="question-content"
  @click.stop="handleQuestionClick(question)"               <!-- PC 端点击 -->
  @touchstart="handleContentTouchStart($event, question)"  <!-- 移动端主入口 -->
  @touchmove="handleContentTouchMove($event)"             
  @wheel="handleContentWheel($event)"                     
>
  <div v-html="renderQuestionContent(question)" class="markdown-content"></div>
</div>
```

```ts
// 只在有滚动条时阻止冒泡，并在触摸开始时触发选中（简单版）
const handleContentTouchStart = (event: TouchEvent, question: { bmNo: string }) => {
  const container = findQuestionContentContainer(event.target)
  if (container && hasScrollbar(container)) {
    // 阻止事件冒泡给 BetterScroll
    event.stopPropagation()
    // 在本组件层完成“点击=选中”的业务逻辑
    handleQuestionClick(question)
  }
}

const handleContentTouchMove = (event: TouchEvent) => {
  const container = findQuestionContentContainer(event.target)
  if (container && hasScrollbar(container)) {
    event.stopPropagation()
  }
}

const handleContentWheel = (event: WheelEvent) => {
  const container = findQuestionContentContainer(event.target)
  if (container && hasScrollbar(container)) {
    event.stopPropagation()
  }
}

const handleQuestionClick = (question: { bmNo: string; atUserList?: boolean }) => {
  if (!question.atUserList) {
    handleToggleSelection(question.bmNo)
  }
}
```

## 关键代码/公式
- 代码片段1：判断容器是否有滚动条：

```ts
const hasScrollbar = (element: HTMLElement): boolean => {
  if (!element) return false
  const hasVerticalScrollbar = element.scrollHeight > element.clientHeight
  const hasHorizontalScrollbar = element.scrollWidth > element.clientWidth
  return hasVerticalScrollbar || hasHorizontalScrollbar
}
```

- 代码片段2：根据事件 target 向上查找 `.question-content` 容器：

```ts
const findQuestionContentContainer = (target: EventTarget | null): HTMLElement | null => {
  if (!target || !(target instanceof HTMLElement)) return null

  let element: HTMLElement | null = target
  while (element && element !== document.body) {
    if (element.classList.contains('question-content')) {
      return element
    }
    element = element.parentElement
  }
  return null
}
```

- 代码片段3：v-on 事件对象传递的正确用法示例：

```vue
<!-- 只要事件对象 -->
<div @click="onClick"></div>

<!-- 同时要事件对象和自定义参数 -->
<div @click="onClick($event, item)"></div>
```

```ts
const onClick = (event: MouseEvent, item: Item) => {
  // event 是原生事件对象
  // item 是当前项数据
}
```

## 预防措施
- 措施1：在调整事件处理函数签名（参数列表）时，务必同步检查模板中的 v-on 绑定，保证 `$event` 和自定义参数的一一对应关系。
- 措施2：对滚动容器与 BetterScroll 等库集成时，将“滚动控制”和“点击逻辑”拆分为职责单一的函数，避免在同一事件处理中即控制滚动又改变业务状态。
- 措施3：在触摸端交互中，谨慎依赖合成 `click` 事件；对于关键业务操作（如选中、提交），建议直接基于 `touchstart` / `touchend` 实现，尤其是在配合第三方滚动库时。

## 可复用经验
- 经验1：在复杂滚动/嵌套滚动场景中，优先将滚动事件与业务点击事件解耦，通过 `stopPropagation` + 单一职责函数避免互相干扰。
- 经验2：使用 v-on 传递事件对象时，养成习惯：
  - 只要事件：`@xxx="fn"` + `fn(event)`；
  - 要事件 + 其他参数：`@xxx="fn($event, other)"` + `fn(event, other)`，始终保持参数顺序明确。
- 经验3：在移动端配合 BetterScroll 这类库时，对于“点击=选中”这类业务，不要依赖浏览器合成的 `click`；直接在 touch 事件阶段完成更可靠。
