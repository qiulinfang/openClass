问题序号：点击未聚焦月球触发两次点击逻辑导致误弹气泡问题

## 问题元信息
- **问题分类**：`[前端/交互]`
- **严重程度**：`[中]`
- **影响范围**：`[知识图谱视图，所有点击月球的用户]`
- **发现日期**：`2025-11-21`
- **解决状态**：`[已解决]`

## 问题现象
在知识图谱中，当用户点击一个“未聚焦”的月球时，本来期望行为是：
- 第一次点击：只聚焦该月球，不弹出气泡菜单。
- 第二次点击：在已聚焦的月球上点击，弹出气泡菜单。

但实际行为为：
- 第一次点击未聚焦月球时，既发生了聚焦，又立即弹出了气泡菜单，相当于“点击被处理了两次”。

调试 `console.log('closestIndex  state.focusedIndex', closestIndex, state.focusedIndex)` 发现：一次点击会打印两行日志，例如：
```txt
closestIndex  state.focusedIndex 5 0
closestIndex  state.focusedIndex 5 5
```
说明 `handleClick` 被执行了两次。

## 复现步骤
1. 打开知识图谱视图，保证有多个章节（月球）。
2. 点击一个当前未聚焦的月球。
3. 观察行为：
   - 月球被聚焦。
   - 同时气泡菜单立即弹出。
4. 打开控制台，看到 `handleClick` 的日志在一次点击中出现两条。

## 用户体验
- 影响点1：用户无法区分“聚焦”和“查看菜单”的两步操作，感觉行为不直观。
- 影响点2：误触发菜单，影响连续操作体验。
- 影响点3：与设计预期不符，增加学习成本。

## 相关文件/模块
- **涉及文件**：
  - `imates-web/src/components/knowledge-graph/newGrap.vue`：`handleClick`、`onStart`、`onEnd` 等交互逻辑。
- **涉及模块**：
  - Canvas 交互处理模块（点击、拖拽）。

## 技术原因 (❌)
1. 原因1：同时绑定了 `mousedown/mouseup` 和 `touchstart/touchend` 事件，并在 `onEnd` 中根据点击距离调用 `handleClick`：
```ts
canvas.addEventListener('mousedown', onStart);
canvas.addEventListener('touchstart', onStart, { passive: false });

window.addEventListener('mouseup', onEnd);
window.addEventListener('touchend', onEnd);

function onEnd(e) {
  // ...
  if (!state.interactionMode) {
    if (dist < 10) {
      handleClick(clientX, clientY); // 这里触发点击
    }
  }
}
```

2. 原因2：在某些环境下，一次触摸操作会先触发 `touch` 事件，再由浏览器模拟触发 `mouse` 事件，导致 `onEnd` 被调用两次，从而 `handleClick` 也被执行两次。
3. 原因3：`handleClick` 本身没有做防抖/去重处理，导致重复逻辑生效。

## 正确实现方案 (✅)
1. 方案1：在 `handleClick` 函数内部增加简单的时间防抖，避免短时间内重复处理相同点击。
2. 方案2：根据实际需要，可进一步区分事件来源：如在触摸事件中 `preventDefault`，避免触摸后再触发模拟鼠标事件；但为简单起见，本次主要通过防抖解决。
3. 方案3：在“命中月球”逻辑中根据 `focusedIndex` 决定是聚焦还是弹出气泡，逻辑本身是正确的，保留不变。

✅ 添加防抖后的 `handleClick` 关键实现：
```ts
// 统一的点击处理
let lastClickTime = 0;
function handleClick(x: number, y: number) {
  // 防止 touch/mouse 重复触发
  const now = Date.now();
  if (now - lastClickTime < 100) return; // 100ms 内重复点击直接忽略
  lastClickTime = now;

  // 1. 指示器
  const indicatorIndex = checkIndicatorHit(x, y);
  if (indicatorIndex !== -1) {
    if (indicatorIndex !== state.focusedIndex) focusOnIndex(indicatorIndex);
    return;
  }

  // 2. 卫星
  // ...

  // 3. 月球
  let minDist = Infinity;
  let closestIndex = -1;
  // 遍历所有月球找到最近的
  // ...

  if (closestIndex !== -1) {
    if (closestIndex === state.focusedIndex) {
      showBubble('moon', closestIndex); // 已聚焦 -> 弹气泡
    } else {
      focusOnIndex(closestIndex);       // 未聚焦 -> 只聚焦
    }
  } else {
    hideBubble();
  }
}
```

## 关键代码/公式
- 代码片段1：`handleClick` 增加 `lastClickTime` 防抖逻辑。
- 代码片段2：点击月球时判断 `closestIndex === state.focusedIndex` 决定行为的逻辑。

## 测试验证
- **测试场景**：
  - 场景1：在触摸设备（或模拟器）上快速点击未聚焦月球。
    - 预期：第一次点击只聚焦，不弹气泡；第二次点击才弹出气泡。
  - 场景2：在桌面浏览器上使用鼠标点击。
    - 预期：行为与触摸场景一致，无重复触发。
- **验证方法**：
  - 通过日志确认每次点击只输出一条 `closestIndex state.focusedIndex` 日志。
  - 人工体验确认气泡不再误弹。

## 预防措施
- 措施1：在统一点击入口函数中增加防抖/去重机制，是处理多事件源（鼠标+触摸）时的通用手段。
- 措施2：在绑定触摸和鼠标事件时，明确策略：如仅在某平台启用某一类事件，或在触摸事件中 `preventDefault` 防止后续鼠标事件。
- 措施3：为关键交互路径增加日志与测试用例，便于捕捉类似双触发问题。

## 可复用经验
- 经验1：在同时使用 `touch` 和 `mouse` 事件时，要格外注意浏览器“事件模拟”机制，容易出现重复触发。
- 经验2：对所有“集中入口”的事件处理函数加一层简单的时间防抖，可以避免大量意料之外的重复调用。
- 经验3：通过日志打印关键状态（如 `closestIndex`, `focusedIndex`）是排查复杂交互问题的有效手段。
