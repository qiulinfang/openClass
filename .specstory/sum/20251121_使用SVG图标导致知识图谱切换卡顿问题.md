问题序号：使用SVG图标导致知识图谱切换卡顿问题

## 问题元信息
- **问题分类**：`[前端/性能]`
- **严重程度**：`[中]`
- **影响范围**：`[知识图谱视图，低中端设备上的所有用户]`
- **发现日期**：`2025-11-21`
- **解决状态**：`[已解决]`

## 问题现象
知识图谱新版在使用 SVG 图标（例如中心节点 `centerNode.svg`、卫星学习状态图标 `learned.svg`、`lastLearned.svg`、`notLearned.svg`）绘制 Canvas 时，用户在切换章节或聚焦/取消聚焦月球时，出现明显的卡顿和掉帧现象，体验不如纯 Canvas 绘制版本流畅。

## 复现步骤
1. 在 `KnowledgeGraphView` 中打开某章节的知识图谱。
2. 通过点击右侧指示器或切换章节，使图谱多次重新聚焦不同月球。
3. 在设备（尤其是中低端 Android 设备）的 WebView 中观察动画流畅度，发现帧率下降，交互明显不如只用几何图形绘制的版本顺滑。

## 用户体验
- 影响点1：聚焦动画卡顿，用户感觉“顿挫感”明显。
- 影响点2：频繁操作（多次切换章节或拖动）时，WebView 渲染压力明显增大。
- 影响点3：整体观感不如旧版，容易认为“新版更重更慢”。

## 相关文件/模块
- **涉及文件**：
  - `imates-web/src/components/knowledge-graph/newGrap.vue`：月球和卫星使用 SVG 图标绘制的主要逻辑。
  - `imates-web/src/views/KnowledgeGraphView.vue`：图标资源加载和知识图谱入口。
- **涉及模块**：
  - Canvas 绘制模块。
  - 图标资源加载模块（SVG 图片）。

## 技术原因 (❌)
1. 原因1：在动画循环 `loop()` 中，每一帧对所有月球和卫星调用 `context.drawImage(img, ...)`，直接使用 SVG 图标进行绘制，浏览器需要频繁将矢量 SVG 栅格化为位图，渲染成本高。

```ts
// ❌ 简化示例：每帧直接对 SVG Image 做 drawImage
if (img && img.complete) {
  context.drawImage(img, this.x - size / 2, this.y - size / 2, size, size);
}
```

2. 原因2：图标文件本身分辨率较大（例如用于多处 UI 的通用图标），在知识图谱中频繁缩放绘制，放大了性能开销。
3. 原因3：未对图片进行“离屏缓存（Offscreen Canvas）”处理，每次绘制都从原始 `Image` 对象重新拉取像素数据。

## 正确实现方案 (✅)
1. 方案1：引入离屏 Canvas 缓存，将每个 SVG 图标在加载完成后绘制到一个固定大小的 Canvas 上，并缓存该 Canvas。
2. 方案2：在实际渲染循环中，只对离屏 Canvas 调用 `drawImage`，避免对 SVG 做重复栅格化。
3. 方案3：根据实际显示尺寸，控制离屏 Canvas 的大小（如 128x128 或 256x256），在清晰度和性能之间取得平衡。

✅ 实现的离屏缓存关键代码：
```ts
// --- 图片离屏缓存优化 ---
const imageCache = new Map<string, HTMLCanvasElement>();

function getCachedImageCanvas(img: HTMLImageElement | null) {
  if (!img || !img.complete) return null;

  if (imageCache.has(img.src)) {
    return imageCache.get(img.src)!;
  }

  const size = 256; // 统一缩放到 256x256
  const canvas = document.createElement('canvas');
  canvas.width = size;
  canvas.height = size;
  const ctx = canvas.getContext('2d')!;

  ctx.drawImage(img, 0, 0, size, size);

  imageCache.set(img.src, canvas);
  return canvas;
}
```

在卫星绘制中使用缓存：
```ts
const size = r * 2;
const cachedCanvas = getCachedImageCanvas(img);

if (cachedCanvas) {
  context.drawImage(cachedCanvas, this.x - size / 2, this.y - size / 2, size, size);
} else {
  // 回退到菱形绘制
}
```

在聚焦月球绘制中使用缓存：
```ts
const img = centerNodeImage;
const size = r * 2;
const cachedCanvas = getCachedImageCanvas(img);

if (cachedCanvas) {

} else {
  // 回退到渐变圆
}
```

## 测试验证
- **测试场景**：
  - 场景1：在开启 SVG 图标绘制的情况下，多次快速切换章节和聚焦月球。
    - 预期：动画帧率明显好于未使用缓存时，卡顿感显著降低。
  - 场景2：在中低端 Android 设备 WebView 中进行同样操作。
    - 预期：CPU 占用降低，渲染掉帧减少。
- **验证方法**：
  - 使用浏览器 Performance 面板对比优化前后的帧时间。
  - 在真机上进行主观体验对比。

## 预防措施
- 措施1：对于高频绘制的图像（特别是矢量图），优先采用离屏缓存思路，避免直接在主渲染循环中频繁栅格化。
- 措施2：在设计 Canvas 动画时，提前评估图像资源的大小与格式，避免过大的 SVG 在高频场景中直接使用。
- 措施3：引入性能基线测试，对关键动画场景进行定期性能回归。

## 可复用经验
- 经验1：在 Canvas 动画中，凡是高频重复绘制的图像，都应考虑使用离屏 Canvas 或纹理缓存技术。
- 经验2：SVG 适合用于静态/少量绘制场景，在高频动画中更适合提前栅格化为位图进行二次使用。
- 经验3：将性能优化封装为通用工具函数（例如 `getCachedImageCanvas`），方便跨项目/跨组件复用。
