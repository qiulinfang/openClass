# 问题序号：MySQL 远程连接配置与 Navicat 握手失败问题

## 问题元信息
- **问题分类**：数据库 / 网络 / 运维
- **严重程度**：中（生产数据可访问性受影响，但数据库本身在容器中可用）
- **影响范围**：研伴服务（`blw_edu` 等数据库）、外部运维/开发人员通过 Navicat 访问数据库
- **发现日期**：2026-01-04
- **解决状态**：进行中（已定位主要原因与可行解决步骤，待执行权限/防火墙变更或采用 SSH 隧道）

## 问题现象
- 客户端（Navicat）尝试连接 `www.imates.com.cn:3306` 报错：
  - `2013 - Lost connection to server at 'handshake: reading initial communication packet', system error: 0`
  - 在尝试直接使用 `mysql -h ...` 时，早期出现过 `ERROR 2002 ... Can't connect to local MySQL server through socket '/var/lib/mysql/mysql.sock'`（那是因为宿主机上本地 MySQL 服务未启，实际数据库运行在 Docker 容器内）
  - 通过服务器 shell 检查发现：MySQL 运行在 Docker 容器 `mysql`（image `mysql:8.0.22`），容器 root 密码可读为 `MYSQL_ROOT_PASSWORD=sF7yB8eE`，容器端口已映射到宿主 `0.0.0.0:3306`。
  - 使用 `docker exec mysql ...` 在容器内可执行 SQL，但外部 Navicat 握手阶段被中断或返回非 MySQL 响应/拒绝。
  - 宿主机上 `ss/netstat` 显示 `docker-proxy` 在 0.0.0.0:3306 上监听，容器日志含 `mbind: Operation not permitted`（常见警告，不直接致命）。

4. 尝试用 Navicat 连接数据库（首次错误）：输入 `http://www.imates.com.cn` 导致 “Can't open named pipe... pipe: http://...” —— 主机格式错误。

7. 在服务器上尝试 `mysql -u root -p` 报 `ERROR 2002 ... Can't connect to local MySQL server through socket`（宿主机未运行本地 mysqld）。由此转向检查容器化部署。  
8. 检查文件系统，发现数据库数据位于 `/imates/database/`（包含 `ibdata1`、`.ibd` 等），表明数据存在且为容器或宿主绑定数据卷。  
9. 检查 Docker：确认 Docker 服务在运行，`docker ps -a` 显示名为 `mysql` 的容器，端口映射 `0.0.0.0:3306->3306`。容器环境变量显示 `MYSQL_ROOT_PASSWORD=sF7yB8eE`。  
10. 容器日志包含 `mbind: Operation not permitted`（内核警告），但并非直接致命信息；继续查看更长日志以定位具体错误。

12. 在远程连接尝试中出现 `ERROR 1045 Access denied for user 'username'@'IP'`，表明 MySQL 用户权限/host 限制阻止远程访问。  
13. 排查并提出解决思路：创建专用远程用户、调整用户认证插件为 `mysql_native_password`（兼容性）、检查防火墙/安全组、或使用 SSH 隧道临时访问。

## 复现步骤
1. 在 Navicat 新建 MySQL 连接，主机填写 `www.imates.com.cn`，端口 3306，用户名 `root`，密码（容器的root密码或空）。
2. 点击“测试连接” → 出现 `2013 — handshake` 错误。
3. 在服务器上运行 `docker ps -a`，确认有名为 `mysql` 的容器，且端口 3306 已映射到宿主机。
4. 在宿主机上运行 `ss -tlnp | grep 3306`，返回 `docker-proxy` 在 0.0.0.0:3306 监听。
5. 在容器内运行 `mysql -u root -p'PASSWORD' -e "SELECT VERSION();" ` 可以成功（如果容器内 MySQL 启动并正常响应）。

> 注：如果容器内 `mysql` 未能成功启动或数据目录出问题，容器日志会返回具体 InnoDB/权限等错误，需要另外处理。

## 技术原因 (❌)
1. 认证/权限问题：MySQL 的 root 用户（或用于连接的用户）没有被授权从外部主机/特定客户端 IP 连接（`Access denied for user 'username'@'IP'`），导致握手后被拒。
2. 握手被中断：网络/防火墙/中间代理在握手阶段拦截或返回非 MySQL 响应（导致 Navicat 报 `handshake: reading initial communication packet`）。
3. 配置/环境问题：宿主机本地尝试用 socket 连接失败（因为宿主机上并未运行本地 MySQL 服务；数据库运行在 Docker 容器里）；若容器内 MySQL 使用 `caching_sha2_password` 但客户端不支持，也可能导致握手失败。

### 错误示例（shell 输出）
```bash
# Navicat 客户端错误
2013 - Lost connection to server at 'handshake: reading initial communication packet', system error: 0

# 宿主机 netstat/ss:
LISTEN  0      2048   0.0.0.0:3306   0.0.0.0:*   users:(("docker-proxy",pid=...,fd=4))

# Docker 环境变量（容器内）
MYSQL_ROOT_PASSWORD=sF7yB8eE
```

## 正确实现方案 (✅)
1. 以最小权限原则创建专用远程用户，并避免使用 root 来远程登录：
   - 在容器内或通过 `docker exec` 创建 `remote_user`，使用 `mysql_native_password` 以兼容老客户端：
```bash
docker exec mysql mysql -u root -p'sF7yB8eE' -e "CREATE USER 'remote_user'@'%' IDENTIFIED WITH mysql_native_password BY 'StrongP@ssw0rd!'; GRANT SELECT,LOCK TABLES,SHOW VIEW ON blw_edu.* TO 'remote_user'@'%'; FLUSH PRIVILEGES;"
```
2. 若必须远程管理数据库（仅对信任 IP），授权时限制来源 IP 而非 `%`，例如 `'remote_user'@'203.0.113.45'`。
3. 检查宿主机防火墙/云安全组，确保入站 TCP 3306 对目标客户端开放（或根据策略限制为某些 IP）。
4. 若客户端仍然报 handshake 相关错误，尝试：
   - 在 Navicat 高级设置中禁用/启用 SSL 以配合服务器配置
   - 使用 SSH 隧道将本地端口映射到宿主机 3306（更安全，也会绕过防火墙问题）
5. 若容器内 MySQL 使用 `caching_sha2_password` 且客户端不兼容，可切换到 `mysql_native_password`（见第1步）。

```bash
# 然后 Navicat 连接 127.0.0.1:3307（用户名 remote_user，密码 StrongP@ssw0rd!）
```

# MySQL远程连接配置问题

## 问题元信息
- **问题分类**：`数据库`
- **严重程度**：`高`
- **影响范围**：`数据库访问功能，影响Navicat等工具连接数据库`
- **发现日期**：`2026-01-04`
- **解决状态**：`已解决`

## 问题现象
用户无法通过Navicat等工具远程连接MySQL数据库，出现错误：
- `1045 - Access denied for user 'root'@'xxx.xxx.xxx.xxx'(using password: YES)`
- MySQL服务看似正常运行但无法建立远程连接

## 复现步骤
1. 步骤1：在服务器上检查MySQL服务状态，显示服务正常运行
2. 步骤2：尝试从外部IP连接MySQL数据库
3. 步骤3：收到"Access denied"错误，提示用户权限问题

## 用户体验

## 相关文件/模块
- **涉及文件**：
  - `/etc/mysql/conf.d/mysql.cnf`：MySQL配置文件

## 技术原因 (❌)
1. **MySQL配置问题**：bind-address默认设置为127.0.0.1，只允许本地连接
   ```ini
   # 错误的配置
   [mysqld]
   # 缺少bind-address配置，默认只允许localhost连接
   ```
2. **用户权限不足**：MySQL用户只允许localhost连接，没有远程访问权限
   ```sql
   -- 错误的用户权限设置
   SELECT user, host FROM mysql.user;
   -- 只显示 root@localhost，没有root@'%'
   ```
3. **Docker网络配置**：容器内MySQL监听设置不正确

## 正确实现方案 (✅)
1. **修改MySQL配置**：设置bind-address为0.0.0.0允许所有接口连接
   ```ini
   # 正确的配置
   [mysqld]
   bind-address = 0.0.0.0
   ```
2. **设置用户权限**：创建允许远程连接的用户
   ```sql
   -- 正确的用户权限设置
   CREATE USER 'remote_user'@'%' IDENTIFIED BY 'strong_password';
   GRANT ALL PRIVILEGES ON *.* TO 'remote_user'@'%' WITH GRANT OPTION;
   FLUSH PRIVILEGES;
   ```
3. **验证配置生效**：重启MySQL服务并验证监听状态

## 按错误顺序的详细问题与修复（每个报错 → 排查 → 处理）
下面按我们遇到的实际错误顺序，逐条列出错误现象、复现命令、排查思路与已执行或建议的修复步骤，便于回溯和复现。

1) 错误：APK 安装失败 — "Unknown failure: '[CDS]close[0]'"  
   - 复现：在 Android 设备/模拟器上安装构建好的 APK（app-1.0.69-69.apk）时出现。  
   - 排查要点：检查 APK 签名与设备上已安装包签名是否冲突；检查 gradle 配置是否使用了 debug 签名打 release。  
   - 已执行/建议修复：将 release build 的 signingConfig 指向正式签名（非 signingConfigs.debug）；如设备已装不同签名版本，先 adb uninstall 包名 后再安装。  
   - 关键命令示例：无（为构建/签名层面修改）  

2) 错误：Navicat 报 "Can't open named pipe to host: . pipe: http://www.imates.com.cn"（主机格式错误）  
   - 复现：Navicat 主机填写 `http://www.imates.com.cn` 并测试连接。  
   - 排查：观察错误提示包含 "pipe" 与 HTTP URL，说明主机填写错误或选错连接方式（命名管道 vs TCP/IP）。  
   - 修复：在 Navicat 中将主机填为 `www.imates.com.cn`（无 http://），选择 TCP/IP 连接，并填写端口 3306。  
   - 验证：点击测试连接成功。  

3) 错误：Navicat 报 "2013 - Lost connection ... handshake: reading initial communication packet"（握手阶段失败）  
   - 复现：Navicat 使用正确主机与端口测试连接仍报该错误。  
   - 排查：按层次检查（容器内 MySQL → 宿主端口映射 → 宿主防火墙/安全组 → 客户端网络/认证插件/SSL）；检查 docker 容器是否运行、端口是否映射、容器内 MySQL 是否可响应、是否有 Access denied。  
   - 已执行命令示例：  
     - `docker ps -a`（确认 mysql 容器存在）  
     - `ss -tlnp | grep 3306`（宿主监听）  
     - `docker logs mysql --tail 200`（查看容器日志）  
   - 常见原因与修复：开放防火墙/安全组、创建远程用户并使用兼容的认证插件、在 Navicat 调整 SSL/认证设置或使用 SSH 隧道。  
   - 推荐验证：在宿主机执行 `mysql -h 127.0.0.1 -P 3306 -u remote_user -p'pwd' -e "SELECT 1;"` 成功则说明 docker-proxy 转发正常。  

4) 错误：宿主机 `mysql -u root -p` 报 "ERROR 2002 Can't connect to local MySQL server through socket '/var/lib/mysql/mysql.sock'"  
   - 复现：在宿主机直接执行 `mysql -u root -p`。  
   - 排查：这是本地 socket 连接失败，常见原因是宿主机没有本地 mysqld 服务（数据库运行在容器中）。  
   - 处理：使用容器内 mysql 客户端或通过映射端口连接宿主 127.0.0.1:3306；不要误以为宿主机上有本地 mysqld。  
   - 验证命令：`docker exec -it mysql mysql -u root -p'sF7yB8eE' -e "SHOW DATABASES;"`  

5) 错误：`sudo systemctl status mysqld` 显示 mysqld.service failed（宿主 mysqld 未就绪）  
   - 复现：在宿主机检查 systemd 服务状态。  
   - 排查：检查 `/var/log/mysql/` 或 `journalctl -u mysqld` 获取错误细节；确认是否使用容器化部署（若是容器化，宿主 mysqld 可失败且无影响）。  
   - 处理：若数据库在容器中运行，可忽略宿主 mysqld 状态，转而检查容器内 mysqld；若期望宿主运行，则根据 error.log 修复 InnoDB/权限/配置问题。  

6) 错误：容器日志包含大量 `mbind: Operation not permitted` 警告  
   - 复现：`docker logs mysql` 输出多行该警告。  
   - 排查：该警告通常与内核内存策略或容器 sysctl/安全限制有关，常见但通常不致命。需要查看更详尽日志以确认 MySQL 是否成功启动。  
   - 处理：如果 MySQL 启动并能响应查询，则可忽略；否则查看 `/tmp/mysql_error.log` 或容器完整日志，定位 InnoDB/权限等致命错误并修复（修权限、调整权限/selinux或内核参数）。  

7) 错误：`ERROR 1045 (28000): Access denied for user 'username'@'IP'`（用户权限被拒）  
   - 复现：从外部 IP 或 Navicat 使用某用户尝试连接时出现。  
   - 排查：检查 `mysql.user` 表中该用户的 host 字段，确认是否存在 `'user'@'%'` 或 `'user'@'client_ip'`；确认使用的认证插件（plugin 列）。  
   - 已执行命令：`docker exec mysql mysql -u root -p'sF7yB8eE' -e "SELECT user, host, plugin FROM mysql.user;"`  
   - 处理：创建受限远程用户或授权现有用户，例如：  
     ```sql
     CREATE USER 'remote_user'@'%' IDENTIFIED WITH mysql_native_password BY 'StrongP@ssw0rd!';
     GRANT SELECT,LOCK TABLES,SHOW VIEW ON blw_edu.* TO 'remote_user'@'%';
     FLUSH PRIVILEGES;
     ```  
   - 验证：宿主机 `mysql -h 127.0.0.1 -P 3306 -u remote_user -p'pwd' -e "SELECT 1;"` 成功；Navicat 使用该用户连接成功。  

8) 问题：客户端认证插件不兼容（`caching_sha2_password` vs `mysql_native_password`）  
   - 复现：客户端（旧版Navicat或驱动）在握手阶段失败或提示认证错误。  
   - 排查：查看 `SELECT user, host, plugin FROM mysql.user;`，如 plugin 为 `caching_sha2_password` 且客户端不支持则需转换。  
   - 处理：为兼容老客户端创建使用 `mysql_native_password` 的用户，或升级客户端/驱动。  

9) 问题：网络/防火墙/云安全组阻断外部访问  
   - 复现：宿主机本地能连（127.0.0.1），但外部客户端无法连通（PowerShell Test-NetConnection 报 False 或超时）。  
   - 排查：在宿主机检查 `firewall-cmd --list-all`、`iptables -L -n`；在云平台检查安全组入站规则是否放行 3306。  
   - 处理：按最小权限原则开放客户端 IP 到 3306，或使用 SSH 隧道避免直接开放数据库端口。  

10) 临时绕过方案：使用 SSH 隧道或在 Navicat 使用 SSH 选项  
    - 操作：`ssh -L 3307:127.0.0.1:3306 user@www.imates.com.cn`，Navicat 连接 `127.0.0.1:3307`。  
    - 优点：安全，不改防火墙配置，便于临时管理与数据导出。
