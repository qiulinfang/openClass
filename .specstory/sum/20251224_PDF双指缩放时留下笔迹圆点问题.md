# PDF双指缩放时留下笔迹圆点问题

## 问题元信息
- **问题分类**：`前端`
- **严重程度**：`中`
- **影响范围**：`PDF阅读器画笔功能，影响所有使用画笔工具的用户`
- **发现日期**：`2025-12-24`
- **解决状态**：`已解决`

## 问题现象
在 PDF 阅读器中使用画笔工具时，如果用户单指按下（出现起点圆点）后立即进行双指缩放操作，会出现以下问题：
1. 起点圆点不会立即消失
2. 多次重复"单指按下→双指缩放"操作会累积多个圆点
3. 圆点会一直残留在画布上，直到触发橡皮擦工具或其他重绘操作时才消失

## 复现步骤
1. 打开 PDF 阅读器，切换到画笔模式
2. 单指按下（此时会绘制起点圆点）
3. 不移动手指，立即用第二根手指按下进行双指缩放
4. 观察到起点圆点仍然残留在画布上
5. 重复步骤 2-3 多次，会累积多个圆点
6. 切换到橡皮擦模式并触碰屏幕，所有圆点立即消失

## 用户体验
- 画笔工具使用体验差，双指缩放时会留下意外的笔迹圆点
- 用户需要手动清除这些圆点，增加操作负担
- 与参考实现 `lsdjf.html` 的体验不一致，后者完全不会出现此问题
- 影响用户对产品质量的信任

## 技术原因 (❌)

### 1. 缺少 `isZooming` 状态标志
`PdfPage.vue` 缺少全局的 `isZooming` 标志来标记双指缩放状态，导致无法在各个事件处理函数中判断是否处于缩放状态。

### 2. 第一根手指按下时未检查缩放状态
在 `onPointerDown` 中，当第一根手指按下时，没有检查 `!isZooming` 条件就开始绘制：

```typescript
// ❌ 错误代码
if (currentMode.value !== 'pan' && loc) {
  isPanningInDrawMode = false;
  dragStartPage.value = loc.pageIndex;
  currentDragPath.value = [{ x: loc.x, y: loc.y }];
  // ... 绘制起点圆点
  drawStartDot(loc.pageIndex, { x: loc.x, y: loc.y }, currentMode.value);
}
```

### 3. 双指按下时清除机制不可靠
双指按下时依赖 `restoreInkCanvasBackup()` 来恢复备份，但这个机制存在以下问题：
- 备份可能不完整
- 异步渲染导致时序问题
- 如果备份机制失效，圆点会残留

```typescript
// ❌ 错误代码
if (currentMode.value === 'pen' || currentMode.value === 'highlighter') {
  restoreInkCanvasBackup(pageIdx); // 依赖备份恢复，不可靠
} else {
  renderInkLayer(pageIdx);
}
```

### 4. `onPointerMove` 中未检查缩放状态
在 `onPointerMove` 中，当 `dragStartPage.value !== -1` 时会继续绘制，但没有检查 `!isZooming`：

```typescript
// ❌ 错误代码
} else if (dragStartPage.value !== -1) {
  // 没有检查 !isZooming，缩放时仍可能继续绘制
  const loc = getPdfPoint(e.clientX, e.clientY);
  // ...
}
```

## 正确实现方案 (✅)

### 1. 添加 `isZooming` 状态标志
在状态管理区添加全局的 `isZooming` 标志：

```typescript
// ✅ 正确代码
// 交互临时状态
const dragStartPage = ref<number>(-1);
const currentDragPath = ref<Point[]>([]);
const currentDragRect = ref<{ x: number, y: number, w: number, h: number } | null>(null);
let isZooming = false; // 双指缩放状态标记
```

### 2. 第一根手指按下时检查缩放状态
在 `onPointerDown` 中，只有在非缩放状态下才允许开始绘制：

```typescript
// ✅ 正确代码
// 关键：只有在非缩放状态下才允许开始绘制
if (currentMode.value !== 'pan' && loc && !isZooming) {
  isPanningInDrawMode = false;
  dragStartPage.value = loc.pageIndex;
  currentDragPath.value = [{ x: loc.x, y: loc.y }];
  
  if (currentMode.value === 'pen') {
    backupInkCanvas(loc.pageIndex);
    drawStartDot(loc.pageIndex, { x: loc.x, y: loc.y }, currentMode.value);
  }
  // ...
}
```

### 3. 双指按下时强制重绘清除圆点
双指按下时，统一使用 `renderInkLayer` 强制重绘整个墨迹层，而不是依赖备份恢复：

```typescript
// ✅ 正确代码
} else if (activePointers.size === 2) {
  // 立即取消当前绘制并清除已绘制的起点圆点
  if (dragStartPage.value !== -1) {
    const pageIdx = dragStartPage.value;
    // 关键：必须先清空状态，再重绘，确保临时路径不会被绘制
    dragStartPage.value = -1;
    currentDragPath.value = [];
    currentDragRect.value = null;
    
    // 强制重绘整个墨迹层以清除起点圆点（不依赖备份恢复）
    renderInkLayer(pageIdx);
  }
  
  isZooming = true; // 标记进入缩放模式
  const pts = Array.from(activePointers.values());
  lastPinchDist = Math.hypot(pts[0].x - pts[1].x, pts[0].y - pts[1].y);
  lastPinchCenter = { x: (pts[0].x + pts[1].x) / 2, y: (pts[0].y + pts[1].y) / 2 };
}
```

### 4. `onPointerMove` 中检查缩放状态
在 `onPointerMove` 中，只有在非缩放状态下才允许继续绘制：

```typescript
// ✅ 正确代码
} else if (dragStartPage.value !== -1 && !isZooming) {
  const loc = getPdfPoint(e.clientX, e.clientY);
  // ... 继续绘制逻辑
}
```

### 5. 手指抬起时重置缩放状态
在 `onPointerUp` 中，当所有手指抬起时重置 `isZooming`：

```typescript
// ✅ 正确代码
const onPointerUp = (e: PointerEvent) => {
  activePointers.delete(e.pointerId);
  if (activePointers.size === 0) {
    // ... 其他逻辑
    isZooming = false; // 重置缩放状态
  }
  // ...
};
```

### 三重防护机制
完整的防护机制包括三个层次：

```typescript
// 1. 第一根手指按下时的防护（第 836 行）
if (currentMode.value !== 'pan' && loc && !isZooming) {
  // 只有在非缩放状态下才开始绘制

// 2. 第二根手指按下时的防护（第 858-874 行）

    currentDragRect.value = null;
    renderInkLayer(pageIdx);
  }

}

// 3. 移动时的防护（第 901 行）
} else if (dragStartPage.value !== -1 && !isZooming) {

// 4. 手指抬起时重置（第 945 行）
```

### `renderInkLayer` 清除原理
`renderInkLayer` 只会绘制 `allStrokes` 中保存的笔迹，而单点路径（只有起点圆点）不会被保存：

```typescript
// finishDrawing 中的保存条件（第 965 行）
} else if (save && path.length > 1) {
  // 只有 path.length > 1 才会保存到 allStrokes
  // 单点路径（只有起点）不会被保存
}

// renderInkLayer 重绘逻辑（第 528-555 行）
const renderInkLayer = (pageIndex: number) => {
  ctx.clearRect(0, 0, canvas.width, canvas.height);
  
  // 只绘制 allStrokes 中保存的笔迹
  const pageStrokes = allStrokes.value.filter(s => s.pageIndex === pageIndex);
  pageStrokes.forEach(stroke => drawStroke(ctx, stroke));
  
  // 只有当 dragStartPage 和 currentDragPath 有效时才绘制临时路径
  if (dragStartPage.value === pageIndex && currentDragPath.value.length > 0) {
    // 绘制临时路径
  }
};
```

## 可复用经验
1. **触摸事件状态管理**：在处理复杂的触摸交互时，使用全局状态标志（如 `isZooming`、`isPanning`）来明确标记当前的交互状态，避免状态混乱
2. **临时内容清除策略**：对于临时绘制的内容，应该使用可靠的清除机制：
   - 优先使用重绘整个图层（`renderInkLayer`）而不是依赖备份恢复
   - 确保在清除前先清空相关状态（`dragStartPage`、`currentDragPath`）
   - 重绘时只绘制已保存的内容，临时内容自然消失
3. **多层防护设计**：对于关键的交互逻辑，实现多层防护：
   - 第一层：事件开始时检查状态（如第一根手指按下时检查 `!isZooming`）
   - 第二层：状态切换时立即清理（如第二根手指按下时清空绘制状态）
   - 第三层：事件处理中持续检查（如 `onPointerMove` 中检查 `!isZooming`）
   - 第四层：事件结束时重置状态（如所有手指抬起时重置 `isZooming`）
4. **参考实现的价值**：当遇到复杂的交互问题时，参考已验证的正确实现（如 `lsdjf.html`）可以快速定位问题根源，避免走弯路
5. **Canvas 绘制最佳实践**：
   - 临时内容（如起点圆点）不应该直接保存到数据结构中
   - 使用 `renderInkLayer` 统一管理所有绘制内容
   - 通过条件判断（如 `dragStartPage.value === pageIndex`）来决定是否绘制临时内容
