问题序号：PDF 双指手势误触绘图工具问题

## 问题元信息
- **问题分类**：`前端`
- **严重程度**：`中`
- **影响范围**：`PDF 浏览页面的触摸交互（平板/触控设备所有用户）`
- **发现日期**：`2025-11-18`
- **解决状态**：`已解决`

## 问题现象
在 PDF 浏览页面中：
- 单指用于绘图工具（荧光笔、画笔、橡皮等）。
- 双指用于缩放/平移（捏合、双指拖动）。

原实现中，当用户已经选中某个绘图工具时：
- 尝试使用双指缩放或双指平移时，其中一根手指按下/抬起会被当成普通指针事件处理；
- 导致触发当前绘图工具的笔迹逻辑（开始/移动/结束），出现“用双指操作却画出线条或误触工具”的情况。

## 复现步骤
1. 在 PDF 页面中选择绘图相关工具：例如 `荧光笔` 或 `画笔`。
2. 在文档页面上用单指正常书写，确认绘图功能正常。
3. 保持当前工具不变，改用双指在页面上进行捏合缩放或双指拖动：
   - 两指依次落下并移动。
4. 观察：
   - 双指操作过程中，某些时刻会出现非预期的笔迹；
   - 或者当前工具的 `pointerdown/move/up` 被触发，留下多余线段。

## 用户体验
- 影响点1：用户想缩放/拖动页面，却意外在 PDF 上画线或擦除内容，造成笔迹污染。
- 影响点2：用户需要频繁切换到 `手型工具` 才能缩放/拖动，打断阅读和批注的流畅体验。
- 影响点3：在教学或演示场景下，误画的笔迹影响展示效果，需要额外时间清理。

## 相关文件/模块
- **涉及文件**：
  - `imates-web/src/components/PdfPage.vue`：
    - 承载 PDF 页面渲染、手势识别（touch/pointer）、绘图工具逻辑。
  - `imates-web/src/views/PdfViewerView.vue`：
    - 统一工具栏与 `PdfPage` 的工具模式联动（hand/highlighter/pen/eraser-draw/note/screenshot）。
- **涉及模块**：
  - PDF 手势与缩放模块：捏合缩放、双指平移、惯性滚动。
  - PDF 绘图工具模块：荧光笔、画笔、橡皮擦和截图框选。

## 技术原因 (❌)
1. 原始实现只通过 `isZooming` 标记来屏蔽缩放中的笔迹，但没有显式区分“多指手势”和“单指绘制”：
   - 当第二根手指按下/抬起的瞬间，可能还未正确设置或重置 `isZooming`，导致部分 `pointer` 事件仍被绘图逻辑消费。
2. PDF 页面只在 touch 层处理缩放/平移逻辑，没有为多指手势建立“临时工具模式（hand）”的状态机：
   - `currentMode` 始终保持为绘图工具（例如 `pen`），
   - 双指期间落下的某些指针会被视为绘制，而不是手势控制。
3. 绘图入口函数 `handleHighlightPointerDown/Move/Up` 缺少“多指期间全局暂停绘图”的保护开关：
   - 仅依赖缩放标记 `isZooming`，无法覆盖所有多指边界场景（例如刚开始或刚结束捏合时的残余事件）。

### 错误代码示例 (片段)
❌ 绘图入口未区分多指手势，仅依赖 zoom 状态：
```ts

```

❌ 多指开始时只设置缩放相关状态，没有临时切换工具，也没有暂停绘图：
```ts

  if (event.touches.length === 2) {
    isZooming.value = true
    event.preventDefault()

    const [touch1, touch2] = [event.touches[0], event.touches[1]]
    lastTouchDistance = getTouchDistance(touch1, touch2)
    pinchStartScale = store.scale

  }

```

## 正确实现方案 (✅)
1. 为多指手势增加独立的“临时工具切换”状态：
   - 新增 `lastToolMode: PdfInteractionMode | null`：记录进入多指手势前的工具模式。
   - 新增 `isPointerToolSuspended: Ref<boolean>`：标记多指/缩放期间，统一暂停所有绘图工具逻辑。
2. 在 `handleTouchStart` 中，当 `event.touches.length === 2` 时：
   - 若尚未暂停绘图：
     - 记录当前工具：`lastToolMode = currentMode.value`；
     - 设置 `isPointerToolSuspended.value = true`；
     - 将 `currentMode.value` 临时切换为 `'hand'`（如果当前不是 hand）。
   - 继续执行原有捏合初始化（`lastTouchDistance`、`pinchStartScale` 等）。
3. 在 `handleTouchEnd` 中，当 `event.touches.length < 2` 时：
   - 若处于暂停绘图状态：
     - 清除 `isPointerToolSuspended.value`；
     - 将 `currentMode.value` 恢复为 `lastToolMode`（如果非 hand）；
     - 清空 `lastToolMode`。
   - 同时重置 `isZooming`、`lastTouchDistance` 等缩放标记，并保留原有的惯性滚动逻辑。
4. 在绘图入口函数 `handleHighlightPointerDown/Move/Up` 中，增加对 `isPointerToolSuspended` 的检查：
   - 若为 `true`，则直接返回（`pointerup` 时还需清理临时笔迹和预览）。
   - 确保多指期间所有 pointer 事件不会落入绘图逻辑。

### 正确代码示例 (片段)
✅ 多指期间临时切为 hand 并暂停绘图工具：
```ts
// 多指手势期间临时切换工具状态
let lastToolMode: PdfInteractionMode | null = null // 记录进入多指手势前的工具
const isPointerToolSuspended = ref(false) // 多指/缩放期间暂停绘图工具
```

```ts
// 触摸开始（双指）
const handleTouchStart = (event: TouchEvent) => {
  if (isScreenshotMode.value && event.touches.length === 1) {
    event.preventDefault()
    return
  }
  // 高亮、画笔或橡皮擦模式下，优先将触摸事件用于绘制，避免触发浏览器滚动/缩放手势
  if (['highlighter', 'pen', 'eraser-draw'].includes(currentMode.value)) {
    event.preventDefault()
  }
  if (!containerRef.value || !viewerContainer.value) return

  if (event.touches.length === 2) {
    // 多指开始：临时切换为 hand 模式并暂停绘图工具
    if (!isPointerToolSuspended.value) {
      lastToolMode = currentMode.value
      isPointerToolSuspended.value = true
      if (currentMode.value !== 'hand') {
        currentMode.value = 'hand'
      }
    }
    isZooming.value = true
    event.preventDefault()
    // ... 原有捏合初始化逻辑
  }
}
```

✅ 多指结束时恢复原工具并恢复绘图：
```ts
// 触摸结束
const handleTouchEnd = (event: TouchEvent) => {
  if (event.touches.length < 2) {
    // 多指结束：恢复之前的工具模式并恢复绘图工具
    if (isPointerToolSuspended.value) {
      isPointerToolSuspended.value = false
      if (lastToolMode && lastToolMode !== 'hand') {
        currentMode.value = lastToolMode
      }
      lastToolMode = null
    }
    // 所有缩放手势结束时重置 isZooming
    isZooming.value = false
    lastTouchDistance = 0
    isPinching = false
    // ... 保留原有惯性滚动逻辑
  }
}
```

✅ 绘图入口统一尊重暂停标记：

## 关键代码/公式
- **关键状态变量**：
  - `currentMode: Ref<PdfInteractionMode>`：当前交互模式（hand / note / highlighter / pen / eraser-draw）。
  - `lastToolMode: PdfInteractionMode | null`：多指手势前的工具模式备份。
  - `isPointerToolSuspended: Ref<boolean>`：多指/缩放期间暂停绘图工具的总开关。
  - `isZooming: Ref<boolean>`、`isPinching: boolean`：捏合缩放状态标记。

- **关键逻辑公式**：
  - 多指开始条件：`event.touches.length === 2`。
  - 多指结束条件：`event.touches.length < 2`。
  - 暂停绘图判定：`if (isPointerToolSuspended.value) return`。

## 测试验证
- **测试场景**：
  - 场景1：
    - 选择 `画笔` 工具 → 单指连续书写 → 双指捏合缩放 → 松手后继续单指书写。
    - 预期：双指期间不产生任何新笔迹，松手后仍留在画笔工具，可继续书写。
  - 场景2：
    - 选择 `荧光笔` 工具 → 双指平移页面 → 松手后继续使用荧光笔绘制。
    - 预期：双指期间只发生平移，不会画线；松手后自动恢复荧光笔。
  - 场景3：
    - 选择 `橡皮擦` 工具 → 单指擦除 → 双指缩放 → 松手后继续擦除。
    - 预期：缩放过程中不会误擦，松手恢复橡皮工具。

- **验证方法**：
  - 方法1：在真实设备（平板或触控屏）上多次测试捏合/双指拖动，确认无误画/误擦现象。
  - 方法2：观察 `currentMode` 状态变化（可通过调试日志/调试面板）确认：
    - 多指开始时变为 `hand`；
    - 多指结束后恢复为原工具。

## 预防措施
- 措施1：所有需要“暂时接管交互”的手势（如多指、长按）应配套设计“临时状态 + 恢复逻辑”，避免与现有工具逻辑竞争。
- 措施2：在绘图入口统一增加“模式/状态总开关”（如 `isPointerToolSuspended`），防止遗漏单个事件处理函数。
- 措施3：针对触摸交互，优先在真机进行多场景测试（单指、多指、快速切换），避免只在桌面浏览器模拟。

- 经验1：在复杂交互场景中，使用“临时模式 + 全局暂停开关”可以优雅地协调多个工具/手势的优先级。
