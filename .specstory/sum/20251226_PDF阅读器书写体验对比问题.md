问题序号：PDF阅读器书写体验对比问题

## 问题元信息
- **问题分类**：`前端/性能`
- **严重程度**：`中`
- **影响范围**：`PDF 阅读器组件的书写体验，与专业绘图板组件对比`
- **发现日期**：`2025-12-26`
- **解决状态**：`已解决`

## 问题现象
在分析 PdfPage.vue 和 drawingBoardNew.vue 两个组件的书写体验时，发现：
- PdfPage.vue 在内容很多时仍保持流畅，而 drawingBoardNew.vue 在笔迹增多后性能下降明显
- 两个组件在书写平滑度、事件采样精度等方面存在差异
- 专业绘图板组件（drawingBoardNew.vue）在书写体验上更胜一筹

## 复现步骤
1. 步骤1：分析两个组件的源码实现，比较其绘制算法和事件处理逻辑
2. 步骤2：对比两个组件在笔迹数量增多时的性能表现
3. 步骤3：观察两个组件在快速书写时的线条平滑度和精确度差异

## 用户体验
- 影响点1：PDF阅读器书写体验相对粗糙，线条不够圆润
- 影响点2：PDF阅读器在海量内容下仍能保持流畅，但书写质量不如专业绘图板
- 影响点3：专业绘图板组件提供更精细的书写体验，但在大文档下性能下降明显

## 相关文件/模块
- **涉及文件**：
  - `imates-web/src/components/PdfPage.vue`：PDF阅读器组件
  - `imates-web/src/components/drawingBoardNew.vue`：专业绘图板组件
- **涉及模块**：
  - Canvas 渲染引擎：两个组件都使用 Canvas 进行绘制
  - 事件处理系统：Pointer Events vs Touch/Mouse Events
  - 性能优化策略：空间索引、增量渲染等

## 技术原因 (❌)
1. 原因1：**事件采样策略差异**
   - drawingBoardNew.vue 使用 `getCoalescedEvents()` 获取高频采样点
   - PdfPage.vue 使用标准的 touchmove/mousemove 事件，采样频率较低

2. 原因2：**线条平滑算法不同**
   - drawingBoardNew.vue 使用二次贝塞尔曲线 + 高频事件合并
   - PdfPage.vue 最初使用直线连接，后升级为贝塞尔曲线但采样频率不足

3. 原因3：**性能优化策略差异**
   - PdfPage.vue 使用页面隔离架构，避免全局重绘
   - drawingBoardNew.vue 采用全局渲染，性能随内容线性下降

错误示例（PdfPage.vue 初始实现）：
```typescript
// ❌ 直线连接，采样频率低
const moveDrawing = (x, y) => {
  currentDragPath.value.push({ x, y });
  renderInkLayer(dragStartPage.value); // 全量重绘
};
```

## 正确实现方案 (✅)
1. 方案1：**升级事件采样策略**
   - 使用 `getCoalescedEvents()` 获取高频触摸点
   - 实现事件合并处理，避免帧率波动影响

2. 方案2：**优化线条平滑算法**
   - 采用二次贝塞尔曲线插值
   - 实现增量绘制，避免全量重绘

3. 方案3：**平衡性能与体验**
   - 结合页面隔离和增量渲染
   - 在 PDF 阅读场景下保持流畅体验

正确示例：
```typescript
// ✅ 高频事件采样 + 增量绘制
const onPointerMove = (e) => {
  const events = e.getCoalescedEvents ? e.getCoalescedEvents() : [e];
  events.forEach(ev => {
    const loc = getPdfLocation(ev.clientX, ev.clientY);
    if (loc) {
      currentPath.value.push({ x: loc.x, y: loc.y });
      drawIncremental(loc.pageIndex, currentPath.value); // 增量绘制
    }
  });
};
```
