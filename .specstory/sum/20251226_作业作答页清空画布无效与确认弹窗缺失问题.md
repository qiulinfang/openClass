问题序号：作业作答页清空画布无效与确认弹窗缺失问题

## 问题元信息
- **问题分类**：`前端`
- **严重程度**：`中`
- **影响范围**：`作业作答（homework-answer）白板清空功能`
- **发现日期**：`2025-12-26`
- **解决状态**：`已解决`

## 问题现象
在作业作答页点击白板工具栏“清空”没有反应，或清空后未能正确同步缓存；同时缺少类似画板页的“确认清空”弹窗。

## 复现步骤
1. 步骤1：进入作业作答页 `homework-answer`。
2. 步骤2：在白板上绘制内容。
3. 步骤3：点击工具栏“清空”。
4. 步骤4：观察画布未清空/或清空后切题切回仍有残留（缓存未同步）。

## 用户体验
- 影响点1：用户无法清空当前白板，操作无反馈。
- 影响点2：清空与缓存不一致时，切题/翻页后出现“清空又回来”的错觉。
- 影响点3：缺少确认弹窗，容易误触导致数据丢失（期望与 DrawingBoardView 一致）。

## 相关文件/模块
- **涉及文件**：
  - `imates-web/src/views/HomeworkAnswerView.vue`：作业作答白板/缓存管理。
  - `imates-web/src/views/DrawingBoardView.vue`：参考实现（确认弹窗 + loadData 清空）。
  - `imates-web/src/components/DrawingBoardNew.vue`：`@clear` 事件仅 emit，实际清空应由父组件执行。
- **涉及模块**：
  - homeworkStore：`answerDataCache` 缓存

## 技术原因 (❌)
1. `DrawingBoardNew` 的清空按钮触发的是 `emit('clear')`，父组件未监听时不会清空。
2. 作业作答页清空实现与画板页不一致：
   - 没有确认弹窗
   - 使用 `clearAll()` / 或未同步写回缓存，导致状态不一致

错误代码示例（节选）：
```ts
// ❌ 没有弹窗确认；且仅清 UI 或写入 null，可能导致恢复逻辑不一致
board.clearAll()
cache.pages[pageIndex] = null
```

## 正确实现方案 (✅)
1. `HomeworkAnswerView` 监听 `@clear`，改为先打开确认弹窗。
2. 确认后使用与 `DrawingBoardView` 一致的“空数据”方式清空：
   - `loadData({ objects: [], history: [[]], historyIndex: 0 })`
3. 清空后立即 `saveData()`，同步写回 `answerDataCache` 当前页，确保切题/恢复时一致。
4. 补充确认弹窗文案区域样式。

正确代码示例（节选）：
```vue
<DrawingBoardNew @clear="handleClearRequest" />
<DraggableDialog v-model="showClearDialog" @confirm="confirmClearCanvas" @cancel="cancelClearCanvas">
  <div class="delete-confirm-content">确定要清空画布吗？此操作不可撤销。</div>
</DraggableDialog>
```

```ts
const confirmClearCanvas = () => {
  board.loadData({ objects: [], history: [[]], historyIndex: 0 })
  const clearedData = board.saveData()
  cache.pages[pageIndex] = clearedData
}
```

## 关键代码/公式
- 代码片段1：`HomeworkAnswerView.vue`：`handleClearRequest/confirmClearCanvas/cancelClearCanvas`
- 代码片段2：`DrawingBoardView.vue`：`confirmClearCanvas()`（参考实现）

## 测试验证
- **测试场景**：
  - 场景1：白板有内容 -> 点击清空 -> 弹窗出现 -> 点击“清空” -> 画布清空。
  - 场景2：清空后切换题目再切回/翻页再回来 -> 仍保持清空。
- **验证方法**：
  - 方法1：观察 UI 是否弹出确认框。
  - 方法2：观察 `answerDataCache[questionKey].pages[pageIndex]` 被写入空白板数据。

## 预防措施
- 措施1：统一约定：`DrawingBoardNew` 的“清空”永远只 emit，所有业务页必须显式处理。
- 措施2：清空操作统一使用 `loadData(空数据)`，避免多种清空方式导致恢复逻辑分叉。

## 可复用经验
- 经验1：可复用组件的 destructive action（清空/删除）应由业务层统一弹确认。
- 经验2：UI 状态变更后要同步更新持久化/缓存，避免“切换后回滚”。
