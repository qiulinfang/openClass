问题序号：PDF画笔轨迹不圆滑与丢笔迹问题

## 问题元信息
- **问题分类**：前端
- **严重程度**：中
- **影响范围**：PDF 阅读页手写画笔（pen）工具，在平板/触控设备上的书写体验
- **发现日期**：2025-11-18
- **解决状态**：已解决

## 问题现象
在 `PdfPage.vue` 中使用画笔工具（`pen`）快速书写时，用户发现：

- 画出的线条不够圆滑，存在明显折线、锯齿感。
- 快速书写时，部分笔迹会出现“缺口”或“断笔”，看起来像是采样点丢失。
- 高亮工具问题不明显，但签名/书写文字时体验较差。

## 复现步骤
1. 打开 PDF 阅读页，进入 `PdfViewerView.vue`，确保工具栏默认在 `hand` 模式。
2. 点击工具栏上的画笔工具 `pen`，切换到手写模式。
3. 在触控设备（或触摸板）上快速书写文字或画 S 型曲线：
   - 快速移动手写笔或手指。
4. 观察生成的笔迹：
   - 线条呈现折线、不平滑。
   - 局部存在“断裂”或丢失一部分路径的情况。

## 用户体验
- 影响点1：手写文字不自然，线条生硬，影响阅读和标注体验。
- 影响点2：快速书写时出现“断笔”，用户需要反复重写，增加操作成本。
- 影响点3：与预期的“流畅书写体验”不符，整体观感和信心下降。

## 相关文件/模块
- **涉及文件**：
  - `imates-web/src/components/PdfPage.vue`：PDF 页面渲染、手势和手写工具的主要实现文件。
  - `imates-web/src/views/PdfViewerView.vue`：顶部工具栏切换 `pen` / `hand` / `highlighter` 等工具，驱动 `PdfPage` 的交互模式。
- **涉及模块**：
  - PDF 手写绘制模块：处理 `pointer` 事件、构造 `HighlightStroke` 点列，创建 MuPDF Ink 注释。
  - 手势/缩放模块：`isZooming`、`isPinching` 控制缩放与绘制之间的互斥。

## 技术原因 (❌)
1. 原因1：**时间节流导致采样点过少**
   - 原始实现中在 `handleHighlightPointerMove` 使用了基于时间的节流：
   - 约 16ms 才允许一次预览更新，很多 `pointermove` 事件被丢弃。
   - 对高亮影响较小，但对细线画笔会导致路径采样点过稀，形成折线和缺口。

2. 原因2：**缺少距离阈值和几何层面的插值/平滑**
   - 原始实现只是简单地把采样点 push 进数组，在 MuPDF 中直接连接这些点：
   - 没有使用“最小距离阈值”去控制采样密度。
   - 没有任何线条平滑或插值算法，轨迹完全依赖设备事件频率，易受硬件/帧率波动影响。

3. 原因3：**所有模式共用同一节流策略**
   - 高亮、画笔、橡皮擦共用同一个时间节流策略，未针对 `pen` 模式做单独优化。
   - 导致在 `pen` 模式下快速书写时，采样频率不足，而高亮和橡皮擦其实更容忍节流。

**错误代码示例（节流导致点稀疏）：**
```ts
// 旧实现片段（简化示意）
let lastHighlightPreviewTime = 0
const HIGHLIGHT_PREVIEW_INTERVAL = 16 // ms

const handleHighlightPointerMove = (
  event: PointerEvent,
  pageIndex: number,
  layout: { width: number; height: number }
) => {
  // ... 省略模式判断
  const point = screenPointToPdfPoint(event.clientX, event.clientY, pageIndex, layout)
  if (!point) return

  currentStroke.value.points.push(point)

  const now = performance.now()
  if (now - lastHighlightPreviewTime < HIGHLIGHT_PREVIEW_INTERVAL) {
    return
  }
  lastHighlightPreviewTime = now

  // 直接用当前点列绘制预览
  drawStrokePreview(pageIndex, layout)
}
```

## 正确实现方案 (✅)
1. 方案1：**对 pen 模式使用“距离阈值”控制采样密度**
   - 为 `pen` 模式引入 `MIN_PEN_POINT_DIST2` 常量，只在相邻点距离超过阈值时采样：
   - 避免点过于稀疏导致断笔，又防止点过密带来的性能问题。

2. 方案2：**取消 pen 的时间节流，仅对高亮/橡皮擦保留节流**
   - 保证 `pen` 模式几乎可以响应所有 `pointermove` 事件，轨迹更跟手。
   - 对高亮/橡皮擦继续使用 16ms 节流，减轻开销。

3. 方案3：**在笔画结束时对 pen 轨迹做简单插值/平滑**
   - 引入 `smoothStrokePoints`：
     - 先对原始点列做一次细分，在每对相邻点之间插入中点。
     - 再对细分后的点列做三点移动平均平滑，去除尖锐抖动。
   - 只对 `stroke.mode === 'pen'` 使用该平滑结果写入 MuPDF Ink 注释，高亮保持原样。

**修正后关键代码示例（采样 + 平滑）：**
```ts
// PdfPage.vue 中 pen 模式的最小点间距
const MIN_PEN_POINT_DIST2 = 0.8 * 0.8 // 可根据实际调，单位是 PDF 坐标系距离

// 手写高亮 / 画笔 / 橡皮擦：移动过程中追加点
const handleHighlightPointerMove = (
  event: PointerEvent,
  pageIndex: number,
  layout: { width: number; height: number }
) => {
  // ... 省略缩放/截图判断

  if (!['highlighter', 'pen', 'eraser-draw'].includes(currentMode.value)) return
  if (!currentStroke.value) return
  if (currentStroke.value.pageIndex !== pageIndex) return

  const point = screenPointToPdfPoint(event.clientX, event.clientY, pageIndex, layout)
  if (!point) return

  const stroke = currentStroke.value
  const lastPoint = stroke.points[stroke.points.length - 1]

  // pen 模式使用距离阈值控制采样密度
  if (stroke.mode === 'pen') {
    const dx = point.x - lastPoint.x
    const dy = point.y - lastPoint.y
    const dist2 = dx * dx + dy * dy
    if (dist2 >= MIN_PEN_POINT_DIST2) {
      stroke.points.push(point)
    }
  } else {
    // 高亮 / 橡皮擦仍然每次都追加点
    stroke.points.push(point)
  }

  // 预览节流：仅对高亮/橡皮擦模式应用，pen 模式不过滤 pointermove
  if (stroke.mode !== 'pen') {
    const now = performance.now()
    if (now - lastHighlightPreviewTime < HIGHLIGHT_PREVIEW_INTERVAL) {
      return
    }
    lastHighlightPreviewTime = now
  }

  if (stroke.mode === 'eraser') {
    void drawEraserHitPreview(pageIndex, layout, stroke.points)
  } else {
    drawStrokePreview(pageIndex, layout)
  }
}

// 笔迹平滑工具（仅对 pen 模式做简单平滑）
const smoothStrokePoints = (points: HighlightStrokePoint[]): HighlightStrokePoint[] => {
  if (points.length <= 2) {
    return points
  }

  const subdivided: HighlightStrokePoint[] = []

  for (let i = 0; i < points.length - 1; i++) {
    const p0 = points[i]
    const p1 = points[i + 1]
    subdivided.push(p0)

    // 在每对相邻点之间插入一个中点
    const mid: HighlightStrokePoint = {
      x: (p0.x + p1.x) / 2,
      y: (p0.y + p1.y) / 2,
    }
    subdivided.push(mid)
  }
  subdivided.push(points[points.length - 1])

  if (subdivided.length <= 2) {
    return subdivided
  }

  // 三点移动平均平滑
  const smoothed: HighlightStrokePoint[] = []
  smoothed.push(subdivided[0])

  for (let i = 1; i < subdivided.length - 1; i++) {
    const pPrev = subdivided[i - 1]
    const p = subdivided[i]
    const pNext = subdivided[i + 1]

    const avg: HighlightStrokePoint = {
      x: (pPrev.x + p.x + pNext.x) / 3,
      y: (pPrev.y + p.y + pNext.y) / 3,
    }
    smoothed.push(avg)
  }

  smoothed.push(subdivided[subdivided.length - 1])

  return smoothed
}

// 结束笔画并创建 MuPDF Ink 注释（仅片段）
const handleHighlightPointerUp = async (event: PointerEvent, pageIndex: number, layout: { width: number; height: number }) => {
  // ... 省略截图/判空逻辑

  const stroke = currentStroke.value
  currentStroke.value = null
  clearDrawingCanvas(pageIndex)
  if (!stroke || stroke.points.length < 2) return

  // 橡皮擦模式单独处理
  if (stroke.mode === 'eraser') {
    await eraseInkByEraserPath(pageIndex, stroke.points)
    return
  }

  const pdf = pdfDoc.value.asPDF()
  if (!pdf) return

  pdf.beginOperation?.('stroke')
  pdf.beginImplicitOperation?.()
  try {
    const page = pdf.loadPage(pageIndex) as mupdf.PDFPage
    const annot = page.createAnnotation('Ink')

    // 对 pen 模式的轨迹做一次简单平滑，高亮模式保持原始点列
    const sourcePoints =
      stroke.mode === 'pen' ? smoothStrokePoints(stroke.points) : stroke.points

    const inkList = [sourcePoints.map((p: HighlightStrokePoint) => [p.x, p.y] as mupdf.Point)]
    ;(annot as any).setInkList?.(inkList)

    // ... 设置颜色和线宽，更新页面
  } finally {
    pdf.endOperation?.()
  }

  await renderPage(pageIndex)
  void saveCurrentPdfToStorage()
}
```

## 关键代码/公式
- **关键代码片段1：pen 模式距离阈值采样**
  - 控制点的最小间距，避免断笔和点过密：`MIN_PEN_POINT_DIST2 = 0.8 * 0.8`。

- **关键代码片段2：细分 + 三点移动平均平滑**
  - 通过插入中点和三点平均让轨迹更平滑，减弱抖动。

- **关键公式：三点移动平均**
  - 对三点 `p_{i-1}, p_i, p_{i+1}`：

```text
p'_i = (p_{i-1} + p_i + p_{i+1}) / 3
```

## 测试验证
- **测试场景**：
  - 场景1：在平板上用手写笔快速写字、画圆、画 S 形曲线，观察线条是否连续、圆滑。
  - 场景2：慢速细写，确认轨迹没有明显“抖动放大”或形状被过度平滑。
  - 场景3：使用高亮工具和橡皮擦，验证行为未受新逻辑影响。

- **验证方法**：
  - 方法1：对比修改前后同一手写轨迹的视觉效果（可以录屏或截图对比）。
  - 方法2：在多个不同缩放倍数下书写，确认平滑逻辑与坐标转换配合正常。
  - 方法3：多次写入、关闭/重新打开 PDF，确认笔迹持久化后形状保持一致。

## 预防措施
- 措施1：对不同交互模式（高亮/画笔/橡皮/截图）设置独立的采样策略和节流参数，不要“一刀切”。
- 措施2：在引入时间节流时，同时考虑“空间采样”的最小距离阈值，保证几何密度足够。
- 措施3：对用户主观感受很强的交互（如手写）优先做实际设备测试，及时调整参数和算法。
