问题序号：教师题目会话存储格式优化

## 问题元信息
- **问题分类**：`[前端/架构]`
- **严重程度**：`[中]`
- **影响范围**：`[教师题目会话管理功能]`
- **发现日期**：`2025-11-08`
- **解决状态**：`[已解决]`

## 问题现象
教师题目会话（teacher-exercise）的存储方式为每个会话单独存储在一条 localStorage 记录中，导致：
1. localStorage 键数量过多，每个会话占用一个键
2. 存储管理分散，不便于统一管理
3. 读取效率较低，需要遍历多个键才能获取所有会话
4. 与教师通用会话（teacher-general）的存储方式不一致

## 复现步骤
1. 步骤1：创建多个教师题目会话
2. 步骤2：打开浏览器开发者工具，查看 localStorage
3. 步骤3：可以看到每个会话都有一条独立的 localStorage 记录，键名为 `${userId}_teacher-exercise-${sessionId}_session`

## 用户体验
- 影响点1：localStorage 键数量过多，可能影响浏览器性能
- 影响点2：存储管理分散，不便于维护和调试
- 影响点3：与教师通用会话的存储方式不一致，增加维护成本

## 相关文件/模块
- **涉及文件**：
  - `imates-web/src/stores/teacherExerciseChatStore.ts`：教师题目会话存储逻辑
  - `imates-web/src/components/debug/ChatSessionDebugPanel.vue`：调试面板中的会话管理功能
- **涉及模块**：
  - 教师题目会话存储模块：负责会话的持久化存储
  - 调试面板模块：负责会话的加载、删除、导入等功能

## 技术原因 (❌)
1. 原因1：每个会话使用独立的 localStorage 键存储，键名为 `${userId}_teacher-exercise-${sessionId}_session`
2. 原因2：没有统一的会话管理机制，所有会话分散存储
3. 原因3：与教师通用会话的存储方式不一致，教师通用会话已经使用统一存储格式

**错误代码示例**：

```typescript
// ❌ 旧格式：每个会话单独存储
const sessionKey = `${userId}_teacher-exercise-${sessionId}_session`
localStorage.setItem(sessionKey, JSON.stringify(session))

// ❌ 删除会话时直接删除 localStorage 键
localStorage.removeItem(`${userId}_teacher-exercise-${sessionId}_session`)
```

## 正确实现方案 (✅)
1. 方案1：将所有会话存储在一条 localStorage 记录中，键名为 `${userId}_teacher-exercise-sessions`
2. 方案2：使用对象结构存储，以 `sessionId` 为键，会话信息为值
3. 方案3：提供统一的会话管理函数（`getAllSessions()`, `getSession()`, `saveSession()`, `deleteSession()`）
4. 方案4：添加数据迁移功能，自动将旧格式数据迁移到新格式

**正确代码示例**：

```typescript
// ✅ 新格式：所有会话存储在一条记录中
const getSessionsStorageKey = (): string => {
  const userId = getCurrentUserIdOrDefault()
  return `${userId}_teacher-exercise-sessions`
}

// ✅ 加载所有会话
const loadAllSessions = (): Record<string, TeacherExerciseSession> => {
  const storageKey = getSessionsStorageKey()
  const data = localStorage.getItem(storageKey)
  if (!data) return {}
  try {
    return JSON.parse(data) || {}
  } catch (error) {
    console.error('加载教师题目会话失败:', error)
    return {}
  }
}

// ✅ 保存所有会话
const saveAllSessions = (sessions: Record<string, TeacherExerciseSession>): void => {
  const storageKey = getSessionsStorageKey()
  localStorage.setItem(storageKey, JSON.stringify(sessions))
}

// ✅ 获取单个会话
const getSession = (sessionId: string): TeacherExerciseSession | null => {
  const sessions = loadAllSessions()
  return sessions[sessionId] || null
}

// ✅ 保存单个会话
const saveSession = (session: TeacherExerciseSession): void => {
  const sessions = loadAllSessions()
  sessions[session.sessionId] = session
  saveAllSessions(sessions)
}

// ✅ 删除单个会话
const deleteSession = (sessionId: string): void => {
  const sessions = loadAllSessions()
  delete sessions[sessionId]
  saveAllSessions(sessions)
}

// ✅ 数据迁移：从旧格式迁移到新格式
const migrateOldSessions = (): void => {
  const userId = getCurrentUserIdOrDefault()
  const sessions = loadAllSessions()
  
  // 如果已经有新格式数据，不需要迁移
  if (Object.keys(sessions).length > 0) {
    return
  }
  
  // 遍历所有可能的旧格式键
  for (let i = 0; i < localStorage.length; i++) {
    const key = localStorage.key(i)
    if (key && key.startsWith(`${userId}_teacher-exercise-`) && key.endsWith('_session')) {
      try {
        const sessionData = localStorage.getItem(key)
        if (sessionData) {
          const session = JSON.parse(sessionData) as TeacherExerciseSession
          if (session.sessionId) {
            sessions[session.sessionId] = session
            // 迁移后删除旧格式数据
            localStorage.removeItem(key)
          }
        }
      } catch (error) {
        console.error('迁移会话失败:', key, error)
      }
    }
  }
  
  // 保存迁移后的数据
  if (Object.keys(sessions).length > 0) {
    saveAllSessions(sessions)
  }
}
```

## 关键代码/公式
- **统一存储键名**：`${userId}_teacher-exercise-sessions`

- **数据迁移逻辑**：在创建新会话时自动检测并迁移旧格式数据

## 预防措施
- 措施1：统一存储格式设计，在项目初期就确定存储格式，避免后续修改
- 措施2：提供数据迁移机制，在存储格式变更时自动迁移旧数据
- 措施3：保持不同会话类型的存储方式一致，便于维护和理解
- 措施4：添加存储格式版本号，便于后续格式升级和迁移

## 可复用经验
- 经验1：**统一存储格式**：对于同一类型的多个数据项，使用统一存储格式可以减少 localStorage 键数量，提高管理效率
- 经验2：**数据迁移机制**：在存储格式变更时，提供自动迁移机制，确保用户数据不丢失
- 经验3：**向后兼容**：在修改存储格式时，考虑向后兼容，自动迁移旧格式数据
- 经验4：**统一管理接口**：提供统一的 CRUD 接口（`getAllSessions()`, `getSession()`, `saveSession()`, `deleteSession()`），便于外部组件使用
- 经验5：**存储格式一致性**：保持不同会话类型的存储方式一致，便于维护和理解
