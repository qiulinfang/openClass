问题序号：退出登录未停止投屏问题

## 问题元信息
- **问题分类**：`前端`
- **严重程度**：`高`
- **影响范围**：`Android WebView 内投屏功能、退出登录流程`
- **发现日期**：`2025-12-26`
- **解决状态**：`已解决`

## 问题现象
用户在投屏状态下点击“退出登录”，页面跳转到登录页，但 Android 侧投屏仍在继续（没有停止投屏/退出课堂）。

## 复现步骤
1. 登录应用并进入课堂/开启投屏。
2. 在主界面底部导航点击“退出登录”。
3. 观察：已跳转登录页，但投屏仍持续（未退出）。

## 用户体验
- 退出登录后仍在投屏，用户误以为已退出但实际仍占用资源。
- 可能导致课堂状态与账号状态不一致。
- 需要用户手动停止投屏，流程割裂。

## 相关文件/模块
- **涉及文件**：
  - `imates-web/src/views/MainView.vue`：退出登录入口 `handleLogoutClick`。
  - `imates-web/src/services/business/android-bridge.ts`：原生桥接接口 `stopScreenProjection/exitClassroom`。
- **涉及模块**：
  - 退出登录流程：导航栏 logout。
  - 投屏/课堂：AndroidBridge 屏幕投屏与课堂退出。

## 技术原因 (❌)
1. 退出登录逻辑仅做路由跳转，未调用原生投屏停止接口。
2. 投屏/课堂状态属于原生侧能力，不会随着前端路由切换自动停止。

错误示例：
```typescript
// ❌ MainView.vue
const handleLogoutClick = async () => {
  // ...
  router.push('/login')
}
```

## 正确实现方案 (✅)
1. 在退出登录入口处（`handleLogoutClick`）在跳转前调用原生接口：
   - `androidBridge.stopScreenProjection()`：停止投屏
   - `androidBridge.exitClassroom()`：退出课堂（可选，但与投屏强关联时建议一起做）
2. 用 `androidBridge.isAndroidBridgeAvailable()` 做环境保护，Web 环境不执行。
3. 原生调用失败不阻塞登出流程，使用 `try/catch` 吞掉异常。

正确示例：
```typescript
// ✅ MainView.vue
import { androidBridge } from '@/services/business/android-bridge'

const handleLogoutClick = async () => {
  if (androidBridge.isAndroidBridgeAvailable()) {
    try { androidBridge.stopScreenProjection() } catch {}
    try { androidBridge.exitClassroom() } catch {}
  }
  router.push('/login')
}
```

## 关键代码/公式
```typescript
androidBridge.isAndroidBridgeAvailable()
androidBridge.stopScreenProjection()
androidBridge.exitClassroom()
```

## 测试验证
- **测试场景**：
  - 场景1：Android WebView 投屏中点击退出登录，预期投屏立即停止。
  - 场景2：Android WebView 未投屏点击退出登录，预期正常跳转且无报错。
  - 场景3：纯 Web 环境点击退出登录，预期仅跳转不报错。
- **验证方法**：
  - 方法1：观察 Android 端投屏回调/状态（`onScreenProjectionStopped`）触发。
  - 方法2：观察课堂状态回调（`onClassroomExited`）或原生日志。

## 预防措施
- 在“退出登录/切换账号/Token 失效强制登出”统一出口封装清理流程（包含原生状态清理）。
- 增加 E2E 用例覆盖：投屏状态下登出。

## 可复用经验
- 原生能力（投屏/录音/相机等）必须在关键业务流程（登出/退出页面）显式清理。
- 登出流程尽量只有一个入口，避免遗漏清理动作。
