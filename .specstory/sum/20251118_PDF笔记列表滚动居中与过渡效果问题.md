问题序号：PDF笔记列表滚动居中与过渡效果问题

## 问题元信息
- **问题分类**：`前端`
- **严重程度**：`低`
- **影响范围**：`从笔记列表点击联动滚动 PDF 页面的位置与体验`
- **发现日期**：`2025-11-18`
- **解决状态**：`已解决`

## 问题现象
在 PDF 阅读页中，点击右侧笔记列表中的某一条笔记，会调用 `scrollToNote` 将左侧 PDF 页面滚动到对应的位置。但存在以下体验问题：

- 之前的实现是将目标笔记对应的 Y 坐标直接对齐到视口顶部，即 `containerRef.value.scrollTop = offsetY * scale`。
- 滚动是瞬间完成的，没有任何过渡效果，给用户带来“突然跳转”的感受。
- 目标笔记往往位于视口的最上方位置，不利于上下文阅读，用户需要额外滚动进行微调。

## 复现步骤
1. 打开 PDF 阅读页，确保右侧笔记列表面板可见，并已有多条笔记分布在不同页面和位置。
2. 在右侧列表中点击某条笔记。
3. 观察左侧 PDF 的表现：
   - 实际表现（问题前）：页面瞬间跳到对应位置，笔记锚点在视口顶部附近，缺少过渡动画。
   - 预期行为：页面以平滑动画滚动，并尽量将笔记锚点滚动到视口中间位置。

## 用户体验
- 影响点1：滚动跳转没有过渡动画，使用户难以感知“从哪里滚到哪里”，容易迷失上下文。
- 影响点2：笔记锚点总是贴在顶部，阅读时上下文信息偏少，需要手动再向下滚动才能看到更多内容。
- 影响点3：与右侧笔记列表高亮联动的交互不够顺滑，整体体验略显生硬。

## 相关文件/模块
- **涉及文件**：
  - `imates-web/src/components/PdfPage.vue`：包含 `scrollToNote` 函数，负责从笔记列表点击滚动 PDF 到对应位置。
- **涉及模块**：
  - PDF 页面滚动与布局模块。
  - 笔记列表与 PDF 主视图联动模块。

## 技术原因 (❌)
1. 原因1：原始实现中仅计算了目标笔记位置的绝对偏移 `offsetY * scale`，并直接赋给 `scrollTop`，没有考虑视口高度和“居中”体验。
2. 原因2：滚动使用同步赋值 `scrollTop = ...`，没有利用浏览器原生的 `scrollTo({ behavior: 'smooth' })` 或其他动画方案，导致跳转生硬。
3. 原因3：缺乏对容器高度 `clientHeight` 与 `scrollHeight` 的边界控制，未防止目标滚动位置超出顶部或底部。

❌ 错误代码示例：
```ts
// PdfPage.vue（问题前，节选）
const scrollToNote = (note: PageNote) => {
  if (!containerRef.value || pageLayouts.value.length === 0) return

  const pageIndex = note.pageIndex
  if (pageIndex < 0 || pageIndex >= pageLayouts.value.length) return

  const pageGap = store.pageGap
  let offsetY = 0
  for (let i = 0; i < pageIndex; i++) {
    offsetY += pageLayouts.value[i].height + pageGap
  }

  const layout = pageLayouts.value[pageIndex]
  offsetY += note.y * layout.height

  const scale = store.scale || 1
  const targetScrollTop = offsetY * scale

  // ❌ 直接跳转，无过渡，也没有居中
  containerRef.value.scrollTop = targetScrollTop
  activeNoteId.value = note.id
}
```

## 正确实现方案 (✅)
1. 方案1：在 `scrollToNote` 中引入视口高度 `containerHeight`，基于目标位置 `rawScrollTop` 计算期望滚动到视口中间的位置：`rawScrollTop - containerHeight / 2`。
2. 方案2：通过 `container.scrollHeight - containerHeight` 计算最大可滚动距离 `maxScrollTop`，对 `targetScrollTop` 做上下界裁剪，防止滚动位置超出文档顶部或底部。
3. 方案3：使用浏览器原生的 `container.scrollTo({ top: targetScrollTop, behavior: 'smooth' })` 实现平滑滚动效果，提升交互体验。

✅ 正确代码示例：
```ts
// PdfPage.vue（修复后，节选）
const scrollToNote = (note: PageNote) => {
  if (!containerRef.value || pageLayouts.value.length === 0) return

  const pageIndex = note.pageIndex
  if (pageIndex < 0 || pageIndex >= pageLayouts.value.length) return

  const pageGap = store.pageGap
  let offsetY = 0
  for (let i = 0; i < pageIndex; i++) {
    offsetY += pageLayouts.value[i].height + pageGap
  }

  const layout = pageLayouts.value[pageIndex]
  offsetY += note.y * layout.height

  const scale = store.scale || 1
  const rawScrollTop = offsetY * scale

  const container = containerRef.value
  const containerHeight = container.clientHeight || (window.innerHeight - toolbarHeight.value)

  // 期望让笔记大致在屏幕中间
  let targetScrollTop = rawScrollTop - containerHeight / 2

  // 边界处理，防止滚动超出
  const maxScrollTop = container.scrollHeight - containerHeight
  if (targetScrollTop < 0) targetScrollTop = 0
  if (targetScrollTop > maxScrollTop) targetScrollTop = maxScrollTop

  // 带过渡效果的滚动
  container.scrollTo({
    top: targetScrollTop,
    behavior: 'smooth',
  })

  activeNoteId.value = note.id
}
```

## 关键代码/公式
- 代码片段1：滚动目标位置居中公式：

```ts
let targetScrollTop = rawScrollTop - containerHeight / 2
```

- 代码片段2：滚动边界裁剪与平滑滚动：

```ts
const maxScrollTop = container.scrollHeight - containerHeight
if (targetScrollTop < 0) targetScrollTop = 0
if (targetScrollTop > maxScrollTop) targetScrollTop = maxScrollTop

container.scrollTo({
  top: targetScrollTop,
  behavior: 'smooth',
})
```

## 测试验证
- **测试场景**：
  - 场景1：在 PDF 文档顶部、中部、底部附近分别创建多条笔记，从右侧列表点击不同位置的笔记，观察滚动是否平滑，且目标笔记大致位于视口中央。
  - 场景2：在缩放比例较大或较小时重复测试，验证滚动位置计算在不同 scale 下仍然正确。
- **验证方法**：
  - 方法1：通过浏览器开发者工具观察 `scrollTop` 的变化趋势，确认是通过动画缓慢变化而非瞬间跳变。
  - 方法2：在极端场景（靠近顶部或底部）点击笔记，确认不会出现滚动过头导致空白区域的问题。

## 预防措施
- 措施1：在实现“滚动到指定元素/位置”需求时，优先考虑用户感知体验（是否需要居中、是否需要平滑过渡），而不仅仅是技术上的定位准确。
- 措施2：统一封装滚动工具函数，避免在多个地方重复编写 `scrollTop` 计算逻辑，降低出错概率。
- 措施3：针对与滚动相关的体验优化（如居中、动画），增加手动测试用例，特别是在大文档、不同缩放比例下验证行为。
