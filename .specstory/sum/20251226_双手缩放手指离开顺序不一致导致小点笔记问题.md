问题序号：双手缩放手指离开顺序不一致导致小点笔记问题

## 问题元信息
- **问题分类**：`前端/事件处理`
- **严重程度**：`中`
- **影响范围**：`PDF阅读器双指缩放功能，用户缩放操作体验`
- **发现日期**：`2025-12-26`
- **解决状态**：`已解决`

## 问题现象
在PDF阅读器中进行双指缩放时：
- 手指离开顺序不同会导致意外生成小圆点笔记
- 缩放操作完成后屏幕上出现多余的笔记标记
- 影响了缩放操作的纯净体验

## 复现步骤
1. 步骤1：打开PDF阅读器，启用双指缩放
2. 步骤2：用两根手指进行缩放操作
3. 步骤3：先放开一根手指，再放开另一根手指，观察是否有小点生成

## 用户体验
- 影响点1：缩放操作产生意外的笔记，污染文档
- 影响点2：用户需要清理多余的笔记标记
- 影响点3：缩放手势的可靠性下降

## 相关文件/模块
- **涉及文件**：
  - `index.html`：PDF阅读器双指缩放和笔记绘制实现
- **涉及模块**：
  - 双指手势识别：多触点状态管理和事件处理
  - 笔记绘制逻辑：currentPath 和笔记生成逻辑
  - 状态清理：触点释放和路径清理

## 技术原因 (❌)
1. 原因1：**状态切换时机不当**
   - 双指缩放开始时没有及时清理当前的绘制状态
   - 从单指绘制切换到双指缩放时遗留了绘制路径

2. 原因2：**触点状态管理混乱**
   - 手指离开顺序影响了状态判断逻辑
   - 单指状态和双指状态之间的转换不完整

3. 原因3：**事件处理时序问题**
   - pointerdown 事件触发绘制，但后续的双指事件没有撤销
   - 导致意外的单点绘制被确认

错误示例：
```typescript
// ❌ 双指缩放开始时没有清理绘制状态
const onPointerDown = (e) => {
  activePointers.set(e.pointerId, { x: e.clientX, y: e.clientY });
  
  if (activePointers.size === 1) {
    // 第一根手指按下，开始绘制
    startDrawing(e.clientX, e.clientY);
  } else if (activePointers.size === 2) {
    // 第二根手指按下，切换到缩放，但绘制状态未清理
    // ❌ 这里应该撤销绘制状态
  }
};
```

## 正确实现方案 (✅)
1. 方案1：**及时的状态清理**
   - 双指缩放开始时立即撤销单指绘制状态
   - 防止遗留的绘制路径被意外确认

2. 方案2：**严格的模式互斥**
   - 绘制模式和缩放模式严格互斥
   - 双指操作时强制结束绘制模式

3. 方案3：**状态同步管理**
   - 触点状态变化时同步更新所有相关状态
   - 确保状态转换的原子性

正确示例：
```typescript
// ✅ 双指缩放开始时清理绘制状态
const onPointerDown = (e) => {
  activePointers.set(e.pointerId, { x: e.clientX, y: e.clientY });
  
  if (activePointers.size === 1) {
    if (isDrawing.value) {
      startDrawing(e.clientX, e.clientY);
    }
  } else if (activePointers.size === 2) {
    // 双指缩放开始：立即结束绘制，避免遗留状态
    endDrawing(); // 关键：清理任何遗留的绘制状态
    // 初始化缩放参数
    const pts = Array.from(activePointers.values());
    lastPinchDist = Math.hypot(pts[0].x - pts[1].x, pts[0].y - pts[1].y);
    lastPinchCenter = {
      x: (pts[0].x + pts[1].x) / 2,
      y: (pts[0].y + pts[1].y) / 2
    };
  }
};
```
