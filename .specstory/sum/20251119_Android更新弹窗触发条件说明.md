# Android 更新弹窗触发条件说明

## 1. 相关问题

- 问题：什么情况会弹出更新对话框？
- 目标：结合当前项目实际代码，明确更新对话框出现的前提条件与触发时机。

## 2. 更新弹窗依赖的关键组件

- 更新 URL：`ApiUrl.URL_APP_UPDATE`
  - 正式环境：`https://www.imates.com.cn/bj101/appupdate.json`
  - 测试环境：`https://www.imates.com.cn/appupdate_test.json`
- 更新库：`EasyUpdate`（对 XUpdate 的简化封装）
  - 调用方式：`EasyUpdate.create(context, ApiUrl.URL_APP_UPDATE).isAutoMode(false).update();`
  - 职责：
    - 访问更新 JSON（`appupdate.json`）。
    - 解析其中的版本信息和更新状态。
    - 对比服务器版本与本地 App 版本。
    - 判断是否需要更新，并在需要时弹出更新对话框。

## 3. 项目中哪些页面会触发更新检查

### 3.1 MainWebViewActivity

- 在 `onCreate` 中调用 `initUpdateCheck()`：
  - 启动后约 10 秒执行首次更新检查。
  - 之后每 60 秒执行一次 `mCheckUpdateRunnable`。
- `mCheckUpdateRunnable` 的逻辑：
  - 取 `updateUrl = ApiUrl.URL_APP_UPDATE`。
  - 调用 `checkUpdateWithHttpRequest(updateUrl)` 发送 HTTP 请求获取更新配置。
- `checkUpdateWithHttpRequest(updateUrl)` 中：
  - 使用 OkHttp 向 `updateUrl` 发送 GET 请求。
  - 收到 JSON 后解析 `VersionName`，并通过 `dispatchAppVersionEvent(serverVersion)` 通知 Web 端。
  - 在 UI 线程调用：
    ```java
    EasyUpdate.create(MainWebViewActivity.this, updateUrl)
            .isAutoMode(false)
            .update();
    ```

### 3.2 KnowledgeGraphActivity

- 在 `miscellaneousInitialization()` 中：
  - 立即调用一次：
    ```java
    EasyUpdate.create(this, ApiUrl.URL_APP_UPDATE)
            .isAutoMode(false)
            .update();
    ```
  - 同时启动定时任务，按 60 秒 tick、1 小时节流检查更新：
    - 每当距离上次检查超过 1 小时时，再次调用 EasyUpdate。

### 3.3 LoginActivity

- 结构与知识图谱类似：
  - 维护 `mCheckUpdateTick` 和 `mCheckUpdateHandler`。
  - 每 60 秒运行 runnable，一小时内只真正调用 `EasyUpdate.update()` 一次。

> 综上：当用户打开主 Web 页、知识图谱页或在登录页停留时，都有可能触发更新检查，从而进入弹窗判定逻辑。

## 4. 弹出更新对话框的必要条件

结合项目现有代码和 XUpdate/EasyUpdate 的典型行为，可以归纳为：

1. **EasyUpdate.update() 被调用**
   - 触发位置：
     - MainWebViewActivity：`checkUpdateWithHttpRequest()` 中，成功解析到服务器版本号后。
     - KnowledgeGraphActivity：启动时和之后的定时任务。
     - LoginActivity：定时任务（如已启动）。

2. **服务器更新配置允许更新**
   - `appupdate.json` 中通常包含：
     - `UpdateStatus`：是否有更新 / 是否强制更新。
     - `VersionCode` / `VersionName`：服务器最新版本号。
     - `DownloadUrl`：APK 下载地址。
     - `ApkMd5`：完整性校验。
   - 只有当 `UpdateStatus` 表示“有更新”（通常为 1 或 2）时，才继续按版本号判断。

3. **服务器版本号大于本地版本号**
   - XUpdate 的版本比较规则：
     - 以整数 `VersionCode`/`versionCode` 为主进行比较，而不是仅看 `VersionName`。
   - 条件类似：
     ```java
     if (serverVersionCode > localVersionCode) {
         // 需要更新，进入弹窗逻辑
     } else {
         // 不更新，不弹窗
     }
     ```
   - 若 `VersionCode` 与本地相等或更小，即使 `VersionName` 不同，也不会弹窗。

4. **AutoMode 设置为 false**
   - 项目中所有调用都设置：`.isAutoMode(false)`。
   - 表示不做静默更新，而是当满足更新条件时，显示可见的更新对话框，让用户手动确认和操作。

> 整体结论：**当某个 Activity 触发了 EasyUpdate.update()，且服务器 `appupdate.json` 中的 `UpdateStatus` 表示有更新、并且 `VersionCode` 大于本地 `versionCode` 时，就会弹出更新对话框。**

## 6. 调试弹窗相关问题的建议

1. **确认 EasyUpdate 是否被调用**
   - 通过在各调用点添加日志确认：
     - `MainWebViewActivity` 的 `checkUpdateWithHttpRequest`。
     - `KnowledgeGraphActivity.miscellaneousInitialization` 和定时 runnable。
     - `LoginActivity` 的定时 runnable。

2. **检查服务器返回的 JSON**
   - 用抓包或日志打印 `appupdate.json` 的完整内容。
   - 重点关注：`UpdateStatus`、`VersionCode`、`VersionName`、`DownloadUrl`。

3. **核对本地版本号配置**
   - 查看 `app/build.gradle` 中：
     ```gradle
     defaultConfig {
         versionCode X
         versionName "Y.Z.W"
     }
     ```
   - 确保服务器 `VersionCode` 严格大于此值。

4. **关注 EasyUpdate/XUpdate 自身日志**
   - 通过 tag 或官方文档提供的日志开关，查看内部判定“不更新”的原因（如 `isForce`, `ignoreVersion` 等）。
