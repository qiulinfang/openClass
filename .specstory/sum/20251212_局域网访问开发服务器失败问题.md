问题序号：局域网访问开发服务器失败问题

## 问题元信息
- **问题分类**：`[前端]`
- **严重程度**：`[中]`
- **影响范围**：`[局域网内需要联调或验收的成员]`
- **发现日期**：`2025-12-12`
- **解决状态**：`[待解决]`

## 问题现象
局域网内其他设备访问 `http://172.168.0.20:5173/` 时直接超时，无法看到正在开发中的 Vue/Vite 页面，即使本机已正常启动 dev server 并显示 Network 地址。

## 复现步骤
1. 在开发机执行 `npm run dev` 启动 imates-web 项目的 Vite 开发服务。
2. 另一台接入同一局域网的电脑在浏览器输入 `http://172.168.0.20:5173/`。
3. 页面持续加载后超时，无法建立连接。

## 用户体验
- 影响点1：团队成员或测试同学无法复现或验证最新功能。
- 影响点2：联调周期被迫延长，需要额外录屏/打包。
- 影响点3：多端同步调试流程被阻塞。

## 相关文件/模块
- **涉及文件**：
  - `imates-web/vite.config.ts`：Vite dev server 网络监听配置。
  - `package.json`：开发脚本是否显式传入 `--host`.
- **涉及模块**：
  - imates-web 前端开发环境。
  - 局域网调试/联调流程。

## 技术原因 (❌)
1. 原因1：Vite dev server 默认仅绑定 `localhost`，未显式监听 `0.0.0.0`。
2. 原因2：Windows 防火墙阻止了 Node 监听端口 5173 的入站请求。
3. 原因3：局域网设备未确认在同一网段或被路由器隔离。

```bash
# 错误示例：脚本未设置 host，默认只监听 127.0.0.1
npm run dev
```

## 正确实现方案 (✅)
1. 方案1：启动脚本追加 `--host 0.0.0.0`，确保对局域网开放。
2. 方案2：在 Windows 防火墙或安全软件中为 Node/Vite 的 5173 端口添加入站放行规则。
3. 方案3：确保所有联调设备连接同一网段，并通过 `ping` 验证互通。

```bash
# 正确示例：显式监听 0.0.0.0
npm run dev -- --host 0.0.0.0 --port 5173
```

## 关键代码/公式
- 代码片段1：vite.config.ts 中 server 配置
```ts
export default defineConfig({
  server: {
    host: '0.0.0.0', // ✅ 对局域网开放
    port: 5173,
  },
})
```
- 代码片段2：package.json dev 脚本
```json
{
  "scripts": {
    "dev": "vite --host 0.0.0.0 --port 5173"
  }
}
```

## 测试验证
- **测试场景**：
  - 场景1：启动 dev server，另一台电脑访问页面应成功加载。
  - 场景2：关闭防火墙后再次测试，确认访问结果一致，排除防火墙影响。
- **验证方法**：
  - 方法1：在其他电脑上 `ping 172.168.0.20`，确认连通。
  - 方法2：浏览器访问 `http://172.168.0.20:5173/` 返回页面且无超时。

## 预防措施
- 措施1：在模板/脚本中默认加入 `--host 0.0.0.0`。
- 措施2：第一次启动 Vite 时选择允许 Windows 防火墙访问。
- 措施3：联调前统一确认 IP、网段和安全策略。
