问题序号：AI聊天流式接口调用规范缺失问题

## 问题元信息
- **问题分类**：`[后端]`
- **严重程度**：`[中]`
- **影响范围**：`[AI聊天入口 / ChatInput 前端调用链]`
- **发现日期**：`2025-12-12`
- **解决状态**：`[已解决]`

## 问题现象
前端在对接 `/ai/chat-stream` 接口时缺乏请求/响应协议说明：
- 不确定应使用 `POST` 还是 SSE。
- 不清楚请求体 `MessageVO` 需要哪些字段、是否必须带登录态。
- 不知道响应是 `text/plain` 的逐行流，而不是 JSON，一次性读取会失败。

## 复现步骤
1. 在浏览器或前端项目中直接 `axios.post('/ai/chat-stream', {...})`，未做流式处理。
2. 请求体缺少如 `sessionId`、`role`、`isWebSearch` 等字段。
3. 期待一次性返回 JSON，结果一直 pending 或解析失败。

## 用户体验
- 聊天输入后无任何响应或报错。
- 浏览器 Network 显示请求挂起但页面无显示。
- 开发人员无法定位问题来源，严重影响体验调试效率。

## 技术原因 (❌)
1. 接口未在文档中声明其为 `text/plain` 流式返回，前端默认 JSON 解析导致阻塞。
2. `MessageVO` 字段（如 `coversation`、`sessionId`、`role`、`isWebSearch`）为后端必填，但前端缺乏说明导致请求体不全。
3. 控制器依赖 `JwtUtil.getUserInfo()` 取得用户身份，如未带 token 会抛异常，缺乏文档提醒。

```ts
// ❌ 错误示例：一次性读取 JSON，且缺少鉴权字段
const resp = await axios.post('/ai/chat-stream', {
  chatRole: 'mate',
  message: 'hi'
});
console.log(resp.data.answer); // 实际不会返回，且后端抛异常
```

## 正确实现方案 (✅)
1. 使用 `POST /ai/chat-stream`，`Content-Type: application/json`，body 满足 `MessageVO` 关键字段。
2. 请求需携带与业务接口相同的鉴权（Cookie / Authorization header）。
3. 通过 `fetch` + `ReadableStream` 逐行解码响应，实时渲染。

```ts
// ✅ 正确示例：使用 fetch 读取流并带上 token
async function callChatStream({ sessionId, text, role = 'mate', token }) {
  const resp = await fetch('/ai/chat-stream', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      Authorization: `Bearer ${token}`,
    },
    body: JSON.stringify({
      reason: 'start',
      coversation: text,
      sessionId,
      isWebSearch: '0',
      role,
    }),
  });
  const reader = resp.body?.getReader();
  const decoder = new TextDecoder('utf-8');
  while (reader) {
    const { value, done } = await reader.read();
    if (done) break;
    console.log(decoder.decode(value, { stream: true }));
  }
}
```
