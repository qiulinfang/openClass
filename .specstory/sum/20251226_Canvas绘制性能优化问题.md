# 问题序号：Canvas绘制性能优化问题

## 问题元信息
- **问题分类**：性能
- **严重程度**：高
- **影响范围**：Canvas 绘制功能，影响所有使用DrawingBoardNew组件的页面
- **发现日期**：2025-12-26
- **解决状态**：已解决

## 问题现象
在Canvas上绘制大量笔迹时出现严重的卡顿现象，尤其是在笔迹数量较多的情况下，每次绘制新笔迹都会触发全量重绘，导致O(N)性能问题。

## 复现步骤
1. 步骤1：在Canvas上连续绘制大量笔迹（50+条）
2. 步骤2：继续绘制新笔迹
3. 步骤3：观察到明显的卡顿延迟，帧率下降，交互不流畅

## 用户体验
- 影响点1：绘制体验卡顿，笔迹跟随延迟严重
- 影响点2：大量笔迹时页面响应变慢
- 影响点3：影响创作和学习效率

## 相关文件/模块
- **涉及文件**：
  - `imates-web/src/components/drawingBoardNew.vue`：主要的Canvas绘制组件
- **涉及模块**：
  - Canvas绘制引擎：负责笔迹渲染和交互

## 技术原因 (❌)
导致问题的技术原因：

1. **O(N)全量重绘**：每次绘制新笔迹时调用`renderAll()`重绘所有现有笔迹
2. **缺少分层渲染**：历史笔迹和实时笔迹都在同一层绘制
3. **频繁对象重建**：每次mousemove都创建新对象和数组拷贝
4. **Vue响应式深度观察**：对大型笔迹数据结构进行深度观察导致GC压力
5. **缺少视口剔除**：超出视口的笔迹仍参与绘制计算

❌ **错误代码示例：**
```typescript
// 每次绘制都全量重绘
function handlePointerMove(e) {
  // ... 处理绘制逻辑 ...
  renderAll() // ❌ O(N)性能问题
}

// Vue深度观察大型数据结构
const objects = ref<DrawObject[]>([]) // ❌ 深度观察所有笔迹数据
```

## 正确实现方案 (✅)
采用多层Canvas和优化策略解决性能问题：

1. **双层Canvas架构**：历史层+实时层分离绘制
2. **增量绘制策略**：历史层固定，实时层动态更新
3. **对象重用优化**：避免频繁创建新对象
4. **响应式优化**：使用`shallowRef`和`markRaw`控制观察深度
5. **视口剔除**：只绘制可见区域的笔迹

✅ **正确代码示例：**
```typescript
// 双层Canvas架构
const canvasRef = ref<HTMLCanvasElement>()
const liveCanvasRef = ref<HTMLCanvasElement>()

// 分层渲染
function render() {
  // 历史层：固定笔迹
  ctx.clearRect(0, 0, width, height)
  // 只重绘历史笔迹
}

function renderLiveLayer() {
  // 实时层：当前绘制笔迹
  liveCtx.clearRect(0, 0, width, height)
  // 只绘制当前笔迹
}

// 响应式优化
const objects = shallowRef<DrawObject[]>([])
objects.value.push(markRaw(obj)) // ✅ 浅层观察+标记原始对象

// 对象重用

```

## 关键代码/公式
**性能优化核心算法：**

- **双层渲染策略**：历史层O(1) + 实时层O(1) = O(1)总复杂度
- **增量更新**：新笔迹直接绘制到历史层，避免全量重绘
- **视口剔除**：使用AABB检测判断笔迹是否在可见区域
