问题序号：手写高亮预览跟手性与路径偏移问题

## 问题元信息
- **问题分类**：前端
- **严重程度**：中
- **影响范围**：Web 端 PDF 手写高亮的实时预览体验（鼠标 + 触摸）
- **发现日期**：2025-11-17
- **解决状态**：已解决

## 问题现象
在 Web 端 PDF 阅读器中使用手写高亮功能时，曾出现以下几个与“预览跟手性”和“路径偏移”相关的问题：

1. **触摸设备上预览中途停顿，不再跟手**：
   - 鼠标绘制时 PointerMove 日志持续输出，预览曲线从头到尾连续；
   - 触摸屏（pointerType: 'touch'）绘制时，起初 PointerDown/Move/预览日志都有，但滑动一段距离后 PointerMove 日志停止，预览中途不再更新。

2. **放大/缩小时预览轨迹相对于指针位置发生偏移**：
   - 在缩放 100% 下预览和实际 Ink 路径对齐；
   - 在放大 200% 或缩小时，预览线条偏向右下或左上，而最终 PDF 渲染出的 Ink 位置正确；
   - 说明 PDF 坐标是对的，但预览层的坐标映射随缩放出现了系统性偏移。

3. **长线绘制时预览变得不够跟手或卡顿**：
   - 一条很短的线预览很顺滑；
   - 同一条线拉得很长时，后半段预览帧率下降，感觉“不跟手”。

## 复现步骤
1. 打开 Web 端 PDF 阅读页面，加载任意 PDF。
2. 切换到“手写高亮模式”。
3. 在触摸屏上：
   1. 用一根手指画线，注意控制台日志：
      ```
      [手写高亮] PointerDown 事件 { pointerType: 'touch', ... }
      [手写高亮] PointerMove 追加点 { ... }
      [手写高亮] drawStrokePreview 绘制预览 { ... }
      ```
   2. 滑动一段后，日志中 PointerMove 停止出现，预览也停止更新。
4. 在缩放 200% 时用鼠标/触摸画线：
   - 观察预览线条与指针位置有明显偏移；
   - 松手后 PDF 渲染出的 Ink 线条位置正确。
5. 在 100% 缩放下画短线与超长线：
   - 短线预览流畅；
   - 长线后段预览有掉帧感。

## 用户体验
- 影响点1：触摸绘制时预览中途停止，用户误以为功能卡死或失效，降低信任感。
- 影响点2：缩放后预览轨迹与真实 Ink 位置不一致，导致用户难以判断实际标注范围。
- 影响点3：长线绘制不够跟手，尤其在教学、批注等需要连贯书写的场景下体验较差。

- **涉及模块**：

## 技术原因 (❌)
1. **触摸事件被浏览器默认滚动/手势抢占，导致 PointerMove 中途停止**：
   - 外层容器监听了 `@touchstart/@touchmove` 用于捏合缩放和滚动，但在高亮模式下没有阻止默认行为；
   - 单指或多指滑动一段后，浏览器将触摸解释为滚动/系统手势，PointerMove 不再分发给 `.page` 元素；
   - 结果是触摸路径一开始有若干 PointerMove，之后事件被“抢走”，预览中断。

2. **预览 canvas 与坐标计算存在双重缩放，造成路径偏移**：
   - 页面布局：
     ```ts
     const viewerInnerStyle = computed(() => ({
       width: `${maxWidth.value}px`,
       minHeight: `${totalHeight.value}px`,
       position: 'relative' as const,
       transform: `scale(${store.scale})`,
       transformOrigin: 'top left',
     }))
     ```
   - 即 `.viewer-inner` 整体通过 `transform: scale(scale)` 进行缩放，内部的 `.page` 和 `drawing-canvas` 会一起被放大/缩小。
   - 初期预览逻辑中：
     - `drawing-canvas` 的 `width/height` 也乘了 `store.scale`；
     - `pdfPointToScreenOnPage` 中又按 `nx * layout.width * scale` 计算屏幕坐标；
   - 这导致：
     - 坐标在 canvas 内部已经按 scale 放大；
     - 外层 transform 再次缩放；
     - 放大时偏向右下，缩小时偏向左上——典型的双重缩放导致的偏移。

3. **长线预览每次重绘整条路径，且在高缩放下像素量大导致卡顿**：
   - PointerMove 每次追加点后：
     ```ts
     drawStrokePreview(pageIndex, layout)
     ```
     - `drawStrokePreview` 会 `clearRect` 整个 canvas，然后遍历 `stroke.points` 的全部点，绘制完整 Bézier 曲线；
   - 当线很长时：
     - 点数量多，每一帧重绘成本大；
     - 在高 scale 下，视觉上绘制的长度更长、线宽更粗，fill 的像素更多，帧耗时明显增加。

## 正确实现方案 (✅)
1. **高亮模式下禁止默认触摸滚动/手势，保证 PointerMove 持续触发**：
   - 在 `.page` 上增加高亮模式类，结合 `touch-action` 控制：
     ```vue
     <div
       v-for="(layout, index) in pageLayouts"
       :key="index"
       class="page"
       :class="{ 'page-highlighting': isHighlightMode }"
       :style="getPageStyle(layout)"
       @pointerdown.passive="handleHighlightPointerDown($event, index, layout)"
       @pointermove.passive="handleHighlightPointerMove($event, index, layout)"
       @pointerup.passive="handleHighlightPointerUp($event, index, layout)"
       @pointercancel.passive="handleHighlightPointerUp($event, index, layout)"
     >
     ```
     ```css
     .page-highlighting {
       /* 高亮模式下，由组件自行处理触摸，不让浏览器触发滚动/缩放手势 */
       touch-action: none;
     }
     ```
   - 在触摸手势处理函数中，针对高亮模式 `preventDefault()`：
     ```ts
     const handleTouchStart = (event: TouchEvent) => {
       if (isHighlightMode.value) {
         event.preventDefault()
       }
       // ... 原有捏合初始化逻辑
     }

     const handleTouchMove = (event: TouchEvent) => {
       if (isHighlightMode.value) {
         event.preventDefault()
       }
       // ... 原有捏合缩放逻辑
     }
     ```
   - 这样在高亮模式下，触摸事件优先用于绘制，不会轻易被滚动/捏合抢占。

2. **统一预览坐标系：使用页面逻辑尺寸 + transform 统一缩放，避免双重 scale**：
   - 将 `drawing-canvas` 固定在 layout 逻辑尺寸，不再乘 scale：
     ```vue
     <canvas
       v-if="isHighlightMode && currentStroke?.pageIndex === index"
       :ref="(el) => setDrawingCanvasRef(el, index)"
       class="drawing-canvas"
       :width="layout.width"
       :height="layout.height"
       :style="{
         width: `${layout.width}px`,
         height: `${layout.height}px`,
       }"
     ></canvas>
     ```
   - 修改 `pdfPointToScreenOnPage`，返回 layout 坐标（不再乘 scale）：
     ```ts
     const pdfPointToScreenOnPage = (
       pdfPoint: PdfPoint,
       pageIndex: number,
       layout: { width: number; height: number },
     ): { x: number; y: number } | null => {
       // ... 通过 pageBoundsCache 或 getBounds 拿到 bounds
       const pageWidth = bounds[2] - bounds[0]
       const pageHeight = bounds[3] - bounds[1]

       const nx = (pdfPoint.x - bounds[0]) / pageWidth
       const ny = (pdfPoint.y - bounds[1]) / pageHeight

       // 返回页面逻辑坐标，缩放交给外层 transform 统一处理
       return {
         x: nx * layout.width,
         y: ny * layout.height,
       }
     }
     ```
   - 外层 `.viewer-inner` 的 `transform: scale` 负责统一放大/缩小主 canvas 和预览 canvas，保证两者在任何缩放倍数下对齐。

3. **对 PointerMove 做轻量节流，减轻长线预览重绘压力**：
   - 在 `handleHighlightPointerMove` 中增加时间节流：
     ```ts
     let lastHighlightPreviewTime = 0
     const HIGHLIGHT_PREVIEW_INTERVAL = 16 // ms，约 60fps

     const handleHighlightPointerMove = (event, pageIndex, layout) => {
       if (!isHighlightMode.value) return
       if (!currentStroke.value) return
       if (currentStroke.value.pageIndex !== pageIndex) return

       const point = screenPointToPdfPoint(event.clientX, event.clientY, pageIndex, layout)
       if (!point) return

       currentStroke.value.points.push(point)

       const now = performance.now()
       if (now - lastHighlightPreviewTime < HIGHLIGHT_PREVIEW_INTERVAL) {
         return
       }
       lastHighlightPreviewTime = now

       drawStrokePreview(pageIndex, layout)
     }
     ```
   - 保证长线也只在约 60fps 的频率下重绘完整笔画，减轻 CPU 压力，同时保持视觉跟手。

## 关键代码/公式
- **统一坐标系的关键：layout 空间 + transform scale**：

  // PDF -> layout 坐标
  const nx = (pdfX - x0) / pageWidth
  const ny = (pdfY - y0) / pageHeight

  screenX_layout = nx * layout.width
  screenY_layout = ny * layout.height

## 测试验证
- **测试场景**：
  - 场景1：触摸绘制跟手性
    - 在高亮模式下用手指画长线，观察 PointerMove/预览日志是否持续输出直到 PointerUp；
    - 预期：预览不断线、不断流、中途不停止。
  - 场景2：缩放后的路径对齐
    - 在 0.75x、1x、2x 缩放下分别画线；
    - 松手后对比预览轨迹与 PDF 最终 Ink 线位置，预期两者重合或几乎重合。
  - 场景3：长线性能
    - 在 1x 和 2x 下画超长线，观察是否仍然跟手、没有明显卡顿。

- **验证方法**：
  - 方法1：控制台日志
    - 确认触摸模式下 PointerDown/Move/Up 和 drawStrokePreview 日志全程存在；
  - 方法2：视觉对比
    - 截图预览状态和 PDF 最终渲染状态，确认轨迹和线宽在不同缩放下对齐且流畅。

## 预防措施
- 措施1：在引入复杂触摸交互（手写、缩放、滚动）时，提前划分“模式”，在特定模式下禁止与之冲突的默认行为。
- 措施2：统一坐标系和缩放策略，将视觉缩放交给 CSS transform，逻辑计算尽量在单一坐标系中完成，避免双重缩放。
- 措施3：对高频绘制操作（PointerMove + Canvas 绘制）默认加上节流/抽样机制，避免长度/缩放增加时性能非线性恶化。

## 可复用经验
- 经验1：在多输入（鼠标/触摸/笔）场景下，用 PointerEvent 统一事件流是不错的选择，但必须结合 `touch-action` 和 `preventDefault` 才能保证触摸不被默认滚动/缩放抢占。
- 经验2：Canvas 预览层要和主渲染层共享统一的坐标系和缩放策略，否则很容易在缩放时出现偏移问题。
- 经验3：对实时预览这类高频绘制逻辑，先保证“坐标正确、帧率平稳”，再通过节流和局部优化（如降低预览分辨率）来平衡性能与体验，是一个较为稳妥的演进路径。
