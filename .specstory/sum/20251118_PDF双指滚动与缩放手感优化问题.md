问题序号：PDF双指滚动与缩放手感优化问题

## 问题元信息
- **问题分类**：前端
- **严重程度**：中
- **影响范围**：PDF 阅读页的双指缩放与滚动手势体验（Android WebView / 浏览器）
- **发现日期**：2025-11-18
- **解决状态**：待解决

## 问题现象
当前 PDF 阅读页在双指操作时，用户期望的体验类似「微信/系统相册」：
- 双指可以边捏合边拖拽内容；
- 放大/缩小要比较容易触发，不需要很大幅度捏合。

实际行为中：
- 双指手势一开始会被判定为 `pan` 或 `zoom` 某一种模式，并在整个手势过程中保持不变；
- 当双指同时存在平移和捏合时，当前实现默认优先判定为 `pan`；
- 这会导致部分场景下「想缩放，结果主要在滚动」，放大/缩小触发不够灵敏，手感不如系统相册自然。

## 复现步骤
1. 在支持触摸的设备（平板/触摸屏）上打开 `PdfPage` 对应的 PDF 阅读页面；
2. 使用双指在页面中部进行操作：
   - 轻微捏合的同时略微移动双指；
   - 或先略微平移，再逐渐加大捏合幅度；
3. 观察缩放触发时机与滚动行为：
   - 某些情况下页面大多只是上下/左右滚动；
   - 缩放触发需要更明显的捏合动作，难以做到边拖边放大类似原生相册的手感。

## 用户体验
- 用户期望的「相册式」双指交互没有完全实现：
  - 捏合缩放触发不够灵敏，需要更大动作；
  - 一次手势容易被锁定为平移模式，缩放介入不自然。
- 在阅读和批注 PDF 时，用户频繁使用捏合放大查看细节，体验不顺会直接影响使用效率和舒适度。
- 对比原生相册/微信等常见应用，当前手势交互存在明显落差。

## 相关文件/模块
- **涉及文件**：
  - `imates-web/src/components/PdfPage.vue`：PDF 阅读页面组件，包含双指手势逻辑。
- **涉及模块**：
  - PDF 阅读视图：负责 PDF 渲染、缩放与滚动。
  - 手势处理模块：`handleTouchStart` / `handleTouchMove` / `handleTouchEnd` 中的双指捏合与滚动逻辑。

## 技术原因 (❌)
1. 手势模式采用一次性判定并锁定：
   - 在 `handleTouchMove` 中，当前逻辑仅在 `gestureMode === 'none'` 时，根据位移和距离变化判定一次 `pan` 或 `zoom`，之后整个手势不再重新评估；
   - 代码示例：

```typescript
// 旧逻辑片段（简化）
if (gestureMode === 'none') {
  const isPanCandidate = Math.abs(dx) > panThreshold.value || Math.abs(dy) > panThreshold.value
  const scaleFactor = currentDistance / lastTouchDistance
  const distanceChange = Math.abs(scaleFactor - 1)
  const isZoomCandidate = distanceChange > zoomThreshold.value

  // 优先滚动
  if (isPanCandidate && !isZoomCandidate) {
    gestureMode = 'pan'
  } else if (isZoomCandidate && !isPanCandidate) {
    gestureMode = 'zoom'
  } else if (isPanCandidate && isZoomCandidate) {
    gestureMode = 'pan'
  }
}
```

2. pan/zoom 冲突时统一优先 pan：
   - 当平移与缩放两个条件同时满足时，逻辑固定选择 `pan`；
   - 对用户而言，典型操作往往是「轻微平移 + 捏合」的组合，这种场景下缩放会经常被压制。

3. 阈值组合更偏向「避免误触缩放」而非「相册式手感」：
   - `zoomThreshold` 设为 `0.09`（约 9% 距离变化），轻微捏合比较难触发缩放；
   - `panThreshold` 设为 `14` 像素，双指中心轻微抖动就可能被视为平移候选，有利于触发 pan 而非 zoom。

## 正确实现方案 (✅)
1. 允许在一次手势中动态重新评估模式：
   - 不再仅在 `gestureMode === 'none'` 时判定，而是每一帧都根据 `dx/dy` 与 `distanceChange` 重新评估当前更偏向 `pan` 还是 `zoom`；
   - 保留一定的「惯性」或门槛，避免 pan/zoom 在小范围抖动下频繁切换。

2. 在 pan 与 zoom 同时明显时优先 zoom（向相册手感靠拢）：
   - 当 `isPanCandidate && isZoomCandidate` 时，将 `gestureMode` 设为 `zoom`；
   - 或根据归一化程度（例如 `distanceChange/zoomThreshold` vs `max(|dx|,|dy|)/panThreshold`）决定更接近哪一类，再进行选择。

3. 调整阈值使缩放更易触发：
   - 将 `zoomThreshold` 从 `0.09` 下调到 `0.05 ~ 0.07` 区间；
   - 适度提高 `panThreshold`（如 `18 ~ 24` 像素），减少双指微小抖动被过早认定为 pan 的情况。

示例逻辑（思路示例）：

```typescript
const isPanCandidate =
  Math.abs(dx) > panThreshold.value || Math.abs(dy) > panThreshold.value
const scaleFactor = currentDistance / lastTouchDistance
const distanceChange = Math.abs(scaleFactor - 1)
const isZoomCandidate = distanceChange > zoomThreshold.value

if (isZoomCandidate && !isPanCandidate) {
  gestureMode = 'zoom'
} else if (isPanCandidate && !isZoomCandidate) {
  gestureMode = 'pan'
} else if (isPanCandidate && isZoomCandidate) {
  // 相册式手感：两者都明显时偏向 zoom
  gestureMode = 'zoom'
} else {
  // 两者都不明显时保持原状态
}
```

- 关键代码片段 2：缩放与滚动的组合逻辑（当前实现）

```typescript
// 双指滚动：始终根据 dx / dy 调整 scroll
if (dx !== 0 || dy !== 0) {
  const container = containerRef.value
  const maxScrollY = container.scrollHeight - container.clientHeight
  const maxScrollX = container.scrollWidth - container.clientWidth

  const nextScrollTop = Math.min(Math.max(0, container.scrollTop - dy), maxScrollY)
  const nextScrollLeft = Math.min(Math.max(0, container.scrollLeft - dx), maxScrollX)

  container.scrollTop = nextScrollTop
  container.scrollLeft = nextScrollLeft

  const dt = now - lastPanTime
  if (dt > 0) {
    panVelocityX = -dx / dt
    panVelocity = -dy / dt
  }
  lastPanX = centerXAbs
  lastPanY = centerYAbs
  lastPanTime = now
}

// 只有 gestureMode === 'zoom' 时才更新缩放比例
if (gestureMode === 'zoom') {
  const newScale = Math.max(
    minScale.value,
    Math.min(maxScale.value, pinchStartScale * scaleFactor)
  )

  if (newScale !== store.scale) {
    store.setScale(newScale)
    nextTick(() => {
      if (!containerRef.value) return
      const newScrollTop = pinchStartContentOffsetY * newScale - pinchStartMouseY
      const newScrollLeft = pinchStartContentOffsetX * newScale - pinchStartMouseX
      containerRef.value.scrollTop = Math.max(0, newScrollTop)
      containerRef.value.scrollLeft = Math.max(0, newScrollLeft)
    })
  }
}
```

## 测试验证
- **测试场景**：
  - 场景1：轻微捏合 + 轻微平移
    - 步骤：在页面中间轻轻捏合，顺带轻微上下移动。
    - 预期：可以明显看到缩放发生，同时内容略有拖动，整体手感类似系统相册。
  - 场景2：大幅平移、轻微捏合
    - 步骤：以平移为主，顺带带一点捏合。
    - 预期：主要表现为滚动，但在捏合幅度足够时也能触发缩放。
  - 场景3：连续多次放大/缩小
    - 步骤：多次双指放大、缩小，看手势是否顺畅连贯。
    -预期：缩放触发稳定、无明显卡顿或误判。

- **验证方法**：
  - 方法1：对比微信/系统相册的同类操作，在同一设备上进行主观体验对比；
  - 方法2：观察调试面板中的 `zoomThreshold`、`panThreshold` 变化对体验的影响，并记录最佳参数组合；
  - 方法3：在安卓 WebView 和桌面浏览器中分别验证，确保行为一致、无平台差异问题。

## 预防措施
- 措施1：为手势判定逻辑增加单元化的「调试模式/面板」，允许实时调整阈值并记录最佳配置（当前已通过 `PdfGestureDebugPanel` 初步实现）。
- 措施2：将 pan/zoom 行为和工具模式（高亮/画笔/橡皮擦）解耦，通过 `isPointerToolSuspended` 等状态明确界定各自职责，避免改动手势逻辑时引入对绘图行为的回归。
- 措施3：在引入/调整触摸手势时，统一在多终端（Windows 触摸屏、Android 平板等）做对比测试，积累一套「相册式手势」的验收标准。

## 可复用经验
- 经验1：
  - 对双指手势而言，「只判一次模式」往往过于刚性，允许在一次手势过程中动态调整 pan/zoom 更符合用户直觉。
- 经验2：
  - `zoomThreshold` 与 `panThreshold` 的组合决定了「偏向缩放」还是「偏向滚动」，需要通过调试面板在真实设备上反复调参，不能只凭经验值。 
- 经验3：
  - 在实现复杂手势时，应尽量将「模式判定」、「滚动逻辑」、「缩放逻辑」、「惯性逻辑」拆分成相对独立的块，便于调试和局部替换。
