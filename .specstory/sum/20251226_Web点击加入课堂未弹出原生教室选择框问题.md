问题1：Web点击加入课堂未弹出原生教室选择框问题

## 问题元信息
- **问题分类**：`前端`
- **严重程度**：`中`
- **影响范围**：`我的-加入课堂（投屏）功能；Android WebView 内 H5 与原生交互`
- **发现日期**：`2025-12-26`
- **解决状态**：`已解决`

## 问题现象
- 用户在 Web UI（我的页面）点击“加入课堂”后，弹出的是 H5 的教室选择/确认对话框（`DraggableDialog`），而不是期望的 Android 原生 `ClassroomSelectionDialog`。
- 原生侧虽然存在 `ClassroomSelectionDialog` 能力，但 Web 入口并未触发。

## 复现步骤
1. 打开 WebView 内的“我的”页面（`MyProfileView.vue`）。
2. 点击“加入课堂”。
3. 观察：出现 H5 可拖拽对话框，并在 H5 内选择城市/学校/教室；未出现原生选择框。

## 用户体验
- 交互不一致：与原生体验割裂，且 H5 选择器在 WebView 内体验较差。
- 维护成本高：教室树数据需要先取到 Web 再渲染，链路更复杂。
- 风险上升：H5 与原生两套 UI 并存，容易出现状态不同步/兼容性问题。

## 相关文件/模块
- **涉及文件**：
  - `imates-web/src/views/MyProfileView.vue`：加入课堂按钮点击逻辑、原 H5 教室选择 UI。
  - `imates-web/src/services/business/android-bridge.ts`：H5 调用原生桥、原生回调监听封装。
  - `imates-web/src/types/bridge.ts`：`window.AndroidBridge` 方法与回调的 TS 声明。
  - `app/src/main/java/com/cosinetech/imates/ui/webview/common/WebAppInterface.java`：`addJavascriptInterface` 的桥接实现（AndroidBridge）。
  - `app/src/main/java/com/cosinetech/imates/screencasting/DeviceClientWrapper.java`：封装并显示 `ClassroomSelectionDialog`。
  - `app/src/main/java/com/cosinetech/imates/screencasting/ui/ClassroomSelectionDialog.java`：原生三级联动教室选择 Dialog。
- **涉及模块**：
  - WebView JSBridge（`AndroidBridge`）
  - 投屏/加入课堂（screencasting）

## 技术原因 (❌)
1. **Web 侧点击加入课堂仍走 H5 弹窗流程**：`toggleJoinClass` 打开 `DraggableDialog`，并依赖 `fetchClassroomTree()` 获取数据后在 H5 渲染选择器。
2. **Android Bridge 未暴露“弹出原生选择框”的方法**：`WebAppInterface` 虽有 `fetchClassroomTree/joinClassroom`，但没有 `showClassroomSelectionDialog` 入口。

❌ 错误代码示例（简化）
```typescript
// MyProfileView.vue
const toggleJoinClass = () => {
  // 加载教室树并打开 H5 DraggableDialog
  loadClassroomTree()
  showJoinClassDialog.value = true
}
```

## 正确实现方案 (✅)
1. **Android 侧新增 JSBridge 方法**：在 `WebAppInterface` 增加 `@JavascriptInterface showClassroomSelectionDialog()`。
2. **Android 侧通过 evaluateJavascript 回调 Web**：选择完成回调 `window.onClassroomSelected(payload)`，取消回调 `window.onClassroomSelectionCancelled()`。
3. **Web 侧改造加入课堂入口**：点击“加入课堂”时不再打开 H5 Dialog，而是调用 `androidBridge.showClassroomSelectionDialog()`；收到 `onClassroomSelected` 后再调用 `joinClassroom`。
4. **补齐 TS 桥接声明与封装**：在 `types/bridge.ts` 增加方法/回调声明，在 `android-bridge.ts` 增加封装与事件派发。

✅ 正确代码示例（简化）
```java
// WebAppInterface.java
@JavascriptInterface
public String showClassroomSelectionDialog() {
  client.showClassroomSelectionDialog(new DeviceClientWrapper.OnClassroomSelectedListener() {
    @Override
    public void onSelected(String city, String school, ClassroomInfo classroom) {
      executeJavaScript("if(window.onClassroomSelected){window.onClassroomSelected({\"city\":\"" + city + "\"});}");
    }

    @Override
    public void onCancelled() {
      executeJavaScript("if(window.onClassroomSelectionCancelled){window.onClassroomSelectionCancelled();}");
    }
  });
  return createResponseWithJsonData(true, "已打开教室选择框", "{\"shown\":true}");
}
```

```typescript
// MyProfileView.vue
const toggleJoinClass = () => {
  if (isInClass.value) {
    showJoinClassDialog.value = true
    return
  }
  androidBridge.showClassroomSelectionDialog()
}
```

## 测试验证
- **测试场景**：
  - 场景1：不在课堂时点击“加入课堂”，应直接弹出原生 `ClassroomSelectionDialog`。
  - 场景2：在原生 Dialog 选择城市/学校/教室并确认，Web 应提示“已加入课堂”，并触发原生加入流程。
  - 场景3：在原生 Dialog 点击取消，Web 应提示“已取消选择”，且不应进入课堂。
- **验证方法**：
  - 方法1：观察 UI：是否出现原生 Dialog（非 H5 DraggableDialog）。
  - 方法2：通过 Web 控制台/Logcat 查看：是否触发 `onClassroomSelected/onClassroomSelectionCancelled` 回调。

## 预防措施
- 措施1：对 JSBridge 能力做“能力枚举/对齐”清单，Web 侧只调用桥接能力，不再重复实现 UI。
- 措施2：增加桥接接口的契约测试（至少 TS 类型 + 基本回调示例）。
- 措施3：加入课堂相关链路埋点（traceId），便于排查“未弹窗/未回调”。

## 可复用经验
- 经验1：H5 与原生混合开发优先以“原生为准”，H5 做入口与状态展示。
- 经验2：新增桥接方法时必须同时补齐 TS 声明 + 事件回调规范。
- 经验3：异步 UI（原生 Dialog）必须通过回调驱动后续业务（joinClassroom），避免同步返回值误导。
