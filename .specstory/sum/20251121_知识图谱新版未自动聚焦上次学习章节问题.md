问题序号：知识图谱新版未自动聚焦上次学习章节问题

## 问题元信息
- **问题分类**：`[前端]`
- **严重程度**：`[中]`
- **影响范围**：`[知识图谱视图，所有进入图谱学习的用户]`
- **发现日期**：`2025-11-21`
- **解决状态**：`[已解决]`

## 问题现象
新版知识图谱组件 `newGrap.vue` 集成后，进入某章节的知识图谱时，初始聚焦始终停留在第一个章节（月球），没有自动跳转到“上次学到”的章节位置，导致用户无法直观看到自己上次学习到哪一节。

## 复现步骤
1. 在老版本中产生“上次学到”记录（某小节/知识点被标记为 `lastLearned`）。
2. 打开新版本应用，对应学科和教材，进入某一章节的知识图谱视图。
3. 观察知识图谱初始界面，发现始终聚焦在第一个月球，而不是包含 `lastLearned` 状态的章节。

## 用户体验
- 影响点1：用户无法一眼看到“上次学到哪一节”，需要自己寻找。
- 影响点2：与旧版体验不一致，降低了连续学习的流畅度。
- 影响点3：容易误以为学习进度丢失或未记录。

## 相关文件/模块
- **涉及文件**：
  - `imates-web/src/views/KnowledgeGraphView.vue`：将章节结构映射为 `newGrapData`，并计算 `learningStatus`。
  - `imates-web/src/components/knowledge-graph/newGrap.vue`：知识图谱 Canvas 绘制与初始化聚焦逻辑。
- **涉及模块**：
  - 知识图谱数据映射模块（`mapToNewGrapChapter`）。
  - 知识图谱渲染模块（`newGrap`）。

## 技术原因 (❌)
1. 原因1：`newGrap.vue` 初始化函数 `init()` 中，聚焦逻辑写死为 `focusOnIndex(0, true)`，始终定位到第一个章节：
```ts
// ❌ 错误示例：始终聚焦第 0 个章节
function init() {
  resize();
  state.moons = [];
  const sections = props.data.children || [];
  if (sections.length > 0) {
    sections.forEach((section, index) => {
      state.moons.push(new Moon(index, sections.length, section));
    });
    focusOnIndex(0, true); // 焦点固定为 0
  }
}
```
2. 原因2：虽然在 `KnowledgeGraphView.vue` 中已经为每个 section 聚合了 `learningStatus` 字段（根据子知识点的状态），但 `newGrap` 初始化时并未利用该字段来决定初始聚焦索引。
3. 原因3：缺乏“最近一次学习位置”相关的整体设计联动，仅在数据层记录了状态，但在视图初始化逻辑中没有统一使用该状态。

## 正确实现方案 (✅)
1. 方案1：在数据映射阶段，为每个 section 计算好 `learningStatus`，包括 `lastLearned` 状态（现有逻辑已具备）。
2. 方案2：在 `newGrap.vue` 的 `init()` 函数中，遍历 `sections`，找到第一个 `learningStatus === 'lastLearned'` 的章节索引，作为初始聚焦索引。
3. 方案3：如果不存在 `lastLearned`，则回退至默认聚焦第一个章节，避免空状态。

✅ 修正后的 `init()` 关键实现：
```ts
function init() {
  resize(); // 初始化大小
  state.moons = [];
  const sections = props.data.children || [];
  if (sections.length > 0) {
    let initialFocusIndex = 0;
    sections.forEach((section, index) => {
      state.moons.push(new Moon(index, sections.length, section));
      // 如果该章节聚合状态为 lastLearned，则记录为初始聚焦索引
      if (section.learningStatus === 'lastLearned') {
        initialFocusIndex = index;
      }
    });
    focusOnIndex(initialFocusIndex, true); // 聚焦到上次学习章节
  }

  if (!animationFrameId) loop();
}
```

## 关键代码/公式
- 代码片段1：`KnowledgeGraphView.vue` 中为 section 聚合学习状态：
```ts
// 根据子节点聚合 section 的学习状态：lastLearned > learned > notLearned
if (kpList.some(kp => kp.learningStatus === 'lastLearned')) {
  section.learningStatus = 'lastLearned'
} else if (kpList.some(kp => kp.learningStatus === 'learned')) {
  section.learningStatus = 'learned'
} else {
  section.learningStatus = 'notLearned'
}
```
- 代码片段2：`newGrap.vue` 初始化聚焦逻辑（修复后）：
```ts
const sections = props.data.children || [];
if (sections.length > 0) {
  let initialFocusIndex = 0;
  sections.forEach((section, index) => {
    state.moons.push(new Moon(index, sections.length, section));
    if (section.learningStatus === 'lastLearned') {
      initialFocusIndex = index;
    }
  });
  focusOnIndex(initialFocusIndex, true);
}
```

## 测试验证
- **测试场景**：
  - 场景1：存在某章节的某知识点为 `lastLearned` 状态。
    - 步骤：进入该章节知识图谱。
    - 预期：图谱初始聚焦在该章节所在的月球，且右侧指示器同步高亮。
  - 场景2：没有任何知识点为 `lastLearned`，仅有部分 `learned`。
    - 预期：初始聚焦仍为第一个章节，行为与旧版保持兼容。
- **验证方法**：
  - 通过 log 打印 `initialFocusIndex` 与 `section.learningStatus`，核对是否命中预期章节。
  - 人工验证 UI：进入图谱页面，观察初始聚焦位置是否为“上次学到”的章节。

## 预防措施
- 措施1：在设计新组件时，统一梳理旧版关键体验（如“上次学习位置”），并在需求文档中显式列出。
- 措施2：在集成新组件前，列出与旧版的对比清单，对“重要行为”逐条回归测试。
- 措施3：在数据模型中增加类型约束（如 `learningStatus`），并在视图初始化逻辑中强制要求使用该状态。

## 可复用经验
- 经验1：状态型功能（如进度、上次位置）在重构 UI 时必须同步梳理并验证，否则容易造成“体验回退”。
- 经验2：初始化逻辑应尽量依赖数据层的显式状态（如 `learningStatus`），而非写死索引或硬编码。
- 经验3：在大型前端重构中，建立“旧版关键能力清单”，作为回归测试依据，可以显著减少这种体验性回归问题。
