# LaTeX预处理导致块级公式渲染异常问题

## 问题元信息
- **问题分类**：前端
- **严重程度**：中
- **影响范围**：所有使用useMessageRenderer处理LaTeX公式的页面，包括聊天消息、题目内容等
- **发现日期**：2025-11-08
- **解决状态**：已解决

## 问题现象
在渲染包含LaTeX块级公式的文本时，`\[...\]`格式的公式被错误处理，导致：
1. 公式内容被挤压成一行显示
2. 周围文本出现异常的空行和段落布局
3. 公式无法正确居中显示为块级元素

例如：`若数列\(\{a_n\}\)的前n项和\[S_n = n^2 - 10n \quad (n \in \mathbb{N}^*)\]` 会导致A/B/C/D选项被挤成奇怪的段落和大空行。

## 复现步骤
1. 步骤1：准备包含`\[...\]`格式块级公式的文本
2. 步骤2：使用useMessageRenderer处理该文本
3. 步骤3：观察渲染结果，块级公式未正确换行和居中

## 用户体验
- 数学公式显示不规范，影响阅读体验
- 文本布局混乱，可能导致选项内容难以辨认
- 影响学习内容的准确传达和专业性

## 技术原因 (❌)
1. **预处理逻辑缺陷**：`\[...\]`被转换为`$$$$...$$$$`，缺少必要的换行符
2. **markdown-it-mathjax3解析要求**：块级公式需要独立成段（前后留空行）
3. **正则表达式处理不当**：直接替换为连续的$符号导致解析器 confusion

错误的代码示例：
```typescript
// ❌ useMessageRenderer.ts - 错误的块级公式处理
const displayRegex = /\\\[(.*?)\\\]/gs
processedContent = processedContent.replace(displayRegex, '$$$$$1$$$$')
```

## 正确实现方案 (✅)
1. **添加换行符**：将`\[...\]`转换为`\n\n$$...$$\n\n`，确保块级公式独立成段
2. **使用回调函数**：在replace中使用回调函数处理匹配内容，确保正确的字符串插值
3. **保持向后兼容**：不影响其他LaTeX格式的处理

正确的代码示例：
```typescript
// ✅ useMessageRenderer.ts - 正确的块级公式处理
const displayRegex = /\\\[(.*?)\\\]/gs
processedContent = processedContent.replace(displayRegex, (_match, content) => {
  const trimmed = String(content ?? '').trim()
  return `\n\n$$${trimmed}$$\n\n`
})
```
