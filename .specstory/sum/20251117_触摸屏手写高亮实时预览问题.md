问题序号：触摸屏手写高亮实时预览问题

## 问题元信息
- **问题分类**：前端
- **严重程度**：中
- **影响范围**：使用触摸屏（平板/二合一设备）在 Web 端 PDF 中手写高亮的用户
- **发现日期**：2025-11-17
- **解决状态**：已解决

## 问题现象
在 Web 端 PDF 阅读器中：
- 使用鼠标进行手写高亮时，可以正常实时预览，PointerMove 日志持续输出，预览曲线连续、跟手。
- 在触摸屏设备上（`pointerType: 'touch'`）：
  - PointerDown、PointerMove、drawStrokePreview 一开始都能正常触发，日志显示点数量递增；
  - 但在滑动一段距离后，日志输出会“自动停止”，预览线条不再更新；
  - 实际表现为：手指一开始画线有预览，但继续滑动时预览中途“断掉”，不像鼠标一样从头到尾连续。

## 复现步骤
1. 在触摸屏设备上打开 Web 端 PDF 阅读页面。
2. 切换到“手写高亮”模式（`isHighlightMode = true`）。
3. 用手指在某一页上从上往下滑动绘制高亮线条：
   - 可以观察到控制台日志：
     ```
     [手写高亮] PointerDown 事件 { pointerType: 'touch', ... }
     [手写高亮] PointerDown 开始绘制 ...
     [手写高亮] PointerMove 追加点 ...
     [手写高亮] drawStrokePreview 绘制预览 ...
     ```
   - 滑动一段后，PointerMove 和 drawStrokePreview 日志不再输出，预览线条停止更新。
4. 同样操作在桌面浏览器使用鼠标进行绘制时，日志始终持续到 PointerUp，预览过程完整，无中断。

## 用户体验
- 影响点1：触摸屏用户在划线时，预览轨迹会莫名中断，容易误以为高亮功能异常或失灵。
- 影响点2：在平板上进行批注时，如果预览不连续，用户无法准确判断自己的笔迹范围和轨迹。
- 影响点3：鼠标与触摸的体验不一致，降低了整体产品在触摸设备上的专业感和可用性。

## 相关文件/模块
- **涉及文件**：
  - `imates-web/src/components/PdfPage.vue`
- **涉及模块**：
  - 手写高亮模块（PointerDown/Move/Up + drawStrokePreview）
  - 触摸手势模块（`handleTouchStart/handleTouchMove` 用于捏合缩放/滚动）

## 技术原因 (❌)
1. **触摸滑动被浏览器识别为滚动/缩放，PointerMove 分发被中断**：
   - 在触摸设备上，默认情况下单指滑动通常被浏览器识别为“滚动页面”，双指滑动被识别为“捏合缩放”。
   - 虽然组件使用了 PointerEvent (`@pointerdown/@pointermove/@pointerup`) 来捕获手写，但如果没有阻止默认的触摸行为，浏览器在一定距离后可能将触摸事件转交给滚动/系统手势。
   - 结果就是：
     - 一开始会收到几次 `PointerMove`（预览有显示）；
     - 随着滑动，浏览器开始滚动/处理手势，后续 PointerMove 不再发给 `.page` 元素，导致预览停止。

2. **触摸手势模块与绘制模块之间缺乏高亮模式下的行为区分**：
   - 在 `PdfPage.vue` 顶部容器上绑定了触摸事件：
     ```vue
     <div
       ref="containerRef"
       class="pdf-page"
       :style="pdfPageStyle"
       @wheel="handleWheel"
       @touchstart="handleTouchStart"
       @touchmove="handleTouchMove"
       @touchend="handleTouchEnd"
       @touchcancel="handleTouchEnd"
       @scroll="handleScroll"
     >
     ```
   - 在未区分模式的情况下，触摸操作既被用于缩放/滚动，又想用于手写绘制，二者存在冲突。

3. **没有针对高亮模式明确禁止默认触摸行为**：
   - 初始实现中，`.page` 容器没有设置 `touch-action`，触摸手势没有 `preventDefault()`，导致浏览器有较大自由度决定如何解释触摸（滚动/缩放优先）。

## 正确实现方案 (✅)
1. **在高亮模式下，为每页 `.page` 元素增加禁止默认触摸行为的样式**：
   - 在模板中为 `.page` 增加一个高亮模式下的额外类名：
     ```vue
     <div
       v-for="(layout, index) in pageLayouts"
       :key="index"
       class="page"
       :class="{ 'page-highlighting': isHighlightMode }"
       :style="getPageStyle(layout)"
       @pointerdown.passive="handleHighlightPointerDown($event, index, layout)"
       @pointermove.passive="handleHighlightPointerMove($event, index, layout)"
       @pointerup.passive="handleHighlightPointerUp($event, index, layout)"
       @pointercancel.passive="handleHighlightPointerUp($event, index, layout)"
     >
     ```
   - 在样式中为该类添加触摸行为控制（伪代码示意，实际已在样式中改造）：
     ```css
     .page-highlighting {
       /* 高亮模式下，由我们自己处理触摸，不让浏览器滚动/缩放 */
       touch-action: none;
     }
     ```

2. **在触摸手势处理函数中，高亮模式下主动 `preventDefault()`**：
   - 在 `handleTouchStart` 中：
     ```ts
     const handleTouchStart = (event: TouchEvent) => {
       // 高亮模式下，优先将触摸事件用于绘制，避免触发浏览器滚动/缩放手势
       if (isHighlightMode.value) {
         event.preventDefault()
       }
       if (!containerRef.value || !viewerContainer.value) return
       // ... 现有双指捏合初始化逻辑
     }
     ```
   - 在 `handleTouchMove` 中：
     ```ts
     const handleTouchMove = (event: TouchEvent) => {
       // 高亮模式下阻止默认滚动行为，保证 PointerMove 持续触发用于手写预览
       if (isHighlightMode.value) {
         event.preventDefault()
       }
       if (!containerRef.value || !viewerContainer.value) return
       // ... 现有捏合缩放逻辑
     }
     ```
   - 这样，当 `isHighlightMode` 为 `true` 时：
     - 单指/多指触摸都不会触发滚动和浏览器默认手势；
     - PointerEvent 会持续分发到 `.page` 元素，`handleHighlightPointerMove` 能完整收到所有移动事件。

3. **保持鼠标行为不变，仅对触摸高亮做抑制**：
   - `pointerType === 'mouse'` 的路径不受上述改动影响，仍按原逻辑处理。
   - 只有在高亮模式（`isHighlightMode`）下，并且是触摸设备时，才会禁用默认滚动/手势，确保触摸绘制和鼠标绘制体验一致。

## 测试验证
- **测试场景**：
  - 场景1：触摸单条长线
    - 步骤：在高亮模式下，用手指在同一页上划一条长线。
    - 预期：日志中持续出现 `PointerMove 追加点` 与 `drawStrokePreview 绘制预览`，直到 PointerUp，预览线不断裂。
  - 场景2：触摸多条短线
    - 步骤：连续画多条短线，观察预览是否完整、无中途停止。
    - 预期：每条线都有完整的 PointerDown → 多次 PointerMove → PointerUp 日志，预览完整。
  - 场景3：非高亮模式下触摸滚动
    - 步骤：退出高亮模式，尝试用手指在 PDF 区域滚动。
    - 预期：页面可以正常滚动，说明行为限制仅作用于高亮模式。

- **验证方法**：
  - 方法1：对比鼠标与触摸的 PointerEvent 日志，确认触摸模式下 PointerMove 不再被中途中断。
  - 方法2：实际绘制体验对比，确认触摸手写高亮的预览效果与鼠标一致。

## 预防措施
- 措施1：在设计手势相关功能（缩放/滚动/手写）时，明确各模式下的触摸行为优先级，避免“既想缩放又想绘制”的冲突。
- 措施2：对触摸密集交互（手写绘制、拖拽等），注意使用 `touch-action` 和 `preventDefault()` 控制浏览器默认行为。
- 措施3：在开发阶段使用 PointerEvent 日志（包含 `pointerType`）区分鼠标和触摸路径，及时调整不一致行为。

## 可复用经验
- 经验1：在移动端/触摸端做手写、拖拽等复杂交互时，**必须明确处理浏览器默认触摸行为**（滚动、缩放、双击缩放等），否则事件流很容易被中断。
- 经验2：使用 PointerEvent 统一鼠标/触摸/手写笔输入是一个好方向，但仍需结合 `touch-action` 与 `preventDefault()` 才能在触摸设备上行为一致。
- 经验3：将“模式开关”（如 `isHighlightMode`）作为行为分界点，是控制复杂交互时非常实用的设计模式，可以避免不同功能之间互相干扰。
