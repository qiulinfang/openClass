# Pdf 工具枚举统一与模式状态重构

## 背景

- **涉及组件**：
  - `imates-web/src/components/UnifiedToolbar.vue`
  - `imates-web/src/views/PdfViewerView.vue`
  - `imates-web/src/components/PdfPage.vue`
- **初始问题**：
  - 工具栏（UnifiedToolbar）中的工具值使用 `highlighter`、`pen`、`eraser-draw`、`hand` 等字符串。
  - `PdfViewerView` 和 `PdfPage` 内部使用了另一套枚举：`gesture`、`highlight`、`eraser` 等。
  - `PdfPage` 内部同时存在多个布尔状态（`isHighlightMode`、`isPenMode`、`isEraserMode`、`isAddingNote`）和新的 `currentMode`，导致逻辑混乱。

## 问题表现

- **工具选中状态不同步**：
  - 工具栏按钮的选中态（通过 `store.selectedTool` 控制）与实际 `PdfPage` 的交互模式不一致。
- **绘图模式错误/不生效**：
  - 工具栏切到高亮/画笔/橡皮擦后，`PdfPage` 内部仍然处于旧的 `gesture`/`highlight`/`eraser` 枚举或布尔状态，导致 Pointer 逻辑提前 return，无法绘制。
- **模板判断混乱**：
  - 模板中既使用 `isHighlightMode` 等布尔，又引入了 `currentMode`，容易出现部分逻辑走新状态，部分逻辑走旧状态的问题。

## 技术根因

1. **缺少“单一真相来源”的工具枚举**：
   - UnifiedToolbar 自己维护一套工具值；
   - PdfViewerView 在 `handleToolChange` 中做了一层映射（`gesture`、`highlight`、`eraser`）；
   - PdfPage 内部又维护了 `PdfInteractionMode`，并使用布尔标志控制行为。

2. **旧布尔状态与新枚举并存**：
   - `isHighlightMode`、`isPenMode`、`isEraserMode`、`isAddingNote` 等布尔仍然存在；
   - 新的 `currentMode` 引入后，只改了一部分逻辑，导致状态判断不统一。

## 解决方案

### 1. 统一工具枚举来源

- 将 **工具栏的工具值** 作为全局唯一枚举来源：
  - `PdfToolId = 'hand' | 'highlighter' | 'pen' | 'eraser-draw'`。
- UnifiedToolbar：
  - `ALL_TOOLS[].value` 即上述字符串，`tool-change` 事件直接用这些值。

### 2. PdfViewerView：只接受并传递统一工具值

- 定义类型：

  ```ts
  type PdfToolId = 'hand' | 'highlighter' | 'pen' | 'eraser-draw'
  const currentTool = ref<PdfToolId>('hand')
  ```

- `handleToolChange` 不再做枚举映射，仅校验 + 分发：

  ```ts
  const handleToolChange = (tool: string) => {
    if (!pdfPageRef.value) return

    if (!['hand', 'highlighter', 'pen', 'eraser-draw'].includes(tool)) {
      return
    }

    const t = tool as PdfToolId

    currentTool.value = t
    store.selectedTool = t

    if (t === 'hand') {
      pdfPageRef.value.toggleGestureMode?.()
    } else if (t === 'highlighter') {
      pdfPageRef.value.toggleHighlightMode?.()
    } else if (t === 'pen') {
      pdfPageRef.value.togglePenMode?.()
    } else if (t === 'eraser-draw') {
      pdfPageRef.value.toggleEraserMode?.()
    }
  }
  ```

- 工具启用状态统一使用工具栏的 ID：

  ```ts
  const toolStates = computed(() => {
    return {
      hand: true,
      highlighter: true,
      pen: true,
      'eraser-draw': true,
      undo: true,
      redo: false,
    }
  })
  ```

### 3. PdfPage：统一交互模式为 PdfInteractionMode

- 定义统一交互模式类型：

  ```ts
  type PdfInteractionMode = 'hand' | 'note' | 'highlighter' | 'pen' | 'eraser-draw'
  const currentMode = ref<PdfInteractionMode>('hand')
  ```

- 删除旧布尔模式状态：
  - 删除 `isHighlightMode`、`isPenMode`、`isEraserMode`、`isAddingNote`；
  - 所有模板和逻辑改为基于 `currentMode` 判断。

- 模板中使用 `currentMode`：

  ```vue
  <div
    class="page"
    :class="{ 'page-highlighting': currentMode === 'highlighter' }"
    ...
  >
    ...
    <canvas
      v-if="['highlighter', 'pen', 'eraser-draw'].includes(currentMode) && currentStroke?.pageIndex === index"
      class="drawing-canvas"
      ...
    ></canvas>
  </div>
  ```

- 笔记点击逻辑：只在笔记模式生效，且非绘图模式：

  ```ts
  const handlePageClick = (event, pageIndex, layout) => {
    if (['highlighter', 'pen', 'eraser-draw'].includes(currentMode.value)) return
    if (currentMode.value !== 'note') return

    // 计算归一化坐标并打开新增笔记弹窗
  }
  ```

### 4. 绘图相关逻辑统一使用 currentMode

- PointerDown / Move / Up 入口统一判断绘图模式：

  ```ts
  if (!['highlighter', 'pen', 'eraser-draw'].includes(currentMode.value)) {
    return
  }
  ```

- 在 PointerDown 中基于 `currentMode` 决定 `StrokeMode`：

  ```ts
  const mode: StrokeMode =
    currentMode.value === 'highlighter'
      ? 'highlight'
      : currentMode.value === 'pen'
      ? 'pen'
      : currentMode.value === 'eraser-draw'
      ? 'eraser'
      : 'highlight'
  ```

  > 说明：对外 UI 使用 `'highlighter' | 'pen' | 'eraser-draw'`，但内部 MuPDF Ink 注释类型仍旧是 `'highlight' | 'pen' | 'eraser'`。

- PointerUp 中只在绘图模式下保留当前 stroke，非绘图模式直接清空：

  ```ts
  if (!['highlighter', 'pen', 'eraser-draw'].includes(currentMode.value)) {
    currentStroke.value = null
    clearDrawingCanvas(pageIndex)
    return
  }
  ```

### 5. PdfPage 向外暴露的模式切换方法

- 在 `defineExpose` 中统一模式切换逻辑：

  ```ts
  defineExpose({
    toggleDebugPanel: () => {
      showDebugPanel.value = !showDebugPanel.value
    },
    // 笔记模式：再次点击切回手势
    toggleNoteMode: () => {
      currentMode.value = currentMode.value === 'note' ? 'hand' : 'note'
    },
    // 高亮模式：再次点击切回手势
    toggleHighlightMode: () => {
      currentMode.value = currentMode.value === 'highlighter' ? 'hand' : 'highlighter'
    },
    // 画笔模式：再次点击切回手势
    togglePenMode: () => {
      currentMode.value = currentMode.value === 'pen' ? 'hand' : 'pen'
    },
    // 橡皮擦模式：再次点击切回手势
    toggleEraserMode: () => {
      currentMode.value = currentMode.value === 'eraser-draw' ? 'hand' : 'eraser-draw'
    },
    // 手势模式：强制切回手势
    toggleGestureMode: () => {
      currentMode.value = 'hand'
    },
    undoLastStroke,
    saveCurrentPdfToStorage,
  })
  ```

- 这样 UnifiedToolbar → PdfViewerView → PdfPage 的模式切换链路全部基于同一套枚举字符串，没有任何中间映射。

## 附录：相关小问题与修复

### 1. 组件导入大小写问题

- 原来：

  ```ts
  import PdfPage from '@/components/pdfpage.vue'
  ```

- 修正为：

  ```ts
  import PdfPage from '@/components/PdfPage.vue'
  ```

- 避免在大小写敏感的文件系统上出现构建或类型检查错误。

### 2. 类型问题：CSSProperties

- 在 `PdfPage.vue` 中使用 `CSSProperties` 作为返回值类型：

  ```ts
  import {
    ...,
    type ComponentPublicInstance,
    type CSSProperties,
  } from 'vue'
  ```

- 对笔记样式函数进行类型标注：

  ```ts
  const getNoteStyle = (note: PageNote, layout: { width: number; height: number }): CSSProperties => ({ ... })
  ```

---

通过以上重构，Pdf 工具模式在组件树中实现了**单一枚举源、一处定义多处复用**，避免了枚举字符串不一致和多重状态并存带来的维护成本，也为后续扩展其他工具模式（例如手型、选择模式）打下了统一的基础。
