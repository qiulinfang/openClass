问题序号：知识图谱初始化入口参数扩展设计问题

## 问题元信息
- **问题分类**：`架构`
- **严重程度**：`中`
- **影响范围**：`知识图谱页面从多个入口初始化（我的资源 / PDF 学习 / 我的练习等）`
- **发现日期**：`2025-11-16`
- **解决状态**：`已解决`

## 问题现象
在同一个 `KnowledgeGraphView` 中，需要支持多种入口：
- 从「我的资源」点击“学习”进入知识图谱；
- 从知识图谱学习对话框跳转 PDF，PDF 返回知识图谱；
- 未来可能还有从「我的练习」或其它页面进入知识图谱。

最初所有入口都复用同一套路由参数（`subject`、`textbookId`），导致：
- 只要路由上出现 `subject` 或 `textbookId`，`initGraph` 就走“路由初始化分支”，**跳过页面状态恢复逻辑**；
- 从 PDF 返回知识图谱时，本意是“回到之前的图谱状态并打开学习对话框”，结果却被当成“新的入口初始化”，丢失了原来的旋转角度、展开状态等上下文。

## 复现步骤
1. 从「我的资源」进入知识图谱，浏览并展开某个知识图谱，形成一份当前页面状态（旋转角度、展开节点等）；
2. 在知识图谱中打开“学习”对话框，跳转到 PDF 页面；
3. 在 PDF 页面点击返回按钮，带着 `textbookId` 和学习相关参数返回 `knowledgeGraph`；
4. 观察返回后的知识图谱：
   - 没有按预期恢复之前的图谱状态；
   - 实际走的是“通过路由参数重新初始化”的分支。

## 用户体验
- 影响点1：从 PDF 返回时，用户期望“回到刚才的知识图谱场景 + 自动弹出继续学习对话框”，结果场景被重置；
- 影响点2：不同入口之间逻辑耦合，通过路由参数难以区分“初次进入”和“带上下文返回”；
- 影响点3：未来增加新入口时（例如从练习页进入），扩展成本高，容易误触发错误的初始化分支。

## 相关文件/模块
- **涉及文件**：
  - `imates-web/src/views/KnowledgeGraphView.vue`：知识图谱主视图与 `initGraph` 初始化逻辑；
  - `imates-web/src/views/MyResourcesView.vue`：从「我的资源」进入知识图谱时的路由跳转；
  - `imates-web/src/views/PdfViewerView.vue`：从 PDF 返回知识图谱的路由跳转及学习参数传递；
- **涉及模块**：
  - 知识图谱初始化模块：负责根据路由参数 / Store 状态 / 页面状态决定初始场景；
  - 路由导航模块：负责不同入口如何向知识图谱传递参数。

## 技术原因 (❌)
1. 原因1：**路由参数语义复用过度**。
   - `subject`、`textbookId` 同时被用于“入口初始化”和“PDF 返回携带信息”，缺少语义区分；
2. 原因2：**初始化分支的触发条件过于宽泛**。
   - `initGraph` 中只要检测到 `subject` 或 `textbookId` 任一存在，就直接走“路由优先分支”，跳过页面状态恢复；
3. 原因3：**入口场景缺乏显式标记**。
   - 没有“这是从学习返回”“这是从资源首次进入”等语义标志，导致后续扩展入口时容易产生冲突。

❌ 错误实现示例（核心问题片段）：

```ts
// 旧逻辑（示意）
const querySubject = route.query.subject as string | undefined
const queryTextbookId = route.query.textbookId as string | undefined
const hasRouteInitParams = !!(querySubject || queryTextbookId)

if (hasRouteInitParams) {
  // 直接走路由初始化分支，跳过恢复 pageState
  // ...
  return
}

// 否则才尝试 restorePageStateFromStore()
```

## 正确实现方案 (✅)
1. 方案1：**为“初始化入口参数”单独定义参数名**。
   - 使用 `initSubject`、`initTextbookId` 作为“入口初始化专用参数”；
   - 保持 `textbookId` 等原参数仅作为“学习对话框”等场景的数据载体。
2. 方案2：**严格限定第 1 初始化分支的触发条件**。
   - `initGraph` 仅在收到 `initSubject` 或 `initTextbookId` 时，才认定为“新入口初始化”；
   - 其他情况下先尝试 `restorePageStateFromStore()`，再回退到 Store 默认值。
3. 方案3：**入口场景与学习对话框解耦**。
   - 初始化谁负责？由 `initSubject/initTextbookId` 决定；
   - 打开学习对话框谁负责？由 `openLearning`、`learningNodeId` 等参数在单独的 `checkAndOpenLearningDialog()` 中处理。

✅ 正确实现示例（已落地逻辑）：

```ts
// ✅ 第 1 步：仅识别 initSubject/initTextbookId 作为“入口初始化”触发条件
const initSubject = route.query.initSubject as string | undefined
const initTextbookId = route.query.initTextbookId as string | undefined
const hasRouteInitParams = !!(initSubject || initTextbookId)

if (hasRouteInitParams) {
  // 学科：initSubject 或默认 math
  let initialSubject = initSubject || 'math'
  if (!subjectOptions.value.some(opt => opt.value === initialSubject)) {
    initialSubject = 'math'
  }
  selectedSubject.value = initialSubject

  await loadTextbookDataBySubject(selectedSubject.value)

  // 教材：优先用 initTextbookId
  if (textbookOptions.value.length > 0) {
    let targetTextbook: TextbookOption | undefined

    if (initTextbookId) {
      targetTextbook = textbookOptions.value.find(
        opt => opt.textbookId === initTextbookId || opt.value.includes(initTextbookId)
      )
    }

    if (!targetTextbook) {
      targetTextbook = textbookOptions.value[0]
    }

    selectedTextbook.value = targetTextbook.value
    // ... 加载章节 & 自动定位
  }

  initGraphDataWithoutReset()
  await nextTick()
  renderGraph()
  return
}

// ✅ 第 2 步：无 init 参数 → 优先尝试恢复页面状态
const stateRestored = await restorePageStateFromStore()
if (stateRestored) {
  await nextTick()
  renderGraph()
  return
}

// ✅ 第 3 步：再从 Store 默认值初始化
// ...
```

## 关键代码/公式
- 代码片段1：**初始化分支选择逻辑**（上文 `initGraph` 片段）；
- 代码片段2：**不同入口的路由参数设计**（`MyResourcesView` vs `PdfViewerView`）。

设计关键点可以抽象为一条规则：

> **入口语义 = 参数前缀 / 命名约定**，初始化只认 `init*`，业务子流程使用其它参数名。

## 测试验证
- **测试场景**：
  - 场景1：从「我的资源」进入知识图谱。
    - 步骤：传 `initSubject/initTextbookId`；
    - 预期：按路由参数初始化学科 + 教材 + 章节，不走 `restorePageStateFromStore()`。
  - 场景2：从知识图谱打开 PDF，学习后返回。
    - 步骤：从 PDF 携带 `openLearning + textbookId + learningNodeId ...` 返回；
    - 预期：优先 `restorePageStateFromStore()` 恢复原图谱状态，然后自动弹出学习对话框。
- **验证方法**：
  - 方法1：在控制台打印 `stateRestored` 和 `hasRouteInitParams`，确认不同入口走的分支是否符合预期；
  - 方法2：手动操作 UI，观察图谱的旋转角度、展开节点、学习对话框行为是否正确。

## 预防措施
- 措施1：**为不同语义的参数定义不同前缀/命名**，避免多个场景复用同一参数名。
- 措施2：在初始化逻辑中，**显式区分“入口初始化”与“状态恢复”两类场景**，并用注释标记清楚；
- 措施3：新增入口时，先设计路由参数约定，再接入初始化逻辑，避免直接复用已有参数。

## 可复用经验
- 经验1：**通过参数命名约定为场景“打标签”**。
  - 例如：`init*` 表示“入口初始化参数”，`*Id` 表示资源 ID，`open*` 表示 UI 行为控制。
- 经验2：**初始化逻辑分三层优先级**：路由参数 > 页面状态恢复 > Store 默认值。
- 经验3：**路由只负责“入口语义”，具体 UI 行为拆到独立函数处理**。
  - 初始化图谱与打开学习对话框分开，互不干扰，方便未来独立扩展。
