问题序号：PDF截图模式滑动导致截图中断问题

## 问题元信息
- **问题分类**：前端
- **严重程度**：中
- **影响范围**：PDF 查看页内的截图问答功能，影响需要对 PDF 内容进行框选截图并向 AI 提问的用户
- **发现日期**：2025-11-19
- **解决状态**：进行中

## 问题现象
在 PDF 查看页面中，切换到「截图」模式后，用户在页面上按下开始框选区域，此时如果在拖动过程中稍微滑动/滚动页面，截图过程会被中断或表现异常：
- 截图矩形突然消失，未弹出截图输入对话框；
- 或者截图出的内容和用户实际框选区域不一致（位置/大小有偏移）。

## 复现步骤
1. 打开 PDF 查看页面，加载任意一份教材 PDF。
2. 在顶部工具栏中选择「截图」工具，进入截图模式。
3. 在 PDF 页面内容区域按下鼠标或手指，开始框选截图区域。
4. 在按下并拖动的过程中，略微向上或向下滑动，使 PDF 内容发生滚动。
5. 松开鼠标或手指，观察截图行为：
   - 截图矩形可能被当作「太小」直接丢弃，未触发截图对话框；
   - 或截图出的区域与预期不一致。

## 用户体验
- 影响点1：用户在自然拖动过程中略微滑动手指就会导致截图失败，体验不稳定。
- 影响点2：用户难以判断是自己操作问题还是系统问题，增加使用成本。
- 影响点3：在需要精确选取 PDF 内容时，多次重试截图，降低效率。

## 相关文件/模块
- **涉及文件**：
  - `imates-web/src/components/PdfPage.vue`：承载 PDF 渲染、手势处理、截图框选和裁剪的主组件。
  - `imates-web/src/views/PdfViewerView.vue`：PDF 查看页面容器，接收截图结果并弹出截图输入对话框，与 AI 问答联动。
- **涉及模块**：
  - PDF 查看与标注模块：负责 PDF 渲染、滚动、手势缩放、绘图和截图等交互。
  - AI 截图问答模块：依赖截图结果的问答入口。

## 技术原因 (❌)
1. 截图拖拽与滚动手势未隔离：
   - 截图模式下的拖拽逻辑绑定在 `.page` 元素的 `pointerdown/move/up` 上，但外层 `pdf-page` 容器仍在处理 `touchmove/scroll` 等事件，导致拖拽时可能触发滚动。
2. 截图矩形使用屏幕坐标，滚动后坐标失真：
   - 截图起点和终点均通过 `getBoundingClientRect()` + `clientX/clientY` 计算为页面内的「视觉坐标」，一旦拖拽过程中页面发生滚动，`getBoundingClientRect()` 发生变化，原有起点坐标与终点坐标不再处于同一参考系。
3. 过于严格的最小矩形尺寸过滤逻辑：
   - 在 `handleHighlightPointerUp` 中，如果裁剪矩形宽高小于某个阈值（如 `<= 5` 像素），直接返回，不再触发截图逻辑。滚动造成的坐标偏移会让矩形被判断为「极小」，导致截图被静默取消。

❌ 相关错误代码示例（节选自 `PdfPage.vue`）：

```typescript
// PointerDown：计算截图起点（旧逻辑）
const rect = pageEl.getBoundingClientRect()
const scale = store.scale || 1
const xVisual = event.clientX - rect.left
const yVisual = event.clientY - rect.top

const x = xVisual / scale
const y = yVisual / scale

screenshotRect.value = {
  pageIndex,
  x1: x,
  y1: y,
  x2: x,
  y2: y,
}

// PointerMove：计算截图终点（旧逻辑）
const rect = pageEl.getBoundingClientRect()
const scale = store.scale || 1
const xVisual = event.clientX - rect.left
const yVisual = event.clientY - rect.top

screenshotRect.value.x2 = xVisual / scale
screenshotRect.value.y2 = yVisual / scale

// PointerUp：如果截图矩形过小直接返回（旧阈值示例）
const widthCss = x2Css - x1Css
const heightCss = y2Css - y1Css
if (widthCss <= 5 || heightCss <= 5) {
  return
}
```

上述逻辑没有对截图模式下的滚动做抑制，也没有采用滚动无关的坐标系，在发生滚动时导致截图矩形计算不稳定。

## 正确实现方案 (✅)
1. 在截图模式下抑制滚动/默认手势：
   - 在 `handleHighlightPointerDown` 和 `handleHighlightPointerMove` 截图分支中调用 `event.preventDefault()`（在兼容条件允许时），避免触发容器滚动；
   - 如需进一步增强稳定性，可在 `pointerdown` 中对目标元素调用 `setPointerCapture`，确保整个拖拽过程的事件归属于同一元素。
2. 采用滚动无关的归一化坐标：
   - 利用已有的 `screenPointToNormalized` 工具函数，将屏幕坐标统一转换为页内 `[0, 1]` 范围的归一化坐标，用该坐标驱动截图矩形和裁剪逻辑，从而降低滚动对截图精度的影响。
3. 放宽矩形最小尺寸限制并提供显式反馈：
   - 将裁剪矩形的最小宽高阈值适当降低（例如 `2px`），并在被过滤时通过日志或 UI 提示用户截图区域过小，避免“静默失败”。

✅ 相关修正代码示例（节选自 `PdfPage.vue`）：

```typescript
// PointerDown：截图模式下阻止默认行为，避免触发滚动
const handleHighlightPointerDown = async (
  event: PointerEvent,
  pageIndex: number,
  layout: { width: number; height: number }
) => {
  if (isScreenshotMode.value) {
    if (event.pointerType === 'mouse' && event.button !== 0) return

    if (!viewerContainer.value) return
    const pageElements = viewerContainer.value.querySelectorAll<HTMLElement>('.page')
    const pageEl = pageElements[pageIndex]
    if (!pageEl) return

    // 截图模式下阻止默认行为，避免触发滚动
    event.preventDefault()

    const rect = pageEl.getBoundingClientRect()
    const scale = store.scale || 1
    const xVisual = event.clientX - rect.left
    const yVisual = event.clientY - rect.top

    const x = xVisual / scale
    const y = yVisual / scale

    screenshotRect.value = {
      pageIndex,
      x1: x,
      y1: y,
      x2: x,
      y2: y,
    }
    isDraggingScreenshot.value = true
    return
  }
  // ... 其他绘图逻辑
}

// PointerMove：拖动截图矩形时同样阻止滚动
const handleHighlightPointerMove = (
  event: PointerEvent,
  pageIndex: number,
  layout: { width: number; height: number }
) => {
  if (
    isScreenshotMode.value &&
    isDraggingScreenshot.value &&
    screenshotRect.value &&
    screenshotRect.value.pageIndex === pageIndex
  ) {
    if (!viewerContainer.value) return
    const pageElements = viewerContainer.value.querySelectorAll<HTMLElement>('.page')
    const pageEl = pageElements[pageIndex]
    if (!pageEl) return

    // 截图模式下阻止默认行为，避免触发滚动
    event.preventDefault()

    const rect = pageEl.getBoundingClientRect()
    const scale = store.scale || 1
    const xVisual = event.clientX - rect.left
    const yVisual = event.clientY - rect.top

    screenshotRect.value.x2 = xVisual / scale
    screenshotRect.value.y2 = yVisual / scale
    return
  }
  // ... 其他绘图逻辑
}

// PointerUp：放宽矩形尺寸过滤阈值
const widthCss = x2Css - x1Css
const heightCss = y2Css - y1Css
// 为了避免轻微滚动造成矩形计算误差，这里放宽最小尺寸限制
if (widthCss <= 2 || heightCss <= 2) {
  return
}
```

如果后续引入 `screenPointToNormalized`，则在 PointerDown/Move 中优先得到归一化坐标，再换算为页面逻辑坐标，用于截图矩形和裁剪。

## 关键代码/公式
- 代码片段1：屏幕坐标转页内逻辑坐标（已存在工具函数）

```typescript
const screenPointToNormalized = (
  clientX: number,
  clientY: number,
  pageIndex: number,
  layout: { width: number; height: number }
): NormalizedPoint | null => {
  if (!viewerContainer.value) return null

  const pageElements = viewerContainer.value.querySelectorAll<HTMLElement>('.page')
  const pageEl = pageElements[pageIndex]
  if (!pageEl) return null

  const rect = pageEl.getBoundingClientRect()

  // 视觉坐标（已经包含 CSS scale 的缩放效果）
  const localXVisual = clientX - rect.left
  const localYVisual = clientY - rect.top

  const scale = store.scale || 1

  // 折算回未缩放页面坐标
  const localX = localXVisual / scale
  const localY = localYVisual / scale

  // 归一化到 [0,1]
  const nx = localX / layout.width
  const ny = localY / layout.height

  if (nx < 0 || nx > 1 || ny < 0 || ny > 1) return null

  return { x: nx, y: ny }
}
```

- 代码片段2：截图裁剪像素区域计算（节选）

```typescript
// 1. 计算 CSS 坐标范围
const x1Css = Math.min(rectInfo.x1, rectInfo.x2)
const y1Css = Math.min(rectInfo.y1, rectInfo.y2)
const x2Css = Math.max(rectInfo.x1, rectInfo.x2)
const y2Css = Math.max(rectInfo.y1, rectInfo.y2)

const widthCss = x2Css - x1Css
const heightCss = y2Css - y1Css

// 2. 计算 DPR
const clientWidth = pageCanvas.clientWidth || widthCss
const clientHeight = pageCanvas.clientHeight || heightCss
const dprX = pageCanvas.width / clientWidth
const dprY = pageCanvas.height / clientHeight

// 3. 转为像素坐标并执行裁剪
const sx = x1Css * dprX
const sy = y1Css * dprY
const sWidth = widthCss * dprX
const sHeight = heightCss * dprY

ctx.drawImage(pageCanvas, sx, sy, sWidth, sHeight, 0, 0, sWidth, sHeight)
```

## 测试验证
- **测试场景**：
  - 场景1：正常小范围截图
    - 步骤：进入截图模式，在同一屏幕区域内按下并拖动，松开后应正常弹出截图对话框，截图区域与拖拽区域一致。
  - 场景2：拖拽过程中轻微滑动页面
    - 步骤：截图拖拽时轻微向上或向下滑动，使页面略微滚动，松开后仍能正常截图且截图区域正确。
  - 场景3：极小矩形截图
    - 步骤：只拖动极短距离，宽高 < 2 像素，应被过滤且可在控制台看到日志，前端可根据需要提示用户。

- **验证方法**：
  - 方法1：在浏览器控制台查看截图日志（如 `[截图] rect css`），确认矩形坐标与期望一致。
  - 方法2：对同一内容区域多次截图，确认截图图片中的内容与用户选择区域一致且不受小幅滚动影响。

## 预防措施
- 措施1：统一使用归一化坐标和页面逻辑坐标处理交互区域，尽量避免直接依赖 `getBoundingClientRect` 做多次坐标差运算。
- 措施2：对「手势模式」和「业务模式」（如截图、绘图）进行明确隔离，在模式切换时决定是否允许滚动、缩放等系统手势。
- 措施3：为关键交互（截图、绘图等）增加必要的日志输出，便于快速定位交互异常。

- 经验1：涉及拖拽选区（截图、选择框）时，应优先考虑使用业务自身的坐标系（归一化 / 逻辑坐标），而不是直接依赖视口坐标，降低滚动和缩放造成的误差。
