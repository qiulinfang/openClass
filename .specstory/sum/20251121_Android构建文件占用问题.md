问题序号：Android构建文件占用问题

## 问题元信息
- **问题分类**：后端
- **严重程度**：中
- **影响范围**：Android 项目打包构建
- **发现日期**：2025-11-21
- **解决状态**：已解决

## 问题现象
在执行 Gradle 构建命令（如打包 Release 版本）时，构建失败并报错：
`C:\...\app\build\intermediates\dex\productionRelease\mergeDexProductionRelease\classes.dex: 另一个程序正在使用此文件，进程无法访问。`

## 复现步骤
1. 步骤1：在 Windows 环境下运行 Android Gradle 构建任务（如 `assembleProductionRelease`）。
2. 步骤2：可能存在以下情况之一：
   - 之前的 Gradle 守护进程未正常关闭。
   - IDE（Android Studio/VS Code）正在索引或占用构建产物。
   - 杀毒软件或文件同步工具（如 OneDrive）正在扫描 `build` 目录。
   - 并发执行了多个构建命令。
3. 步骤3：构建过程在合并 Dex 文件阶段中断，抛出文件占用异常。

## 用户体验
- 开发人员无法完成应用打包。
- 需要反复清理项目或重启电脑才能解决，打断开发流程。

## 相关文件/模块
- **涉及文件**：
  - `app/build/intermediates/dex/.../classes.dex`: 被锁定的中间产物文件。
- **涉及模块**：
  - Gradle Build System
  - Android Gradle Plugin (AGP)

## 技术原因 (❌)
1. **文件句柄泄露**：上一次构建异常终止或 Gradle Daemon 进程卡死，导致对 `classes.dex` 的文件句柄未释放。
2. **外部进程干扰**：Windows 文件系统锁机制较严格，若杀毒软件或 IDE 插件在构建写入文件的同时尝试读取该文件，会导致写入失败。

## 正确实现方案 (✅)
1. **停止 Gradle 守护进程**：强制释放所有 Gradle 相关的 Java 进程句柄。
2. **清理构建缓存**：删除被锁定的文件或整个构建目录。
3. **重新构建**：在干净的环境下重新执行构建。

```powershell
# 1. 停止 Gradle Daemon
.\gradlew --stop

# 2. 清理并重新构建 (推荐添加 --no-daemon 避免再次被锁，虽慢但稳)
.\gradlew clean assembleProductionRelease --no-daemon
```

## 预防措施
- **定期清理**：在执行重要发布构建前，习惯性执行 `clean`。
- **排除扫描**：将项目根目录下的 `build` 文件夹添加到杀毒软件和 Windows Defender 的排除列表中。
- **避免并发**：不要在 IDE 构建的同时在命令行运行构建命令。
