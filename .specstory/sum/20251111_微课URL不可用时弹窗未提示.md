问题序号：微课URL不可用时弹窗未提示

## 问题元信息
- **问题分类**：`[前端]`
- **严重程度**：`[中]`
- **影响范围**：`[练习解题页-微课弹窗，所有用户]`
- **发现日期**：`2025-11-11`
- **解决状态**：`[已解决]`

## 问题现象
在练习解题页打开“微课”时，如果对应的微课 URL 返回 404 或不可达，直接将该 URL 传入弹窗组件 `MiniClass`。结果在弹窗中无法正常呈现微课，但也没有明确的“暂无微课内容”提示，用户感知为“什么都没加载出来”。

## 复现步骤
1. 在练习解题页选择一题，点击打开微课。
2. 该题目对应的微课资源不存在（URL 404）。
3. 弹窗打开后，用户看不到微课内容，也缺少清晰的“暂无微课内容”提示。

## 用户体验
- 缺少明确反馈，用户误以为系统卡死或网络问题。
- 不清楚是否该题确实没有微课。
- 增加了重复点击和尝试，造成困惑。

## 相关文件/模块
- **涉及文件**：
  - `imates-web/src/views/ExerciseSolveView.vue`：微课打开逻辑入口，负责拼接 URL 和打开弹窗
  - `imates-web/src/components/MiniClass.vue`：微课弹窗组件，负责显示视频或 iframe，以及“暂无微课内容”空状态
- **涉及模块**：
  - 练习解题页：微课打开逻辑
  - UI 弹窗：微课弹窗显示与空状态

## 技术原因 (❌)
1. 未在打开前校验资源可达性：直接将 URL 传入组件，404 时组件端体验不佳。
2. 组件端虽有空状态，但依赖 `classUrl` 为空来触发，未配合调用方逻辑联动。
3. 简单网络错误在 iframe 内部不易被直观感知，缺乏统一前置判断。

错误代码示例（片段，仅示意）

```typescript
// ❌ 直接传入 URL，404 时缺少清晰反馈
const classUrl = `https://www.imates.com.cn:9099/wk/${subjectPrefix}/${bmNo}/${bmNo}.html`
uiStore.openMiniClassDialog(classUrl, questionTitle)
```

## 正确实现方案 (✅)
1. 打开前进行 URL 轻量可达性检测：使用 `Image.onload/onerror`，不受跨域限制，能判断 404/可达性。
2. 检测失败时，打开弹窗但传入空的 `classUrl`，让 `MiniClass` 呈现“暂无微课内容”的空状态。
3. 同时通过全局消息提示“该题目暂无微课”，提升用户感知。

正确代码示例（关键片段）

```typescript
// ✅ 打开前预检，失败走空URL以呈现“暂无微课内容”
const classUrl = `https://www.imates.com.cn:9099/wk/${subjectPrefix}/${bmNo}/${bmNo}.html`

const checkUrlExists = (url: string): Promise<boolean> => {
  return new Promise((resolve) => {
    try {
      const img = new Image()
      img.onload = () => resolve(true)
      img.onerror = () => resolve(false)
      img.src = `${url}${url.includes('?') ? '&' : '?'}_ts=${Date.now()}`
    } catch {
      resolve(false)
    }
  })
}

checkUrlExists(classUrl).then((exists) => {
  const questionTitle = question.title || question.question?.substring(0, 50) || ''
  if (exists) {
    uiStore.openMiniClassDialog(classUrl, questionTitle)
  } else {
    uiStore.openMiniClassDialog('', questionTitle) // 触发 MiniClass 空状态
    showMessage('该题目暂无微课', 'warning')
  }
})
```

## 关键代码/公式
- 预检函数：`Image.onload/onerror` 判断资源是否可达
- 弹窗联动：当 URL 不可达时，传空 `classUrl` → `MiniClass` 展示空状态

```typescript
// 关键：不依赖 CORS，简单可靠
const checkUrlExists = (url: string): Promise<boolean> => new Promise((resolve) => {
  const img = new Image()
  img.onload = () => resolve(true)
  img.onerror = () => resolve(false)
  img.src = `${url}${url.includes('?') ? '&' : '?'}_ts=${Date.now()}`
})
```

## 测试验证
- **测试场景**：
  - 场景1：URL 存在 → 弹窗正常加载微课页面/视频。
  - 场景2：URL 404 → 弹窗显示“暂无微课内容”，并有全局“暂无微课”提示。
- **验证方法**：
  - 方法1：通过构造存在/不存在的 bmNo 验证两类分支。
  - 方法2：网络节流或断网时，确认不会误报“有微课”。

## 预防措施
- 在打开外部资源前统一做可达性预检，尤其是跨域 iframe 或静态资源。
- 组件设计保持“双保险”：调用方预检 + 组件端空状态。
- 针对外链内容建立灰度/回退方案，减少用户困惑。

- 外链资源在 UI 打开前先做轻量预检，可显著改善失败体验。

- `Image` 预检规避跨域限制，简单、通用，适合静态资源可达性判断。
