# 问题序号：持久化数据账号隔离问题

## 问题元信息
- **问题分类**：`前端`
- **严重程度**：`严重`
- **影响范围**：`所有用户的数据隔离、账号切换功能`
- **发现日期**：`2025-11-08`
- **解决状态**：`部分解决`

## 问题现象
切换账号后，不同用户的数据可能混在一起，导致：
- 用户A的题目列表可能显示用户B的题目
- 用户A的学习进度可能显示用户B的进度
- 用户A的聊天历史可能包含用户B的聊天记录
- 用户A的收藏列表可能包含用户B的收藏

## 复现步骤
1. 步骤1：使用账号A登录，进行一些操作（绘制笔记、收藏题目等）
2. 步骤2：退出账号A，切换到账号B登录
3. 步骤3：在账号B中查看数据，可能看到账号A的数据
4. 步骤4：切换回账号A，可能看到账号B的数据

## 用户体验
- 数据混乱，无法区分不同账号的数据
- 账号切换后可能看到其他用户的数据，造成隐私泄露
- 学习进度混乱，影响学习体验
- 数据丢失风险，切换账号可能导致数据被覆盖

## 技术原因 (❌)

1. **数据库名未包含用户ID**：
   - `question-storage.ts` 中数据库名固定为 `ExerciseQuestionsDB`，没有用户ID前缀
   - `chat-storage.ts` 中 localforage 配置的数据库名固定为 `ExerciseSolveApp`，没有用户ID前缀

2. **存储key未包含用户ID**：
   - `KnowledgeGraph.vue` 中 `LAST_LEARNED_NODE_KEY` 和 `LEARNED_NODES_KEY` 没有用户ID前缀
   - `ChatView.vue` 中 `currentTeacherSubject` 没有用户ID前缀
   - 其他用户偏好设置的key也没有用户ID前缀

3. **代码Bug**：
   - `favorites.ts` 中 `removeQaFavorite` 和 `removeExerciseFavorite` 函数使用了未定义的常量 `FAVORITES_STORAGE_KEY`

## 正确实现方案 (✅)

1. **数据库名包含用户ID**：
```typescript
// 修改前
const questionStorage = IndexedDBService.getInstance({
  dbName: 'ExerciseQuestionsDB',  // ❌ 固定名称
})

// 修改后
const userId = getCurrentUserIdOrDefault()
const questionStorage = IndexedDBService.getInstance({
  dbName: `ExerciseQuestionsDB_${userId}`,  // ✅ 包含用户ID
})
```

2. **存储key包含用户ID**：
```typescript
// 修改前
const LAST_LEARNED_NODE_KEY = 'LAST_LEARNED_NODE_ID'

// 修改后
const userId = getCurrentUserIdOrDefault()
const LAST_LEARNED_NODE_KEY = `LAST_LEARNED_NODE_ID_${userId}`
```

3. **修复代码Bug**：
```typescript
// 修改前
localStorage.setItem(FAVORITES_STORAGE_KEY, JSON.stringify(filtered))

// 修改后
const key = getFavoritesStorageKey()
localStorage.setItem(key, JSON.stringify(filtered))
```

## 预防措施
- **措施1**：建立代码审查机制，确保所有存储操作都包含用户ID
- **措施2**：使用统一的工具函数生成存储key，避免手动拼接
- **措施3**：在账号切换时，确保所有存储实例都重新创建
- **措施4**：添加单元测试，验证数据隔离功能
