## 2. 本项目安卓更新的整体流程

### 2.1 更新配置来源与环境切换

- 环境类：`AppEnvConfig`
  - 在 `LoginActivity.onCreate` 中调用 `AppEnvConfig.checkAndUpdateVersion(this)`。
  - 根据当前环境（正式 / 内部测试）调用 `ApiUrl.switchEnv(envType)`。
- 接口配置：`ApiUrl.switchEnv`
  - 正式环境：
    - `URL_APP_UPDATE = "https://www.imates.com.cn/bj101/appupdate.json"`
  - 内部测试环境：
    - `URL_APP_UPDATE = "https://www.imates.com.cn/appupdate_test.json"`

> 结论：所有更新检查最终都指向 `ApiUrl.URL_APP_UPDATE` 对应的 JSON 配置文件。

### 2.2 哪些 Activity 会触发更新检查

- `MainWebViewActivity`（主 Web 容器页）
  - 成员：`mCheckUpdateHandler` + `mCheckUpdateRunnable`。
  - 在 `onCreate` 中调用 `initUpdateCheck()`：
    - 启动后约 10 秒执行第一次检查。
    - 之后每 60 秒执行一次 `mCheckUpdateRunnable`。
  - `mCheckUpdateRunnable` 内部逻辑：
    - 读取 `updateUrl = ApiUrl.URL_APP_UPDATE`。
    - 调用 `checkUpdateWithHttpRequest(updateUrl)` 发送 HTTP 请求检查更新。

- `KnowledgeGraphActivity`
  - 在 `miscellaneousInitialization()` 中：
    - 立即调用：`EasyUpdate.create(this, ApiUrl.URL_APP_UPDATE).isAutoMode(false).update();`
    - 记录 `mCheckUpdateTick = System.currentTimeMillis()`。
    - 通过 `mMainHandler.postDelayed(mCheckUpdateRunnable, 60000)` 启动按 60 秒 tick、内部 1 小时节流的定时检查。

- `LoginActivity`
  - 存在类似的 `mCheckUpdateHandler` + `mCheckUpdateRunnable`：
    - 每 60 秒运行一次 runnable。
    - 仅在距离上次检查超过 1 小时时真正调用：
      `EasyUpdate.create(LoginActivity.this, ApiUrl.URL_APP_UPDATE).isAutoMode(false).update();`

### 2.3 MainWebViewActivity 中的更新检查实现

核心在 `checkUpdateWithHttpRequest(String updateUrl)`：

1. 使用 `OkHttpClient` 构造请求，目标地址为 `updateUrl`（即 `URL_APP_UPDATE`）。
2. 异步 `enqueue` 请求：
   - `onFailure`：当前实现静默失败（后续已补充日志）。
   - `onResponse`：
     - 读取 `statusCode` / `statusMessage` 和 `responseBody`。
     - 如果 `statusCode == 200` 且 `responseBody` 非空：
       - 解析 JSON：`JSONObject jsonObj = new JSONObject(responseBody);`
       - 读取服务器版本：`String serverVersion = jsonObj.optString("VersionName", "");`
       - 如果 `serverVersion` 非空：
         - 调用 `dispatchAppVersionEvent(serverVersion)`，将版本通知 Web 前端。
         - 在 UI 线程中调用：
           ```java
           EasyUpdate.create(MainWebViewActivity.this, updateUrl)
                   .isAutoMode(false)
                   .update();
           ```

> `EasyUpdate.update()` 内部会自行对比当前 App 版本与服务器配置的版本，判定是否需要更新并弹出对话框。

### 2.4 EasyUpdate 的角色（从调用处推断）

- 多处调用方式类似：
  - `EasyUpdate.create(context, ApiUrl.URL_APP_UPDATE).isAutoMode(false).update();`
- 项目注释说明：
  - “内部会自动比较版本号，如果需要更新则执行更新”。
- 推断行为：
  - 访问 `appupdate.json`，解析最新版本、APK 地址、更新日志等字段。
  - 与本地版本（`PackageInfo.versionName/versionCode`）比较。
  - 发现新版本时弹出更新对话框，引导用户下载并安装 APK。
  - `.isAutoMode(false)` 表示不做静默更新，而是始终有可见对话框。

### 2.5 Web 端与原生的联动

- `MainWebViewActivity.checkUpdateWithHttpRequest` 中：
  - 在解析到 `serverVersion` 后调用：`dispatchAppVersionEvent(serverVersion)`。
- 作用：
  - 将服务器版本号通过 WebView 与 JS 通信发送到 Web 前端，使 Web 也能感知最新版本并依据版本做 UI 或逻辑上的处理（如提示“有新版本”）。

## 3. 什么情况下会弹出更新对话框

综合本项目代码与 EasyUpdate 使用方式，可归纳为：

1. **EasyUpdate 被调用**
   - 触发点包括：
     - `MainWebViewActivity` 中在每次成功解析到服务器 JSON 且 `VersionName` 非空后。
     - `KnowledgeGraphActivity` 启动时，以及之后按 1 小时间隔的定时任务。
     - `LoginActivity` 中（若定时任务实际被启动），按 1 小时间隔节流触发。
2. **服务器 `appupdate.json` 中配置的版本高于当前 App 版本**
   - EasyUpdate 内部对比“本地版本号 VS JSON 中的 VersionName/versionCode”。
3. **AutoMode 为 false**
   - 所有调用都显式指定 `.isAutoMode(false)`，意味着只要 EasyUpdate 判定需要更新，就会弹出可见的更新对话框，而不是静默下载。

> 直观表述：当 App 处于上述 Activity 之一，且服务器 `appupdate.json` 中的版本号比当前安装版本新时，就会弹出更新对话框。

## 4. MainWebViewActivity 更新流程相关的日志点

为方便调试“检查更新但不弹窗”等问题，在 `MainWebViewActivity` 中增加了如下日志：

### 4.1 初始化更新检查

- 方法：`initUpdateCheck()`
- 日志：
  - `Log.d(TAG, "[Update] 初始化更新检查机制，将在 10 秒后执行首次更新检查");`

### 4.2 定时任务 Runnable

- 字段：`mCheckUpdateRunnable`
- 关键日志：
  - 进入 `run()`：
    - `Log.d(TAG, "[Update] 定时检查触发，开始执行 mCheckUpdateRunnable.run()");`
  - 记录当前更新 URL：
    - `Log.d(TAG, "[Update] 当前使用的更新检查 URL = " + updateUrl);`

### 4.3 HTTP 请求和响应日志

- 方法：`checkUpdateWithHttpRequest(String updateUrl)`
- 日志点：
  - 发起请求前：
    - `Log.d(TAG, "[Update] 开始请求更新配置，updateUrl = " + updateUrl);`
  - 请求失败：
    - `Log.e(TAG, "[Update] 更新配置 HTTP 请求失败", e);`
  - 请求成功收到响应：
    - `Log.d(TAG, "[Update] 收到更新配置响应，statusCode = " + statusCode
            + ", statusMessage = " + statusMessage
            + ", bodyLength = " + (responseBody != null ? responseBody.length() : 0));`
  - 解析 JSON 版本号：
    - `Log.d(TAG, "[Update] 解析到服务器版本号 VersionName = " + serverVersion);`
  - 通知 Web 端：
    - `Log.d(TAG, "[Update] 已将服务器版本号发送给 Web 端: " + serverVersion);`
  - 即将调用 EasyUpdate：
    - `Log.d(TAG, "[Update] 即将调用 EasyUpdate 进行更新检查和可能的弹窗");`
  - JSON 中缺少版本号：
    - `Log.w(TAG, "[Update] 更新配置 JSON 中缺少 VersionName 或为空，不执行更新");`
  - 响应码异常：
    - `Log.w(TAG, "[Update] 更新配置响应异常，statusCode = " + statusCode + ", 不进行更新处理");`
  - 解析 JSON 失败：
    - `Log.e(TAG, "[Update] 解析更新响应JSON失败", e);`
  - 处理响应时发生其他异常：
    - `Log.e(TAG, "[Update] 处理更新响应失败", e);`

### 4.4 日志使用建议

- 在 Logcat 中使用过滤：
  - 按 `TAG` 过滤 `MainWebViewActivity`，并结合关键字 `[Update]`。
- 调试“对话框不弹”的思路：
  1. 确认能看到“初始化”和“定时检查触发”的日志，排除 Handler 没启动的问题。
  2. 确认 HTTP 请求和响应日志，排除网络 / URL 配置错误。
  3. 看解析到的 `VersionName` 是否正确，是否为空。
  4. 确认是否执行到了“即将调用 EasyUpdate”的日志。

> 若已经进入 EasyUpdate 调用但仍未弹窗，则需要配合 EasyUpdate 库内部日志或其配置（如忽略某些版本、强制更新标志等）进一步排查。
