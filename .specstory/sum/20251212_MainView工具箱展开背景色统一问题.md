问题序号：MainView 工具箱展开背景色统一问题

## 问题元信息
- **问题分类**：`前端`
- **严重程度**：`中`
- **影响范围**：`MainView 根视图、工具箱打开时的背景`
- **发现日期**：`2025-12-12`
- **解决状态**：`已解决`

## 问题现象
MainView 根据路由渲染不同的渐变背景。在工具箱（位于左侧抽屉）弹出时，页面右侧内容仍保持原有渐变，导致工具箱与内容区之间出现色块冲突，视觉上类似“抽屉悬浮在另一套背景之上”，影响整体一致性。

## 复现步骤
1. 在 Web 端打开主页任意路由（如 myHomework）。
2. 点击左侧导航中的“工具箱”按钮。
3. 工具箱出现，但主背景依旧是路由对应的渐变色，与工具箱自身配色冲突。

## 用户体验
- 工具箱覆盖在浅色渐变背景上，视觉层次混乱。
- 同时存在多套背景色，用户误以为工具箱只是弹窗而非全局模式。
- 影响暗紫主题氛围，显得不统一。

## 相关文件/模块
- **涉及文件**：
  - `imates-web/src/views/MainView.vue`：主视图背景样式计算。
- **涉及模块**：
  - MainView 布局与样式系统。
  - 工具箱交互逻辑。

## 技术原因 (❌)
1. `mainViewStyle` 仅根据 `route.name` 返回背景，未考虑 `showToolbox` 状态。
2. 工具箱配色固定为深紫色，与部分路由的浅色渐变碰撞但没有统一策略。
3. 缺少“全局模式”判断，导致工具箱与内容区并列渲染不同背景。

错误代码节选：
```ts
const mainViewStyle = computed(() => {
  const routeName = route.name
  switch (routeName) {
    case 'myHomework':
      return {
        background: 'linear-gradient(to bottom, #ffffff 50%, #f1f3ff 50%)',
      }
    // ... 其他路由
  }
})
```

## 正确实现方案 (✅)
1. 当 `showToolbox.value` 为 `true` 时，优先返回统一背景色 `#3d3070`。
2. 仅在工具箱关闭时才根据路由决定渐变。
3. 给注释注明“工具箱弹出时统一深紫背景，避免冲突”。

实现代码：
```ts
const mainViewStyle = computed(() => {
  if (showToolbox.value) {
    return { background: '#3d3070' }
  }
  const routeName = route.name
  switch (routeName) {
    case 'myHomework':
      return {
        background: 'linear-gradient(to bottom, #ffffff 50%, #f1f3ff 50%)',
      }
    // ... 其他路由
    default:
      return { background: '#3d3070' }
  }
})
```

## 关键代码/公式
- 关键计算属性：`MainView.vue` 中的 `mainViewStyle`。

## 测试验证
- **场景 1**：任何路由下点击工具箱，主背景应立即变为 `#3d3070`。
- **场景 2**：关闭工具箱后，背景恢复为对应路由渐变。
- **验证方法**：开发模式下观察 `mainViewStyle` 输出及实际背景颜色。

## 预防措施
- 对全局背景这类视觉状态，统一由计算属性先判断“模式”，再判断“路由”。
- 组件内的视觉模式（如工具箱/全屏遮罩）应有优先级，以免与页面背景冲突。

## 可复用经验
- 在多主题或多模式页面中，背景样式需要先判断“模式层”再判断“内容层”。
- 工具箱、对话框等“霸占视图”的组件应当统一背景，减少与底层路由背景互相干扰。
