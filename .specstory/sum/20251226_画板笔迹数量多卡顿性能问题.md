问题序号：01 画板笔迹数量多卡顿性能问题

## 问题元信息
- **问题分类**：`性能`
- **严重程度**：`高`
- **影响范围**：`imates-web 画板/草稿本手写与形状绘制；笔迹数量多时交互明显卡顿`
- **发现日期**：`2025-12-26`
- **解决状态**：`进行中`

## 问题现象
- 画板上绘制对象（尤其是 path 笔迹）数量多后：
  - 鼠标/触摸移动时明显掉帧
  - 拖拽选框、橡皮擦悬停、移动对象时卡顿
- 典型表现为：每次 `mousemove/touchmove` 都触发一次全量 `render()`，渲染时间随对象数量线性增长。

## 复现步骤
1. 打开草稿本/画板页面，使用画笔连续绘制大量笔迹（例如 200~1000 条）。
2. 在画布上移动鼠标（或手指滑动），或切换到选择/橡皮擦工具进行移动/悬停。
3. 观察帧率下降、交互延迟。

## 用户体验
- 操作明显不跟手，延迟感强。
- 复杂草稿（大量笔迹）基本不可用。
- 容易误操作（拖拽/擦除位置偏差）。

## 相关文件/模块
- **涉及文件**：
  - `imates-web/src/components/DrawingBoard.vue`：主画板组件，存在高频全量重绘。
- **涉及模块**：
  - Canvas 渲染与事件处理（mousemove/touchmove）
  - 对象管理（objects/tempObject/hover/selection）

## 技术原因 (❌)
1. **全量重绘**：在 `mousemove/touchmove` 中频繁调用 `render()`，每次 `render()` 需要遍历 `objects` 并逐个绘制。
2. **高频触发**：事件触发频率可能高于屏幕刷新率（>60Hz），导致堆积。
3. **混合渲染内容**：背景图、已完成对象、临时对象（预览）、hover 高亮、selectionBox 都在同一个 render 路径中绘制，无法区分“静态/动态”。

错误示例（概念示意）：
```ts
// ❌ 每次 move 都全量重绘
const handleMouseMove = () => {
  render()
}

const render = () => {
  ctx.clearRect(0, 0, w, h)
  drawBackground()
  objects.forEach(drawObject)
  drawTempObject()
  drawSelectionBox()
}
```

## 正确实现方案 (✅)
1. **分层/离屏缓存**：使用离屏 canvas 缓存“背景 + 已完成对象”，在 move 时只绘制“缓存 + 覆盖层”。
2. **rAF 合帧**：统一用 `requestAnimationFrame` 调度渲染，避免同一帧重复 render。
3. **脏标记**：当 `objects` 发生变更（新增/删除/撤销重做/移动）时才重建缓存。

正确示例（概念示意）：
```ts
// ✅ 合帧渲染
const requestRender = () => {
  if (pending) return
  pending = true
  requestAnimationFrame(() => {
    pending = false
    renderNow()
  })
}

// ✅ 缓存层仅在 dirty 时重建
const renderNow = () => {
  if (cacheDirty) rebuildCache()
  ctx.drawImage(cacheCanvas, 0, 0)
  drawOverlay() // temp/selection/highlight
}
```

## 关键代码/公式
- **关键点**：渲染复杂度从“每次 move O(N)”降低为“每次 move O(1)+覆盖层”。
- **缓存层**：`cacheCanvas` + `cacheDirty` + `rebuildCache()`。

## 测试验证
- **测试场景**：
  - 场景1：绘制 500 条笔迹后移动鼠标，观察跟手性。
  - 场景2：框选拖拽移动一组对象，观察是否掉帧。
- **验证方法**：
  - 方法1：Chrome DevTools Performance 对比 render 耗时与帧率。
  - 方法2：在高笔迹数量下手动体验（明显是否更顺滑）。

## 预防措施
- 将渲染调度统一封装为 `requestRender()`，禁止在事件中直接全量 `render()`。
- 对象变更时统一走“数据变更 -> 标脏 -> 合帧渲染”的流程。
- 新增性能回归用例：大笔迹数据集下的交互帧率验收。

## 可复用经验
- 静态内容缓存 + 动态覆盖层，是 Canvas 复杂场景常用优化模式。
- 高频事件渲染应使用 rAF 合帧，避免重复绘制。
- “dirty flag” 是避免重复重建缓存的关键。
