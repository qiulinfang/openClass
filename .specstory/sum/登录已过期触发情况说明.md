# 登录已过期触发情况说明

## 概述

"登录已过期，请重新登录" 消息会在以下情况下出现：

1. **API 返回 401 未授权错误**
2. **自动重新登录失败**

## Token 来源

### 1. Token 获取流程

Token 来源于后端服务器的登录接口响应。系统支持两种登录方式：

#### 1.1 学班登录（管理员登录）

**接口路径**：`/admin/login`  
**方法**：`apiService.loginXueban(account, password)`

**位置**：`imates-web/src/services/api-service.ts` (第 1152-1187 行)

```1152:1187:imates-web/src/services/api-service.ts
  public async loginXueban(account: string, password: string): Promise<string> {
    try {
      // 第1步：发送登录请求
      const response = await httpClient.post<XuebanLoginResponse>(
        getApiUrl(API_ENDPOINTS.USER.XUEBAN_LOGIN),
        {
          account,
          password
        }
      )
      
      // 检查响应结构：response.data 是 XuebanLoginResponse
      if (!response.success) {
        throw new Error(response?.data?.message || '登录失败')
      }

      const token = response.data.data.token
      
      if (!token) {
        throw new Error('登录失败：未获取到token')
      }
      
      // 第2步：保存token和用户凭据到localStorage
      localStorage.setItem('XUEBAN_TOKEN', token)
      localStorage.setItem('userId', account)
      localStorage.setItem('userPassword', password)
      
      // 更新登录时间戳，用于会话管理
      localStorage.setItem('lastLoginTime', Date.now().toString())

      // 第3步：返回token
      return token
    } catch (error: unknown) {
      throw new Error(error instanceof Error ? error.message : '登录失败')
    }
  }
```

### 2. Token 存储位置

| Token 类型 | 存储键名 | 使用场景 |
|-----------|---------|---------|
| 学班 Token | `XUEBAN_TOKEN` | `/permission/*`, `/admin/info`, `/biologyTopicKnowledge/*` |
| 研伴 Token | `YANBAN_TOKEN` | `/blw-edu-yb/*` |

### 3. Token 使用流程

1. **用户登录** → 调用登录接口 → 服务器返回 token
2. **保存 Token** → 存储到 `localStorage`（根据登录类型选择不同的键名）
3. **API 请求** → 从 `localStorage` 读取 token → 添加到请求头
4. **Token 过期** → 返回 401 → 清除旧 token → 尝试自动重新登录 → 获取新 token

## 触发"登录已过期"的具体情况

### 情况1：后端返回 401 错误

**原因**：
- Token 已过期（服务器端 token 过期时间到期）
- Token 无效（token 格式错误或被篡改）
- Token 被撤销（用户在其他设备登录，当前 token 被撤销）
- 账号被禁用或删除
- 服务器端认证服务异常

**触发时机**：
- 任何需要认证的 API 请求
- 包括但不限于：
  - `/permission/*` - 权限相关接口
  - `/admin/info` - 用户信息接口
  - `/biologyTopicKnowledge/*` - 生物知识点接口
  - `/blw-edu-yb/*` - 研伴相关接口

### 情况2：自动登录失败

当检测到 401 错误后，系统会尝试自动重新登录。如果自动登录失败，就会显示"登录已过期"。

**自动登录失败的原因**：

#### 2.1 没有保存的用户凭据
- **条件**：`!userId || !password`
- **原因**：
  - 用户首次登录，未保存凭据
  - 用户清除了浏览器数据（localStorage）
  - 用户使用了隐私模式/无痕模式
  - 存储空间不足，数据被清除

#### 2.2 用户凭据无效
- **条件**：`userId === 'undefined' || password === 'undefined'`
- **原因**：
  - 存储时出错，保存了字符串 "undefined"
  - 数据被意外修改

#### 2.3 登录 API 调用失败
- **网络错误**：
  - 网络连接断开
  - 请求超时
  - DNS 解析失败
  - 服务器不可达

- **服务器错误**：
  - 服务器返回 5xx 错误
  - 服务器返回非 200 状态码

#### 2.4 登录 API 返回失败
- **密码错误**：
  - 用户修改了密码
  - 密码被重置
  - 存储的密码不正确

- **账号问题**：
  - 账号被禁用
  - 账号被删除
  - 账号被锁定

- **业务逻辑错误**：
  - 登录接口返回 `success: false`
  - 登录接口返回错误消息

## 不同接口的 Token 管理

系统根据接口路径使用不同的 token：

| 接口路径 | Token 类型 | 存储键名 | 登录方式 |
|---------|-----------|---------|---------|
| `/permission/*` | 学班 Token | `XUEBAN_TOKEN` | `loginXueban()` |
| `/admin/info` | 学班 Token | `XUEBAN_TOKEN` | `loginXueban()` |
| `/biologyTopicKnowledge/*` | 学班 Token | `XUEBAN_TOKEN` | `loginXueban()` |
| `/blw-edu-yb/*` | 研伴 Token | `YANBAN_TOKEN` | `loginYanban()` |
| 其他 | 研伴 Token | `YANBAN_TOKEN` | `loginYanban()` |

## 处理流程

```
API 请求
  ↓
返回 401 错误
  ↓
清除对应的 token (clearTokenByPath)
  ↓
尝试自动重新登录 (tryAutoRelogin)
  ↓
  ├─ 成功 → 重新发起原请求（只重试一次）
  └─ 失败 → 显示"登录已过期，请重新登录"
```

## 常见场景

### 场景1：Token 自然过期
- **描述**：用户长时间未操作，token 过期
- **行为**：系统自动尝试重新登录，如果成功则继续，失败则提示用户

### 场景2：多设备登录
- **描述**：用户在设备A登录后，在设备B登录，设备A的 token 被撤销
- **行为**：设备A的下一次请求返回 401，尝试自动登录，如果设备A保存的凭据仍然有效，会自动重新登录

### 场景3：密码修改
- **描述**：用户修改了密码
- **行为**：旧 token 失效，自动登录时使用旧密码会失败，提示用户重新登录

### 场景4：清除浏览器数据
- **描述**：用户清除了浏览器数据或使用隐私模式
- **行为**：没有保存的凭据，无法自动登录，提示用户重新登录

### 场景5：网络问题
- **描述**：网络连接不稳定或断开
- **行为**：自动登录请求失败，提示用户重新登录（但可能是网络问题，不是登录过期）

## 注意事项

1. **自动登录只重试一次**
   - 避免无限循环
   - 使用 `skipAuth401Retry` 标志位控制

2. **不同接口使用不同的 token**
   - 学班相关接口使用 `XUEBAN_TOKEN`
   - 研伴相关接口使用 `YANBAN_TOKEN`
   - 401 错误时只清除对应的 token

3. **用户凭据存储**
   - 从 `authStorage` 统一存储读取
   - 需要确保登录时正确保存用户凭据

4. **错误提示**
   - 使用 `showMessage('登录已过期，请重新登录', 'warning')` 提示用户
   - 抛出错误，由调用方处理

## 改进建议

1. **区分网络错误和认证错误**
   - 网络错误时提示"网络连接失败，请检查网络"
   - 认证错误时提示"登录已过期，请重新登录"

2. **记录失败原因**
   - 记录自动登录失败的具体原因
   - 便于调试和问题排查

3. **提供重试机制**
   - 对于网络错误，可以提示用户重试
   - 对于认证错误，引导用户重新登录

4. **优化用户体验**
   - 自动登录时显示加载提示
   - 登录失败时提供明确的错误信息
