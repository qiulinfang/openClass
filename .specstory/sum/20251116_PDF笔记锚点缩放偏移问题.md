问题序号：PDF笔记锚点缩放偏移问题

## 问题元信息
- **问题分类**：前端
- **严重程度**：中
- **影响范围**：PDF 阅读器中的文字笔记锚点功能（所有 Web 端 PDF 用户）
- **发现日期**：2025-11-16
- **解决状态**：已解决

## 问题现象
在 Web 端 PDF 查看器中：
- 页面缩放比例为 1 时，在页面上点击添加文字笔记锚点，锚点图标显示位置与点击位置基本一致。
- 当放大或缩小 PDF（通过 CSS `transform: scale(...)` 实现缩放）后，在页面上点击添加笔记：
  - 笔记锚点渲染出来的位置会明显偏离用户点击的位置。
  - 缩放倍数越大，偏移越明显，看起来像是“多放大了一次”的错位。

## 复现步骤
1. 打开 Web 端 PDF 阅读页面（`PdfViewerView.vue` + `PdfPage.vue`）。
2. 加载任意 PDF，并确认默认缩放比例为 1。
3. 切换到“添加笔记”模式，在页面上点击某个位置添加文字笔记，观察锚点位置正确。
4. 使用缩放功能把 PDF 放大到 2 倍或 3 倍（通过滚轮 + Ctrl / 触摸缩放）。
5. 在放大后的页面任意位置点击添加笔记：
   - 笔记弹窗出现，保存后锚点显示出来。
   - 观察锚点位置与实际点击位置有明显偏移。

## 用户体验
- 影响点1：用户在放大后点击某处添加笔记，但锚点出现在偏移的位置，会误导用户，以为“记录错地方了”。
- 影响点2：用户需要多次尝试点击不同位置才能“猜中”锚点最终落点，操作成本高、体验差。
- 影响点3：在教学或批注场景中，笔记锚点不准确会影响讲解内容的定位与理解。

## 相关文件/模块
- **涉及文件**：
  - `imates-web/src/components/PdfPage.vue`：PDF 渲染、缩放、手写高亮和笔记锚点逻辑的核心组件。
- **涉及模块**：
  - PDF Viewer 组件：负责 PDF 页面布局、缩放和交互。
  - 笔记系统：负责文字笔记的创建、存储和渲染。

## 技术原因 (❌)
1. **点击时归一化坐标忽略了 CSS 缩放比例**：
   - 代码中使用 `layout.width` / `layout.height` 作为归一化除数，但 `getBoundingClientRect()` 返回的是已经被 `transform: scale(...)` 缩放后的尺寸。
   - 没有将视觉坐标除以 `scale`，导致保存的 `x` / `y` 比真实值大 `scale` 倍。

2. **渲染时再次叠加 CSS 缩放**：
   - 锚点渲染使用 `note.x * layout.width`、`note.y * layout.height` 再乘上 CSS transform 的 `scale`，相当于把上一步多出来的 `scale` 再放大一次。

3. **坐标系基准不一致**：
   - 点击时使用的是“缩放后的视觉坐标 / 未缩放的布局宽高”；
   - 渲染时使用的是“归一化坐标 * 未缩放布局宽高 * CSS scale”；
   - 两者不在同一个坐标系上，导致锚点位置与点击位置不一致。

**错误代码示例 (❌)：**
```ts
// PdfPage.vue 中原始实现
// 点击页面添加笔记
const handlePageClick = (
  event: MouseEvent,
  pageIndex: number,
  layout: { width: number; height: number },
) => {
  if (isHighlightMode.value) return
  if (!isAddingNote.value) return
  const target = event.currentTarget as HTMLElement
  const rect = target.getBoundingClientRect()

  // ❌ 忽略了 CSS transform 的缩放比例
  const x = (event.clientX - rect.left) / layout.width
  const y = (event.clientY - rect.top) / layout.height

  if (x < 0 || x > 1 || y < 0 || y > 1) return

  pendingNotePosition.value = { pageIndex, x, y }
  noteDialogMode.value = 'add'
  noteDialogText.value = ''
  isNoteDialogOpen.value = true
}

// 渲染锚点位置（正常）
const getNoteStyle = (note: PageNote, layout: { width: number; height: number }): CSSProperties => ({
  position: 'absolute',
  left: `${note.x * layout.width}px`,
  top: `${note.y * layout.height}px`,
})
```

## 正确实现方案 (✅)
1. **点击时计算“未缩放页面坐标”，再做归一化**：
   - 先用 `rect` 得到鼠标在缩放后页面中的视觉坐标。
   - 使用当前 `scale`（来自 `store.scale`，对应 CSS `transform: scale(scale)`）除掉缩放影响，得到未缩放页面坐标。
   - 再用 `layout.width` / `layout.height` 归一化到 `[0,1]` 范围。

2. **渲染时继续使用归一化坐标 + 布局尺寸**：
   - 渲染逻辑不需要改，继续用 `note.x * layout.width`、`note.y * layout.height` 即可，CSS `transform` 会自然应用缩放。

3. **保证坐标系一致性**：
   - 点击时和渲染时都以“未缩放的布局尺寸 + 归一化坐标”为基准，缩放只通过 CSS `scale` 统一控制，避免重复放大。

**修复后代码示例 (✅)：**
```ts
// PdfPage.vue 修复后的实现
// 点击页面添加笔记
const handlePageClick = (
  event: MouseEvent,
  pageIndex: number,
  layout: { width: number; height: number },
) => {
  if (isHighlightMode.value) return
  if (!isAddingNote.value) return

  const target = event.currentTarget as HTMLElement
  const rect = target.getBoundingClientRect()

  // 当前视觉缩放比例（由 CSS transform: scale 控制）
  const scale = store.scale || 1

  // 鼠标在缩放后页面中的位置（视觉坐标）
  const localXVisual = event.clientX - rect.left
  const localYVisual = event.clientY - rect.top

  // 折算回未缩放页面坐标
  const localX = localXVisual / scale
  const localY = localYVisual / scale

  // 归一化到 [0,1]
  const x = localX / layout.width
  const y = localY / layout.height

  if (x < 0 || x > 1 || y < 0 || y > 1) return

  pendingNotePosition.value = { pageIndex, x, y }
  noteDialogMode.value = 'add'
  noteDialogText.value = ''
  isNoteDialogOpen.value = true
}

// 渲染锚点位置（保持不变）
const getNoteStyle = (note: PageNote, layout: { width: number; height: number }): CSSProperties => ({
  position: 'absolute',
  left: `${note.x * layout.width}px`,
  top: `${note.y * layout.height}px`,
})
```

## 关键代码/公式
- **归一化坐标计算公式**：
  ```ts
  // 未缩放页面坐标
  localX = (clientX - rect.left) / scale
  localY = (clientY - rect.top) / scale

  // 归一化到 [0,1]
  x = localX / layout.width
  y = localY / layout.height
  ```

- **锚点渲染公式**：
  ```ts
  left = note.x * layout.width
  top  = note.y * layout.height
  // 实际视觉位置还会乘以 CSS transform 的 scale
  ```

## 测试验证
- **测试场景**：
  - 场景1：缩放比例为 1
    - 步骤：加载 PDF，保持默认缩放，在页面不同位置点击添加笔记。
    - 预期：锚点显示位置与点击位置基本重合。
  - 场景2：放大到 2x
    - 步骤：将 PDF 放大到 2 倍，在页中部和四角分别点击添加笔记。
    - 预期：所有锚点都精准落在点击位置附近（允许 1px 级误差）。
  - 场景3：缩小到 0.5x
    - 步骤：将 PDF 缩小，在页面点击多个位置添加笔记。
    - 预期：锚点位置正常，不随缩放产生偏移。

- **验证方法**：
  - 方法1：肉眼对比点击位置和锚点位置，尤其是在 2x、3x 放大时观察是否有明显偏移。
  - 方法2：在控制台打印保存的 `(x, y)` 与点击时的像素坐标，交叉验证计算是否符合预期。

## 预防措施
- 措施1：**统一坐标系约定**：在组件内明确约定“内部逻辑使用未缩放布局坐标 + 归一化坐标”，缩放只通过 CSS 控制。
- 措施2：**封装坐标转换函数**：将“screen → page → normalized”与“normalized → page → screen”的转换封装成工具函数，避免在多个地方手写重复逻辑。
- 措施3：**添加缩放场景的自动化测试 / 手动测试用例**：每次调整缩放或坐标相关逻辑后，必须在多个缩放比例下验证锚点、注释等功能。

## 可复用经验
- 经验1：**统一使用归一化坐标存储位置数据**，在需要适配各种分辨率、缩放、设备的场景中非常重要（尤其是 PDF、图片编辑器、画布工具等）。
- 经验2：当使用 CSS `transform: scale` 做视觉缩放时，任何与点击位置相关的逻辑都要显式考虑当前 `scale`，否则很容易出现“视觉上对不齐”的问题。
- 经验3：对于“点击 → 存储 → 渲染”这类流程，最好画出坐标系转换链路（Screen ↔ Page ↔ Normalized ↔ PDF），逐步确认每一层的基准和单位，避免隐式假设导致的偏差问题。
