问题序号：PDF双指滚动与缩放手势实现问题

## 问题元信息
- **问题分类**：`前端`
- **严重程度**：`中`
- **影响范围**：`PDF 阅读页在 Android WebView 中的触摸交互体验`
- **发现日期**：`2025-11-15`
- **解决状态**：`已解决`

## 问题现象
- 在 PDF 阅读页中，双指触摸时存在以下问题：
  - 双指上下滑动时，既会滚动也会缩放，难以控制，仅想滚动时容易误触发缩放。
  - 双指上下滑动结束后没有自然的惯性滚动，和 Android 原生列表滚动手感差距较大。
  - 当用户先让双指稳定贴在屏幕上再开始移动时，几乎总是进入缩放模式，很难只滚动。

## 复现步骤
1. 在 Android WebView 中打开集成了 `pdfpage.vue` 的 PDF 阅读页。
2. 用两指在 PDF 内容上做上下滑动：
   - 观察双指移动过程中，内容既在缩放又在滚动。
3. 用两指轻微捏合或拉开再滑动：
   - 发现稍有距离变化就会被识别为缩放，滚动难以触发。
4. 快速滑动后松手：
   - 没有明显惯性效果，滚动立即停止，与原生滚动手感不一致。

## 用户体验
- 滚动和缩放频繁“抢手势”，阅读体验不连贯。
- 惯性缺失或不自然，用户需要多次拖动才能浏览长文档。
- 先按住再滑动时几乎只能缩放，用户难以完成细节滚动。

## 相关文件/模块
- **涉及文件**：
  - `src/components/pdfpage.vue`：PDF 阅读页核心组件，包含双指缩放、滚动和惯性逻辑。
- **涉及模块**：
  - PDF 手势交互层：负责处理 touch 事件、缩放与滚动状态。

## 技术原因 (❌)
1. 原始实现中，双指手势仅根据两指距离变化判断缩放，没有区分“滚动候选”和“缩放候选”。
2. 缩放判定阈值 `zoomThreshold` 初始设置过小（甚至被手动调到 `0.008`），导致极轻微的距离抖动也会被识别为缩放：
   ```typescript
   const scaleFactor = currentDistance / lastTouchDistance
   const distanceChange = Math.abs(scaleFactor - 1)
   const zoomThreshold = 0.008 // 距离变化 0.8% 就触发缩放
   if (distanceChange > zoomThreshold) {
     gestureMode = 'zoom'
   }
   ```
3. 惯性实现最初为线性减速：每帧减去固定 `decel`，导致减速不够自然，与 Android 原生 `fling` 的指数衰减模型不一致：
   ```typescript
   const decel = friction * dt
   if (panVelocity > 0) {
     panVelocity = Math.max(0, panVelocity - decel)
   } else if (panVelocity < 0) {
     panVelocity = Math.min(0, panVelocity + decel)
   }
   ```

## 正确实现方案 (✅)
1. 手势模式优先级改造：
   - 引入 `gestureMode: 'none' | 'zoom' | 'pan'`，在 `gestureMode === 'none'` 时：
     - 先判定是否为“滚动候选”：`|dx| > panThreshold` 或 `|dy| > panThreshold`；
     - 再判定是否为“缩放候选”：`distanceChange > zoomThreshold`；
     - 优先滚动：
       - 只有明显平移 → `pan`；
       - 只有明显捏合 → `zoom`；
       - 同时明显 → 默认 `pan`，避免轻微捏合导致无法滚动。
2. 缩放阈值与滚动阈值调优：
   - `zoomThreshold` 调整到 `0.04 ~ 0.15` 区间，减少轻微抖动误触缩放。
   - `panThreshold` 根据设备实际像素滑动调整（如 `0.5 ~ 14`），避免手指抖动就触发滚动。
3. 惯性滚动改用指数衰减：
   - 使用 `Math.exp(-friction * dt)` 对速度做比例衰减，更接近安卓原生滚动手感：
   ```typescript
   const frictionValue = friction.value
   const step = () => {
     const now = performance.now()
     const dt = now - lastTime
     lastTime = now

     const deltaX = panVelocityX * dt
     const deltaY = panVelocity * dt
     // 更新 scrollLeft / scrollTop ...

     // 指数衰减：
     const damping = Math.exp(-frictionValue * dt)
     panVelocityX *= damping
     panVelocity *= damping

     if (Math.abs(panVelocity) <= threshold && Math.abs(panVelocityX) <= threshold) {
       panVelocityX = 0
       panVelocity = 0
       inertiaFrameId = null
       return
     }

     inertiaFrameId = requestAnimationFrame(step)
   }
   ```
4. 支持调试参数配置化：
   - 将 `minScale/maxScale/zoomThreshold/panThreshold/friction/inertiaThreshold` 抽到响应式变量中，并通过 `PdfGestureDebugPanel` 提供 UI 调整入口。

## 关键代码/公式
- 手势模式判定核心：
  ```typescript
  const scaleFactor = currentDistance / lastTouchDistance
  const distanceChange = Math.abs(scaleFactor - 1)

  if (gestureMode === 'none') {
    const isPanCandidate = Math.abs(dx) > panThreshold.value || Math.abs(dy) > panThreshold.value
    const isZoomCandidate = distanceChange > zoomThreshold.value

    // 优先滚动
    if (isPanCandidate && !isZoomCandidate) {
      gestureMode = 'pan'
    } else if (isZoomCandidate && !isPanCandidate) {
      gestureMode = 'zoom'
    } else if (isPanCandidate && isZoomCandidate) {
      gestureMode = 'pan'
    }
  }
  ```
- 惯性指数衰减公式：
  - 速度更新：`v(t + dt) = v(t) * e^{-k * dt}`，其中 `k` 由 `friction` 控制。

## 测试验证
- **测试场景**：
  - 场景1：双指平行上下滑动。
    - 预期：进入 `pan` 模式，仅滚动 + 惯性，不缩放。
  - 场景2：明显捏合缩放。
    - 预期：进入 `zoom` 模式，按两指距离平滑缩放，中心点基本保持位置。
  - 场景3：快速滑动后松手。
    - 预期：有自然的惯性滚动，速度逐渐减小并在阈值附近平滑停止。
- **验证方法**：
  - 使用真实 Android 设备，通过对比原生列表滚动手感，对照 `friction` 和 `inertiaThreshold` 调整参数，直至主观体验接近原生。

## 预防措施
- 将手势参数抽象为配置项，并通过调试面板实时调节和观察效果。
- 为关键阈值设置合理默认区间，避免直接在代码中写死极端值（如 `0.008`）。
- 在未来修改手势逻辑时，优先保证“手势模式判定清晰（缩放/滚动分离）”，再考虑细节调参。

## 可复用经验
- 将复杂手势的判定拆分为“模式判定 + 行为执行”两层结构，有助于控制优先级和避免冲突。
- 惯性滚动使用指数衰减，可更好模拟原生体验，并通过 1~2 个参数控制手感强弱。
- 为交互参数提供调试面板，大幅降低「手感调优」的迭代成本。
