问题序号：公式定界符后多余空格与换行导致渲染异常问题

## 问题元信息
- **问题分类**：`前端`
- **严重程度**：`高`
- **影响范围**：`AI聊天/用户输入的数学公式渲染`
- **发现日期**：`2025-12-26`
- **解决状态**：`已解决`

## 问题现象
AI 或用户输入中常出现以下非标准写法：
- 行内：`$  a > b$`、`$a>b  $`（定界符内侧带多余空格）
- “孤立 $ 块”：`$\n...\n$` 或 `$  \n...\n  $`（$ 独占一行、内容多行）
- 公式后紧接中文标点但被插入空格/换行：`$...$ \n，已知...`

导致：
- MathJax/markdown-it-mathjax3 识别不稳定
- Markdown 被拆段，视觉上“公式独占一行/像块公式”

## 复现步骤
1. 在聊天气泡输入：
   - `若  $a > b$ , 给出下列不等关系:\n$  \n① ... \n$`
2. 发送后观察：
   - 有时 LaTeX 原文直接显示（未渲染）
   - 或公式/标点被拆段，排版异常

## 用户体验
- 公式阅读困难，影响解题/讲解连贯性。
- 同一类内容在不同消息里表现不一致，用户不信任渲染效果。

## 相关文件/模块
- **涉及文件**：
  - `imates-web/src/composables/useMessageRenderer.ts`：`preprocessLatexFormats` 预处理逻辑
- **涉及模块**：
  - Markdown 渲染（markdown-it）
  - 公式渲染（markdown-it-mathjax3 / MathJax）

## 技术原因 (❌)
1. markdown-it 会把空行/换行视为段落边界；非标准的 `$ ... $` 布局会被拆段。
2. 定界符内侧空白导致 math 匹配边界不清晰。
3. 公式与标点之间插入空白/换行导致 “`$...$`” 被单独包在段落里。

## 正确实现方案 (✅)
在 `preprocessLatexFormats` 中增加“输入归一化”规则：
1. **孤立 `$\n...\n$` 统一转块级**：`\n\n$$...$$\n\n`
2. **行内 `$...$` 内侧空白清理**：兼容仅左/仅右/两侧空格
3. **收紧公式与标点**：`$...$ ，`、`$...$\n，` 统一成 `$...$，`

```typescript
// ✅ 关键规则（节选）
const lonelyDollarBlockRegex = /(^|\n)\s*\$(?:[\t ]*)\r?\n([\s\S]*?)\r?\n\s*\$\s*(?=\n|$)/g
processedContent = processedContent.replace(lonelyDollarBlockRegex, (_m, prefix, content) => {
  const trimmed = String(content ?? '').trim()
  return `${prefix}\n\n$$${trimmed}$$\n\n`
})

const inlineDollarTrimLeftRegex = /\$(?!\$)[\t ]+([^\r\n$]+?)\s*\$(?!\$)/g
const inlineDollarTrimRightRegex = /\$(?!\$)([^\r\n$]+?)[\t ]+\$(?!\$)/g

const mathToPunctRegex = /(\$\$[\s\S]*?\$\$|\$[^\r\n$]*?\$)\s*(?:\r?\n)+\s*([，。；：、！？,.;:!?])/g
```

## 测试验证
- **测试场景**：
  - 场景1：`$  a>b$`、`$a>b  $` 能渲染且不额外空白。
  - 场景2：`$\n①...\n$` 会被转换为 `$$...$$` 并正常渲染。
  - 场景3：`$a>b$\n，已知` 会合并为 `$a>b$，已知`。
- **验证方法**：
  - 渲染测试页/聊天气泡中查看 HTML 输出与实际渲染一致。
