## 问题现象
当前系统通过对话形式实现题目/消息录入，但未明确区分"题库题目录入"和"师生问答消息"两种场景

## 相关文件/模块
- **涉及文件**：
  - `d:/Project/研伴-后端/src/main/java/com/blw/edu/yb/modules/alc/service/AlcQuestionService.java`：核心消息处理逻辑
  - `d:/Project/研伴-后端/src/main/java/com/blw/edu/yb/api/ApiTeacherChatController.java`：教师端消息录入接口

## 技术实现方案 (✅)
1. **消息类型处理**：
   - 文本消息直接存储
   - 图片/语音转为base64格式推送
   ```java
   // 图片处理示例
   String base64Prefix = String.format(BASE64_PREFIX_IMG_TEMPLATE, suffix);
   byte[] bytes = Files.readAllBytes(file.toPath());
   String base64 = Base64.getEncoder().encodeToString(bytes);
   messageBase64 = base64Prefix + base64;
   ```

2. **持久化设计**：
   - 使用`alc_question`表存储原始消息
   - 通过`sessionId`关联对话上下文

3. **消息推送**：
   - 通过RabbitMQ按学生账号路由
   ```java
   String routerKey = MqConstant.QUESTION_REPLY_KEY_PREFIX + student.getAccount();
   rabbitTemplate.convertAndSend(MqConstant.QUESTION_EXCHANGE, routerKey, message);
   ```

## 关键代码
- 消息实体结构：
  ```java
  @Table("alc_question")
  public class AlcQuestion {
      private String id;         // 消息ID
      private String sessionId;  // 会话ID
      private String msgType;    // 0-文本 1-图片 2-语音
      private String msgContent; // 内容/文件路径
  }
  ```

## 可复用经验
1. 文件类消息应采用"存储路径+实时转换"策略，避免直接存大文件数据
2. 消息推送应建立接收方专属路由，确保消息隔离
