问题序号：PDF内联笔记状态管理问题

## 问题元信息
- **问题分类**：`前端`
- **严重程度**：`中`
- **影响范围**：`PDF 阅读页内联文字笔记的创建与自动保存`
- **发现日期**：`2025-11-18`
- **解决状态**：`已解决`

## 问题现象
在实现 PDF 内联文字笔记时，`PdfPage.vue` 中使用的 `inlineNoteText` 与 `PdfNoteAnchor.vue` 组件内部的文本状态不同步：

- `PdfNoteAnchor` 的 create 模式内部使用 `localText` 存储输入内容，并通过 `emit('confirm', localText.value)` 将文本回传。
- `PdfPage` 中的 `inlineNoteText` 没有参与实际输入绑定，始终为空字符串或旧值。
- 在 `handlePageClick` 中，通过 `inlineNoteText.value.trim()` 判断是否有内容来决定是“自动保存并关闭”还是“取消并关闭”，导致逻辑失效：
  - 即使用户已在气泡输入了内容，`inlineNoteText` 仍可能为空，点击其他地方会被当成“无内容”，直接取消输入，造成笔记丢失。

## 复现步骤
1. 切换到 PDF 页面 `PdfPage.vue` 的 note 模式。
2. 在 PDF 页面上点击某处，弹出内联新增输入气泡（`PdfNoteAnchor` create 模式）。
3. 在气泡中输入一些文字，但不要点击确认按钮。
4. 点击页面上其他位置，触发 `handlePageClick`。
5. 观察行为：
   - 预期：检测到当前气泡有内容，应先自动保存为新笔记，再关闭输入。
   - 实际：由于 `inlineNoteText` 未更新，被认为无内容，直接调用取消逻辑，输入内容丢失。

## 用户体验
- 影响点1：用户在内联笔记气泡中输入的内容会在点击其他区域时“悄悄消失”，造成严重的输入丢失体验。
- 影响点2：用户难以理解为何自己的文字没有被保存，降低对内联笔记功能的信任感。
- 影响点3：与常见的“点击外部自动保存草稿”的交互预期不一致，易导致误操作。

## 相关文件/模块
- **涉及文件**：
  - `imates-web/src/components/PdfPage.vue`：管理内联笔记状态 `editingInlineNote`、`inlineNoteText` 和 `handlePageClick`、`handleInlineCreateConfirm`、`handleInlineCreateCancel`。
  - `imates-web/src/components/PdfNoteAnchor.vue`：内联笔记锚点组件，负责 create/display 模式输入和展示。
- **涉及模块**：
  - PDF 笔记锚点与内联输入模块。
  - 笔记数据持久化模块（IndexedDB）。

## 技术原因 (❌)
1. 原因1：`PdfNoteAnchor` 在 create 模式中使用独立的 `localText` 来管理输入，未对外暴露 `v-model` 接口，导致父组件无法实时获取输入内容。
2. 原因2：`PdfPage` 仍保留了早期方案中的 `inlineNoteText` 变量，但它没有与子组件输入进行绑定，导致用于判断“是否有内容”的依据失真。
3. 原因3：`handlePageClick` 的“自动保存/取消”逻辑依赖 `inlineNoteText.value.trim()`，在未同步的情况下该逻辑总是误判。

## 正确实现方案 (✅)
1. 方案1：将 `PdfNoteAnchor` 的 create 模式改为受控组件，通过 `modelValue` / `update:modelValue` 与父组件的 `inlineNoteText` 双向绑定。
2. 方案2：在 `PdfPage` 中，将 create 模式锚点的 `model-value` 绑定到 `inlineNoteText`，同时监听 `update:model-value` 更新该值，从而保证父组件始终掌握当前输入内容。
3. 方案3：保留 `handleInlineCreateConfirm(textFromChild: string)` 的参数，但内部以 `textFromChild.trim()` 为准；`handlePageClick` 在“点击其他地方”时仍可以使用 `inlineNoteText.value.trim()` 进行自动保存/取消逻辑判断。

✅ 正确代码示例 1：子组件改为受控输入
```vue
<!-- PdfNoteAnchor.vue（修复后，节选） -->
<q-input
  :model-value="modelValue"
  @update:model-value="(val) => emit('update:modelValue', val)"
  type="textarea"
  autogrow
  borderless
  autofocus
  dense
  placeholder="输入笔记"
  :input-style="{ fontSize: '12px' }"
/>

interface Props {
  mode: 'marker' | 'create' | 'display'
  x: number
  y: number
  pageLayout: { width: number; height: number }
  text?: string
  active?: boolean
  inlineActive?: boolean
  modelValue?: string
}

const emit = defineEmits<{
  (e: 'confirm', text: string): void
  (e: 'cancel'): void
  (e: 'marker-click'): void
  (e: 'update:modelValue', val: string): void
}>()

const handleConfirm = () => {
  isOpen.value = false
  emit('confirm', (props.modelValue || '').trim())
}
```

✅ 正确代码示例 2：父组件绑定 v-model 并使用统一判断逻辑
```vue
<!-- PdfPage.vue 模板节选 -->
<PdfNoteAnchor
  v-if="editingInlineNote && editingInlineNote.pageIndex === index"
  mode="create"
  :x="editingInlineNote.x"
  :y="editingInlineNote.y"
  :page-layout="layout"
  :inline-active="true"
  :model-value="inlineNoteText"
  @update:model-value="(val) => (inlineNoteText = val)"
  @confirm="handleInlineCreateConfirm"
  @cancel="handleInlineCreateCancel"
/>
```

```ts
// PdfPage.vue 逻辑节选
const handleInlineCreateConfirm = (textFromChild: string) => {
  if (!editingInlineNote.value) return

  const text = textFromChild.trim()
  if (!text) {
    editingInlineNote.value = null
    inlineNoteText.value = ''
    activeNoteId.value = null
    return
  }

  const { pageIndex, x, y } = editingInlineNote.value
  const now = Date.now()
  const id = `${now}-${Math.random().toString(36).slice(2)}`

  notes.value.push({
    id,
    pageIndex,
    x,
    y,
    text,
    createdAt: now,
  } as any)

  editingInlineNote.value = null
  inlineNoteText.value = ''
  activeNoteId.value = null
  void saveNotesToDb()
}

const handleInlineCreateCancel = () => {
  editingInlineNote.value = null
  inlineNoteText.value = ''
  activeNoteId.value = null
}

// 点击其他地方时自动保存/取消
const handlePageClick = (event: MouseEvent, pageIndex: number, layout: { width: number; height: number }) => {
  if (['highlighter', 'pen', 'eraser-draw'].includes(currentMode.value)) return
  if (currentMode.value !== 'note') return

  if (editingInlineNote.value) {
    const text = inlineNoteText.value.trim()
    if (text) {
      handleInlineCreateConfirm(text)
      return
    } else {
      handleInlineCreateCancel()
      return
    }
  }

  // ...后续创建新 tempNote 的逻辑
}
```

## 测试验证
- **测试场景**：
  - 场景1：在 create 模式输入内容后点击页面其他区域，应自动保存成新笔记并关闭输入气泡。
  - 场景2：在 create 模式不输入任何内容直接点击其他区域，应仅关闭输入气泡且不新增笔记。
- **验证方法**：
  - 方法1：通过控制台或 Vue DevTools 观察 `inlineNoteText` 与 `notes` 数组变化，确认保存/取消逻辑符合预期。
  - 方法2：多次在不同页、多处位置创建内联笔记，验证不会出现“漏保存”或“误保存空笔记”的情况。

## 预防措施
- 措施1：在组件设计时优先采用受控组件模式（`v-model`），确保父组件对关键表单状态有完全控制权。
- 措施2：避免在父组件中使用与子组件内部状态重复的变量，防止逻辑分裂与状态不同步问题。
- 措施3：在实现“点击外部自动保存/取消”类逻辑时，明确数据源来源必须是**当前真实输入值**，而不是缓存或过期变量。

## 可复用经验
- 经验1：当父组件需要根据输入内容做复杂逻辑（如自动保存、校验）时，应将输入状态提升到父组件统一管理。
- 经验2：组件间传递表单值时，优先使用 `modelValue` / `update:modelValue` 约定，避免本地 state 与外部 state 双轨制。
- 经验3：涉及“自动处理未保存输入”的交互时，务必增加针对性测试，防止用户输入被静默丢弃的严重体验问题。
