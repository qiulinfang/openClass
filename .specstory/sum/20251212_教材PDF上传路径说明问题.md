问题序号：教材PDF上传路径说明问题

## 问题元信息
- **问题分类**：后端
- **严重程度**：中
- **影响范围**：教师教材上传接口、资源文件管理
- **发现日期**：2025-12-09
- **解决状态**：已解决

## 问题现象
教师端反馈“教材 PDF 上传后存储到服务器的具体路径不清楚”，无法确认文件是否落盘成功、也无法提供下载路径给前端，导致资源查验和排查困难。

## 复现步骤
1. 通过 `/api/teacher/resource-file-upload` 上传教材 PDF。
2. 上传成功后返回的 `path` 仅是相对路径，未说明实体路径。
3. 开发/运维无法找到文件在服务器上的准确目录结构。

## 用户体验
- 无法确认上传是否成功落盘。
- 排查文件或人工替换文件成本高。
- 影响后续资源关联与下载。

## 相关文件/模块
- **涉及文件**：
  - `src/main/resources/application.yml`：`global.upload` 根目录配置。
  - `src/main/java/com/blw/edu/yb/common/pojo/properties/UploadProperty.java`：上传目录拼接逻辑。
  - `src/main/java/com/blw/edu/yb/modules/base/service/ResourceFileService.java`：资源文件保存与路径落盘实现。
- **涉及模块**：
  - 上传配置模块：负责解析 `global.upload.*`。
  - 资源文件服务：负责保存 PDF 并写入数据库。

## 技术原因 (❌)
1. 未在文档中明确 `global.upload.folder` 与 `global.upload.resource` 的组合路径。
2. `ResourceFileService` 只返回相对路径（`fileUrl`），开发者忽略了需要将其与根目录拼接。
3. 运维侧未同步应用配置，导致不知道 `/usr/files/upload/resource/yyyymmdd` 的目录结构。

错误代码示例：
```java
resp.setPath(resourceFile.getFileUrl()); // 仅返回相对路径，未解释物理路径
```

## 正确实现方案 (✅)
1. 在运维/开发文档中明确：物理路径 = `global.upload.folder + "/" + global.upload.resource + "/yyyyMMdd/uuid.ext"`。
2. 若需要绝对路径，可在响应中附带 `uploadProperty.getResource()` 前缀或提供下载接口。
3. 将 `application.yml` 中的 `global.upload` 配置同步给相关人员。

正确代码示例：
```java
String saveFolderPath = uploadProperty.getResource() + "/" + DateUtil.format(new Date(), "yyyyMMdd");
String finalFilePath = saveFolderPath + "/" + IdUtil.fastSimpleUUID() + ".pdf";
```

## 关键代码/公式
- `UploadProperty.getResource()`：`return folder + "/" + resource;`
- `ResourceFileService.upload`：保存路径 `saveFolderPath + "/" + uuid + suffix`。

## 测试验证
- **测试场景**：
  - 场景1：上传 PDF，检查服务器 `/usr/files/upload/resource/<当天日期>/` 是否生成文件。
  - 场景2：比对响应 `path` 与数据库 `base_resource_file.file_url`，确认相对路径一致。
- **验证方法**：
  - 方法1：通过 SSH/容器查看目录写入情况。
  - 方法2：调用下载接口或 Nginx 静态映射进行访问测试。

## 预防措施
- 在 README/接口文档中记录上传目录结构。
- 脚本或监控定期校验上传根目录是否可写。
- 代码中增加日志打印物理路径，便于排查。

- 上传路径统一集中在配置文件，便于多环境切换。
- 响应应返回相对路径 + 补充说明，减少运维沟通成本。
- 上传服务应提供日志/校验工具，方便定位文件。
