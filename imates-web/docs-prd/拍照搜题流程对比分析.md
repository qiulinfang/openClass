# 拍照搜题流程对比分析

// 初始化裁剪画布
const initCropCanvas = () => {
  if (!cropCanvas.value || !currentImage.value) return

  const canvas = cropCanvas.value
  const ctx = canvas.getContext('2d')
  if (!ctx) return

  const img = new Image()
  img.onload = () => {
    // 设置画布大小
    const maxWidth = canvas.parentElement?.clientWidth || window.innerWidth
    const maxHeight = (canvas.parentElement?.clientHeight || window.innerHeight) - 200
    const scale = Math.min(maxWidth / img.width, maxHeight / img.height, 1)
    
    canvas.width = img.width * scale
    canvas.height = img.height * scale
    
    // 绘制图片
    ctx.drawImage(img, 0, 0, canvas.width, canvas.height)
    
    // 初始化裁剪区域（全图）
    cropRect.value = {
      x: 0,
      y: 0,
      width: canvas.width,
      height: canvas.height,
    }
  }
  img.src = currentImage.value.preview
}
```

**技术特点**：
- 使用HTML5 Canvas进行裁剪
- 通过鼠标/触摸事件手动绘制裁剪区域
- 裁剪结果需要从Canvas中提取为File对象
- 完全在前端实现，不依赖原生组件

public async recognizeImage(imageFile: File | Blob, subject: string): Promise<any | null> {
  try {
    // 根据科目选择对应的API端点
    const endpoint = subject.toLowerCase() === 'biology' 
      ? API_ENDPOINTS.IMAGE_RECOGNITION.BIOLOGY 
      : API_ENDPOINTS.IMAGE_RECOGNITION.MATH
    
    const url = getApiUrl(endpoint)

    // 构建FormData，与Android端保持一致
    const formData = new FormData()
    formData.append('imgFile', imageFile, 'default.jpg')

    // 使用httpClient发送multipart/form-data请求
    const response = await httpClient.post<{
      success: boolean
      code: number
      message: string
      data: {
        item: {
          questionsConfirm: Array<{
            bmNo: string
            title: string
            answer: string
            explanation: string
            analysisData: string
            id: string
          }>
        }
      }
    }>(url, formData)

    if (response.success && response.data?.data?.item?.questionsConfirm && response.data.data.item.questionsConfirm.length > 0) {
      const questionData = response.data.data.item.questionsConfirm[0]
      return {
        id: questionData.id,
        bmNo: questionData.bmNo,
        title: questionData.title,
        question: questionData.title, // 兼容旧版本
        answer: questionData.answer,
        explanation: questionData.explanation,
        analysisData: questionData.analysisData,
        subject: subject.toLowerCase(),
      }
    }
    return null
  } catch (error) {
    console.error('[API] 图片识别失败:', error)
    return null
  }
}
```

**技术特点**：
- 使用FormData上传File对象
- 使用统一的httpClient发送请求
- 识别结果在页面中显示，支持文本搜索降级

## 三、核心区别对比

### 3.1 架构层面

| 对比项 | 安卓原生 | Vue实现 |
|--------|---------|---------|
| **实现方式** | 独立Activity | WebView中的单页路由 |
| **生命周期** | Android Activity生命周期 | Vue组件生命周期 |
| **内存管理** | 系统自动管理 | WebView管理 |
| **状态保持** | Activity状态保存 | Vue Router状态管理 |

### 3.2 相机功能

| 对比项 | 安卓原生 | Vue实现 |
|--------|---------|---------|
| **预览方式** | CameraX实时预览 | 无预览，直接拍照 |
| **拍照API** | ImageCapture直接拍照 | 调用原生bridge接口 |
| **图片格式** | File对象（临时文件） | base64编码字符串 |
| **性能** | 原生性能，无转换开销 | 需要base64解码 |

### 3.3 图片裁剪

| 对比项 | 安卓原生 | Vue实现 |
|--------|---------|---------|
| **裁剪组件** | CropImageView（第三方库） | HTML5 Canvas |
| **交互方式** | 原生手势操作 | 鼠标/触摸事件 |
| **裁剪结果** | Bitmap对象 | File对象（从Canvas提取） |
| **用户体验** | 原生UI体验 | Web端UI体验 |

### 3.4 图片识别

| 对比项 | 安卓原生 | Vue实现 |
|--------|---------|---------|
| **数据格式** | Bitmap对象 | File对象 |
| **网络请求** | OkHttp | Fetch API |
| **错误处理** | Toast提示 | Message提示 |
| **动画效果** | 扫描线动画 | 加载动画 |

### 3.5 数据流向

**安卓原生流程**：
```
拍照 → File → CropImageView → Bitmap → API识别 → Question对象 → 添加到列表 → 启动WebView
```

**Vue流程**：
```
拍照 → base64 → File → Canvas裁剪 → File → API识别 → Question对象 → 添加到列表 → Router跳转
```

### 3.6 用户体验

**安卓原生优势**：
- ✅ 实时相机预览，所见即所得
- ✅ 原生UI交互，响应速度快
- ✅ 扫描动画效果，视觉反馈好
- ✅ 独立Activity，不依赖WebView

**Vue实现优势**：
- ✅ 统一的UI风格，与Web端一致
- ✅ 代码复用，维护成本低
- ✅ 支持文本搜索降级
- ✅ 路由跳转，页面切换流畅

## 五、总结

### 5.1 技术选型差异

**安卓原生**：
- 使用CameraX实现相机功能
- 使用CropImageView实现裁剪
- 使用OkHttp进行网络请求
- 完全原生实现，性能最优

**Vue实现**：
- 通过Bridge调用原生相机
- 使用Canvas实现裁剪
- 使用Fetch API进行网络请求
- 跨平台代码复用

### 5.2 适用场景

**安卓原生适合**：
- 需要实时相机预览的场景
- 追求最佳性能的场景
- 需要复杂相机操作的场景

**Vue实现适合**：
- 需要统一UI风格的场景
- 需要跨平台复用的场景
- 需要快速迭代的场景

### 5.3 改进建议

1. **Vue实现可以增强**：
   - 如果可能，添加实时相机预览功能
   - 优化base64解码性能
   - 改进Canvas裁剪的用户体验

2. **安卓原生可以优化**：
   - 添加文本搜索降级功能
   - 优化Activity启动速度
   - 改进错误提示信息
