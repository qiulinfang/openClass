# 撤销重做按钮置灰问题分析

## 问题描述
PdfViewerView.vue的撤销和重做按钮一直处于置灰状态，即使用户进行了绘制操作也无法使用撤销重做功能。

## 问题分析

### 1. 历史记录初始化问题

在`PdfPage.vue`的`loadAnnotations`函数中，存在历史记录初始化逻辑：

```typescript
// 初始化历史记录（保存初始状态）
history.value = [JSON.parse(JSON.stringify(objects.value))]
historyIndex.value = 0
```

**问题**：
- 初始状态`history.value = [[]]`，即包含一个空数组
- `historyIndex.value = 0`
- 此时`canUndo = historyIndex > 0 = false`（因为0不大于0）
- `canRedo = historyIndex < history.length - 1 = 0 < 0 = false`

### 2. 页面注册逻辑问题

在`PdfViewerView.vue`中，`toolStates`计算属性逻辑：

```typescript
const toolStates = computed(() => {
  const lastModifiedPage = store.lastModifiedPage
  if (lastModifiedPage === null) {
    return {
      undo: false,
      redo: false,
    }
  }
  // ...
})
```

**问题**：
- 当没有页面被修改时（`lastModifiedPage === null`），直接返回`undo: false, redo: false`
- 即使用户在某个页面进行了绘制，如果`lastModifiedPage`为null，按钮也会置灰

### 3. 保存状态逻辑问题

在`PdfPage.vue`中，`saveState`函数只在用户绘制操作后被调用，但初始加载注释数据后没有正确更新历史状态。

## 根本原因

1. **历史记录初始化不完整**：加载注释数据后，历史记录只保存了初始状态，但没有考虑这个初始状态是否应该可撤销
2. **工具栏状态计算逻辑过于严格**：`toolStates`计算属性在没有`lastModifiedPage`时直接返回false
3. **页面组件注册时机问题**：页面组件注册时可能没有正确同步历史状态

## 解决方案

### 方案1：修改历史记录初始化逻辑

修改`PdfPage.vue`中的`loadAnnotations`函数，确保历史记录正确初始化：

```typescript
// 加载笔记
const loadAnnotations = async () => {
  try {
    // ... 加载注释数据 ...
    
    // 初始化历史记录（确保初始状态可撤销）
    if (objects.value.length > 0) {
      // 如果有初始数据，保存两个状态：空状态和当前状态
      history.value = [[], JSON.parse(JSON.stringify(objects.value))]
      historyIndex.value = 1  // 指向当前状态
    } else {
      // 如果没有数据，只保存空状态
      history.value = [[]]
      historyIndex.value = 0
    }
  } catch (err) {
    console.error(`第 ${props.layout.pageNum} 页加载笔记失败:`, err)
    objects.value = []
    history.value = [[]]
    historyIndex.value = 0
  }
}
```

### 方案2：修改工具栏状态计算逻辑

修改`PdfViewerView.vue`中的`toolStates`计算属性：

```typescript
const toolStates = computed(() => {
  const lastModifiedPage = store.lastModifiedPage
  
  // 如果没有最后修改的页面，尝试使用当前可见页面
  let targetPage = lastModifiedPage
  if (targetPage === null) {
    // 获取第一个有历史记录的页面
    for (const [pageNum, component] of pageComponents.value.entries()) {
      if (component.canUndo || component.canRedo) {
        targetPage = pageNum
        break
      }
    }
    
    // 如果还是没有，使用第一个页面
    if (targetPage === null && pageComponents.value.size > 0) {
      targetPage = Array.from(pageComponents.value.keys())[0]
    }
  }
  
  if (targetPage === null) {
    return {
      undo: false,
      redo: false,
    }
  }

  const pageComponent = pageComponents.value.get(targetPage)
  if (pageComponent) {
    return {
      undo: pageComponent.canUndo,
      redo: pageComponent.canRedo,
    }
  }

  return {
    undo: false,
    redo: false,
  }
})
```

### 方案3：优化页面组件注册

确保页面组件在注册时正确暴露历史状态：

```typescript
// 在PdfPage.vue的onMounted中
onMounted(async () => {
  // ... 其他初始化 ...
  
  // 注册到父组件
  if (registerPageComponent) {
    registerPageComponent(props.layout.pageNum, {
      undo,
      redo,
      get canUndo() { return canUndo.value },
      get canRedo() { return canRedo.value }
    })
  }
})
```

## 实施建议

建议采用**方案1+方案2**的组合：

1. **方案1**解决历史记录初始化问题，确保初始状态可撤销
2. **方案2**解决工具栏状态计算问题，确保按钮状态正确反映可用性

这样可以确保：
- 用户加载已有笔记时，撤销按钮可用（可以撤销到空状态）
- 工具栏按钮状态正确反映当前页面的历史状态
- 提供更好的用户体验

## 已实施的解决方案

### ✅ 方案1：修改历史记录初始化逻辑
**文件**：`src/components/PdfPage.vue`
**修改**：在`loadAnnotations`函数中，根据是否有初始数据来初始化历史记录
- 有初始数据时：`history = [[], 当前数据]`，`historyIndex = 1`
- 无初始数据时：`history = [[]]`，`historyIndex = 0`

### ✅ 方案2：修改工具栏状态计算逻辑  
**文件**：`src/views/PdfViewerView.vue`
**修改**：在`toolStates`计算属性中，当`lastModifiedPage`为null时，智能选择目标页面
- 优先选择有历史记录的页面（`canUndo || canRedo`为true）
- 如果没有，选择第一个页面
- 确保工具栏按钮状态正确反映可用性

## 预期效果

1. **加载已有笔记**：撤销按钮可用，用户可以撤销到空状态
2. **空页面**：撤销按钮保持不可用（因为没有历史记录）
3. **多页面文档**：工具栏会根据当前页面的历史状态动态更新
4. **用户体验**：用户可以随时使用撤销重做功能，不再受限于按钮置灰状态
