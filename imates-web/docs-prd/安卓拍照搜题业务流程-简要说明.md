# 安卓拍照搜题业务流程 - 简要说明

## 业务流程概览

```
启动拍照 → 相机预览 → 拍照/选择图片 → 裁剪图片 → 识别题目 → 显示结果 → 添加到列表 → 返回习题列表
```

---

## 详细步骤

### 1️⃣ **启动拍照搜题**
- **入口**：`ExerciseSolveActivity` 点击拍照按钮，或通过JS接口调用
- **方式**：使用Intent启动独立的 `PhotoSearchActivity`
- **参数**：传递科目类型（数学/生物）

### 2️⃣ **相机预览与拍照**
- **技术**：使用CameraX库实现实时预览
- **操作**：用户点击拍照按钮
- **结果**：照片保存为临时File文件

### 3️⃣ **图片裁剪**
- **技术**：使用CropImageView组件
- **操作**：用户调整裁剪区域
- **结果**：获取裁剪后的Bitmap对象

### 4️⃣ **图片识别**
- **API调用**：根据科目选择对应的识别接口（数学/生物）
- **数据格式**：直接上传Bitmap对象
- **效果**：显示扫描动画（扫描线）
- **结果**：
  - ✅ 成功：显示识别到的题目内容
  - ❌ 失败：提示"没有搜到题目"，可跳转文本搜索

### 5️⃣ **添加到列表**
- **操作**：用户确认添加题目
- **API调用**：调用添加题目到列表接口
- **数据**：包含题目ID和当前列表所有题目ID

### 6️⃣ **返回结果**
- **操作**：停止相机，关闭当前Activity
- **跳转**：启动 `MainWebViewActivity`，导航到 `/exercise-solve?subject=xxx`
- **结果**：在WebView中显示更新后的题目列表

---

## 关键技术点

| 环节 | 技术实现 |
|------|---------|
| **相机功能** | CameraX + PreviewView（实时预览） |
| **图片裁剪** | CropImageView（第三方库） |
| **网络请求** | OkHttp |
| **图片格式** | File → Bitmap（无需base64转换） |
| **UI交互** | 原生Android UI，支持扫描动画 |

---

## 数据流向

```
用户操作
  ↓
Intent启动Activity
  ↓
CameraX拍照 → File临时文件
  ↓
CropImageView裁剪 → Bitmap对象
  ↓
API识别 → Question对象
  ↓
显示结果 → 用户确认
  ↓
API添加到列表
  ↓
启动WebView → 显示题目列表
```

---

## 与Vue实现的主要区别

| 对比项 | 安卓原生 | Vue实现 |
|--------|---------|---------|
| **启动方式** | 独立Activity | WebView路由 |
| **相机预览** | ✅ 实时预览 | ❌ 无预览 |
| **图片格式** | File → Bitmap | base64 → File |
| **裁剪组件** | 原生CropImageView | Canvas裁剪 |
| **性能** | 原生性能最优 | 需要转换开销 |

---

## 总结

安卓原生实现的核心优势：
- ✅ **实时相机预览**：用户体验更好
- ✅ **原生性能**：无数据转换开销
- ✅ **独立Activity**：不依赖WebView，更稳定
- ✅ **动画效果**：扫描线动画提供视觉反馈

**适用场景**：需要最佳性能和用户体验的拍照搜题功能。
