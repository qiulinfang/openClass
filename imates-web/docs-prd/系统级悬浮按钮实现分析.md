# 系统级悬浮按钮实现分析

## 📋 概述

本文档分析当前项目中悬浮按钮的实现方式，并设计系统级悬浮按钮的实现方案，使其功能与MainView中的悬浮按钮一致。

## 🎯 现有实现分析

### 1. MainView中的悬浮按钮（Vue Web实现）

#### 1.1 实现方式
- **位置定位**：使用CSS的`position: fixed`实现悬浮效果
- **拖拽功能**：通过鼠标和触摸事件（`mousedown`、`touchstart`、`mousemove`、`touchmove`）实现
- **样式**：使用Quasar框架的`q-fab`组件

#### 1.2 核心代码结构

**位置状态管理**：
```typescript
const fabPosition = ref({ x: 0, y: 0 })  // 相对右下角的位置
const isDragging = ref(false)
const dragStartPos = ref({ x: 0, y: 0 })
const dragOffset = ref({ x: 0, y: 0 })
const hasMoved = ref(false)
```

**拖拽逻辑**：
- **开始拖动**：记录起始位置和鼠标相对按钮的偏移量
- **拖动中**：计算新位置，限制在视口范围内
- **停止拖动**：重置拖动状态

**功能实现**：
- 草稿本：打开`DraftDialog`对话框
- AI聊天：打开`UnifiedChatDialog`对话框

#### 1.3 特点
- ✅ 只能在应用内显示
- ✅ 需要应用处于前台
- ✅ 实现简单，无需特殊权限
- ❌ 无法跨应用显示
- ❌ 应用切换时不可见

### 2. FloatingRobotService（系统级悬浮按钮）

#### 2.1 实现方式
- **窗口类型**：使用`WindowManager.LayoutParams.TYPE_APPLICATION_OVERLAY`
- **服务类型**：前台Service（Foreground Service）
- **拖拽功能**：通过`MotionEvent`处理触摸事件

#### 2.2 核心代码结构

**WindowManager配置**：
```java
WindowManager.LayoutParams layoutParams = new WindowManager.LayoutParams(
    ViewGroup.LayoutParams.WRAP_CONTENT,
    ViewGroup.LayoutParams.WRAP_CONTENT,
    WindowManager.LayoutParams.TYPE_APPLICATION_OVERLAY,
    WindowManager.LayoutParams.FLAG_NOT_FOCUSABLE,
    PixelFormat.TRANSLUCENT);
```

**拖拽逻辑**：
- **ACTION_DOWN**：记录初始位置和触摸点坐标
- **ACTION_MOVE**：计算偏移量，更新窗口位置
- **ACTION_UP**：判断是否为点击事件（移动距离小于阈值）

**权限要求**：
- `SYSTEM_ALERT_WINDOW`权限（Android 6.0+）
- 通过`Settings.canDrawOverlays()`检查
- 需要用户手动在设置中授权

#### 2.3 特点
- ✅ 可以跨应用显示
- ✅ 应用后台时仍可见
- ✅ 系统级别悬浮
- ❌ 需要特殊权限
- ❌ 实现相对复杂
- ❌ 需要前台服务（显示通知）

## 🔧 设计方案

### 目标
实现一个系统级悬浮按钮，功能与MainView中的悬浮按钮完全一致：
1. 草稿本功能
2. AI聊天功能
3. 可拖拽功能
4. 位置记忆功能

### 实现方案

#### 方案一：扩展现有FloatingRobotService（推荐）

**优点**：
- 复用现有权限和服务框架
- 代码维护成本低
- 可以复用现有的窗口管理逻辑

**实现步骤**：
1. 在`FloatingRobotService`中添加新的悬浮按钮视图
2. 实现与MainView相同的拖拽逻辑
3. 添加草稿本和AI聊天的功能入口
4. 实现位置持久化存储

#### 方案二：创建新的FloatingFabService

**优点**：
- 职责清晰，独立管理
- 不影响现有FloatingRobotService功能
- 便于单独配置和管理

**实现步骤**：
1. 创建新的`FloatingFabService`类
2. 实现与FloatingRobotService类似的窗口管理
3. 实现拖拽和功能逻辑

#### 3. 拖拽功能实现

**触摸事件处理**：
```java
floatingFabView.setOnTouchListener(new View.OnTouchListener() {
    private int initialX;
    private int initialY;
    private float initialTouchX;
    private float initialTouchY;
    
    @Override
    public boolean onTouch(View v, MotionEvent event) {
        switch (event.getAction()) {
            case MotionEvent.ACTION_DOWN:
                // 记录初始位置
                initialX = layoutParams.x;
                initialY = layoutParams.y;
                initialTouchX = event.getRawX();
                initialTouchY = event.getRawY();
                return true;
                
            case MotionEvent.ACTION_MOVE:
                // 计算偏移量
                int offsetX = (int) (event.getRawX() - initialTouchX);
                int offsetY = (int) (event.getRawY() - initialTouchY);
                
                // 限制在屏幕范围内
                int newX = Math.max(0, Math.min(
                    screenWidth - fabWidth, 
                    initialX + offsetX));
                int newY = Math.max(0, Math.min(
                    screenHeight - fabHeight, 
                    initialY + offsetY));
                
                // 更新位置
                layoutParams.x = newX;
                layoutParams.y = newY;
                windowManager.updateViewLayout(floatingFabView, layoutParams);
                return true;
                
            case MotionEvent.ACTION_UP:
                // 判断是否为点击（移动距离小于阈值）
                float deltaX = Math.abs(event.getRawX() - initialTouchX);
                float deltaY = Math.abs(event.getRawY() - initialTouchY);
                if (deltaX < 10 && deltaY < 10) {
                    // 点击事件：展开功能菜单
                    toggleFabMenu();
                } else {
                    // 保存位置
                    saveFabPosition(layoutParams.x, layoutParams.y);
                }
                return true;
        }
        return false;
    }
});
```

#### 5. 位置持久化

**保存位置**：
```java
private void saveFabPosition(int x, int y) {
    SharedPreferences.Editor editor = prefs.edit();
    editor.putInt("fab_x", x);
    editor.putInt("fab_y", y);
    editor.apply();
}
```

**恢复位置**：
```java
private void restoreFabPosition() {
    int x = prefs.getInt("fab_x", defaultX);
    int y = prefs.getInt("fab_y", defaultY);
    layoutParams.x = x;
    layoutParams.y = y;
    windowManager.updateViewLayout(floatingFabView, layoutParams);
}
```

#### 6. 权限检查

**权限检查逻辑**：
```java
private boolean checkOverlayPermission() {
    if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.M) {
        return Settings.canDrawOverlays(this);
    }
    return true;
}
```

**启动服务前检查**：
```java
public static void startService(Context context) {
    if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.M) {
        if (!Settings.canDrawOverlays(context)) {
            // 引导用户去设置页面授权
            Intent intent = new Intent(Settings.ACTION_MANAGE_OVERLAY_PERMISSION,
                    Uri.parse("package:" + context.getPackageName()));
            context.startActivity(intent);
            return;
        }
    }
    
    Intent serviceIntent = new Intent(context, FloatingFabService.class);
    context.startForegroundService(serviceIntent);
}
```

## 🔍 关键点说明

### 1. WindowManager.LayoutParams配置

**TYPE_APPLICATION_OVERLAY**：
- Android 6.0+必须使用此类型
- 需要悬浮窗权限
- 可以跨应用显示

**FLAG_NOT_FOCUSABLE**：
- 按钮不获取焦点，不影响其他应用操作
- 点击时仍可响应触摸事件

**PixelFormat.TRANSLUCENT**：
- 支持透明背景
- 适合悬浮按钮场景

### 2. 拖拽边界限制

**屏幕边界检查**：
```java
int maxX = screenWidth - fabWidth;
int maxY = screenHeight - fabHeight;
layoutParams.x = Math.max(0, Math.min(maxX, newX));
layoutParams.y = Math.max(0, Math.min(maxY, newY));
```

### 3. 点击与拖拽区分

**阈值判断**：
```java
float deltaX = Math.abs(event.getRawX() - initialTouchX);
float deltaY = Math.abs(event.getRawY() - initialTouchY);
if (deltaX < 10 && deltaY < 10) {
    // 点击事件
} else {
    // 拖拽事件
}
```

### 4. 位置坐标系统

**WindowManager坐标**：
- `layoutParams.x`：距离屏幕左边缘的距离
- `layoutParams.y`：距离屏幕顶部的距离
- `gravity`：定位基准点（TOP|START, BOTTOM|END等）

**与MainView的差异**：
- MainView使用`right`和`bottom`（相对右下角）
- WindowManager使用`x`和`y`（绝对坐标）
- 需要进行坐标转换

- 拖拽结束时显示位置提示

## ⚠️ 注意事项

1. **权限管理**：必须在启动服务前检查权限
2. **内存泄漏**：Service销毁时必须移除WindowManager中的View
3. **前台服务**：必须显示通知，否则Android 9.0+会限制服务
4. **性能优化**：避免频繁更新窗口位置，可以添加节流
5. **兼容性**：注意不同Android版本的API差异
