# PRD 文档使用指南

## 📋 概述

本文档说明如何使用和管理 imates-web 项目的 PRD 文档。

## 🎯 PRD 文档的目的

PRD（Product Requirements Document，产品需求文档）文档用于：

1. **项目理解**：帮助团队成员理解每个文件的功能和职责
2. **迁移规划**：为 React Native 迁移提供详细的参考
3. **开发参考**：作为新成员入职和代码重构的参考资料

## 📂 文档结构

PRD 文档目录结构与源码目录结构完全对应：

```
docs-prd/
├── README.md                    # 文档说明
├── 使用指南.md                   # 本文档
├── 项目总体架构.md               # 项目整体架构
├── React-Native-迁移方案.md      # 迁移整体方案
├── 依赖库迁移对照表.md           # 依赖库对照表
├── PRD-模板.md                  # PRD 编写模板
├── generate-prd.js             # PRD 生成脚本
├── 配置文件/                    # 配置文件 PRD
│   ├── package.json.md
│   └── ...
├── 入口文件/                    # 入口文件 PRD
│   ├── src-main.ts.md
│   └── ...
├── 服务层/                      # 服务层 PRD
│   └── src-services-*.md
├── 状态管理/                    # 状态管理 PRD
│   └── src-stores-*.md
├── 组件/                        # 组件 PRD
│   └── src-components-*.md
└── 视图/                        # 视图 PRD
    └── src-views-*.md
```

## 🚀 快速开始

### 1. 自动生成 PRD 框架

使用提供的脚本自动为所有文件生成 PRD 框架：

```bash
cd imates-web/docs-prd
node generate-prd.js
```

**脚本功能**：
- 自动扫描 `src/` 和 `scripts/` 目录
- 为每个文件生成 PRD 文档框架
- 跳过已存在的 PRD 文档
- 自动创建必要的目录结构

**生成的文档**：
- 包含基本信息（文件路径、类型、职责）
- 包含模板结构（功能需求、技术实现、迁移方案等）
- 需要手动补充详细内容

### 2. 手动编写 PRD

如果自动生成的框架不符合需求，可以手动编写：

1. **复制模板**
   ```bash
   cp PRD-模板.md 新的PRD文档.md
   ```

2. **填充内容**
   - 填写文件路径、类型、职责
   - 补充功能需求
   - 补充技术实现细节
   - 补充迁移方案

3. **保存文档**
   - 保存到对应的目录结构中
   - 文件命名：`目录-文件名.md`

## 📝 PRD 文档编写规范

### 1. 必须包含的章节

每个 PRD 文档应包含以下章节：

#### ✅ 概述
- 文件路径
- 文件类型
- 主要职责

#### ✅ 功能需求
- 核心功能点
- 功能边界
- 输入输出

#### ✅ 技术实现
- 依赖关系
- 关键代码逻辑
- 数据流

#### ✅ 迁移到 React Native
- 等价实现
- 需要的第三方库
- 迁移步骤
- 注意事项

#### ✅ 测试要点
- 功能测试场景
- 边界测试场景

#### ✅ 参考资源
- 相关文档链接

### 2. 内容要求

- **准确性**：确保功能描述准确
- **完整性**：覆盖所有主要功能点
- **可操作性**：迁移步骤清晰可执行
- **可读性**：使用清晰的语言和格式

### 3. 格式规范

- 使用 Markdown 格式
- 代码块使用语法高亮
- 使用表格展示对照关系
- 使用列表展示步骤

## 🔍 查找 PRD 文档

### 方法 1：按文件路径查找

PRD 文档路径与源码路径对应：

```
源码路径：src/services/api-service.ts
PRD 路径：docs-prd/服务层/src-services-api-service.ts.md
```

### 方法 2：按功能模块查找

- **路由配置**：`入口文件/src-router-index.ts.md`
- **用户认证**：`状态管理/src-stores-userStore.ts.md`
- **AI 聊天**：`组件/src-components-ChatView.vue.md`
- **知识图谱**：`视图/src-views-KnowledgeGraphView.vue.md`

### 方法 3：使用搜索

在 `docs-prd/` 目录下搜索关键词：

```bash
# 搜索包含 "chat" 的 PRD 文档
grep -r "chat" docs-prd/ --include="*.md"

# 搜索包含 "migration" 的 PRD 文档
grep -r "migration" docs-prd/ --include="*.md"
```

## 🔄 更新和维护

### 何时更新 PRD

- 文件功能发生重大变化
- 添加新的功能模块
- 迁移过程中发现新的问题
- 技术选型发生变化

### 如何更新 PRD

1. **打开对应的 PRD 文档**
2. **更新相关章节**
   - 功能需求发生变化 → 更新"功能需求"章节
   - 技术实现发生变化 → 更新"技术实现"章节
   - 迁移方案发生变化 → 更新"迁移到 React Native"章节
3. **更新文档版本号**
   - 在文档底部更新版本号和更新日期

### 维护检查清单

定期检查以下内容：

- [ ] PRD 文档是否与源码同步
- [ ] 迁移方案是否仍然有效
- [ ] 依赖库对照表是否最新
- [ ] 新文件的 PRD 是否已生成

## ❓ 常见问题

### Q1: 为什么要创建这么多 PRD 文档？

A: PRD 文档帮助我们：
- 全面理解项目结构
- 规划迁移方案
- 为新成员提供参考

### Q2: 是否每个文件都需要 PRD？

A: 建议为核心文件创建 PRD：
- ✅ 配置文件
- ✅ 入口文件
- ✅ 服务层
- ✅ 状态管理
- ✅ 核心组件
- ✅ 页面视图
- ⚠️ 工具函数（可选）
- ⚠️ 类型定义（可选）

### Q3: PRD 文档是否需要与源码同步？

A: 是的，PRD 文档应该：
- 与源码功能保持一致
- 及时更新以反映变化
- 作为源码的有效补充

### Q4: 如何贡献新的 PRD 文档？

A: 
1. 使用脚本生成框架，或复制模板
2. 补充详细内容
3. 提交 Pull Request
4. 代码审查通过后合并
