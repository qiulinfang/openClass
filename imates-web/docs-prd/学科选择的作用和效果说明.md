# 学科选择的作用和效果说明

## 📚 什么是"只能选择学科，不能选择具体老师"

### 当前实现的含义

**"只能选择学科（数学或生物），不能选择具体的老师"** 意思是：

1. ✅ **可以选择学科**：用户可以选择发送消息给**数学老师**或**生物老师**
2. ❌ **不能选择具体老师**：用户**不能选择**具体是哪个老师（比如"张老师"、"李老师"）
3. 🔀 **自动分配**：系统会根据学科**自动分配**给对应的老师处理

---

## 🎯 选择不同学科的效果

### 1. 学科映射关系

当前系统支持两种学科：

| 前端选择 | 后端学科ID | 说明 |
|---------|-----------|------|
| `math` | `"2"` | 数学学科 |
| `biology` | `"6"` | 生物学科 |

**代码位置**：`WebAppInterface.java` 第256-264行

```java
// 第2步：确定学科类型
String teacherSubject;
if ("biology".equals(subject)) {
    teacherSubject = "6"; // SCHOOL_SUBJECT_BIOLOGY
} else if ("math".equals(subject)) {
    teacherSubject = "2"; // SCHOOL_SUBJECT_MATH
} else {
    return createResponse(false, "不支持的学科类型", null);
}
```

---

### 2. 消息发送流程

#### 当前流程（共享队列模式）

```
学生选择学科（math/biology）
    ↓
前端发送消息（包含 subject 参数）
    ↓
Android Bridge 接收（WebAppInterface.java）
    ↓
转换为学科ID（"2" 或 "6"）
    ↓
创建 StudentMessage（包含 subjectId）
    ↓
发送到 RabbitMQ（共享队列）
    ↓
所有老师从共享队列消费
    ↓
老师根据 subjectId 判断是否处理
    ↓
符合条件的老师回复
```

---

### 3. 学科在消息中的位置

#### StudentMessage 数据结构

```java
public class StudentMessage {
    private String userId;        // 学生ID
    private String messageId;      // 消息ID
    private String sessionId;     // 会话ID
    private String subjectId;     // ⭐ 学科ID（"2" 或 "6"）
    private int messageType;      // 消息类型（0=文本，1=语音，2=图片）
    private String content;       // 消息内容
    private long timestamp;       // 时间戳
}
```

**关键字段**：`subjectId` 字段标识了消息属于哪个学科。

---

### 4. RabbitMQ 路由机制

#### 当前实现（共享队列）

```java
// RabbitMQManager.java 第136-157行
public String sendMessageToTeacher(StudentMessage message) {
    // ...
    // 所有消息都发送到同一个共享队列
    channel.basicPublish(
        EXCHANGE_NAME,
        ROUTE_KEY_STUDENT_TO_TEACHER,  // 固定路由键
        properties,
        message.toJsonString().getBytes(StandardCharsets.UTF_8)
    );
    // ...
}
```

**特点**：
- ✅ 所有学科的消息都发送到**同一个队列**：`QUESTION_RECEIVE_QUEUE`
- ✅ 所有老师都从**同一个队列**消费消息
- ✅ 老师根据消息中的 `subjectId` 判断是否处理

---

### 5. 老师端的处理逻辑（推测）

虽然我们看不到老师端的代码，但根据架构推测，老师端应该是：

1. **监听共享队列**：所有老师都监听 `QUESTION_RECEIVE_QUEUE`
2. **读取消息**：从队列中取出消息
3. **判断学科**：检查消息中的 `subjectId` 字段
4. **决定是否处理**：
   - 如果 `subjectId` 匹配自己的学科 → 处理并回复
   - 如果 `subjectId` 不匹配 → 忽略（不处理）

**示例**：
- 数学老师看到 `subjectId = "2"` 的消息 → 处理
- 数学老师看到 `subjectId = "6"` 的消息 → 忽略
- 生物老师看到 `subjectId = "6"` 的消息 → 处理
- 生物老师看到 `subjectId = "2"` 的消息 → 忽略

## ❓ 为什么不能选择具体老师？

### 当前架构的限制

#### 1. 数据结构不支持

**当前 StudentMessage 没有 teacherId 字段**：

```java
public class StudentMessage {
    // ❌ 没有 teacherId 字段
    private String subjectId;  // ✅ 只有学科ID
    // ...
}
```

#### 2. RabbitMQ 路由不支持

**当前使用固定路由键**：

```java
// 所有消息都发送到同一个路由键
ROUTE_KEY_STUDENT_TO_TEACHER = "student_route_teacher"
```

**不支持指定老师的路由**：
- ❌ 没有 `"student_route_teacher_teacher001"` 这样的路由键
- ❌ 没有为每个老师创建独立队列

#### 3. 前端界面不支持

**当前前端没有教师选择界面**：
- ❌ 没有显示教师列表
- ❌ 没有教师选择下拉框
- ❌ 只能选择学科（math/biology）

## 🆚 对比：学科选择 vs 老师选择

### 当前实现（学科选择）

| 特点 | 学科选择 |
|------|---------|
| **选择粒度** | 粗（只能选学科） |
| **路由方式** | 共享队列 + 学科过滤 |
| **消息分配** | 自动分配（哪个老师先处理谁回复） |
| **老师选择** | ❌ 不能选择 |
| **数据结构** | 只有 `subjectId` |
| **RabbitMQ** | 固定路由键 |

### 理想实现（老师选择）

| 特点 | 老师选择 |
|------|---------|
| **选择粒度** | 细（可以选择具体老师） |
| **路由方式** | 独立队列或主题路由 |
| **消息分配** | 指定老师（必须由指定老师回复） |
| **老师选择** | ✅ 可以选择 |
| **数据结构** | 有 `subjectId` + `teacherId` |
| **RabbitMQ** | 动态路由键 |

## 📊 实际使用场景

### 场景1：学生问数学题

**用户操作**：
1. 选择学科：数学
2. 输入问题："这道题怎么做？"
3. 发送消息

**系统处理**：
1. 消息 `subjectId = "2"`（数学）

3. 数学老师看到消息，判断 `subjectId = "2"` → 处理
4. 生物老师看到消息，判断 `subjectId = "6"` → 忽略
5. 数学老师回复

**结果**：✅ 数学老师收到并回复

## 🎯 总结

### 学科选择的作用

1. **消息分类**：标识消息属于哪个学科
2. **路由过滤**：老师根据学科判断是否处理
3. **会话管理**：不同学科的聊天记录分开管理
4. **UI 显示**：界面显示"数学答疑"或"生物答疑"

### 学科选择的限制

1. **不能指定老师**：只能选择学科，不能选择具体老师
2. **自动分配**：系统自动分配给该学科的任意一个老师
3. **共享队列**：所有消息都发送到同一个队列

### 如果要支持选择具体老师

需要改动：
1. ✅ 数据结构：添加 `teacherId` 字段
2. ✅ 路由逻辑：支持动态路由键
3. ✅ 前端界面：添加教师选择功能
4. ✅ 后端 API：提供教师列表接口（可选）
