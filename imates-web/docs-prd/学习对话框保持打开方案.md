# 学习对话框保持打开方案

## 问题描述

用户在 `LearningView` 点击"去学习"按钮后，会跳转到 `PdfViewerView`，但对话框会被关闭。用户希望对话框能够保持打开状态。

## 当前实现

在 `LearningView.vue` 的 `startLearning` 函数中：
```typescript
const startLearning = async (resource: ResourceFile) => {
  // ...
  // 关闭对话框
  localVisible.value = false  // 第433行
  
  // 执行路由跳转
  await router.push({
    name: routeName,
    query: { ... }
  })
}
```

## 解决方案

### 方案1：简单方案 - 不关闭对话框（推荐）

**优点**：实现简单，改动最小  
**缺点**：需要处理 z-index 层级，确保 PDF 查看器在对话框上方

#### 实现步骤

1. **移除关闭对话框的代码**
   - 注释掉或删除 `localVisible.value = false`
   
2. **调整 PDF 查看器的 z-index**
   - 确保 PDF 查看器页面的 z-index 高于对话框（Quasar 对话框默认 z-index 较高）

3. **可选：添加最小化功能**
   - 在对话框上添加最小化按钮
   - 最小化时保持状态，但不显示对话框

#### 代码修改

```typescript
// LearningView.vue - startLearning 函数
const startLearning = async (resource: ResourceFile) => {
  if (!currentScheme.value) {
    console.error('没有选中的学习方案')
    return
  }

  isLoading.value = true

  try {
    const selectedScheme = currentScheme.value
    const routeName = getViewerRouteName(resource.fileName)

    // 不关闭对话框，保持打开状态
    // localVisible.value = false  // 注释掉这行

    // 执行路由跳转
    await router.push({
      name: routeName,
      query: {
        id: id.value,
        textbookName: sectionName.value,
        resourceId: resource.id,
        fileName: resource.fileName,
        packageId: selectedScheme.id,
        packageName: selectedScheme.packageName,
        fromLearning: 'true',
        learningNodeId: sectionId.value,
        learningLevel: props.level?.toString() || '1',
      },
    })

    // 标记节点为已学习
    if (sectionId.value && sectionId.value.trim() !== '') {
      markNodeAsLearned(sectionId.value)
    }
  } catch (error) {
    console.error('开始学习失败:', error)
  } finally {
    isLoading.value = false
  }
}
```

#### 样式调整（如果需要）

```css
/* PdfViewerView.vue 或全局样式 */
.content-layout {
  position: relative;
  z-index: 3000; /* 确保高于对话框的 z-index */
}
```

### 方案2：全局状态管理方案

**优点**：状态管理清晰，支持多页面共享  
**缺点**：需要创建新的 store，改动较大

#### 实现步骤

1. **创建/更新 UI Store**
   ```typescript
   // stores/uiStore.ts
   export const useUIStore = defineStore('ui', {
     state: () => ({
       learningDialogVisible: false,
       learningDialogData: null as {
         nodeId: string
         sectionName: string
         level: number
         textbookId: string
       } | null,
       // 是否在查看器中保持对话框打开
       keepLearningDialogOpen: false
     }),
     actions: {
       openLearningDialog(data: { nodeId: string, sectionName: string, level: number, textbookId: string }) {
         this.learningDialogData = data
         this.learningDialogVisible = true
       },
       closeLearningDialog() {
         this.learningDialogVisible = false
         this.learningDialogData = null
       },
       setKeepDialogOpen(keep: boolean) {
         this.keepLearningDialogOpen = keep
       }
     }
   })
   ```

2. **修改 LearningView**
   ```typescript
   const startLearning = async (resource: ResourceFile) => {
     // ...
     const uiStore = useUIStore()
     
     // 根据配置决定是否关闭
     if (!uiStore.keepLearningDialogOpen) {
       localVisible.value = false
     }
     // ...
   }
   ```

3. **修改 KnowledgeGraphView**
   ```typescript
   import { useUIStore } from '@/stores/uiStore'
   
   const uiStore = useUIStore()
   const learningDialogVisible = computed({
     get: () => uiStore.learningDialogVisible,
     set: (value) => {
       if (!value && !uiStore.keepLearningDialogOpen) {
         uiStore.closeLearningDialog()
       }
     }
   })
   ```

### 方案3：最小化/隐藏方案

**优点**：对话框状态保持，但视觉上不遮挡  
**缺点**：需要修改 Modal 组件，增加复杂度

#### 实现步骤

1. **扩展 DraggableDialog 组件**
   - 添加 `minimized` prop
   - 添加最小化状态样式
   - 添加最小化按钮

2. **修改 LearningView**
   ```typescript
   const isMinimized = ref(false)
   
   const startLearning = async (resource: ResourceFile) => {
     // ...
     // 最小化对话框而不是关闭
     isMinimized.value = true
     // ...
   }
   ```

3. **传递 minimized prop 给 DraggableDialog**
   ```vue
   <DraggableDialog
     v-model="localVisible"
     :minimized="isMinimized"
     ...
   >
   ```

### 方案4：路由守卫方案

**优点**：利用路由系统管理状态  
**缺点**：需要修改路由配置，逻辑较复杂

#### 实现步骤

1. **在路由守卫中保存对话框状态**
   ```typescript
   router.beforeEach((to, from, next) => {
     if (from.name === 'knowledgeGraph' && to.name === 'pdfViewer') {
       // 保存对话框状态到 sessionStorage
       const dialogState = {
         visible: learningDialogVisible.value,
         data: learningDialogData.value
       }
       sessionStorage.setItem('learningDialogState', JSON.stringify(dialogState))
     }
     next()
   })
   ```

2. **在路由返回时恢复状态**
   ```typescript
   router.afterEach((to, from) => {
     if (from.name === 'pdfViewer' && to.name === 'knowledgeGraph') {
       const savedState = sessionStorage.getItem('learningDialogState')
       if (savedState) {
         const { visible, data } = JSON.parse(savedState)
         if (visible && data) {
           learningDialogVisible.value = true
           learningDialogData.value = data
         }
         sessionStorage.removeItem('learningDialogState')
       }
     }
   })
   ```

## 推荐方案对比

| 方案 | 实现难度 | 用户体验 | 代码改动 | 维护成本 |
|------|---------|---------|---------|---------|
| 方案1：不关闭 | ⭐ 简单 | ⭐⭐⭐ 好 | ⭐ 最小 | ⭐ 低 |
| 方案2：全局状态 | ⭐⭐ 中等 | ⭐⭐⭐⭐ 很好 | ⭐⭐⭐ 较大 | ⭐⭐ 中等 |
| 方案3：最小化 | ⭐⭐⭐ 复杂 | ⭐⭐⭐⭐⭐ 最好 | ⭐⭐⭐⭐ 很大 | ⭐⭐⭐ 较高 |
| 方案4：路由守卫 | ⭐⭐ 中等 | ⭐⭐⭐ 好 | ⭐⭐ 中等 | ⭐⭐ 中等 |

## 最终推荐

**推荐使用方案1（简单方案）**，理由：
1. 实现简单，改动最小
2. 用户体验良好（对话框保持打开，可以继续查看其他资源）
3. 维护成本低
4. 如果后续需要更复杂的功能，可以在此基础上扩展

如果需要更精细的控制（如最小化功能），可以后续升级到方案3。

### 注意事项

1. **z-index 层级**：PDF 查看器页面应该已经覆盖在对话框上方（Quasar 路由视图默认 z-index 较高）
2. **对话框交互**：用户仍然可以手动关闭对话框
3. **返回逻辑**：从 PDF 查看器返回时，如果路由参数中有 `fromLearning: 'true'`，会重新打开对话框（现有逻辑已支持）

### 测试要点

1. ✅ 点击"去学习"后，对话框保持打开
2. ✅ PDF 查看器正常显示，可以正常操作
3. ✅ 从 PDF 查看器返回时，对话框状态正确恢复
4. ✅ 用户可以手动关闭对话框
5. ✅ 对话框不会遮挡 PDF 查看器的操作
