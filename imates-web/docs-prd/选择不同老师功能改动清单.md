```java
// 当前代码（第136行）
public String sendMessageToTeacher(StudentMessage message)
        throws IOException, JSONException, IllegalStateException {
    // ...
    channel.basicPublish(
        EXCHANGE_NAME,
        ROUTE_KEY_STUDENT_TO_TEACHER,  // 固定路由键
        properties,
        message.toJsonString().getBytes(StandardCharsets.UTF_8)
    );
    // ...
}

// 修改后
public String sendMessageToTeacher(StudentMessage message)
        throws IOException, JSONException, IllegalStateException {
    // ...
    
    // 根据 teacherId 选择路由键
    String routeKey;
    if (message.getTeacherId() != null && !message.getTeacherId().isEmpty()) {
        // 指定了老师，使用特定路由键
        routeKey = "student_route_teacher_" + message.getTeacherId();
        
        // 确保老师队列存在（动态创建）
        String teacherQueueName = "teacher_" + message.getTeacherId() + "_q";
        channel.queueDeclare(teacherQueueName, true, false, false, null);
        channel.queueBind(teacherQueueName, EXCHANGE_NAME, routeKey);
    } else {
        // 未指定老师，使用共享队列
        routeKey = ROUTE_KEY_STUDENT_TO_TEACHER;
    }
    
    channel.basicPublish(
        EXCHANGE_NAME,
        routeKey,  // 动态路由键
        properties,
        message.toJsonString().getBytes(StandardCharsets.UTF_8)
    );
    // ...
}
```

**优点**：
- 改动最小，风险低
- 向后兼容（不传 `teacherId` 时使用共享队列）
- 可以先不改 UI，只改底层逻辑

**缺点**：
- 用户无法选择老师（只能通过代码指定）
- 需要后续再补 UI 改动

## 📝 注意事项

1. **向后兼容**：
   - `teacherId` 应该是可选参数
   - 不传 `teacherId` 时，使用原有的共享队列模式

2. **数据迁移**：
   - 已有会话不需要 `teacherId` 字段
   - 新会话可以选择性添加 `teacherId`

3. **错误处理**：
   - 如果指定的老师不存在，如何处理？
   - 建议：回退到共享队列模式

4. **测试要点**：
   - 不传 `teacherId`：使用共享队列（原有功能）
   - 传 `teacherId`：使用特定老师队列（新功能）
   - 传无效 `teacherId`：错误处理

## ✅ 总结

**是的，前后端都需要改动**，但可以通过**渐进式改造**和**向后兼容**设计，降低改动风险。

**建议**：
1. 先改数据结构（阶段1）
2. 再改功能逻辑（阶段2）
