### 1.1 会话匹配场景

#### ✅ 场景1：消息属于当前会话
**描述**：学生正在查看该会话，收到老师回复  
**处理方式**：
- 直接处理消息，添加到消息列表
- 显示全局通知
- 保存聊天历史

**代码位置**：`teacherChatStore.ts:1028`

**核心代码逻辑**：
```typescript
// 第1步：检查消息是否属于当前会话
const isCurrentSession = currentSession.value?.sessionId === data.sessionId

// 第2步：显示全局通知（无论是否在当前会话）
let notificationText = ''
if (data.messageType === 'IMAGE') {
  notificationText = '收到老师发送的图片'
} else if (data.messageType === 'VOICE') {
  notificationText = '收到老师发送的语音'
} else {
  // 文本消息，显示内容预览（最多50个字符）
  const contentPreview = data.content?.substring(0, 50) || ''
  notificationText = contentPreview.length >= 50 ? `${contentPreview}...` : contentPreview
}

// 如果不在当前会话，添加提示

  notificationText = `[其他会话] ${notificationText}`
}

showMessage(notificationText, 'info', 3000)

// 第3步：如果消息属于当前会话，直接处理消息（跳过会话恢复逻辑）
// 继续执行后续的消息处理逻辑（1100行之后）
```

**执行流程**：
1. ✅ 比较 `currentSession.value?.sessionId` 与 `data.sessionId`
2. ✅ 如果匹配，`isCurrentSession = true`
3. ✅ 显示通知（不添加"[其他会话]"前缀）
4. ✅ 跳过会话恢复逻辑（1059-1098行）
5. ✅ 直接进入消息处理逻辑（1100行之后）

#### ✅ 场景2：消息不属于当前会话 - 会话存在于localStorage
**描述**：学生切换到其他会话，但收到之前会话的回复  
**处理方式**：
- 从localStorage恢复会话数据
- 设置为当前会话
- 触发`teacher-session-restored`事件
- 继续处理消息

**代码位置**：`teacherChatStore.ts:1065-1085`

**核心代码逻辑**：
```typescript
// 第1步：检查消息不属于当前会话
if (!isCurrentSession) {
  // 第2步：尝试从 localStorage 恢复会话
  const userId = getCurrentUserIdOrDefault()
  const sessionKey = `${userId}_teacher_chat_${data.sessionId}_session`
  const sessionData = localStorage.getItem(sessionKey)
  
  // 第3步：如果会话数据存在
  if (sessionData) {
    try {
      // 解析会话数据
      const restoredSession = JSON.parse(sessionData) as TeacherSession
      
      // 设置为当前会话
      currentSession.value = restoredSession
      
      // 触发自定义事件，通知组件刷新会话列表
      window.dispatchEvent(new CustomEvent('teacher-session-restored', {
        detail: { sessionId: restoredSession.sessionId, session: restoredSession }
      }))
      
      // 恢复会话后，继续处理消息（不返回）
      // 继续执行后续的消息处理逻辑
    } catch (error) {
      // 解析失败，降级到场景3：创建新会话
      console.error('[TeacherStore] ❌ 解析会话数据失败:', error)
      await createOrRestoreSessionForMessage(data.sessionId)
    }
  }
}
```

**执行流程**：
1. ✅ 检测到 `isCurrentSession = false`
2. ✅ 构建localStorage键名：`${userId}_teacher_chat_${sessionId}_session`
3. ✅ 从localStorage读取会话数据
4. ✅ 如果数据存在，解析JSON
5. ✅ 将解析的会话设置为当前会话：`currentSession.value = restoredSession`
6. ✅ 触发 `teacher-session-restored` 事件，通知UI组件刷新
7. ✅ 继续处理消息（不返回，执行1100行之后的消息处理逻辑）

**关键点**：
- ✅ **sessionKey格式一致性**：恢复会话使用的sessionKey格式为 `${userId}_teacher_chat_${sessionId}_session`，与创建会话时使用的格式完全一致（见场景3的710行），确保能够正确读取之前保存的会话数据
- 使用用户ID + sessionId 作为存储键，确保多用户隔离
- 解析失败时降级到场景3（创建新会话）
- 事件通知机制确保UI及时更新会话列表

#### ✅ 场景3：消息不属于当前会话 - 会话不存在
**描述**：学生删除了会话，但老师仍在回复  
**处理方式**：
- 调用`createOrRestoreSessionForMessage`创建新会话
- 使用默认科目（从localStorage获取或默认math）
- 加载聊天历史（如果存在）
- 继续处理消息

**核心代码逻辑**：

**调用处（1086-1089行）**：

**实现函数（678-735行）**：
```typescript
const createOrRestoreSessionForMessage = async (sessionId: string): Promise<void> => {
  try {
    // 第1步：确定科目和会话名称（默认值）
    let subject: 'biology' | 'math' = 'math' // 默认使用数学
    let sessionName = '老师答疑'
    
    // 第2步：尝试从 localStorage 获取最后使用的科目
    try {
      const userId = getCurrentUserIdOrDefault()
      const storedSubject = localStorage.getItem(`${userId}_currentTeacherSubject`)
      if (storedSubject === 'BIOLOGY') {
        subject = 'biology'
        sessionName = '生物答疑'
      } else if (storedSubject === 'MATH') {
        subject = 'math'
        sessionName = '数学答疑'
      }
    } catch (error) {
      console.warn('[TeacherStore] ⚠️ 获取科目信息失败，使用默认值:', error)
    }
    
    // 第3步：创建新会话对象
    const newSession: TeacherSession = {
      sessionId: sessionId,
      sessionName: sessionName,
      subject: subject,
      createTime: Date.now()
    }
    
    // 第4步：保存到 localStorage
    const userId = getCurrentUserIdOrDefault()
    const storageKey = `${userId}_teacher_chat_${sessionId}_session`
    localStorage.setItem(storageKey, JSON.stringify(newSession))
    
    // 第5步：设置为当前会话
    currentSession.value = newSession
    
    // 第6步：加载聊天历史（如果存在）
    try {
      await loadChatHistory(sessionId)
    } catch (error) {
      console.warn('[TeacherStore] ⚠️ 加载聊天历史失败（可能是新会话）:', error)
    }
    
    // 第7步：触发自定义事件，通知组件刷新会话列表
    try {
      window.dispatchEvent(new CustomEvent('teacher-session-restored', {
        detail: { sessionId, session: newSession }
      }))
    } catch (error) {
      console.warn('[TeacherStore] ⚠️ 触发事件失败:', error)
    }
  } catch (error) {
    console.error('[TeacherStore] ❌ 创建或恢复会话失败:', error)
    throw error
  }
}
```

**执行流程**：
1. ✅ 检测到localStorage中没有会话数据
2. ✅ 调用 `createOrRestoreSessionForMessage(sessionId)`
3. ✅ 尝试从localStorage获取用户最后使用的科目（`${userId}_currentTeacherSubject`）
4. ✅ 如果获取失败，使用默认值：`subject = 'math'`, `sessionName = '老师答疑'`
5. ✅ 创建新会话对象，包含：`sessionId`, `sessionName`, `subject`, `createTime`
6. ✅ 保存到localStorage：`${userId}_teacher_chat_${sessionId}_session`
7. ✅ 设置为当前会话：`currentSession.value = newSession`
8. ✅ 尝试加载聊天历史（如果IndexedDB中有历史记录）
9. ✅ 触发 `teacher-session-restored` 事件
10. ✅ 返回调用处，继续处理消息

**关键点**：
- ✅ **sessionKey格式一致性**：创建会话使用的storageKey格式为 `${userId}_teacher_chat_${sessionId}_session`，与恢复会话时使用的格式完全一致（见场景2的1062行），确保后续能够正确恢复会话
- 使用用户最后使用的科目作为默认值，提升用户体验
- 即使创建新会话，也会尝试加载历史记录（可能之前有消息但会话被删除）
- 创建失败会抛出异常，触发场景4的处理

#### ✅ 场景4：会话恢复失败
**描述**：无法恢复或创建会话  
**处理方式**：
- 标记为未读消息
- 不添加到消息列表
- 返回，不继续处理

**代码位置**：`teacherChatStore.ts:1091-1097`

**核心代码逻辑**：
```typescript
// 第1步：如果恢复/创建后仍然不是当前会话
if (currentSession.value?.sessionId !== data.sessionId) {
  // 第2步：标记为未读消息
  const unreadStore = useUnreadMessageStore()
  const unreadKey = `teacher_${data.sessionId}`
  unreadStore.markUnread(unreadKey)
  
  // 第3步：返回，不继续处理消息
  return
}
```

**执行流程**：
1. ✅ 在场景2或场景3执行后，再次检查会话是否恢复成功
2. ✅ 如果 `currentSession.value?.sessionId !== data.sessionId`，说明恢复失败
3. ✅ 使用未读消息Store标记该会话有未读消息
4. ✅ 构建未读键名：`teacher_${sessionId}`
5. ✅ 调用 `unreadStore.markUnread(unreadKey)` 标记未读
6. ✅ **直接返回**，不执行后续的消息处理逻辑（1100行之后）

**触发条件**：
- 场景2：localStorage数据解析失败，且创建新会话也失败
- 场景3：`createOrRestoreSessionForMessage` 抛出异常
- 其他异常情况：localStorage写入失败、内存不足等

**关键点**：
- 使用防御性编程，即使恢复失败也不影响应用稳定性
- 标记未读确保用户不会丢失消息（可以在会话列表中看到未读提示）
- 直接返回避免处理无效消息，防止UI错误

### 2.2 网络和连接场景

#### ❌ 场景21：网络断开后恢复
**描述**：学生网络断开，恢复后收到消息  
**当前状态**：

- ❌ **遗漏**：没有明确的网络状态提示

- ❌ **遗漏**：Web端没有明确的连接状态提示
- ❌ **遗漏**：没有显示"连接断开，正在重连"的提示

### 2.3 消息顺序和重复场景

#### ❌ 场景23：多条消息同时到达
**描述**：老师快速发送多条消息，几乎同时到达  
**当前状态**：
- ✅ 每条消息独立处理
- ❌ **遗漏**：没有消息去重机制（如果messageId重复）
- ❌ **遗漏**：没有消息排序机制（如果时间戳异常）

**建议**：
- 检查messageId是否已存在
- 按时间戳排序消息
- 处理时间戳异常的情况

#### ❌ 场景24：消息重复接收
**描述**：同一条消息被接收多次（RabbitMQ重复投递）  
**当前状态**：
- ❌ **遗漏**：没有消息去重检查
- ❌ **遗漏**：如果messageId重复，会添加多条相同消息

**建议**：
- 检查messageId是否已存在
- 如果已存在，忽略重复消息
- 记录重复消息日志

#### ❌ 场景25：消息时间戳异常
**描述**：消息时间戳是未来时间或过去很久的时间  
**当前状态**：
- ✅ 直接使用时间戳
- ❌ **遗漏**：没有验证时间戳合理性
- ❌ **遗漏**：未来时间戳会导致消息排序错误

**建议**：
- 验证时间戳范围（不能是未来时间）
- 如果时间戳异常，使用当前时间
- 记录异常日志

- 记录异常日志

- 捕获存储异常
- 显示存储空间不足提示
