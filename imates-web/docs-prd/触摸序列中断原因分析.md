# 触摸序列中断原因分析

## 问题描述

在触摸移动期间，当知识图谱收缩时，触摸序列会中断，导致旋转操作无法持续进行。

## 根本原因分析

### 1. 触摸事件监听位置

触摸事件监听器绑定在 `viewport-clipper` 容器上：

```vue
<div class="viewport-clipper"
  @touchstart="handleTouchStart"
  @touchmove="handleTouchMove"
  @touchend="handleTouchEnd"
>
```

**✅ 优点**：理论上，即使子元素（圆周节点）被移除或隐藏，触摸事件仍然会被容器捕获。

### 2. 圆周节点的渲染方式

圆周节点使用 `v-for` 渲染，**不会从 DOM 中移除**：

```vue
<GraphNode
  v-for="(child, index) in getCircularNodes(chapterDetails)" 
  :key="child.id"
  type="circular"
  :show="isExpanded || hasExpandedGraph"
/>
```

**关键点**：节点始终存在于 DOM 中，只是通过 CSS 动画控制显示/隐藏。

### 3. 收缩时的 DOM/CSS 变化

当 `setCurrentChapterExpandedGraph(null)` 被调用时：

1. **状态变化**：
   - `isExpanded` 变为 `false`
   - `hasExpandedGraph` 变为 `false`
   - `show` prop 变为 `false`

2. **动画状态变化**：
   ```javascript
   // KnowledgeGraph.vue 第 241-247 行
   else if (!newIsExpanded && oldIsExpanded) {
     animationState.value = 'collapsing'
     setTimeout(() => {
       animationState.value = 'idle'
     }, animationDuration)
   }
   ```

3. **CSS 类应用**：
   ```css
   /* GraphNode.vue 第 1007-1009 行 */
   .graph-node--circular.node-exit {
     animation: node-exit var(--node-animation-duration, 0.6s) forwards;
   }
   
   /* 动画效果 */
   @keyframes node-exit {
     0% { opacity: 1; transform: scale(1); }
     100% { opacity: 0; transform: scale(0); }
   }
   ```

### 4. 触摸序列中断的具体原因

#### 原因 1：触摸目标的可交互区域变化

当圆周节点执行 `node-exit` 动画时：
- `transform: scale(0)` 使节点缩小到几乎不可见
- `opacity: 0` 使节点完全透明

**问题**：虽然节点仍在 DOM 中，但：
- 节点的实际渲染尺寸变为 0 或非常小
- 浏览器可能认为触摸点不再"覆盖"该节点
- 触摸事件的目标可能在动画期间发生变化

#### 原因 2：事件目标元素的变化

在 `handleTouchMove` 中：

```javascript
const target = event.target as HTMLElement
const isOnCircularNode = target?.closest('.graph-node--circular') !== null
```

**问题**：
- 当节点缩小到 `scale(0)` 时，`event.target` 可能从节点元素变为容器元素
- 这会导致 `isOnCircularNode` 的判断结果发生变化
- 可能影响后续的逻辑处理

#### 原因 3：requestAnimationFrame 的时机问题

当前实现：

```javascript
requestAnimationFrame(() => {
  if (getCurrentChapterExpandedGraph() === expandedGraphId) {
    setCurrentChapterExpandedGraph(null)
  }
})
```

**问题**：
- `requestAnimationFrame` 会在下一帧执行收缩
- 但在执行时，用户可能仍在快速拖动
- 动画状态变化会触发 CSS 类的应用，导致节点立即开始缩小
- 即使触摸事件在容器上监听，节点缩小也会影响触摸点的视觉反馈

#### 原因 4：浏览器触摸事件处理机制

浏览器的触摸事件处理机制：
1. 触摸开始时，浏览器会记录触摸目标元素
2. 在触摸移动期间，如果目标元素发生变化（如尺寸变为 0），浏览器可能会：
   - 重新计算触摸目标
   - 触发 `touchcancel` 事件
   - 中断当前的触摸序列

**关键点**：即使触摸事件在容器上监听，**如果触摸开始时触摸点在节点上，浏览器仍然会记录节点作为初始目标**。

### 5. 为什么使用 requestAnimationFrame 还不够？

虽然 `requestAnimationFrame` 可以延迟 DOM 操作的执行，但：

1. **CSS 动画立即生效**：一旦 `animationState` 变为 `collapsing`，CSS 类 `node-exit` 会立即应用，动画立即开始
2. **动画持续时间**：收缩动画通常需要 0.6-0.8 秒，在这期间节点会持续缩小
3. **触摸目标变化**：即使节点没有从 DOM 中移除，其可交互区域也会在动画期间持续缩小

### 6. 真正的根本原因：浏览器触摸事件目标跟踪机制

**关键发现**：根据浏览器触摸事件处理机制：

> **即使触摸事件监听器绑定在父容器上，浏览器仍会根据触摸开始时的目标元素（`event.target`）来处理事件。当该目标元素在触摸过程中尺寸变为 0 或变得不可交互时，浏览器可能无法继续将事件分派给原始目标，从而导致触摸序列中断。**

#### 6.1 核心误解澄清

❌ **错误假设**：
> "只要 `@touchmove` 绑定在父容器上，无论子元素如何变化，触摸移动都应持续触发。"

✅ **实际机制**：
- 触摸开始 (`touchstart`) 时，浏览器会锁定一个「触摸目标」（touch target）
- 后续的 `touchmove` / `touchend` 事件虽然冒泡到监听器所在元素，但其 `event.target` 仍反映当前物理位置下的实际 DOM 元素
- **更重要的是**：如果初始触摸目标在动画中变得"不可交互"（如尺寸为 0、`opacity: 0`、`pointer-events: none`），浏览器可能主动中断触摸序列，触发 `touchcancel`

#### 6.2 浏览器触摸事件的底层行为

**1. 触摸目标（Touch Target）的确定**

- 在 `touchstart` 触发时，浏览器根据触摸坐标，选择最顶层的可交互元素作为 touch target
- 即使你的监听器在 `.viewport-clipper` 上，如果用户手指点在 `.graph-node--circular` 上，那么 `event.target` 就是该节点
- 浏览器内部会记录这个初始 target，并用于后续的"一致性检查"

**2. 触摸序列的连续性依赖于目标元素的"存在感"**

如果该 target 元素在 `touchmove` 期间：
- 被 `display: none`
- `transform: scale(0)` → 实际 hit area 为 0
- `opacity: 0` + `pointer-events: none`
- 从 DOM 中移除（虽然你没移除，但视觉上等效）

**浏览器可能认为"用户已经离开了有效交互区域"，从而主动派发 `touchcancel` 并终止序列。**

📌 **关键点**：即使事件监听器在父容器上，触摸序列的完整性仍依赖于初始触摸目标的"可交互状态"是否维持。

这在 **W3C Touch Events Level 2** 中有隐含逻辑：浏览器需保证触摸上下文的一致性。

#### 6.3 为什么"监听在父容器"还不够？

| 条件 | 是否足够 |
|------|---------|
| 监听器在父容器 | ✅ 事件能冒泡到 |
| 子元素仍在 DOM | ✅ 技术上存在 |
| 子元素 hit area = 0 | ❌ 浏览器认为"目标消失" |
| 子元素 opacity=0 + scale=0 | ❌ 视觉+交互双重消失 |
| 初始 touch target 不再"有效" | ❌ 触发 `touchcancel` |

👉 **结论**：触摸序列的维持不仅依赖事件监听位置，更依赖初始触摸目标在整个过程中保持"可交互状态"。

1. **wasCancelled**：是否触发了 `touchcancel` 事件

2. **wasInterrupted**：是否检测到中断迹象
   - `⚠️ 是`：检测到目标变化或节点尺寸变化
   - `✅ 否`：未检测到中断迹象

3. **collapseTriggered**：是否在触摸期间触发了收缩

4. **collapseDelay**：收缩触发延迟

5. **nodeScaleChanges**：节点尺寸变化次数
   - `> 0`：表示节点在触摸期间发生了尺寸变化
   - `= 0`：表示节点尺寸保持稳定

6. **targetChanges**：目标元素变化次数
   - `> 0`：表示触摸目标在序列期间发生了变化
   - `= 0`：表示触摸目标保持稳定

## 解决方案建议

### 方案 1：视觉缩小但保持 DOM 不变（⭐ 已实现）

**核心思路**：节点保留在 DOM 中，使用 CSS `transform: scale()` 实现视觉缩小，但通过 `pointer-events: none` 避免影响触摸事件。触摸事件在容器上监听，不会因为节点缩小而中断。

**实现方案**：

```css
/* 修改退出动画，实现视觉缩小 */
@keyframes node-exit {
  0% { 
    opacity: 1; 
    transform: scale(1);
  }
  100% { 
    opacity: 0; 
    /* 视觉上缩小到几乎消失，但 DOM 保持不变 */
    transform: scale(0.3);
  }
}

.graph-node--circular.node-exit {
  animation: node-exit var(--node-animation-duration, 0.6s) forwards;
  /* 禁用触摸事件拦截，确保触摸事件由容器捕获 */
  pointer-events: none;
}

/* 当节点处于退出动画时，整个 wrapper 也禁用 pointer-events */
.node-wrapper--circular:has(.graph-node--circular.node-exit) {
  pointer-events: none;
}
```

**为什么这样可以工作**：
1. **触摸事件在容器上监听**：触摸事件在 `viewport-clipper` 容器上监听（`KnowledgeGraphView.vue` 第 149-152 行），而不是在节点上
2. **节点保留在 DOM 中**：节点不会被移除，只是视觉上变小
3. **pointer-events: none**：确保缩小的节点不会拦截触摸事件，触摸事件会穿透到容器
4. **DOM 结构不变**：触摸目标元素（容器）保持不变，不会触发 `touchcancel`

**优点**：
- ✅ 有视觉上的缩小效果（scale + opacity）
- ✅ 节点保留在 DOM 中，DOM 结构不变
- ✅ 触摸事件不会被节点拦截（`pointer-events: none`）
- ✅ 触摸序列完整，不会中断

**代码位置**：
- 动画定义：`GraphNode.vue` 第 969-980 行
- pointer-events 规则：`GraphNode.vue` 第 1014-1018 行、第 600-602 行

### 方案 2：延迟动画状态变化

在触摸移动期间，不立即改变动画状态，而是延迟到触摸结束后：

```javascript
const shouldCollapseOnTouchEnd = ref(false)

const handleTouchMove = (event: TouchEvent) => {
  // ... 旋转逻辑 ...
  
  // 标记需要收缩，但不立即改变动画状态
  const expandedGraphId = getCurrentChapterExpandedGraph()
  if (expandedGraphId !== null && !shouldCollapseOnTouchEnd.value) {
    shouldCollapseOnTouchEnd.value = true
    // 不立即调用 setCurrentChapterExpandedGraph(null)
  }
}

const handleTouchEnd = () => {
  // 触摸结束后再执行收缩
  if (shouldCollapseOnTouchEnd.value) {
    setCurrentChapterExpandedGraph(null)
    shouldCollapseOnTouchEnd.value = false
  }
}
```

**优点**：确保触摸序列完成后再执行收缩，避免中断。

**缺点**：收缩会在触摸结束后才执行，可能不符合"触摸时收缩"的需求。

### 方案 3：监听 touchcancel 并恢复触摸处理

监听 `touchcancel` 事件，当触摸序列被中断时，尝试恢复：

```javascript
const handleTouchCancel = (event: TouchEvent) => {
  console.warn('⚠️ touchcancel 触发，触摸序列被中断')
  // 可以尝试恢复触摸处理，但通常无法完全恢复
}

// 在模板中添加
<div class="viewport-clipper"
  @touchstart="handleTouchStart"
  @touchmove="handleTouchMove"
  @touchend="handleTouchEnd"
  @touchcancel="handleTouchCancel"
>
```

**优点**：可以检测到触摸序列中断。

**缺点**：无法真正解决问题，只能检测到问题发生。

### 方案 4：使用 CSS `will-change` 优化

优化动画性能，减少浏览器重新计算触摸目标：

```css
.graph-node--circular {
  will-change: transform, opacity;
}
```

**优点**：浏览器可以提前优化，减少重绘和重排。

**缺点**：不能完全解决触摸序列中断的问题，只能优化性能。

## 推荐方案

**推荐使用方案 1（在收缩期间保持节点尺寸不变）**，因为：

1. ✅ **唯一能同时满足"触摸时收缩"和"触摸序列不中断"的方案**
2. ✅ 节点边界框保持原尺寸，浏览器不会认为触摸目标失效
3. ✅ 触摸序列不会被中断
4. ✅ 视觉上仍然会淡出（通过 opacity），虽然不会缩小，但可以接受

**如果必须要求节点缩小效果**，可以考虑方案 2（延迟动画状态变化），但这样收缩会在触摸结束后才执行，可能不符合"触摸时收缩"的需求。

**关键理解**：这是浏览器触摸事件处理机制的限制，无法通过代码绕过。唯一的解决方案是在触摸期间保持目标元素的尺寸不变。
