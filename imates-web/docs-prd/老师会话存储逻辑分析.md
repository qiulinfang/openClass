# 老师会话存储逻辑分析

## 概述

老师会话的存储采用**双存储机制**：
1. **会话信息**（元数据）存储在 `localStorage`
2. **聊天历史**（消息内容）存储在 `IndexedDB`（优先）或 `localStorage`（降级）

## 一、会话信息存储（localStorage）

### 1.1 存储键名格式

```
${userId}_teacher_chat_${sessionId}_session
```

**示例：**
```
user123_teacher_chat_teacher-abc123-1234567890_session
```

### 1.2 存储位置

- **存储方式**：`localStorage`
- **原因**：会话信息数据量小，访问频繁，适合同步存储

### 1.3 数据结构

```typescript
interface TeacherSession {
  sessionId: string      // 会话ID，格式：teacher-{hash}-{timestamp}
  sessionName: string    // 会话名称，如"数学答疑"、"生物答疑"
  subject: string       // 科目：'biology' | 'math'
  createTime: number     // 创建时间戳（毫秒）
}
```

### 1.4 存储操作

#### 创建/保存会话

**位置**：`teacherChatStore.ts` - `createTeacherSession()`

```typescript
// 第4步：保存到localStorage（加上用户ID前缀）
const userId = getCurrentUserIdOrDefault()
const storageKey = `${userId}_teacher_chat_${session.sessionId}_session`
localStorage.setItem(storageKey, JSON.stringify(session))
```

#### 加载会话列表

**位置**：多个组件中（`TeacherChatDialog.vue`, `UnifiedChatDialog.vue`, `ChatView.vue`）

```typescript
const userId = getCurrentUserIdOrDefault()
const sessionPrefix = `${userId}_teacher_chat_`

// 遍历localStorage查找所有教师会话
for (let i = 0; i < localStorage.length; i++) {
  const key = localStorage.key(i)
  if (key?.startsWith(sessionPrefix) && key.endsWith('_session')) {
    const sessionData = localStorage.getItem(key)
    const session = JSON.parse(sessionData) as TeacherSession
    // ... 处理会话
  }
}
```

#### 删除会话

**位置**：`teacherChatStore.ts` - `clearChatHistory()`

```typescript
const userId = getCurrentUserIdOrDefault()
const storageKey = `teacher_chat_${sessionId}`
localStorage.removeItem(`${userId}_${storageKey}_session`)
```

### 1.5 去重机制

加载会话列表时会进行去重处理：

1. **检查重复 sessionId**：使用 `Set` 记录已处理的 `sessionId`
2. **验证键名匹配**：确保键名格式为 `${userId}_teacher_chat_${sessionId}_session`
3. **清理无效数据**：删除键名不匹配的旧数据

## 二、聊天历史存储（IndexedDB/localStorage）

### 2.1 存储键名格式

**传入的键名**（在 `teacherChatStore` 中）：
```
teacher_chat_${sessionId}
```

**实际存储键名**（在 `asyncStorage` 内部处理）：
```
${userId}_chat_history_teacher_chat_${sessionId}
```

**说明**：`asyncStorage.saveChatHistory()` 方法会自动添加 `${userId}_chat_history_` 前缀

### 2.2 存储位置

- **优先**：`IndexedDB`（通过 `localforage`）
- **降级**：`localStorage`（当 IndexedDB 不可用时）

### 2.3 数据库信息

**IndexedDB 数据库名**：
```
ExerciseSolveApp_${userId}
```

**存储表名**：
```
chat_history
```

### 2.4 数据结构

```typescript
interface ChatHistoryData {
  questionId: string        // 实际为 storageKey（teacher_chat_${sessionId}）
  messages: ChatBubble[]    // 消息列表
  chatResponseTimes: number // 响应次数
  lastUpdated: number       // 最后更新时间戳
}
```

### 2.5 存储操作

#### 保存聊天历史

**位置**：`teacherChatStore.ts` - `saveChatHistory()`

```typescript
const storageKey = `teacher_chat_${currentSession.value.sessionId}`

await asyncStorage.saveChatHistory(storageKey, {
  questionId: storageKey,
  messages: messages.value,
  lastUpdated: Date.now(),
  chatResponseTimes: chatResponseTimes.value
})
```

**防抖机制**：
- 默认延迟 1 秒保存（防抖）
- 可立即保存（`immediate: true`）

#### 加载聊天历史

**位置**：`teacherChatStore.ts` - `loadChatHistory()`

```typescript
const storageKey = `teacher_chat_${sessionId}`
const history = await asyncStorage.loadChatHistory(storageKey)

if (history && history.messages) {
  messages.value = history.messages
  chatResponseTimes.value = history.chatResponseTimes || 0
}
```

#### 删除聊天历史

**位置**：`teacherChatStore.ts` - `clearChatHistory()`

```typescript
const storageKey = `teacher_chat_${sessionId}`
await asyncStorage.removeChatHistory(storageKey)
```

## 三、账号隔离机制

### 3.1 用户ID获取

```typescript
import { getCurrentUserIdOrDefault } from '@/utils/user/userId'

const userId = getCurrentUserIdOrDefault()
// 返回格式：'user123' 或 'default'
```

### 3.2 隔离实现

1. **会话信息**：键名包含 `${userId}_` 前缀
2. **聊天历史**：`asyncStorage` 内部自动添加用户ID前缀
3. **IndexedDB**：数据库名包含用户ID，每个用户拥有独立的数据库

## 四、完整存储流程

### 4.1 创建会话流程

```
1. 生成会话ID（generateSessionId）
   └─> teacher-{hash}-{timestamp}

2. 创建会话对象（TeacherSession）
   ├─> sessionId
   ├─> sessionName
   ├─> subject
   └─> createTime

3. 保存会话信息到 localStorage
   └─> 键名：${userId}_teacher_chat_${sessionId}_session

4. 设置为当前会话
   └─> currentSession.value = session
```

### 4.2 发送消息流程

```
1. 添加消息到列表
   └─> messages.value.push(message)

2. 发送消息（通过 Android Bridge）
   └─> 发送到 RabbitMQ

3. 保存聊天历史（防抖，1秒延迟）
   ├─> 构建存储键：teacher_chat_${sessionId}
   ├─> 调用 asyncStorage.saveChatHistory()
   └─> 实际存储到：${userId}_chat_history_teacher_chat_${sessionId}
```

### 4.3 加载会话流程

```
1. 从 localStorage 加载会话列表
   ├─> 遍历所有以 ${userId}_teacher_chat_ 开头且以 _session 结尾的键
   ├─> 解析会话数据
   └─> 去重处理

2. 选择会话后，加载聊天历史
   ├─> 调用 asyncStorage.loadChatHistory(storageKey)
   └─> 从 IndexedDB 或 localStorage 加载消息列表
```

## 六、注意事项

### 6.1 键名一致性

⚠️ **重要**：确保所有地方使用相同的键名格式：

- ✅ 正确：`${userId}_teacher_chat_${sessionId}_session`
- ❌ 错误：`teacher_chat_${sessionId}_session`（缺少 userId 前缀）

### 6.2 存储大小限制

- **localStorage**：通常限制为 5-10MB
- **IndexedDB**：通常限制为 50MB 或更大

建议监控存储使用情况，必要时清理过期数据。

### 6.3 降级策略

当 IndexedDB 不可用时，`asyncStorage` 会自动降级到 localStorage：
- 保存时自动降级
- 加载时自动降级
- 删除时自动降级

### 6.4 数据同步

- 会话信息和聊天历史是**分离存储**的
- 删除会话时，需要同时删除：
  1. localStorage 中的会话信息
  2. IndexedDB/localStorage 中的聊天历史

## 八、总结

老师会话的存储逻辑采用**分离存储**的设计：

1. **会话元数据** → `localStorage`（快速访问，数据量小）
2. **聊天历史** → `IndexedDB`（大容量，异步操作）

这种设计的好处：
- ✅ 快速加载会话列表（localStorage 同步访问）
- ✅ 大容量存储聊天历史（IndexedDB 支持大量数据）
- ✅ 账号隔离（通过用户ID前缀实现）
- ✅ 自动降级（IndexedDB 不可用时使用 localStorage）

需要注意：
- ⚠️ 键名格式必须一致（包含 userId 前缀）
- ⚠️ 删除会话时需要同时删除会话信息和聊天历史
- ⚠️ 监控存储使用情况，避免超出限制
