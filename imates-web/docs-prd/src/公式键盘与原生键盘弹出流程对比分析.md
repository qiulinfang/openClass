# 公式键盘与原生键盘弹出流程对比分析

## 一、场景一：点击公式编辑器，公式键盘弹出

### 1.1 触发流程

```
用户点击公式编辑器(math-field)
    ↓
MathLive元素获得焦点
    ↓
MathLive触发focus事件
    ↓
MathLive虚拟键盘自动弹出（配置：virtualKeyboardMode: "onfocus"）
    ↓
MathLive触发virtual-keyboard-toggle事件 (visible: true)
    ↓
MathFormulaEditor.vue监听virtual-keyboard-toggle事件
    ↓
触发全局CustomEvent: 'formula-keyboard-toggle' (detail: { visible: true })
    ↓
ChatView.vue监听'formula-keyboard-toggle'事件
    ↓
调用handleFormulaKeyboardToggle函数
```

#### 1.2.2 ChatView.vue - 公式键盘事件处理

```995:1022:imates-web/src/components/ChatView.vue
// 处理公式键盘切换的函数
// 流程：接收公式键盘事件 → 滚动到底部（不压缩页面）
const handleFormulaKeyboardToggle = (event: Event) => {
  // 步骤1：解析事件数据
  const customEvent = event as CustomEvent
  const { visible } = customEvent.detail


  // 步骤2：更新公式键盘状态标记
  isFormulaKeyboardVisible.value = visible

  // 步骤3：根据键盘显示状态执行相应逻辑
  if (visible) {
    // 3.1 显示公式键盘：只滚动到底部，不压缩页面
    scrollToBottom()
  } else {
    // 3.2 隐藏公式键盘：检查焦点状态避免误隐藏
    const isEditorFocused = document.activeElement?.closest('.tiptap-editor-container')
    const isMathFieldFocused = document.activeElement?.tagName === 'MATH-FIELD'

    if (isEditorFocused || isMathFieldFocused) {
      // 编辑器或公式编辑器获得焦点时跳过隐藏，避免误操作
      return
    }

    // 修复：公式键盘隐藏时，确保状态正确更新，为后续原生键盘处理做准备
  }
}
```

### 1.3 处理特点

1. **不压缩页面**：公式键盘是虚拟键盘，不占用系统键盘空间，只需要滚动到底部确保公式编辑器可见
2. **纯滚动操作**：调用 `scrollToBottom()` 函数，使用 BScroll 滚动到底部
3. **状态标记**：更新 `isFormulaKeyboardVisible.value = true`，用于后续原生键盘处理时判断是否跳过

## 二、场景二：点击输入区域，原生键盘弹出

### 2.1 触发流程

```
用户点击输入区域（Quill编辑器或普通输入框）
    ↓
输入元素获得焦点（focus事件）
    ↓
Android WebView检测到输入元素获得焦点
    ↓
Android系统自动弹出原生键盘
    ↓
Android端监听键盘弹出（通过ViewTreeObserver或窗口变化）
    ↓
Android端触发JavaScript事件：'keyboard-show' (detail: { height, duration })
    ↓
ChatView.vue监听'keyboard-show'事件
    ↓
调用handleKeyboardShown函数
```

### 2.2 关键代码位置

#### 2.2.1 ChatView.vue - 原生键盘事件监听

```2081:2106:imates-web/src/components/ChatView.vue
    // 3.3 监听原生键盘事件（处理系统键盘，只压缩页面不滚动）
    // 动态控制原生键盘事件监听，避免与公式键盘冲突
    let nativeKeyboardListenersEnabled = true
```

#### 2.2.2 ChatView.vue - 原生键盘显示处理

```1044:1091:imates-web/src/components/ChatView.vue
// 处理原生键盘显示的函数
// 流程：压缩页面高度 → 焦点处理（不滚动，因为压缩后输入框自动可见）
const handleKeyboardShown = async (data: { height: number; duration: number }) => {

  // 步骤1：检查公式键盘状态 - 如果公式键盘正在显示，跳过原生键盘处理
  if (isFormulaKeyboardVisible.value) {
    return
  }

  // 步骤2：防重复执行检查
  if (isAnimating.value) {
    return
  }

  // 步骤3：数据预处理
  isKeyboardAnimating.value = true
  keyboardAnimationHeight.value = data.height
  isKeyboardVisible.value = true
  keyboardHeight.value = dynamicKeyboardHeight.value
  isAnimating.value = true

  // 步骤4：记录原始高度 - 增强保护机制
  if (originalChatViewHeight.value === 0) {
    // 首次记录原始高度
    originalChatViewHeight.value = chatViewRef.value?.offsetHeight || 0
  } else {
    // 验证已记录的高度是否仍然有效
    const currentHeight = chatViewRef.value?.offsetHeight || 0
    if (Math.abs(originalChatViewHeight.value - currentHeight) > 50) {
      originalChatViewHeight.value = currentHeight
    }
  }

  // 步骤5：移动端焦点处理
  // 原生键盘显示时不需要滚动，因为页面压缩后输入框会自动可见
  if (typeof window !== 'undefined' && window.innerWidth <= 768) {
    const inputElement = document.querySelector('.chat-input-field input') as HTMLInputElement
    if (inputElement) {
      inputElement.focus()
    }
  }

  // 步骤6：延迟执行动画
  nextTick(() => {
    animationStartTime.value = Date.now()
    compressChatViewHeight()
  })
}
```

#### 2.2.3 ChatView.vue - 页面高度压缩

```557:595:imates-web/src/components/ChatView.vue
/**
 * 压缩ChatView高度（仅用于原生键盘）
 * 作用：将ChatView高度压缩以适应原生键盘显示，并应用平滑的过渡动画
 * 注意：原生键盘不需要滚动，因为压缩后输入框会自动保持在可见区域
 */
const compressChatViewHeight = () => {


  // 步骤1：状态验证
  if (!isAnimating.value || !isKeyboardVisible.value) {
    return
  }

  // 步骤2：记录原始高度
  if (originalChatViewHeight.value === 0) {
    originalChatViewHeight.value = chatViewRef.value?.offsetHeight || 0
  }

  // 步骤3：获取CSS动画参数
  const cssParams = getCSSAnimationParams()

  // 步骤4：执行高度变化动画
  if (chatViewRef.value) {
    const newHeight = Math.max(originalChatViewHeight.value - keyboardHeight.value, 200)

    chatViewRef.value.style.height = `${newHeight}px`
    chatViewRef.value.style.transition = `height ${cssParams.duration} ${cssParams.curve}`
  }

  // 步骤5：动画完成后清理
  setTimeout(() => {
    isAnimating.value = false
    if (chatViewRef.value) {
      chatViewRef.value.style.transition = ''
    }
    // 动画完成后再次确保滚动到底部
    scrollToBottom()
  }, parseInt(cssParams.duration))
}
```

### 2.3 处理特点

1. **压缩页面高度**：原生键盘会遮挡页面，需要压缩 ChatView 的高度来适应键盘
2. **不滚动**：压缩后输入框会自动可见，不需要滚动操作（但动画完成后会调用一次 scrollToBottom）
3. **CSS动画**：使用 CSS transition 实现平滑的高度变化动画
4. **状态检查**：如果公式键盘正在显示，跳过原生键盘处理，避免冲突

## 三、两种场景的对比

### 3.1 触发机制对比

| 对比项 | 公式键盘 | 原生键盘 |
|--------|---------|---------|
| **触发方式** | MathLive虚拟键盘自动弹出 | Android系统键盘自动弹出 |
| **事件来源** | MathLive的virtual-keyboard-toggle事件 | Android端检测键盘弹出后触发 |
| **事件名称** | 'formula-keyboard-toggle' | 'keyboard-show' |
| **事件数据** | `{ visible: boolean }` | `{ height: number, duration: number }` |

### 3.2 处理方式对比

| 对比项 | 公式键盘 | 原生键盘 |
|--------|---------|---------|
| **页面操作** | 只滚动，不压缩 | 压缩页面高度 |
| **滚动操作** | ✅ 调用scrollToBottom() | ❌ 不滚动（压缩后自动可见） |
| **高度变化** | ❌ 不改变页面高度 | ✅ 压缩ChatView高度 |
| **动画效果** | ❌ 无动画 | ✅ CSS transition动画 |
| **状态标记** | `isFormulaKeyboardVisible` | `isKeyboardVisible` |

### 3.3 冲突处理机制

1. **公式键盘优先**：当公式键盘显示时（`isFormulaKeyboardVisible.value === true`），原生键盘处理会被跳过
2. **状态检查**：在 `handleKeyboardShown` 函数中，首先检查公式键盘状态：
   ```typescript
   if (isFormulaKeyboardVisible.value) {
     return  // 跳过原生键盘处理
   }
   ```
3. **动态控制**：原生键盘监听器可以通过 `disableNativeKeyboardListeners()` 和 `enableNativeKeyboardListeners()` 动态控制

### 3.4 代码执行流程对比图

#### 公式键盘流程：
```
点击公式编辑器
  → MathLive focus事件
  → MathLive virtual-keyboard-toggle事件
  → 触发全局 'formula-keyboard-toggle' 事件
  → ChatView.handleFormulaKeyboardToggle()
  → 更新 isFormulaKeyboardVisible = true
  → scrollToBottom() [只滚动，不压缩]
```

#### 原生键盘流程：
```
点击输入区域
  → 输入元素focus事件
  → Android系统弹出键盘
  → Android端触发 'keyboard-show' 事件
  → ChatView.handleNativeKeyboardShow()
  → ChatView.handleKeyboardShown()
  → 检查公式键盘状态 [如果公式键盘显示则跳过]
  → 更新键盘状态变量
  → compressChatViewHeight() [压缩页面高度]
  → CSS动画执行
```

## 四、关键设计点

### 4.1 公式键盘设计要点

1. **MathLive配置**：`virtualKeyboardMode: "onfocus"` - 焦点时自动弹出
2. **事件转发**：MathLive的事件需要转发为全局事件，让ChatView处理
3. **纯滚动**：虚拟键盘不占用系统空间，只需要滚动确保可见

### 4.2 原生键盘设计要点

1. **高度压缩**：原生键盘会遮挡页面，必须压缩页面高度
2. **动画过渡**：使用CSS transition实现平滑的高度变化
3. **状态管理**：记录原始高度，计算新高度，管理动画状态

### 4.3 冲突避免机制

1. **状态标记**：使用 `isFormulaKeyboardVisible` 标记公式键盘状态
2. **优先级处理**：公式键盘显示时，原生键盘处理被跳过
3. **焦点检查**：公式键盘隐藏时，检查焦点状态避免误隐藏

---

## 五、总结

1. **公式键盘**：虚拟键盘，只需要滚动到底部，不压缩页面
2. **原生键盘**：系统键盘，需要压缩页面高度适应键盘，不滚动
3. **冲突处理**：公式键盘优先，通过状态标记避免冲突
4. **用户体验**：两种键盘都有平滑的动画效果，确保输入框始终可见
