# 资源切换笔记加载错误问题分析

## 一、问题描述

当打开资源A并做笔记，然后打开新资源B时，资源A的笔记被错误地加载到资源B上。

## 二、问题分析

### 2.1 问题流程

1. **打开资源A**：
   - 设置当前文件信息：`store.setCurrentFileInfo(idA, resourceIdA)`
   - 加载资源A的笔记：`store.loadAnnotationsFromLocalFile()`
   - 资源A的笔记被加载到 `store.allAnnotations`

2. **切换到资源B**：
   - 设置当前文件信息：`store.setCurrentFileInfo(idB, resourceIdB)`
   - 加载资源B的笔记：`store.loadAnnotationsFromLocalFile()`
   - **问题**：如果资源B没有笔记，`loadAnnotationsFromLocalFile()` 直接返回，不会清空 `allAnnotations`
   - 结果：资源A的笔记仍然保留在 `allAnnotations` 中，被错误地显示在资源B上

### 2.2 问题根源

**代码位置**：`imates-web/src/stores/pdfViewerStore.ts` 第429-449行

```typescript
async loadAnnotationsFromLocalFile() {
  if (!this.currentFileId || !this.currentResourceId) {
    return  // ❌ 直接返回，不清空 allAnnotations
  }
  
  try {
    const textbook = await resourceManager.indexedDB.get('textbooks', this.currentFileId) as UserTextbookInfo
    if (!textbook || !textbook.localFiles) {
      return  // ❌ 直接返回，不清空 allAnnotations
    }
    
    const localFile = textbook.localFiles.find((file: LocalFileInfo) => file.id === this.currentResourceId)
    if (localFile && localFile.annotations) {
      this.allAnnotations = localFile.annotations  // ✅ 有笔记时赋值
    }
    // ❌ 如果没有找到 localFile 或没有 annotations，不会清空 allAnnotations
  } catch (error) {
    console.warn('从localFiles加载笔记失败:', error)
    // ❌ 错误时也不清空 allAnnotations
  }
}
```

**问题点**：
- 当资源B没有笔记时，`loadAnnotationsFromLocalFile()` 方法不会清空 `allAnnotations`
- 导致资源A的笔记数据残留在 `allAnnotations` 中
- 这些残留的笔记会被渲染到资源B上

### 2.3 调用流程

## 三、解决方案

### 3.1 修复方案

在 `loadAnnotationsFromLocalFile()` 方法中，无论是否找到笔记，都应该先清空 `allAnnotations`，然后再加载新资源的笔记。

**修复逻辑**：
1. 在方法开始时，先清空 `allAnnotations` 和 `notes`
2. 如果找到新资源的笔记，再加载到 `allAnnotations`
3. 如果没有找到笔记，`allAnnotations` 保持为空对象 `{}`

### 3.2 修复代码

修改 `pdfViewerStore.ts` 的 `loadAnnotationsFromLocalFile()` 方法：

```typescript
async loadAnnotationsFromLocalFile() {
  // 第1步：先清空所有笔记，避免资源切换时笔记残留
  this.allAnnotations = {}
  this.notes.clear()
  
  if (!this.currentFileId || !this.currentResourceId) {
    return
  }
  
  try {
    // 第2步：获取教材信息
    const textbook = await resourceManager.indexedDB.get('textbooks', this.currentFileId) as UserTextbookInfo
    if (!textbook || !textbook.localFiles) {
      return
    }
    
    // 第3步：查找对应的本地文件
    const localFile = textbook.localFiles.find((file: LocalFileInfo) => file.id === this.currentResourceId)
    
    // 第4步：如果找到笔记数据，加载到 allAnnotations
    if (localFile && localFile.annotations) {
      this.allAnnotations = localFile.annotations
    }
    // 如果没有找到笔记，allAnnotations 保持为空对象 {}
  } catch (error) {
    console.warn('从localFiles加载笔记失败:', error)
  }
}
```

## 四、影响范围

### 4.1 受影响的功能
- PDF资源切换时的笔记显示
- 笔记数据的正确加载和清空

### 4.2 测试场景
1. **场景1**：资源A有笔记，切换到资源B（无笔记）
   - 预期：资源B不显示任何笔记
   - 当前：资源B显示资源A的笔记 ❌

2. **场景2**：资源A有笔记，切换到资源B（有笔记）
   - 预期：资源B显示自己的笔记
   - 当前：可能显示资源A的笔记 ❌

3. **场景3**：资源A无笔记，切换到资源B（有笔记）
   - 预期：资源B显示自己的笔记
   - 当前：正常 ✅

## 五、修复步骤

1. 修改 `pdfViewerStore.ts` 的 `loadAnnotationsFromLocalFile()` 方法
2. 在方法开始时先清空 `allAnnotations` 和 `notes`
3. 测试资源切换场景，确保笔记不会残留
