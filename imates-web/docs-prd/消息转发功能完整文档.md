# 消息转发功能完整文档

## 一、功能概述

消息转发功能允许学生将AI对话中的消息转发给老师，实现学生与老师之间的沟通。该功能仅在AI对话场景下可用，支持单条消息转发和批量消息转发两种模式。

### 1.1 核心特性

- ✅ **多场景支持**：AI通用对话、AI题目对话、AI教材对话
- ✅ **多触发方式**：单条消息转发、批量消息转发
- ✅ **多消息类型**：文本、图片、语音消息
- ✅ **智能会话管理**：自动查找或创建老师会话
- ✅ **转发类型分离**：通用会话转发和题目会话转发，确保消息转发到正确的会话类型
- ✅ **完整错误处理**：前端和Android端都有完善的错误处理
- ✅ **良好用户体验**：转发过程中有提示，转发成功后询问用户是否跳转
- ✅ **策略模式架构**：使用策略模式实现，代码结构清晰，易于维护和扩展

## 二、使用场景

### 2.1 支持的页面类型

转发功能仅在以下三种AI对话页面中可用：

1. **AI通用对话页面** (`ai-general`)
   - 通用AI对话场景
   - 学生可以咨询各种问题
   - **特殊处理**：需要用户手动选择老师类型（生物/数学）

2. **AI题目对话页面** (`ai-exercise`)
   - 题目解答场景
   - 学生可以针对具体题目进行提问
   - 自动从题目中获取科目信息
   - **特殊处理**：转发到题目会话（`teacherExerciseChatStore`），而非通用会话

3. **AI教材对话页面** (`ai-textbook`)
   - 教材内容学习场景
   - 学生可以针对教材内容提问
   - 自动从知识图谱store获取科目信息

### 2.2 不支持转发的场景

- **老师对话页面** (`teacher`)：老师对话页面本身不支持转发功能
- **其他页面类型**：任何非AI对话页面都不支持转发

### 2.3 转发按钮显示条件

转发按钮仅在以下条件**全部满足**时显示：

1. 当前页面类型为 `ai-general`、`ai-exercise` 或 `ai-textbook`
2. 消息为最后一条消息（功能按钮仅显示在最后一条消息上）
3. 消息不是欢迎消息（ID不以 `welcome_` 开头）
4. 消息不是流式输出状态（AI消息需等待流式输出完成）

## 四、业务流程详解

### 4.1 会话管理

#### 4.1.1 转发类型

转发功能支持两种会话类型，确保消息转发到正确的会话：

1. **通用会话转发** (`'general'`)
   - 用于：AI通用对话、AI教材对话
   - 存储位置：`teacherGeneralChatStore`
   - 存储键名：`{userId}_teacher-general-sessions`
   - 特点：每个科目只维护一个通用会话

2. **题目会话转发** (`'exercise'`)
   - 用于：AI题目对话
   - 存储位置：`teacherExerciseChatStore`
   - 存储键名：`{userId}_teacher-exercise-sessions`
   - 特点：每个题目可以创建独立的会话，支持题目和科目验证

**转发类型选择：**
- `AiGeneralStrategy` 和 `AiTextbookStrategy`：使用 `'general'` 类型
- `AiExerciseStrategy`：使用 `'exercise'` 类型

#### 4.1.2 会话存储格式

**通用会话存储格式：**
- **存储键名**：`{userId}_teacher-general-sessions`
- **存储格式**：`Record<string, TeacherSession>`
- **键值**：`sessionId`（会话ID）
- **值**：`TeacherSession` 对象

**题目会话存储格式：**
- **存储键名**：`{userId}_teacher-exercise-sessions`
- **存储格式**：`Record<string, TeacherSession>`
- **键值**：`sessionId`（会话ID）
- **值**：`TeacherSession` 对象（包含题目相关信息）

**TeacherSession 接口：**
```typescript
interface TeacherSession {
  sessionId: string
  sessionName: string
  subject: 'biology' | 'math'
  createTime: number
  msgCount?: number
  updateTime?: number
}
```

**示例：**
```json
{
  "teacher-4d90dead-1762611396129": {
    "sessionId": "teacher-4d90dead-1762611396129",
    "sessionName": "生物",
    "subject": "biology",
    "createTime": 1762611396129,
    "msgCount": 5,
    "updateTime": 1762611397000
  },
  "teacher-abc123-1762611400000": {
    "sessionId": "teacher-abc123-1762611400000",
    "sessionName": "数学",
    "subject": "math",
    "createTime": 1762611400000,
    "msgCount": 3
  }
}
```

#### 4.1.3 会话选择逻辑

**核心函数：**
- `selectOrCreateTeacherSession`：选择或创建通用会话
- `selectOrCreateTeacherExerciseSession`：选择或创建题目会话

**位置：** `imates-web/src/components/chat/strategies/ForwardMessageHelper.ts`

**通用会话选择流程：**

1. **获取当前科目**
   - 由各个策略类实现 `getCurrentSubjectForForward()` 方法：
     - `AiGeneralStrategy`：返回 `null`（需要用户手动选择）
     - `AiTextbookStrategy`：从 `knowledgeGraphStore.getCurrentSubjectLowercase()` 获取

2. **AI通用场景特殊处理**（`subject === null`）
   - 显示对话框让用户选择老师类型（生物/数学）
   - 用户选择后：
     - 加载老师会话列表（从 `{userId}_teacher-general-sessions` 加载）
     - 查找该类型是否有会话
     - 如果有会话：复用已有会话
     - 如果没有会话：创建新会话

3. **其他场景处理**（`subject !== null`）
   - 初始化老师消息监听器 (`teacherGeneralChatStore.initMessageReceiver()`)
   - 加载老师会话列表（从 `{userId}_teacher-general-sessions` 加载）
   - 查找对应科目的会话（每个科目只维护一个会话）
   - 如果找到会话：
     - 设置到 `teacherGeneralChatStore`
     - 加载该会话的历史消息
   - 如果没找到会话：
     - 调用 `teacherGeneralChatStore.createTeacherSession()` 创建新会话

**题目会话选择流程：**

1. **验证题目和科目**
   - 检查 `currentQuestion.value` 是否存在
   - 检查 `currentQuestion.value.subject` 是否存在
   - 如果验证失败，返回错误

2. **获取科目信息**
   - 从 `currentQuestion.value.subject` 获取科目（`'biology' | 'math'`）

3. **初始化消息监听器**
   - 调用 `teacherExerciseChatStore.initMessageReceiver()`

4. **加载会话列表**
   - 从 `{userId}_teacher-exercise-sessions` 加载所有会话

5. **查找或创建会话**
   - 查找对应题目的会话（如果存在）
   - 如果没找到会话：
     - 调用 `teacherExerciseChatStore.createTeacherSession()` 创建新会话

#### 4.1.4 会话创建逻辑

**通用会话创建：**

**核心函数：** `createTeacherSession`

**位置：** `imates-web/src/stores/teacherGeneralChatStore.ts`

   - 从统一存储 `{userId}_teacher-exercise-sessions` 加载所有会话
   - 匹配条件：基于题目ID或题目名称匹配
   - 如果已存在，复用已有会话

### 4.2 消息格式转换

#### 4.2.1 转换函数

**核心函数：** `convertMessageForForwarding`

**位置：** `imates-web/src/components/chat/strategies/ForwardMessageHelper.ts` 第15行

**转换规则：**

```typescript
convertMessageForForwarding(msg: ChatBubble)
  ↓
【第1步】获取消息类型
  - 从 msg.messageType 获取数据类型（默认为 'text'）
  - 转换为大写格式（TEXT/IMAGE/VOICE）
  ↓
【第2步】添加角色前缀
  - 如果 msg.type === 'user'：添加 '[学生] ' 前缀
  - 如果 msg.type === 'ai'：添加 '[AI助手] ' 前缀
  ↓
【第3步】清理LaTeX公式
  - 移除 $...$ 格式的LaTeX：.replace(/\$[^$]*\$/g, '')
  - 移除 \command 格式的LaTeX命令：.replace(/\\[a-zA-Z]+/g, '')
  - 移除LaTeX括号：.replace(/[{}()[\]]/g, '')
  - 合并多个空格：.replace(/\s+/g, ' ')
  - 去除首尾空格：.trim()
  ↓
【第4步】构建转发格式对象
  {
    id: msg.id,
    type: messageType,  // TEXT/IMAGE/VOICE
    content: cleanedContent,
    timestamp: ''
  }
```

**详细流程：**

```typescript
forwardMessageToTeacher(messages, sessionId, sessionType)
  ↓
【第1步】转换消息格式
  - 调用 convertMessageForForwarding 转换每条消息
  ↓
【第2步】序列化消息数据

  - 如果序列化失败，返回 false
  ↓
【第3步】验证会话ID

  ↓
【第4步】调用API转发
```

**关键改进：**
- ✅ 支持 `sessionType` 参数，区分通用会话和题目会话
- ✅ 根据 `sessionType` 选择正确的 store 保存消息
- ✅ 默认值为 `'general'`，保持向后兼容

### 4.4 本地存储流程

#### 4.4.1 消息存储格式

**存储键名：** `teacher-general-{sessionId}`

**存储格式：** `ChatHistoryData`
```typescript
interface ChatHistoryData {
  messages: ChatBubble[]
  lastUpdateTime: number
  sessionId: string
}
```

**存储位置：** IndexedDB（通过 `asyncStorage` 服务）

#### 4.4.2 转发成功后的存储

**核心逻辑：**

```typescript
// 转发成功后
if (success) {
  // 第1步：根据 sessionType 选择对应的 store
  const teacherStore = sessionType === 'exercise' 
    ? useTeacherExerciseChatStore() 
    : useTeacherGeneralChatStore()
  
  // 第2步：转换消息格式
  const convertedMessages = messages.map((msg) => ({
    ...msg,
    id: msg.id.startsWith('forwarded_') ? msg.id : 'forwarded_' + msg.id,
    sender: 'user' as const,
    type: 'user' as const,
    messageType: messageType  // text/voice/image
  }))
  
  // 第3步：添加到对应 store 的消息列表
  teacherStore.messages.push(...convertedMessages)
  
  // 第4步：立即保存（不使用防抖）
  await teacherStore.saveChatHistory()
}
```

**关键点：**
- ✅ **会话类型分离**：根据 `sessionType` 选择正确的 store（`teacherGeneralChatStore` 或 `teacherExerciseChatStore`）
- ✅ **立即保存**：使用 `await teacherStore.saveChatHistory()` 立即保存，不使用防抖
- ✅ **消息ID前缀**：添加 `forwarded_` 前缀，避免与原消息冲突
- ✅ **消息类型设置**：设置 `sender = 'user'`，`type = 'user'`

#### 4.4.3 消息丢失问题修复

**问题描述：**
- 转发消息后，如果用户在1秒内点击"前往老师对话"，转发消息可能丢失
- 原因：使用防抖保存（1秒后保存），但 `loadChatHistory()` 在防抖保存之前执行，覆盖了内存中的转发消息

**解决方案：**
- ✅ 转发消息后立即保存，不使用防抖
- ✅ 确保转发消息在用户点击"前往老师对话"之前已经保存到 IndexedDB

**修复代码：**
```typescript
// 修复前（有问题）
await teacherStore.saveChatHistory()  // 使用防抖保存（1秒后）

// 修复后（正确）
await teacherStore.saveChatHistory()  // 立即保存（不使用防抖）
```

## 五、支持的消息类型

### 5.1 文本消息 (TEXT)

**转换规则：**
- 添加角色前缀：[学生] 或 [AI助手]
- 清理LaTeX公式
- 保留原始文本内容

**发送方式：**
```java
sendTextMessageToTeacher(content, teacherSessionId, subject)
```

### 5.2 图片消息 (IMAGE)

**转换规则：**
- 从消息的 `imageData.filePath` 获取图片路径
- 内容字段传递图片路径或base64数据

**发送方式：**
```java
sendPictureToTeacher(imagePath, teacherSessionId, subject)
```

**注意事项：**
- Android端会将文件路径转换为base64
- `base64DataUrl` 仅用于前端UI显示，不用于发送

### 5.3 语音消息 (VOICE)

**转换规则：**
- 从消息的 `voiceData.filePath` 获取语音路径
- 从消息的 `voiceData.duration` 获取语音时长

**发送方式：**
```java
sendVoiceMessageToTeacher(voicePath, duration, teacherSessionId, subject)
```

## 九、注意事项

### 9.1 消息格式限制

- LaTeX公式会被清理，只保留文本内容
- 图片和语音消息需要包含文件路径信息
- 消息ID会自动添加 `forwarded_` 前缀，避免与原消息冲突

### 9.2 会话管理

- 转发前会自动创建老师会话（如果不存在）
- 会话ID从对应 store 的 `sessionId` 获取
- 学科信息从不同场景获取（题目、知识图谱、用户选择）
- **转发类型分离**：
  - AI通用对话和AI教材对话 → 转发到通用会话（`teacherGeneralChatStore`）
  - AI题目对话 → 转发到题目会话（`teacherExerciseChatStore`）

### 9.3 RabbitMQ连接

- Android端会自动检查并初始化RabbitMQ连接
- 如果初始化失败，会返回错误提示
- 最多等待10秒初始化完成

### 9.4 用户体验

- 转发过程中显示"正在转发到老师..."提示
- 转发成功后询问是否前往老师对话
- 支持留在当前会话继续操作

### 9.5 存储格式

- **通用会话存储**：
  - 会话列表：`{userId}_teacher-general-sessions`，格式为 `Record<string, TeacherSession>`
  - 消息存储：IndexedDB，键名为 `teacher-general-{sessionId}`
- **题目会话存储**：
  - 会话列表：`{userId}_teacher-exercise-sessions`，格式为 `Record<string, TeacherSession>`
  - 消息存储：IndexedDB，键名为 `teacher-exercise-{sessionId}`
- **立即保存**：转发消息后立即保存，不使用防抖，避免消息丢失

## 十、已知问题和解决方案

### 10.1 消息丢失问题（已修复）

**问题描述：**
- 转发消息后，如果用户在1秒内点击"前往老师对话"，转发消息可能丢失

**原因：**
- 使用防抖保存（1秒后保存），但 `loadChatHistory()` 在防抖保存之前执行，覆盖了内存中的转发消息

**解决方案：**
- ✅ 转发消息后立即保存，不使用防抖
- ✅ 确保转发消息在用户点击"前往老师对话"之前已经保存到 IndexedDB

**修复位置：**
- `ForwardMessageHelper.ts:200` - `forwardMessageToTeacher` 中立即保存
- `ForwardMessageHelper.ts:250` - `forwardMessagesSeparately` 中立即保存

### 10.2 会话创建重复问题（已修复）

**问题描述：**
- 转发消息时可能创建两条会话记录

**原因：**
- 键名格式不一致：`UnifiedChatDialog.createTeacherSession` 使用 `teacher-general-${sessionId}_session`，而 `teacherStore.createTeacherSession` 使用 `${userId}_teacher-general-${sessionId}_session`

**解决方案：**
- ✅ 统一使用 `teacherStore.createTeacherSession` 创建会话
- ✅ 使用统一存储格式：`{userId}_teacher-general-sessions`

**修复位置：**
- `teacherGeneralChatStore.ts` - 统一会话创建逻辑
- `teacherGeneralChatStore.ts` - 统一会话存储格式

### 10.3 转发类型混淆问题（已修复）

**问题描述：**
- AI题目对话的消息被转发到通用会话，而不是题目会话
- 导致题目相关的消息和通用消息混在一起

**原因：**
- `ForwardMessageHelper.ts` 中硬编码使用了 `teacherGeneralChatStore`，所有转发都保存到通用会话
- `AiExerciseStrategy` 没有使用题目会话的转发逻辑

**解决方案：**
- ✅ 添加 `ForwardSessionType` 类型（`'general' | 'exercise'`）
- ✅ `forwardMessageToTeacher` 和 `forwardMessagesSeparately` 支持 `sessionType` 参数
- ✅ 根据 `sessionType` 选择对应的 store 保存消息
- ✅ `AiExerciseStrategy` 使用 `selectOrCreateTeacherExerciseSession` 创建题目会话
- ✅ `AiExerciseStrategy` 转发时传入 `sessionType: 'exercise'`
- ✅ `AiGeneralStrategy` 和 `AiTextbookStrategy` 显式传入 `sessionType: 'general'`

**修复位置：**
- `ForwardMessageHelper.ts` - 添加转发类型支持
- `AiExerciseStrategy.ts` - 使用题目会话转发逻辑
- `AiGeneralStrategy.ts` - 显式指定通用会话转发
- `AiTextbookStrategy.ts` - 显式指定通用会话转发

## 十一、架构设计

### 11.1 策略模式架构

消息转发功能采用**策略模式**设计，将不同场景的转发逻辑封装到独立的策略类中：

```
ChatView (组件层)
  ↓
ChatStrategy (策略接口)
  ├─ AiGeneralStrategy (AI通用对话策略)
  ├─ AiExerciseStrategy (AI题目对话策略)
  └─ AiTextbookStrategy (AI教材对话策略)
  ↓
ForwardMessageHelper (转发工具类)
  ├─ convertMessageForForwarding (消息格式转换)
  ├─ selectOrCreateTeacherSession (会话管理)
  ├─ forwardMessageToTeacher (单条转发)
  └─ forwardMessagesSeparately (批量转发)
```

### 11.2 策略模式优势

1. **代码复用**：通用转发逻辑集中在 `ForwardMessageHelper`，避免重复代码
2. **易于扩展**：新增场景只需实现 `ChatStrategy` 接口
3. **职责清晰**：每个策略类只负责自己场景的特殊逻辑
4. **易于测试**：策略类可以独立测试
5. **维护简单**：修改转发逻辑只需修改 `ForwardMessageHelper`

### 11.3 策略类职责

| 策略类 | 职责 | 转发类型 |
|--------|------|----------|
| `AiGeneralStrategy` | 处理AI通用对话场景，需要用户手动选择老师类型 | `'general'` |
| `AiExerciseStrategy` | 处理AI题目对话场景，从题目中获取科目信息，验证题目和科目 | `'exercise'` |
| `AiTextbookStrategy` | 处理AI教材对话场景，从知识图谱获取科目信息 | `'general'` |

### 11.4 转发工具类职责

`ForwardMessageHelper` 提供所有策略共用的转发功能：
- 消息格式转换
- 会话选择/创建（支持通用会话和题目会话）
- API调用
- 本地存储（根据转发类型选择正确的 store）
- 用户交互（对话框）

**转发类型支持：**
- `ForwardSessionType`: 定义转发类型（`'general' | 'exercise'`）
- `selectOrCreateTeacherSession`: 选择或创建通用会话
- `selectOrCreateTeacherExerciseSession`: 选择或创建题目会话
- `forwardMessageToTeacher`: 支持 `sessionType` 参数，根据类型选择正确的 store
- `forwardMessagesSeparately`: 支持 `sessionType` 参数，批量转发时使用正确的 store
