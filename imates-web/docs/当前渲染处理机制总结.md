# 研伴题型渲染与交互处理总结 (2026-05-15)

本文档总结了当前研伴前端对后端下发题型的渲染逻辑、交互方式及数据映射规则。

---

## 1. 题型渲染矩阵 (Type Mapping)

系统根据题目的 `type` 字段决定渲染路径，主要分为 **“组件交互模式”** 和 **“白板手写模式”**。

| 题型标识 (type) | 对应组件 | 渲染机制 | 交互方式 |
| :--- | :--- | :--- | :--- |
| `single_choice` | `ChoiceQuestion.vue` | 结构化渲染 | 单选点击 (A/B/C/D) |
| `multiple_choice`| `ChoiceQuestion.vue` | 结构化渲染 | 多选点击 |
| `true_false` | `JudgmentQuestion.vue`| 结构化渲染 | [正确] / [错误] 按钮点击 |
| `fill_in_blank` | `FillBlankQuestion.vue`| 题干解析渲染 | 在 `[blank_x]` 处嵌入 Input 输入框 |
| `subjective` | `DrawingBoardNew.vue` | 白板模式 | HTML 文本背景 + 透明画布手写 |
| `composite` | `DrawingBoardNew.vue` | 兜底白板模式 | 整体 HTML 背景预览 + 全图手写批注 |
| `(其他未知题型)` | `DrawingBoardNew.vue` | 兜底白板模式 | 整体 HTML 背景预览 + 全图手写批注 |

---

## 2. 核心题型交互细节

### 2.1 选择题 (`single_choice` / `multiple_choice`)
- **数据源**：使用 `structuredContent.options` 或 `options` 字段。
- **作答保存**：通过 `v-model` 绑定字符串数组（如 `["A", "C"]`）存入本地缓存。
- **判题**：提交后，将用户数组与后端 `answer` 字段（支持数组或逗号分隔字符串）进行对比。

### 2.2 判断题 (`true_false`)
- **展示逻辑**：界面统一展示 **“正确”** 和 **“错误”** 两个操作块。
- **数据映射**：
    - 点击“正确” -> 内部值记录为 **`"对"`**。
    - 点击“错误” -> 内部值记录为 **`"错"`**。
- **对错校验**：
    - 若后端 `answer` 为布尔值：`true` 对应 `"对"`，`false` 对应 `"错"`。
    - 若后端 `answer` 为字符串：支持 `"对"`, `"√"`, `"正确"`, `"true"` 等多种兼容匹配。

### 2.3 填空题 (`fill_in_blank`)
- **占位符识别**：使用正则 `/\[blank_\d+\]/g` 解析题干。
- **交互实现**：将匹配到的 `[blank_1]` 等标记动态替换为文本输入框，其余部分保留为 HTML。
- **宽度自适应**：输入框宽度根据填入内容的长度动态计算，确保公式或长文本显示完整。

### 2.4 主观解答题 (`subjective`)
- **渲染策略**：将 `stem` 渲染为静态 HTML 预览层，作为底层背景。
- **作答方式**：在其上方覆盖 `DrawingBoardNew` 画布，学生使用画笔直接书写。最终提交的是 **“背景图 + 笔迹”** 合成后的 JPG 图片。

### 2.5 复合材料题 (`composite`) 与 未知题型
- **处理逻辑**：目前代码中**并未**解析 `questionStructureData` 或 `subQuestions` 结构，而是将其统一归类为 **“大主观题”**。
- **渲染机制**：由于不属于选择、判断或填空题型，它会进入 `HomeworkAnswerView.vue` 的最后一个 `v-else` 分支（即 `BaseQuestion` 组件兜底分支）。
- **呈现效果**：
    - **内容来源**：直接渲染后端下发的 `questionContent` 字段（包含所有小题的合并 HTML）。
    - **UI 层级**：将此 HTML 作为底层预览，上方覆盖 `DrawingBoardNew` 透明画布。
- **交互限制**：
    - **不支持结构化交互**：学生无法在复合题内部点击选择题选项、勾选判断题或使用填空输入框。
    - **全图手写**：所有小题的作答均需通过**手写笔迹**在对应位置完成。
- **稳定性保障**：此方案作为“万能兜底”，确保了即便后端下发了全新或极其复杂的复合结构，学生也至少能看到题目并手写答案，实现了业务的 100% 可用性。
