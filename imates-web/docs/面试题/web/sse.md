# SSE (Server-Sent Events) 面试题

### Q1: 什么是 SSE？它与 WebSocket 有什么区别？
- **定义**: SSE 是一种基于 HTTP 的服务器向浏览器推送实时数据的技术。
- **区别**:
  - **方向性**: SSE 是单向的（服务器 -> 客户端），WebSocket 是全双工的双向通信。
  - **协议**: SSE 基于标准 HTTP 协议，WebSocket 是独立的二进制协议。
  - **断线重连**: SSE 原生支持断线重连，WebSocket 需要手动实现。
  - **数据格式**: SSE 仅支持文本（通常是 UTF-8），WebSocket 支持文本和二进制。
  - **轻量级**: SSE 相比 WebSocket 更轻量，在只需要单向推送的场景（如 AI 回复、通知）中更具优势。

### Q2: 在 AI 聊天场景中，为什么通常选择 SSE 而不是 WebSocket？
- **流式输出**: AI 回复通常是分段生成的，SSE 非常适合这种流式文本传输。
- **HTTP 兼容性**: SSE 就是一个长连接的 HTTP 请求，不需要处理复杂的协议转换。
- **重试机制**: SSE 具有内置的自动重试和 `Last-Event-ID` 机制，能确保消息的连续性。
- **代理支持**: 许多企业防火墙或负载均衡器对标准 HTTP (SSE) 的支持比对非标准 WebSocket 更好。

### Q3: SSE 如何处理浏览器连接限制？
- **问题**: 在 HTTP/1.1 中，同一个域名下浏览器限制最大并发连接数为 6 个。如果开启多个 SSE 会话，可能会导致阻塞。
- **解决方案**:
  - **HTTP/2**: 使用 HTTP/2 协议，连接数限制不再是问题（支持多路复用）。
  - **域名分片**: 将 SSE 服务部署在不同的子域名下。
  - **手动管理**: 及时关闭不使用的长连接。

### Q4: SSE 协议的数据格式是怎样的？
- **Content-Type**: 必须设置为 `text/event-stream`。
- **基本格式**:
  ```text
  event: message
  data: 这是一个数据片段
  
  id: 123
  retry: 10000
  ```
- **关键字段**:
  - `data`: 传输的消息内容，多行数据以 `data:` 开头。
  - `event`: 事件类型，前端可以通过 `addEventListener` 监听特定类型的事件。
  - `id`: 消息 ID，重连时客户端会发送 `Last-Event-ID`。
  - `retry`: 设置重连间隔时间。

### Q5: 在本项目中，如何处理 SSE 推送的 Markdown 内容渲染？
- **缓冲策略**: AI 的内容是片段推送的，直接渲染可能导致解析不全。前端通常会建立一个缓冲区，实时追加新接收到的 `data` 片段。
- **性能优化**: 
  - 使用防抖（Debounce）或 `requestAnimationFrame` 限制渲染频率。
  - 采用增量式 Markdown 渲染引擎，或者仅在片段包含完整语义块时触发重绘。
- **错误处理**: 
  - 监听 `onerror` 事件，并在连接异常时展示重试 UI。
  - 结合后端的心跳机制（Keep-Alive），防止连接被中间代理超时断开。
