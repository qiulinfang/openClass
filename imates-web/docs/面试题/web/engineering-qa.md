# Web 面试题 - 工程化与质量保证

> 本面试题基于项目实际代码，深入探讨技术实现细节与业务难点。

## 1. 项目架构与构建

### Q1: 根目录下同时存在 `imates-web` (Vue) 和 `imates-react`，请谈谈你对这种多端/多框架共存架构的看法。
- **优势**: 
  - 灵活性：根据业务场景选择最适合的框架。
  - 独立演进：两套系统可以独立部署和灰度。
- **挑战**: 
  - 逻辑复用：核心算法（如 PDF 处理、公式转换）需要抽离为跨框架的工具库。
  - 构建开销：需要配置复杂的 Vite 或 Webpack 多入口构建。
- **项目实践**: 项目通过 `scripts/` 下的脚本（如 `build-webview-pages.js`）统一管理不同模块的打包逻辑，将特定页面打包为 Webview 离线包。

### Q2: `vite.config.ts` 中针对 Webview 环境有哪些特殊的构建优化？
- **体积压缩**: 开启 `terser` 或 `esbuild` 压缩，移除 `console.log`。
- **资源内联**: 将小图片或字体通过 `base64` 内联，减少离线包的文件数量。
- **外部化（External）**: 对于大依赖（如 MuPDF WASM），采用 CDN 或在原生端单独分发，不打包进 JS Bundle。
- **多模式配置**: 使用 `.env.webview` 等环境变量，在构建时注入特定逻辑（如关闭某些原生不支持的功能）。

## 2. 自动化测试

### Q3: 如何为本项目中的复杂交互编写自动化测试？
- **单元测试 (Vitest)**: 
  - 针对工具函数（如坐标转换、LaTeX 解析）编写纯函数测试。
  - 模拟 Pinia Store 的状态变化。
- **端到端测试 (Playwright)**: 
  - 模拟用户在 Webview 中的操作流程（登录 -> 选择题目 -> 发起对话）。
  - 验证多媒体资源（PDF, Lottie）是否加载成功。
- **混合端测试难点**: 原生 Bridge 的模拟。通过在 `window` 对象上注入 Mock 对象来模拟 `Capacitor.Plugins`。

## 3. 性能监控与异常捕获

### Q4: 如何在 Webview 环境中进行性能监控和错误上报？
- **性能监控**: 
  - 使用 `Performance API` 记录首屏时间、资源加载耗时。
  - 针对 Canvas 渲染耗时，在关键函数前后记录时间戳。
- **错误上报**:
  - 监听 `window.onerror` 和 `unhandledrejection`。
  - 专门针对 WASM 模块（如 MuPDF）的初始化错误进行捕获。
  - 通过 Bridge 将错误日志发送回原生端，由原生端统一上报至监控平台（如 Sentry）。
