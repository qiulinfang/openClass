# 作业板块首次加载渲染异常修复记录

> **文档版本**：v1.0  
> **修复日期**：2026-05-22  
> **影响范围**：作业作答板块（HomeworkAnswerView）、题目列表（QuestionList）、IndexedDB 通用存储服务  
> **严重等级**：高（首次进入页面渲染失败、数据读取异常）

---

## 一、现象描述

### 1.1 用户可见现象
用户在**第一次**进入"作业作答"板块时（即浏览器缓存中无相关数据库连接的初次访问场景），出现以下异常：

1. **题目背景图未渲染**：白板区域应该显示渲染好的题目内容（题干 + 数学公式 + 图片），但实际显示为空白。
2. **快速切换题目时渲染不更新**：在题目列表上连续点击多个题目，UI 仍然停留在第一道题的状态，即使日志显示题目 ID 已经切换。
3. **作答数据丢失**：从 IndexedDB 加载历史作答数据失败，已经做过的题目恢复不出笔迹。
4. **错题状态显示异常**：题目列表中"往日错题"标签初始化失败。

### 1.2 控制台异常日志

#### 1.2.1 IndexedDB 错误（高频）

注意 `currentAnswerQuestion` 始终是 `410724469323173888`，但是切换目标却在不断变化，说明 `handleStartAnswer` 被并发触发，前一次的状态更新还没生效，下一次的调用就已经进来了。

### 1.3 复现条件
- **必要条件**：浏览器首次访问该 Web 应用，或者 IndexedDB 数据库刚被删除/重建。
- **触发动作**：从作业列表页（`MyHomeworkView`）点击进入作业作答页（`HomeworkAnswerView`）。
- **必要数据规模**：作业中题目数量 ≥ 5 道（数量越多，错题状态批量查询的并发越高，越容易触发问题）。

## 二、根因分析

### 2.1 根因一：IndexedDB 并发初始化竞态（核心崩溃源）

#### 2.1.1 调用链路
首次进入页面时，下列调用几乎同时发生：

| 时间点 | 调用方 | 操作的数据库 |
| --- | --- | --- |
| T0 | `homeworkStore.loadHomeworkSubmissionFromDB()` | `HomeworkStorageDB_${userId}` |
| T0+ | `QuestionList` 中 `watch(questions)` 触发 `updateMistakeStatus()`，对每道题并行调用 `isMistake()` | `MistakeStorageDB_${userId}` |
| T0+ | `HomeworkAnswerView` 中 `watch(currentAnswerQuestion)` 触发 `initMistakeStatus()` | `MistakeStorageDB_${userId}` |

#### 2.1.2 竞态产生的原因
原 `IndexedDBService.init()` 实现：

```typescript
public async init(): Promise<void> {
  if (this.isInitialized && this.db) {
    return
  }
  return new Promise((resolve, reject) => {
    const request = indexedDB.open(this.config.dbName, this.config.version)
    // ...
  })
}
```

**问题**：当 `init` 在第一次调用尚未 `resolve` 时被第二次调用，`isInitialized` 仍为 `false`，于是会发起**第二次** `indexedDB.open()`。如果有 50 道题，则会并发触发 50 次 `indexedDB.open()`。

#### 2.1.3 浏览器侧表现
浏览器对同一个 (dbName, version) 的并发 open 处理策略并不一致：
- 某些 open 请求会成功，但可能拿到的是**已经被关闭的旧连接**句柄。
- `request.result` 拿到的 `IDBDatabase` 在尝试 `transaction()` 时，底层连接处于 closing 状态，抛出 `InvalidStateError`。

这就是日志里 `The database connection is closing` 的根本原因。

### 2.2 根因二：渲染链路并发竞态

#### 2.2.1 渲染链路概览
`handleStartAnswer` 是题目切换的入口，完整链路如下：

```
handleStartAnswer(question)
  ├── saveCurrentPage(oldQuestion)            // 保存上一题
  │     └── 触发 htmlToImage.toPng() 截图（同步等待）
  ├── 更新 currentAnswerQuestion / questionHtml
  ├── nextTick()
  ├── restoreCurrentPage(question)            // 恢复笔迹
  └── setTimeout(updateQuestionBackgroundImage, 50)
        └── MathJaxUtils.renderMathAndWait()
        └── 等待图片加载
        └── htmlToImage.toPng()               // 生成背景图
```

整个链路涉及 **DOM 更新 → MathJax 异步渲染 → 图片加载 → html-to-image 截图**，依赖大量异步任务。

#### 2.2.2 并发触发场景
首次进入页面时：
1. `onMounted` 调用 `handleStartAnswer(targetQuestion)` —— 第一次。
2. 与此同时 `QuestionList` 自身也会触发 `selectQuestion` 并 emit `questionSelected`，导致 `handleStartAnswer` 被再次调用 —— 第二次。
3. 用户看到列表渲染完成后又快速点击其他题目 —— 第三次、第四次……

由于原版 `handleStartAnswer` 没有"正在执行中"的状态保护，多个调用会**重叠**执行，互相覆盖：
- 任务 A 刚把 `questionHtml` 设为题目 1，准备截图。
- 任务 B 同步把 `questionHtml` 改为题目 2。
- 任务 A 拿到的是任务 B 写入的 DOM 内容，截图错乱。

### 2.3 根因三：组件挂载时 ref 时间差

#### 2.3.1 问题代码
```typescript
const restoreCurrentPage = (question: ExerciseItem | null) => {
  const board = drawingBoardRefs.value[0]
  if (!board) return  // 静默返回
  // ...
}
```

#### 2.3.2 触发时机
在 `onMounted` → `handleStartAnswer` → `restoreCurrentPage` 链路中：
- `DrawingBoardNew` 由于 `v-if="!isHomeworkLocked"` 等条件，可能还在 patching 中。
- 此时 `drawingBoardRefs.value[0]` 为 `null`，`restoreCurrentPage` 直接 return，笔迹永远恢复不上。

### 2.4 根因四：截图阶段 DOM 内容尚未填充

`updateQuestionBackgroundImage` 中读取的 `questionRenderRef` 是一个隐藏的 div：
```html
<div ref="questionRenderRef" class="question-render-hidden markdown-content">
  <template v-if="currentAnswerQuestion?.structuredContent"> ... </template>
  <div v-else v-html="questionHtml"></div>
</div>
```

由于 Vue 模板渲染是异步的，在某些极端情况下（首次加载，资源较多），即使 `await nextTick()` 也无法保证 `innerHTML` 已经被填充完成，`html-to-image` 会捕获到空 DOM，输出空白图片。

## 三、解决方案

### 3.1 修复一：IndexedDB 单例化初始化保护

**文件**：`@/Project/xueban-qianduan/imates-web/src/services/storage/indexeddb-service.ts`

#### 3.1.1 关键改动

```typescript
export class IndexedDBService {
  // 新增字段
  private initPromise: Promise<void> | null = null

  public async init(): Promise<void> {
    if (this.isInitialized && this.db) return
    
    // 关键：复用进行中的初始化 Promise
    if (this.initPromise) return this.initPromise

    this.initPromise = new Promise((resolve, reject) => {
      const request = indexedDB.open(this.config.dbName, this.config.version)

      request.onerror = () => {
        this.initPromise = null  // 失败时清空，允许重试
        reject(...)
      }

      request.onsuccess = () => {
        this.db = request.result
        this.isInitialized = true
        this.initPromise = null

        // 新增：监听版本变更，避免连接残留
        this.db.onversionchange = () => {
          console.warn(`[IndexedDB] 数据库 ${this.config.dbName} 版本正在变更，关闭连接`)
          this.close()
        }

        // 新增：监听连接关闭，重置标志位
        this.db.onclose = () => {
          this.isInitialized = false
          this.db = null
        }

        this.ensureStoresExist()
        resolve()
      }

      request.onupgradeneeded = (event) => { ... }
      request.onblocked = () => {
        console.warn(`[IndexedDB] 数据库 ${this.config.dbName} 被阻塞，请关闭其它标签页`)
      }
    })

    return this.initPromise
  }
}
```

#### 3.1.2 修复原理
- **`initPromise` 单例**：确保无论有多少并发调用 `init()`，全局只会执行一次 `indexedDB.open()`，其余请求复用同一个 Promise。
- **`onversionchange`**：当其他标签页升级数据库版本时，主动关闭本页连接，避免持有过期连接。
- **`onclose`**：浏览器异常关闭连接时，重置 `isInitialized`，让下次请求重新打开。
- **`onblocked`**：增加诊断日志，帮助排查多标签场景。

### 3.2 修复二：题目切换并发互斥锁

**文件**：`@/Project/xueban-qianduan/imates-web/src/views/HomeworkAnswerView.vue`

#### 3.2.1 关键改动

```typescript
// 新增标志位
const isSwitchingQuestion = ref(false)

const handleStartAnswer = async (question: ExerciseItem) => {
  // 守卫一：正在切换中，直接拒绝
  if (isSwitchingQuestion.value) {
    console.log('[HOMEWORK_IMAGE_PROCESS] handleStartAnswer: 正在切换中，跳过本次请求')
    return
  }

  const questionKey = getQuestionKey(question)
  const oldQuestionKey = getQuestionKey(currentAnswerQuestion.value)

  // 守卫二：同一题，跳过
  if (oldQuestionKey === questionKey && questionKey !== '') return

  try {
    isSwitchingQuestion.value = true
    
    // ... 原有切换逻辑 ...
    
  } finally {
    isSwitchingQuestion.value = false
  }
}
```

#### 3.2.2 修复原理
- 与"重复调用守卫"一起组成两层防护：
    - **守卫一**：阻止并发执行（同一时间最多一个 `handleStartAnswer` 在跑）。
    - **守卫二**：阻止重复执行（已经是当前题目就不再处理）。
- `try/finally` 确保即使中途抛错也会正确释放锁。

### 3.3 修复三：DrawingBoard 引用延迟重试

**文件**：`@/Project/xueban-qianduan/imates-web/src/views/HomeworkAnswerView.vue`

```typescript
const restoreCurrentPage = (question: ExerciseItem | null) => {
  const board = drawingBoardRefs.value[0]
  if (!board) {
    console.warn('[HOMEWORK_IMAGE_PROCESS] restoreCurrentPage: drawingBoardRefs.value[0] 为空, 尝试延迟执行')
    setTimeout(() => {
      const retryBoard = drawingBoardRefs.value[0]
      if (retryBoard) {
        restoreCurrentPage(question)
      } else {
        console.error('[HOMEWORK_IMAGE_PROCESS] restoreCurrentPage: 延迟执行依然失败')
      }
    }, 200)
    return
  }
  // ... 正常恢复逻辑 ...
}
```

#### 3.3.1 修复原理
- 200ms 后再次检查 `drawingBoardRefs`，覆盖了 Vue 组件挂载延迟的常见场景。
- 避免了"静默失败"，且日志便于诊断。

### 3.4 修复四：截图前 DOM 内容稳定性检查

**文件**：`@/Project/xueban-qianduan/imates-web/src/views/HomeworkAnswerView.vue`

```typescript
// updateQuestionBackgroundImage 内部
if (!el.innerHTML || el.innerHTML.trim() === '') {
  console.warn('[HOMEWORK_IMAGE_PROCESS] updateQuestionBackgroundImage: 隐藏容器内容目前为空，等待渲染...')
  await nextTick()
  // 二次重试，给 100ms 缓冲
  if (!el.innerHTML || el.innerHTML.trim() === '') {
    await new Promise(resolve => setTimeout(resolve, 100))
  }
  if (isStale()) return
  if (!el.innerHTML || el.innerHTML.trim() === '') {
    console.error('[HOMEWORK_IMAGE_PROCESS] updateQuestionBackgroundImage: 隐藏容器内容依然为空，截图可能失败')
  }
}
```

#### 3.4.1 修复原理
- **第一次 `nextTick`**：等待当前 Vue 渲染队列完成。
- **第二次 100ms 延迟**：覆盖跨多个 microtask 才能完成的复杂场景（如递归组件、动态 import）。
- **isStale 检查**：在等待期间如果发生新的题目切换，立即放弃当前截图任务，避免覆盖新数据。

### 3.5 修复五：错题状态批量查询优化

**文件**：`@/Project/xueban-qianduan/imates-web/src/components/QuestionList.vue`

#### 3.5.1 改动前（N+1 查询）

```typescript
const updateMistakeStatus = async () => {
  const statusMap = new Map<string, boolean>()
  const promises = questions.value.map(async (q) => {
    const id = getQuestionUniqueId(q)
    if (id) {
      const isM = await isMistake(id)  // 每题一次 IndexedDB 查询
      statusMap.set(id, isM)
    }
  })
  await Promise.all(promises)
  mistakeStatus.value = statusMap
}
```

50 道题就是 50 次并发数据库查询，是触发并发竞态的主要源头之一。

#### 3.5.2 改动后（批量 + 内存比对）

```typescript
import { isMistake, getAllMistakes } from '../services/storage/mistake-storage'

const updateMistakeStatus = async () => {
  try {
    const allMistakes = await getAllMistakes()  // 一次性拉全量
    const mistakeIds = new Set(allMistakes.map(m => m.bmNo))
    
    const statusMap = new Map<string, boolean>()
    questions.value.forEach((q) => {
      const id = getQuestionUniqueId(q)
      if (id) statusMap.set(id, mistakeIds.has(id))
    })
    mistakeStatus.value = statusMap
  } catch (error) {
    console.error('[QuestionList] ❌ 批量更新错题状态失败:', error)
  }
}
```

#### 3.5.3 收益
- IndexedDB 查询数从 **N 次** 降为 **1 次**。
- 即使 `IndexedDBService` 没有单例保护，也能避免触发并发问题。
- 性能提升明显（理论上 50 题查询从 200ms+ 降到 20ms 以内）。

## 六、经验总结

### 6.1 设计原则
1. **单例资源必须有并发保护**：所有"全局只能初始化一次"的资源（数据库、WebSocket、SDK），都应在 init 函数中使用 `initPromise` 模式。
2. **异步流程必须有锁**：长链路异步任务（涉及 DOM、网络、定时器多重依赖）必须用互斥锁防止重入，并配合"过期任务"标志（`isStale`）做最终防护。
3. **批量优于循环**：能用一次查询解决的事情绝不放在循环里查 N 次，特别是 IO 操作。

### 6.2 排查流程
本次问题定位的关键日志链：
1. 通过用户提供的"题目切换日志短时间内多次重复"识别出**并发问题**。
2. 通过 `connection is closing` 错误定位到 **IndexedDB 层**。
3. 通过 `restoreCurrentPage: drawingBoardRefs.value[0] 为空` 定位到**组件挂载时间差**。
4. 通过`updateQuestionBackgroundImage` 链路日志确认了**截图任务空 DOM** 的边缘情况。

### 6.3 后续可优化项
- [ ] 全局 IndexedDB 健康监控：定期检查连接状态，自动重连。
- [ ] 题目截图缓存持久化：`questionImageCache` 当前只在内存，刷新即丢失，可考虑持久化到 IndexedDB。
- [ ] DrawingBoard 组件挂载完成事件：通过 emit 事件主动通知父组件，替代 200ms 轮询。
- [ ] 引入 `dexie` 等成熟封装库逐步替换自研 `IndexedDBService`。
