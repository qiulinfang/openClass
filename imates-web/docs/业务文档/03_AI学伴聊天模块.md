# AI 学伴聊天模块

## 1. 业务逻辑
- **多维度引导**: 支持通用对话、基于特定题目的答疑（SolvingBot）、数学公式专项辅导。
- **启发式提问**: AI 被设定为“学伴”角色，倾向于引导学生思考而非直接告知结果。
- **上下文感知**: 对话能自动感知学生当前正在看的题目（bmNo）或正在查阅的教材章节。
- **记忆管理**: 学生可手动删除单条消息或清空整个会话，以释放“脑容量”。

## 2. 技术实现

### 2.1 流式输出与轮询机制
- **方案选择**: 由于 WebView 环境下 SSE/WebSocket 某些限制，采用了**基于轮询 (Polling) 的伪流式实现**。
- **工作流**: 
  1.  前端发送消息请求。
  2.  后端立即返回任务 ID 或首帧。
  3.  前端以固定频率（如 500ms）轮询后端，获取后续内容片段。
  4.  解析 SSE 格式的报文（如 `data: { "content": "..." }`）。
  5.  检测到 `"message": "end"` 时停止轮询。

### 2.2 打字机渲染效果
- **实现**: 前端维护一个响应式字符串，随着轮询内容的到达不断累加。
- **体验**: 通过 CSS 动画或特定的 `onStream` 回调频率控制，模拟自然的打字交互。

### 2.3 历史记录持久化
- **云端同步**: 每次对话内容均通过后端接口进行存储。
- **记忆裁剪**: 调用 `/history_manage` 接口对 LLM（大模型）的上下文窗口进行精细化控制。
- **本地状态**: Pinia 实时维护当前会话的 `messages` 数组。
