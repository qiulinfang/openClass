# 新增接口开发流程规范 (Skills)

本档总结了在 `imates-web` 项目中新增一个后端接口（或服务模块）的完整标准流程。

## 1. 环境配置 (Environment Config)
首先需要在 `@/config/env-config.ts` 中定义服务的基准地址和路由映射。

- **定义基准地址**: 在 `ADDRESS_CATALOG` 中添加服务域名。
- **配置路由映射**: 在 `getRouteBaseMap()` 中增加前缀映射。这对于 **Android (file://)** 环境下的路径识别至关重要。

```typescript
// @/config/env-config.ts
export const ADDRESS_CATALOG = {
  NEW_SERVICE: 'https://api.example.com',
};

export function getRouteBaseMap() {
  return {
    '/new-prefix': ADDRESS_CATALOG.NEW_SERVICE, // 确保 HttpClient 能识别相对路径
  };
}
```

## 2. Vite 代理配置 (Local Development)
为了在本地开发时解决跨域问题，需在 `vite.config.ts` 中配置代理。

```typescript
// vite.config.ts
proxy: {
  '/new-prefix': {
    target: ADDRESS_CATALOG.NEW_SERVICE,
    changeOrigin: true,
    secure: false,
    configure: (proxy) => attachBasicProxyLog(proxy, '/new-prefix')
  }
}
```

## 3. API 类定义 (Service Layer)
在 `@/services/http/` 目录下创建对应的 API 类，使用 `httpClient` 发起请求。**注意：始终使用相对路径，不要在接口中硬编码完整 URL。**

```typescript
// @/services/http/new-service-api.ts
import { httpClient } from './http-client';

export class NewServiceApi {
  public async getData(params: any) {
    // HttpClient 会根据环境自动补全 URL 或走代理
    return httpClient.get('/new-prefix/get_data', { params });
  }
}
```

## 4. 服务入口集成 (API Service)
将新建的 API 类实例化并集成到 `api-service.ts` 的 `ApiService` 类中，作为全局调用的统一入口。

```typescript
// @/services/http/api-service.ts
export class ApiService {
  public readonly newServiceApi = new NewServiceApi();
  
  // 封装快捷调用方法
  public async getNewData(params: any) {
    return this.newServiceApi.getData(params);
  }
}
```

## 5. 文档与测试 (Documentation & Testing)
- **接口文档**: 在 `imates-web/docs/` 下创建对应的 `.md` 文档。
- **测试页面**: 在 `src/views/ApiTest/` 下创建测试组件，并集成到 `ApiTestIndex` 导航中，确保接口可验证。

---
**核心原则**:
1. **相对路径**: 接口调用处只写 `/prefix/endpoint`。
2. **环境自动感知**: 通过 `getRouteBaseMap` 处理原生环境，通过 `vite.config` 处理开发环境。
3. **单点维护**: 域名统一维护在 `env-config.ts`。
