# 问题总结命令

按照下面要求总结此次对话遇到的每一个问题，如果某个问题已经总结则可以跳过。

## 要求1：文档格式

每个问题文档必须包含以下部分（使用 Markdown 格式）：

```markdown

问题序号：问题名称

## 问题元信息
- **问题分类**：`[前端/后端/数据库/架构/性能/安全/兼容性/其他]`
- **严重程度**：`[严重/高/中/低]`
- **影响范围**：`[影响的功能模块或用户群体]`
- **发现日期**：`YYYY-MM-DD`
- **解决状态**：`[已解决/进行中/待解决]`

## 问题现象
（描述问题的具体表现，包括错误信息、异常行为等）

## 复现步骤
1. 步骤1：描述如何触发问题
2. 步骤2：描述问题发生的条件
3. 步骤3：描述问题的具体表现
（如果问题无法复现，说明原因）

## 用户体验
（描述问题对用户体验的影响，使用列表格式）
- 影响点1
- 影响点2
- 影响点3

## 相关文件/模块
- **涉及文件**：
  - `文件路径1`：说明
  - `文件路径2`：说明
- **涉及模块**：
  - 模块1：说明
  - 模块2：说明

## 技术原因 (❌)
（描述导致问题的技术原因，使用列表格式）
1. 原因1：详细说明
2. 原因2：详细说明
3. 原因3：详细说明

（包含错误的代码示例，使用代码块）

## 正确实现方案 (✅)
（描述正确的解决方案，使用列表格式）
1. 方案1：详细说明
2. 方案2：详细说明
3. 方案3：详细说明

（包含正确的代码示例，使用代码块）

## 关键代码/公式
（提供关键代码片段和公式，使用代码块）
- 代码片段1：说明
- 代码片段2：说明
- 公式/算法：说明

## 测试验证
- **测试场景**：
  - 场景1：测试步骤和预期结果
  - 场景2：测试步骤和预期结果
- **验证方法**：
  - 方法1：如何验证问题已解决
  - 方法2：如何验证不会再次出现

## 预防措施
（如何避免类似问题再次发生）
- 措施1：说明
- 措施2：说明
- 措施3：说明

## 相关链接/参考
- 相关文档：`[链接或路径]`
- 相关Issue：`[链接]`
- 参考资源：`[链接或说明]`

## 可复用经验
（从这个问题中总结出的可复用经验、最佳实践、设计模式等）
- 经验1：说明
- 经验2：说明
- 经验3：说明
```

## 要求2：输出位置

- 输出目录：`.specstory\sum\`
- 如果目录不存在，需要先创建

## 要求3：文件命名

- 格式：`日期_问题名称.md`
- 日期格式：`YYYYMMDD`（例如：`20251108`）
- 问题名称：使用简洁的问题描述，使用中文
- 示例：
  - `20251108_Cursor聊天记录导出统计不准确问题.md`
  - `20251108_持久化数据账号隔离问题.md`
  - `20251108_IndexedDB索引不存在问题.md`

## 检查机制

在总结问题前，先检查 `.specstory\sum\` 目录下是否已存在相同问题的文件：
- 如果已存在相同问题的文件，则跳过
- 如果不存在，则创建新文件

## 注意事项

1. **每个问题单独一个文件**：确保问题文档独立，便于管理和查找
2. **使用 Markdown 格式**：确保代码块有正确的语言标识（如 `typescript`、`python`、`java` 等）
3. **标记清晰**：错误代码使用 `❌` 标记，正确代码使用 `✅` 标记
4. **代码示例完整**：包含必要的上下文，便于理解问题场景
5. **关键代码突出**：关键代码/公式部分要突出重要的实现细节
6. **元信息必填**：问题元信息部分必须填写，便于后续分类和检索
7. **复现步骤详细**：如果问题可以复现，必须提供详细的复现步骤
8. **相关文件明确**：列出所有涉及的文件和模块，便于快速定位
9. **测试验证充分**：提供测试场景和验证方法，确保问题真正解决
10. **预防措施具体**：提供具体的预防措施，避免类似问题再次发生

## 结构说明

### 必填部分
以下部分必须填写：
- 问题元信息
- 问题现象
- 技术原因
- 正确实现方案
- 关键代码/公式

### 可选部分
以下部分根据实际情况填写，如果无法提供可以省略：
- 复现步骤（如果问题无法复现）
- 相关链接/参考（如果没有相关资源）
- 可复用经验（如果问题过于简单或特殊）

### 结构优势
增强后的文档结构具有以下优势：
1. **信息完整**：从问题发现到解决的全流程记录
2. **便于检索**：通过元信息可以快速分类和查找问题
3. **易于维护**：清晰的结构便于后续更新和维护
4. **知识沉淀**：预防措施和可复用经验帮助团队积累知识
5. **问题追踪**：解决状态可以追踪问题的处理进度
